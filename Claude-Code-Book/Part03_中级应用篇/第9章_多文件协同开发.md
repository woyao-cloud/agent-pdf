## 9.2 多模块开发策略

### 9.2.1 模块划分原则

**模块划分准则**

1. **单一职责**：每个模块只负责一项功能
2. **高内聚低耦合**：模块内部紧密相关，模块之间依赖最小化
3. **清晰接口**：模块通过明确定义的接口通信
4. **层次分明**：按功能层次组织模块

**模块结构示例**

```text
my-project/
├── src/
│   ├── core/           # 核心功能
│   ├── features/       # 业务功能
│   ├── infrastructure/ # 基础设施
│   └── api/            # 接口层
```

### 9.2.2 接口设计

**RESTful API 设计**

```python
# 好的接口设计
GET    /api/users          # 获取用户列表
GET    /api/users/{id}     # 获取单个用户
POST   /api/users          # 创建用户
PUT    /api/users/{id}     # 更新用户
DELETE /api/users/{id}     # 删除用户
```

## 9.3 团队协作流程

### 9.3.1 代码审查

**Git Flow 工作流**

```text
main ──────●───────●───────●───
              │       │       └── merge
              │       │
    feature/a ──●───●───●───●
              │       │
    feature/b ──●──●──●───
                        └── merge
```

**代码审查清单**

```markdown
- [ ] 代码符合项目规范
- [ ] 有适当的测试覆盖
- [ ] 没有安全漏洞
- [ ] 性能可接受
- [ ] 文档已更新
```
