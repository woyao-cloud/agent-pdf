# 第9章 设备管理

设备管理是制造执行系统（MES）的核心模块之一，承担着保障生产设备高效稳定运行的重要职责。在离散制造业和流程制造业中，设备是生产的基础，设备管理的好坏直接影响到产能、质量和成本。本章将详细讲解设备管理概述、OEE计算与监控、设备维护管理、设备联网与数据采集四大核心内容。

## 9.1 设备管理概述

设备管理是指对企业生产设备进行全生命周期管理的一系列活动，包括设备规划、选购、安装、调试、使用、维护、改造直至报废的全过程管理。在MES系统中，设备管理主要关注设备的基础信息管理、状态监控、运行效率分析和维护管理，为生产调度和质量控制提供设备层面的支撑。

### 9.1.1 设备分类与编码

设备分类与编码是设备管理的基础，通过科学的分类体系和编码规则，实现设备的规范化管理，便于设备信息的检索、统计和分析。

#### 设备分类体系

设备分类通常采用多层级结构，根据企业的管理需求和设备特点进行划分。第一层级按设备大类分类，如通用设备、专用设备、动力设备、检测设备等；第二层级按设备中类细分，如通用设备下设机床、起重设备、焊接设备等；第三层级按设备小类进一步细分，如机床下设车床、铣床、钻床等。

在制造业中，常用的设备分类方式包括按用途分类、按生产方式分类和按自动化程度分类。按用途分类可分为生产设备（直接参与产品加工的设备）、辅助设备（支持生产但不直接加工的设备）和检测设备（用于质量检测和测量的设备）。按生产方式分类可分为离散制造设备（如数控机床、注塑机、装配线）和流程制造设备（如反应釜、蒸馏塔、灌装机）。按自动化程度分类可分为手动设备、半自动设备和全自动设备。


#### 设备编码规则

设备编码应遵循唯一性、规律性、扩展性和可读性原则。唯一性要求每台设备对应唯一编码，不同型号、不同规格的设备必须区分编码；规律性要求编码具有一定的逻辑结构，便于人工识别和系统处理；扩展性要求编码预留足够的长度空间，支持未来业务增长；可读性要求编码能够直观反映设备类别或特征。

常见的设备编码规则包括分类编码法、顺序编码法和复合编码法。分类编码法按照设备所属类别进行编码，例如按设备大类用一位字母表示（A-生产设备、B-辅助设备、C-检测设备），再在类内按顺序编排。顺序编码法按照设备入库顺序依次编号，优点是简单易行，缺点是无法从编码判断设备类别。复合编码法结合分类编码和顺序编码，是企业最常用的编码方式。

以某汽车零部件制造企业为例，其设备编码采用10位复合编码结构：第1位表示设备大类（P-生产设备、S-辅助设备、Q-检测设备），第2-3位表示设备中类（如P01-加工中心、P02-冲压设备），第4-5位表示设备小类（如P0101-立式加工中心、P0102-卧式加工中心），第6-10位表示顺序号。这种编码结构能够支持约10万台设备的编码需求，且从编码即可判断设备类型和大概位置。

### 9.1.2 设备状态定义

设备状态是设备管理中的核心概念，准确的设备状态定义和实时状态采集是设备效率分析和维护计划制定的基础。设备状态通常分为运行状态、待料状态、故障状态、维修状态、保养状态、停机状态等多种类型。

#### 状态分类与定义

设备运行状态（RUNNING）是指设备正常运行、完成加工任务的狀态。在运行状态下，设备应当有产出，记录设备的运行时间、产量和能耗等数据。设备空转或空载运行也属于运行状态的一种特殊情况。

设备待料状态（IDLE）是指设备正常但因缺少物料、等待上工序、等待订单等原因无法继续生产的状态。待料状态需要记录待料原因和待料时长，用于分析生产瓶颈和优化排程。

设备故障状态（FAULT）是指设备发生异常、无法正常生产的狀态。故障状态需要记录故障发生时间、故障现象、故障原因等信息，为设备维护和故障分析提供数据支撑。

设备维修状态（MAINTENANCE）是指设备正在进行维修或检修的状态。维修状态需要记录维修开始时间、维修类型（自修、外修）、维修人员、维修内容等信息。

设备保养状态（MAINTAINING）是指设备正在进行计划性保养或点检的状态。包括日常保养、定期保养和设备点检等活动。

设备停机状态（STOPPED）是指设备因计划性原因（如节假日、搬迁）或非计划性原因（如安全检查）暂时停用的状态。计划性停机通常可以预测和安排，非计划性停机需要分析原因并采取措施减少。

#### 状态采集方式

设备状态的采集方式直接影响数据的准确性和及时性。常见的状态采集方式包括人工填报、传感器采集和系统对接三种。

人工填报是最简单的方式，通过MES终端或移动设备由操作人员手动选择设备状态。这种方式优点是实施成本低、灵活性高，缺点是依赖人工操作、可能存在滞后和误差。人工填报适用于设备数量较少、对实时性要求不高的场景。

传感器采集通过安装各类传感器（如电流传感器、温度传感器、振动传感器）实时采集设备运行参数，结合算法判断设备状态。这种方式优点是数据准确、实时性高，缺点是实施成本高、需要维护传感器。传感器采集适用于关键设备和对实时性要求高的场景。

系统对接通过与设备自身的控制系统（如PLC、DCS）进行数据交换获取设备状态。这种方式优点是数据最为准确、不需要额外硬件，缺点是需要设备支持通信协议、可能需要设备厂商配合。系统对接是现代化工厂设备状态采集的主流方式。

## 9.2 OEE计算与监控

设备综合效率（Overall Equipment Effectiveness，简称OEE）是衡量设备生产效率的重要指标，通过对设备可用率、性能率和合格率的综合计算，全面评估设备的实际生产能力与理论能力的差距。OEE是精益生产的重要工具，被广泛应用于设备效率分析和持续改进。

### 9.2.1 OEE公式与计算

OEE由三个核心指标组成：可用率（Availability）、性能率（Performance）和合格率（Quality）。OEE的计算公式为：OEE = 可用率 × 性能率 × 合格率。这三个指标分别从时间、速度和质量三个维度评估设备效率。

#### 可用率计算

可用率反映设备的实际运行时间占计划运行时间的比例，计算公式为：可用率 = 实际运行时间 / 计划运行时间 × 100%。实际运行时间是指设备处于运行状态的时间减去非计划停机时间（如故障停机、待料停机）。计划运行时间是指扣除计划停机（如休息时间、保养时间）后的可用生产时间。

可用率计算的关键是准确区分计划停机和非计划停机。计划停机包括休息时间、吃饭时间、设备保养时间、换型时间等；非计划停机包括设备故障、缺料、质量异常、异常停机等。MES系统需要详细记录每种停机类型的发生时间和持续时长，以便准确计算可用率。

```sql
-- 可用率计算示例（按班次）
SELECT
    e.equipment_id,
    e.equipment_name,
    s.shift_date,
    s.shift_code,
    -- 计划运行时间 = 班次时长 - 计划停机时间
    (s.shift_duration_minutes - COALESCE(s.plan_stop_minutes, 0)) AS planned_run_minutes,
    -- 实际运行时间 = 运行状态时长
    COALESCE(SUM(CASE WHEN el.status_code = 'RUNNING' THEN el.duration_minutes ELSE 0 END), 0) AS actual_run_minutes,
    -- 可用率 = 实际运行时间 / 计划运行时间 × 100
    ROUND(
        COALESCE(SUM(CASE WHEN el.status_code = 'RUNNING' THEN el.duration_minutes ELSE 0 END), 0) * 100.0 /
        NULLIF((s.shift_duration_minutes - COALESCE(s.plan_stop_minutes, 0)), 0),
        2
    ) AS availability_rate
FROM equipment e
CROSS JOIN shift_schedule s
LEFT JOIN equipment_status_log el ON e.equipment_id = el.equipment_id
    AND DATE(el.start_time) = s.shift_date
    AND el.start_time >= s.shift_start_time
    AND el.end_time <= s.shift_end_time
WHERE e.equipment_id = 'EQ001'
GROUP BY e.equipment_id, e.equipment_name, s.shift_date, s.shift_code, s.shift_duration_minutes, s.plan_stop_minutes;
```

#### 性能率计算

性能率反映设备的实际产能与理论产能的比例，计算公式为：性能率 = 实际产出 / 理论产出 × 100%。实际产出是指设备在运行时间内实际生产的合格品数量（或标准工时产出）。理论产能是指设备在运行时间内按照标准节拍应该生产的数量。

性能率的关键是准确确定标准节拍（Cycle Time）。标准节拍是指设备完成一个工序或生产一个单位产品所需的标准时间，通常由工艺部门测定并维护。标准节拍应当考虑正常操作速度、设备调整时间等因素，并定期根据实际情况进行修订。

性能率小于100%说明设备运行速度低于标准节拍，可能的原因包括设备老化、操作人员不熟练、设备空转时间过长等。性能率超过100%可能说明标准节拍设定过于宽松，需要重新评估。

```sql
-- 性能率计算示例
SELECT
    e.equipment_id,
    e.equipment_name,
    s.shift_date,
    -- 实际产出数量
    SUM(p.actual_quantity) AS actual_output,
    -- 理论产出 = 运行时间 / 标准节拍
    ROUND(SUM(el.duration_minutes * 60) / NULLIF(e.standard_cycle_time, 0), 0) AS theoretical_output,
    -- 性能率 = 实际产出 / 理论产出 × 100
    ROUND(
        SUM(p.actual_quantity) * 100.0 /
        NULLIF(ROUND(SUM(el.duration_minutes * 60) / NULLIF(e.standard_cycle_time, 0), 0), 0),
        2
    ) AS performance_rate
FROM equipment e
LEFT JOIN production_records p ON e.equipment_id = p.equipment_id
LEFT JOIN equipment_status_log el ON e.equipment_id = el.equipment_id
    AND p.record_date = DATE(el.start_time)
WHERE el.status_code = 'RUNNING'
    AND p.product_id = 'P001'
    AND s.shift_date = '2024-01-15'
GROUP BY e.equipment_id, e.equipment_name, e.standard_cycle_time, s.shift_date;
```

#### 合格率计算

合格率反映设备产出中合格品的比例，计算公式为：合格率 = 合格品数量 / 总产出数量 × 100%。合格品数量是指通过质量检验的产品数量，不包括返工品、返修品和报废品。

合格率的计算需要与MES的质量管理模块紧密集成。每当设备完成一个批次或一定数量的生产时，系统应当自动记录产出数量，并关联质量检验结果。对于连续生产的情况，可以按照一定周期汇总计算合格率。

```sql
-- 合格率计算示例
SELECT
    e.equipment_id,
    e.equipment_name,
    s.shift_date,
    SUM(p.actual_quantity) AS total_output,
    SUM(CASE WHEN p.inspection_result = 'QUALIFIED' THEN p.actual_quantity ELSE 0 END) AS qualified_output,
    -- 合格率 = 合格品数量 / 总产出 × 100
    ROUND(
        SUM(CASE WHEN p.inspection_result = 'QUALIFIED' THEN p.actual_quantity ELSE 0 END) * 100.0 /
        NULLIF(SUM(p.actual_quantity), 0),
        2
    ) AS quality_rate
FROM equipment e
LEFT JOIN production_records p ON e.equipment_id = p.equipment_id
WHERE s.shift_date = '2024-01-15'
GROUP BY e.equipment_id, e.equipment_name, s.shift_date;
```

### 9.2.2 OEE分析与改进

OEE分析是将OEE指标分解为多个维度进行深入分析，找出设备效率损失的根本原因，并制定改进措施的过程。OEE分析通常采用层层分解的方法，从整体OEE到各类损失再到具体原因，逐步深入。

#### OEE损失分析

OEE损失可分为六大类：设备故障损失、安装调整损失、空转短暂停机损失、速度降低损失、开机不良损失和生产废品损失。这六大损失涵盖了所有导致设备效率下降的因素。

设备故障损失是指因设备突发故障导致的停机损失，包括机械故障、电气故障、液压故障等。减少故障损失的关键是加强设备预防性维护、提高设备可靠性。

安装调整损失是指因换型、换模、调试等导致的停机损失。在多品种小批量生产环境中，安装调整损失往往占比较大。减少安装调整损失的方法包括采用快速换型技术（SMED）、标准化换型流程、优化生产批次等。

空转短暂停机损失是指因物料短缺、质量异常、小故障等导致的短时间停机。这类停机通常时间较短但发生频繁，容易被忽视。减少这类损失需要加强生产准备、改进物料配送、提高异常响应速度。

速度降低损失是指设备运行速度低于标准节拍导致的产能损失。可能的原因包括设备老化、润滑不良、模具磨损、操作不当等。通过设备改造、工艺优化和人员培训可以减少速度损失。

开机不良损失是指设备启动到稳定生产阶段的产出损失。新班次开始、设备重启后需要一定时间达到稳定状态，这段时间的产出通常质量不稳定或效率较低。

生产废品损失是指因质量问题导致的合格品减少。包括返工品、返修品和报废品。减少废品损失需要加强质量控制、提高设备精度、改进工艺参数。

```sql
-- OEE综合计算查询
SELECT
    e.equipment_id,
    e.equipment_name,
    s.shift_date,
    -- 可用率
    ROUND(AVG(t.availability_rate), 2) AS availability_rate,
    -- 性能率
    ROUND(AVG(t.performance_rate), 2) AS performance_rate,
    -- 合格率
    ROUND(AVG(t.quality_rate), 2) AS quality_rate,
    -- OEE = 可用率 × 性能率 × 合格率
    ROUND(
        AVG(t.availability_rate) * AVG(t.performance_rate) * AVG(t.quality_rate) / 10000,
        2
    ) AS oee_rate
FROM (
    SELECT
        equipment_id,
        shift_date,
        -- 可用率
        ROUND(SUM(CASE WHEN status_code = 'RUNNING' THEN duration_minutes ELSE 0 END) * 100.0 /
            NULLIF(SUM(CASE WHEN status_code IN ('RUNNING', 'IDLE') THEN duration_minutes ELSE 0 END), 0), 2) AS availability_rate,
        NULL AS performance_rate,
        NULL AS quality_rate
    FROM equipment_status_log
    WHERE shift_date = '2024-01-15'
    GROUP BY equipment_id, shift_date
    UNION ALL
    SELECT
        equipment_id,
        record_date AS shift_date,
        NULL AS availability_rate,
        -- 性能率
        ROUND(actual_output * 100.0 / NULLIF(theoretical_output, 0), 2) AS performance_rate,
        NULL AS quality_rate
    FROM v_equipment_performance_rate
    UNION ALL
    SELECT
        equipment_id,
        record_date AS shift_date,
        NULL AS availability_rate,
        NULL AS performance_rate,
        -- 合格率
        ROUND(qualified_output * 100.0 / NULLIF(total_output, 0), 2) AS quality_rate
    FROM v_equipment_quality_rate
) t
JOIN equipment e ON t.equipment_id = e.equipment_id
JOIN shift_schedule s ON t.shift_date = s.shift_date
GROUP BY e.equipment_id, e.equipment_name, s.shift_date;
```

#### OEE改进方法

OEE改进是一个持续的过程，需要建立系统的改进方法和流程。首先要建立OEE监控机制，通过MES系统实时采集和展示OEE数据，使各级管理人员能够及时了解设备运行状况。其次要建立OEE目标管理体系，设定OEE目标值并分解到各部门和岗位，定期考核和改进。

OEE改进常用的方法是PDCA循环。Plan（计划）阶段分析OEE数据识别损失类型，制定改进计划；Do（执行）阶段实施改进措施；Check（检查）阶段评估改进效果；Act（处置）阶段固化成功经验、推广成功做法。持续的PDCA循环推动OEE不断提升。

### 9.2.3 设备监控

设备监控是MES系统中实时采集、展示设备运行状态和参数的功能模块，为生产调度和设备管理提供决策依据。设备监控通常包括状态监控、参数监控和报警监控三个方面。

#### 状态监控

状态监控实时展示设备的当前状态，包括运行、待料、故障、维修、停机等状态。状态监控界面通常采用图形化方式，如设备状态看板、甘特图、流程图等形式，直观展示设备分布和状态。状态监控应当支持按生产线、按车间、按设备类型等多维度查看。

```sql
-- 设备当前状态查询
SELECT
    e.equipment_id,
    e.equipment_name,
    e.category_id,
    ec.category_name,
    e.location_id,
    l.location_name,
    e.status AS current_status,
    COALESCE(latest_log.end_time, latest_log.start_time) AS status_start_time,
    TIMESTAMPDIFF(MINUTE, COALESCE(latest_log.end_time, latest_log.start_time), NOW()) AS status_duration_minutes,
    -- 计算今日OEE
    ROUND(
        (SELECT COALESCE(AVG(t.availability_rate), 0) FROM v_equipment_oee_daily t WHERE t.equipment_id = e.equipment_id AND t.shift_date = CURDATE()) *
        (SELECT COALESCE(AVG(t.performance_rate), 0) FROM v_equipment_oee_daily t WHERE t.equipment_id = e.equipment_id AND t.shift_date = CURDATE()) *
        (SELECT COALESCE(AVG(t.quality_rate), 0) FROM v_equipment_oee_daily t WHERE t.equipment_id = e.equipment_id AND t.shift_date = CURDATE()) / 10000,
        2
    ) AS today_oee
FROM equipment e
LEFT JOIN equipment_category ec ON e.category_id = ec.category_id
LEFT JOIN location l ON e.location_id = l.location_id
LEFT JOIN (
    SELECT equipment_id, start_time, end_time,
        ROW_NUMBER() OVER (PARTITION BY equipment_id ORDER BY start_time DESC) AS rn
    FROM equipment_status_log
) latest_log ON e.equipment_id = latest_log.equipment_id AND latest_log.rn = 1;
```

#### 参数监控

参数监控实时展示设备的关键运行参数，如温度、压力、转速、电流、振动等。参数监控需要与设备控制系统对接，实时采集参数数据，并以曲线图、仪表盘等形式展示。参数监控还应当支持参数趋势分析，帮助识别设备劣化趋势。

#### 报警监控

报警监控实时展示设备报警信息，包括设备故障报警、工艺参数超限报警、设备状态异常报警等。报警信息应当按照严重程度进行分级，如警告、异常、故障等，并推送给相应的人员。报警监控还应当支持报警历史查询和统计分析，帮助识别高频报警和重复报警。

## 9.3 设备维护管理

设备维护管理是指对设备进行预防性维护和故障维修的管理活动，目标是保持设备良好状态、减少设备故障、延长设备寿命。设备维护管理是设备管理的重要组成部分，与设备效率密切相关。

### 9.3.1 预防性维护

预防性维护（Preventive Maintenance，PM）是指按照预定计划对设备进行定期检查、保养和维修的活动，目的是防止设备故障发生或早期发现设备隐患。预防性维护的核心是计划性，通过定期维护避免设备突发故障。

#### 维护计划制定

维护计划的制定需要考虑设备的重要性、运行时间、故障历史等多方面因素。关键设备应当制定更频繁、更详细的维护计划，非关键设备可以适当简化。维护计划通常包括日点检、周保养、月保养、季度保养、年度保养等多个层次，每个层次有不同的检查和保养内容。

维护计划还应与生产计划协调，避免在生产高峰期进行大规模维护。对于连续生产的企业，需要制定滚动维护计划，利用生产间隙进行设备维护。

#### 维护执行管理

维护计划下达后，维护人员需要按照计划执行维护任务。MES系统应当支持维护任务的派工、执行、验收等流程管理。维护人员通过终端接收维护任务，记录维护过程中的发现和处理情况，维护完成后由管理人员进行验收。

维护执行过程中发现的异常情况应当及时记录，并生成相应的故障报修或改善建议。对于需要备件的维护任务，系统应当支持备件申请和领用流程，确保备件及时供应。

### 9.3.2 预测性维护

预测性维护（Predictive Maintenance，PdM）是指基于设备状态监测数据和历史维护数据，预测设备未来可能发生的故障，并提前进行维护的活动。与预防性维护相比，预测性维护更加精准，能够在设备真正需要维护时才进行维护，避免过度维护或维护不足。

#### 预测性维护技术

预测性维护依赖于设备状态监测技术和数据分析技术。设备状态监测技术包括振动监测、温度监测、油液分析、超声检测、红外热成像等多种手段。这些技术能够实时采集设备运行状态数据，反映设备的劣化程度。

数据分析技术包括统计分析和机器学习两大类。统计分析方法包括趋势分析、阈值分析、相关性分析等，用于识别设备参数的变化趋势和异常模式。机器学习方法能够建立设备故障预测模型，从大量历史数据中学习故障规律，提高预测准确性。

```sql
-- 设备状态监测数据表
CREATE TABLE equipment_monitoring (
    monitoring_id VARCHAR(36) PRIMARY KEY,
    equipment_id VARCHAR(36) NOT NULL,
    parameter_code VARCHAR(50) NOT NULL COMMENT '参数编码',
    parameter_name VARCHAR(100) NOT NULL,
    parameter_value DECIMAL(15,4) NOT NULL,
    unit VARCHAR(20),
    threshold_warning DECIMAL(15,4) COMMENT '警告阈值',
    threshold_alarm DECIMAL(15,4) COMMENT '报警阈值',
    status VARCHAR(20) COMMENT 'NORMAL:正常;WARNING:警告;ALARM:报警',
    collected_at TIMESTAMP NOT NULL,
    source_system VARCHAR(50) COMMENT '数据来源系统',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (equipment_id) REFERENCES equipment(equipment_id)
);

-- 设备健康评分计算（基于监测参数趋势分析）
CREATE PROCEDURE calculate_equipment_health_score(
    IN p_equipment_id VARCHAR(36),
    IN p_days INT
)
BEGIN
    DECLARE v_health_score DECIMAL(5,2) DEFAULT 100;

    -- 基于报警次数扣分
    SELECT GREATEST(0, 100 - COUNT(*) * 5) INTO v_health_score
    FROM equipment_monitoring
    WHERE equipment_id = p_equipment_id
        AND collected_at >= DATE_SUB(NOW(), INTERVAL p_days DAY)
        AND status = 'ALARM';

    -- 基于参数趋势扣分（参数持续上升或下降）
    SELECT GREATEST(0, v_health_score - COALESCE(SUM(trend_score), 0)) INTO v_health_score
    FROM (
        SELECT
            parameter_code,
            -- 计算参数变化斜率
            (LAST_VALUE(parameter_value) OVER w - FIRST_VALUE(parameter_value) OVER w) /
            NULLIF(DATEDIFF(MAX(collected_at) OVER w, MIN(collected_at) OVER w), 0) AS slope,
            CASE
                WHEN ABS(slope) > 10 THEN 10
                WHEN ABS(slope) > 5 THEN 5
                ELSE 0
            END AS trend_score
        FROM equipment_monitoring
        WHERE equipment_id = p_equipment_id
            AND collected_at >= DATE_SUB(NOW(), INTERVAL p_days DAY)
        WINDOW w AS (PARTITION BY parameter_code ORDER BY collected_at)
    ) trend_analysis;

    SELECT v_health_score AS health_score;
END;
```

#### 预测性维护实施

预测性维护的实施需要建立完善的数据采集、分析和决策体系。首先需要在关键设备上部署状态监测传感器，采集设备运行数据。然后建立数据分析平台，对采集的数据进行存储、处理和分析。最后建立维护决策机制，根据分析结果触发维护工单。

预测性维护的成本较高，通常只应用于关键设备和故障后果严重的设备。对于一般设备，可以采用预防性维护或事后维护的方式。企业在实施预测性维护时，应当进行效益分析，选择最合适的维护策略。

## 9.4 设备联网与数据采集

设备联网与数据采集是实现设备信息化管理的基础，通过网络连接和数据交换，将设备的运行状态、生产数据参数等信息实时传输到MES系统，为设备监控、效率分析和维护管理提供数据支撑。

### 9.4.1 工业通信协议

设备联网需要使用工业通信协议，常见的协议包括OPC UA、MQTT、Modbus、Profinet等。不同的协议适用于不同的场景，企业需要根据设备情况和实际需求选择合适的协议。

#### OPC UA协议

OPC UA（Open Platform Communications Unified Architecture）是一种平台无关的工业通信标准，支持设备数据采集、远程控制、事件报警等功能。OPC UA的主要特点包括：平台无关性（可在Windows、Linux、嵌入式系统等平台运行）、安全性（支持身份认证、加密传输）、信息模型扩展性（可自定义数据结构）。

OPC UA采用客户端-服务器架构，服务器端通常部署在设备侧或数据采集网关，MES系统作为客户端连接服务器获取数据。OPC UA支持多种数据访问方式，包括实时数据访问、历史数据访问、报警事件订阅等。

```python
# OPC UA连接示例（Python）
from opcua import Client, ua

class OPCUAClient:
    def __init__(self, url):
        self.url = url
        self.client = Client(url)

    def connect(self):
        self.client.connect()
        print(f"Connected to OPC UA server: {self.url}")

    def disconnect(self):
        self.client.disconnect()
        print("Disconnected from OPC UA server")

    def read_node(self, node_id):
        """读取节点值"""
        node = self.client.get_node(node_id)
        return node.get_value()

    def write_node(self, node_id, value):
        """写入节点值"""
        node = self.client.get_node(node_id)
        node.set_value(ua.Variant(value, ua.VariantType.Double))

    def subscribe_nodes(self, node_ids, callback):
        """订阅节点变化"""
        subscription = self.client.create_subscription(1000, callback)
        for node_id in node_ids:
            node = self.client.get_node(node_id)
            subscription.subscribe_data_change(node)

# 使用示例
if __name__ == "__main__":
    client = OPCUAClient("opc.tcp://192.168.1.100:4840")
    try:
        client.connect()

        # 读取设备运行参数
        speed = client.read_node("ns=2;i=2")  # 设备速度
        temperature = client.read_node("ns=2;i=3")  # 温度
        status = client.read_node("ns=2;i=4")  # 设备状态

        print(f"Speed: {speed}, Temperature: {temperature}, Status: {status}")

    finally:
        client.disconnect()
```

#### MQTT协议

MQTT（Message Queuing Telemetry Transport）是一种轻量级的发布-订阅消息传输协议，广泛应用于物联网数据传输。MQTT的主要特点包括：轻量级（协议开销小）、低带宽占用、支持QoS（服务质量）等级、断开连接时消息缓存。

MQTT采用发布-订阅模式，设备作为发布者（Publisher）将数据发布到主题（Topic），MES系统作为订阅者（Subscriber）订阅相关主题接收数据。MQTT适合数据量大、实时性要求高的场景，如设备传感器数据采集。

```python
# MQTT数据采集示例（Python）
import paho.mqtt.client as mqtt
import json
import time

class MQTTSubscriber:
    def __init__(self, broker_host, broker_port, topic_prefix):
        self.broker_host = broker_host
        self.broker_port = broker_port
        self.topic_prefix = topic_prefix
        self.client = mqtt.Client()
        self.client.on_connect = self.on_connect
        self.client.on_message = self.on_message

    def on_connect(self, client, userdata, flags, rc):
        """连接回调"""
        if rc == 0:
            print(f"Connected to MQTT broker: {self.broker_host}")
            # 订阅设备数据主题
            client.subscribe(f"{self.topic_prefix}/equipment/+/data")
            client.subscribe(f"{self.topic_prefix}/equipment/+/alarm")
        else:
            print(f"Connection failed with code {rc}")

    def on_message(self, message, userdata):
        """消息回调"""
        topic = message.topic
        payload = json.loads(message.payload.decode())

        # 解析设备数据
        if "data" in topic:
            equipment_id = topic.split("/")[2]
            self.handle_equipment_data(equipment_id, payload)
        elif "alarm" in topic:
            equipment_id = topic.split("/")[2]
            self.handle_equipment_alarm(equipment_id, payload)

    def handle_equipment_data(self, equipment_id, data):
        """处理设备数据"""
        # 存储到时序数据库或写入消息队列
        print(f"Equipment {equipment_id}: {data}")

    def handle_equipment_alarm(self, equipment_id, alarm):
        """处理设备报警"""
        # 生成报警记录并推送
        print(f"Equipment {equipment_id} Alarm: {alarm}")

    def connect(self):
        self.client.connect(self.broker_host, self.broker_port, 60)
        self.client.loop_start()

    def disconnect(self):
        self.client.loop_stop()
        self.client.disconnect()

# 使用示例
if __name__ == "__main__":
    subscriber = MQTTSubscriber("192.168.1.100", 1883, "factory/mes")
    subscriber.connect()

    # 保持订阅
    while True:
        time.sleep(1)
```

### 9.4.2 联网方案设计

设备联网方案的设计需要考虑设备类型、通信条件、数据需求和成本预算等因素。常见的联网方案包括直接联网、网关采集和混合架构三种。

#### 直接联网方案

直接联网方案适用于设备自身具备网络通信能力的情况。设备通过以太网口或无线网络直接连接到企业网络，MES系统可以直接访问设备获取数据。这种方案的优点是架构简单、数据延迟低，缺点是对设备有要求，部分老旧设备不支持。

直接联网方案通常采用OPC UA或MQTT协议。设备作为OPC UA服务器或MQTT发布者，MES系统作为客户端连接设备。对于支持OPC UA的设备，可以直接建立OPC UA连接；对于支持MQTT的设备，可以部署MQTT代理接收数据。

#### 网关采集方案

网关采集方案适用于设备不具备直接联网能力或需要协议转换的情况。数据采集网关部署在设备侧，负责采集设备数据并进行协议转换，将数据上传到MES系统或数据平台。网关采集方案的优点是适应性强，可以连接各种类型的设备，缺点是增加了硬件成本和复杂度。

数据采集网关的功能包括：协议解析（支持Modbus、Profinet、OPC UA等多种协议）、数据过滤（只上传需要的数据，减少网络负载）、本地缓存（网络中断时缓存数据，网络恢复后上传）、边缘计算（在网关侧进行数据预处理和报警判断）。

```sql
-- 设备联网配置表
CREATE TABLE equipment_network (
    network_id VARCHAR(36) PRIMARY KEY,
    equipment_id VARCHAR(36) NOT NULL,
    connection_type VARCHAR(20) NOT NULL COMMENT 'DIRECT:直接联网;GATEWAY:网关采集',
    protocol_type VARCHAR(20) NOT NULL COMMENT 'OPC_UA:MQTT:MODBUS:PROFINET',
    endpoint_url VARCHAR(500) COMMENT '连接地址',
    gateway_id VARCHAR(36) COMMENT '网关ID（网关采集时使用）',
    data_points TEXT COMMENT '数据点配置JSON',
    polling_interval INTEGER DEFAULT 1000 COMMENT '轮询间隔(毫秒)',
    is_enabled BOOLEAN DEFAULT TRUE,
    last_connected_at TIMESTAMP,
    connection_status VARCHAR(20) COMMENT 'ONLINE:在线;OFFLINE:离线',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (equipment_id) REFERENCES equipment(equipment_id)
);
```

#### 混合架构方案

混合架构方案结合直接联网和网关采集的优点，适用于企业中设备类型多样、联网条件复杂的情况。对于新购置的先进设备采用直接联网方案，对于老旧设备采用网关采集方案。这种方案能够充分利用现有设备资源，同时逐步推进设备联网进程。

本章详细讲解了MES系统中设备管理的核心功能模块。在设备管理概述部分，介绍了设备分类与编码体系以及设备状态的定义和采集方式，为设备信息化管理奠定了基础。在OEE计算与监控部分，详细讲解了可用率、性能率、合格率三个核心指标的计算方法，以及OEE分析和改进的方法。在设备维护管理部分，介绍了预防性维护和预测性维护两种维护策略及其实现方法。在设备联网与数据采集部分，介绍了OPC UA和MQTT两种主流工业通信协议，以及直接联网、网关采集、混合架构三种联网方案。

设备管理是保障生产连续性的关键，通过科学的设备管理可以提高设备利用率、降低维护成本、延长设备寿命，为企业创造更大的价值。
