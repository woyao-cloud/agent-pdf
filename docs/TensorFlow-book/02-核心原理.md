# 第 2 章 核心原理

> **本章导读**：本章深入 TensorFlow 的四个核心技术：计算图、Eager Execution + tf.function、自动微分、XLA 编译栈。理解这些原理不仅能帮助你写出更高效的代码，还能在遇到奇怪问题时快速定位根因。

## 1. 计算图基础

### 1.1 什么是计算图

计算图（Computation Graph）是 TensorFlow 的心脏。它用有向无环图（DAG）来表达数学运算：

- **节点（Node）**：表示一个算子（Operation），如 `tf.matmul`、`tf.add`
- **边（Edge）**：表示张量（Tensor）的流动方向

```python
# 下面的代码在 Eager 模式下立即执行，但背后仍然是图的构建
import tensorflow as tf

a = tf.constant([[1.0, 2.0], [3.0, 4.0]])
b = tf.constant([[5.0, 6.0], [7.0, 8.0]])
c = tf.matmul(a, b)  # 节点：MatMul
d = tf.add(c, 1.0)   # 节点：Add
print(d)  # 立即得到结果
```

在 TF 1.x 时代，你需要手动构建图然后用 Session 执行。TF 2.x 的 Eager 模式让这成为历史，但图仍然在底层存在——`tf.function` 负责把 Python 代码翻译成图。

### 1.2 静态图 vs 动态图

| 特性 | 静态图（TF 1.x） | 动态图（TF 2.x Eager） |
|------|-----------------|----------------------|
| 定义方式 | 先构图，后执行 | 算子立即求值 |
| 调试 | 困难，需 tfdbg | 方便，可直接 print |
| 性能 | 图优化空间大 | 有 overhead |
| 部署 | 直接序列化 | 需转图（tf.function） |
| 控制流 | `tf.cond`、`tf.while` | Python 原生 if/for |

TF 2.x 的答案是：**动态图易用，静态图性能**。用 `@tf.function` 装饰的函数会：

1. ** tracing 阶段**：用特殊输入运行一次函数，记录执行路径
2. **图构建阶段**：把记录的算子序列转成 TFGraph
3. **后续执行**：直接跑优化后的图，跳过 Python overhead

```python
@tf.function  # 把这个函数变成"图"
def matmul_add(x, W, b):
    return x @ W + b

# 第一次调用：tracing + 图构建（慢）
result = matmul_add(a, W, b)

# 后续调用：直接跑图（快）
for _ in range(100):
    result = matmul_add(a, W, b)  # 复用同一张图
```

### 1.3 图优化的黑魔法

TF 在 `tf.function` 内部做了大量优化：

1. **算子融合（Op Fusion）**：把相邻算子合并成一个内核
   ```python
   # 优化前：MatMul → Add → ReLU（3个内核）
   # 优化后：FusedMatMulAddRelu（1个内核）
   ```

2. **常量折叠（Constant Folding）**：编译期算出常量表达式
   ```python
   # 编译期就算出 2*3=6
   @tf.function
   def f():
       return tf.constant(2) * tf.constant(3)
   ```

3. **内存规划（Memory Planning）**：预分配和复用 GPU 显存

4. **公共子表达式消除（CSE）**：避免重复计算

> ⚠️ **陷阱**：图优化有时会导致意外行为。比如某些 Python 副作用（修改列表、追加日志）不会在图的多次执行中保留，因为图只记录计算，不记录这些操作。

## 2. 自动微分原理

### 2.1 为什么需要自动微分

手推反向传播的梯度公式对简单网络还行，碰到 Transformer、GAN、复杂自定义层，分分钟让你怀疑人生。自动微分（Autodiff）解决了这个问题。

**三种微分方式对比**：

| 方式 | 原理 | 精度 | 效率 |
|------|------|------|------|
| 数值微分 | `(f(x+h)-f(x))/h` | 受 h 影响 | 每参数一次前向 |
| 符号微分 | 手工求导公式 | 精确 | 表达式膨胀 |
| 自动微分 | 链式法则 + 算子级梯度 | 精确 | 最优计算路径 |

### 2.2 TensorFlow 的自动微分实现

TF 用 `tf.GradientTape` 实现自动微分：

```python
x = tf.Variable(3.0)

with tf.GradientTape() as tape:
    y = x ** 2  # y = x^2

# 求 dy/dx
dy_dx = tape.gradient(y, x)
print(dy_dx.numpy())  # 6.0
```

**GradientTape 的工作原理**：

1. 记录前向计算中的所有算子
2. 反向遍历计算图，应用链式法则
3. 返回目标对源的张量梯度

```python
# 多层嵌套的梯度
x = tf.Variable(2.0)

with tf.GradientTape() as tape1:
    with tf.GradientTape() as tape2:
        y = x ** 3  # y = x^3
    dy_dx = tape2.gradient(y, x)  # dy/dx = 3x^2 = 12
d2y_dx2 = tape1.gradient(dy_dx, x)  # d²y/dx² = 6x = 12

print(f"一阶导数: {dy_dx.numpy()}, 二阶导数: {d2y_dx2.numpy()}")
```

### 2.3 高阶梯度与自定义梯度

**高阶梯度（Second-order Gradients）**：

```python
x = tf.Variable(1.0)

with tf.GradientTape() as tape2:
    with tf.GradientTape() as tape1:
        y = x ** 4
    grad1 = tape1.gradient(y, x)  # 一阶导数: 4x³ = 4
grad2 = tape2.gradient(grad1, x)   # 二阶导数: 12x² = 12
```

**自定义梯度（Custom Gradient）**：

对于某些算子，默认梯度可能数值不稳定或效率低下，你需要手动指定：

```python
@tf.custom_gradient
def stable_exp(x):
    """稳定的指数函数，避免溢出"""
    result = tf.exp(tf.clip_by_value(x, -100, 100))
    
    def grad(dy):
        # 自定义梯度计算
        return dy * result
    return result, grad

x = tf.Variable([1.0, 50.0, 100.0])
with tf.GradientTape() as tape:
    y = stable_exp(x)

print(tape.gradient(y, x))  # 使用自定义梯度
```

## 3. XLA 编译栈

### 3.1 XLA 是什么

**XLA（Accelerated Linear Algebra）** 是 TF 的编译器，把高层 TensorFlow 运算转成高度优化的机器码。它在以下层面工作：

```
Python 代码 → TF Graph → TF → XLA HLO → LLVM → CUDA/ROCm/TPU/CPU
```

### 3.2 XLA 带来的优化

1. **算子融合**：把多个 kernel 融合成一个
   - 减少内存带宽压力
   - 减少 kernel 启动开销

2. **内存优化**：
   - 算子间的中间结果可以在寄存器中保留
   - 避免写回全局内存

3. **指令级并行**：
   - 利用 SIMD 指令（CPU AVX/AVX-512）
   - GPU 上的 warp 并行

4. **TPU 专用优化**：
   - 专为 TPU 指令集生成代码
   - 最大化 TPU 矩阵运算单元利用率

### 3.3 启用 XLA

**方式一：tf.function 装饰器（默认开启）**

```python
# tf.function 默认启用 XLA
@tf.function(jit_compile=True)  # 显式启用 XLA
def matmul(x, W, b):
    return x @ W + b
```

**方式二：环境变量全局启用**

```bash
# 在运行前设置
TF_XLA_FLAGS="--tf_xla_auto_jit=2"
```

**验证 XLA 是否生效**：

```python
import tensorflow as tf

@tf.function(jit_compile=True)
def test_xla(x):
    return x * 2

# 查看编译日志
test_xla(tf.constant([1.0]))
# 查看 TF 日志中是否有 "XLA compilation" 字样
```

> ⚠️ **陷阱**：XLA 编译有冷启动开销（首次调用要 0.5-2 秒），但后续执行会很快。如果你的函数只调用几次，可能反而更慢。

### 3.4 什么时候用 XLA

| 场景 | 推荐 | 原因 |
|------|------|------|
| 大模型训练 | ✅ 启用 | 迭代次数多，编译开销可摊销 |
| 小数据实验 | ❌ 关闭 | 避免冷启动 overhead |
| TPU 训练 | ✅ 必须 | XLA 是 TPU 的唯一执行路径 |
| CPU 推理 | 视情况 | 大模型可启用，小模型可能不划算 |

## 4. 设备管理

### 4.1 GPU 内存管理

TensorFlow 的 GPU 内存策略：

```python
# 默认：需要多少占多少（允许增长）
gpus = tf.config.list_physical_devices('GPU')
for gpu in gpus:
    tf.config.experimental.set_memory_growth(gpu, True)

# 或者固定显存分配
tf.config.set_logical_device_configuration(
    gpu,
    [tf.config.LogicalDeviceConfiguration(memory_limit=4096)]  # 4GB
)
```

**显存不足（OOM）的常见原因**：

1. **batch_size 过大**
2. **模型太大**：尝试梯度checkpointing、模型并行
3. **中间张量太大**：尝试减少序列长度、图像分辨率
4. **tf.function 内创建了大量张量**：把常量移到函数外

### 4.2 设备放置策略

```python
# 手动指定设备
with tf.device('/GPU:0'):
    result = model(x)

# 逻辑设备分配
strategy = tf.distribute.MirroredStrategy()
with strategy.scope():
    model = tf.keras.Sequential([...])
```

### 4.3 混合设备训练

```python
# 部分层在 GPU，部分在 CPU
class HybridModel(tf.keras.Model):
    def __init__(self):
        super().__init__()
        self.backbone = ...  # GPU
        self.head = ...      # CPU
    
    @tf.function
    def call(self, x, training=False):
        with tf.device('/GPU:0'):
            features = self.backbone(x, training=training)
        with tf.device('/CPU:0'):
            return self.head(features)
```
