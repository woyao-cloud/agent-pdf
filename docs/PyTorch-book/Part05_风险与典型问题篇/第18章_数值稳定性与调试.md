# 第18章 数值稳定性与调试

数值问题是 PyTorch 中最让人头疼的一类 —— 不报错，但模型悄悄退化；偶尔报错，难以复现。本章把数值稳定性的"原理 + 防护 + 调试技巧"集中讲透。

---

## 18.1 浮点数与神经网络的天然矛盾

IEEE 754 浮点数：

| 类型 | 尾数位 | 最小正规化值 | 最大值 | 机器精度 ε |
|------|------|------------|------|-----------|
| fp32 | 23 | ~1.2e-38 | ~3.4e38 | ~1.2e-7 |
| fp16 | 10 | ~6.1e-5 | ~6.5e4 | ~1e-3 |
| bf16 | 7 | ~1.2e-38 | ~3.4e38 | ~7.8e-3 |

神经网络训练涉及**多次乘法 + 累加**，误差会累积；加上指数 / log / sqrt 等非线性，极易出现 Inf / NaN / 量化失真。

---

## 18.2 数值稳定的常用技巧

### 18.2.1 log-sum-exp 技巧

直接计算 `log(sum(exp(xi)))` 易溢出（exp 大 → Inf）。安全形式：

```
LSE(x) = max(x) + log(sum(exp(x - max(x))))
```

PyTorch 提供 `torch.logsumexp`：

```python
out = torch.logsumexp(x, dim=-1)
```

不要自己写 `log(sum(exp(x)))`！

### 18.2.2 softmax 数值稳定

```python
# 不稳定
e = x.exp()
return e / e.sum(dim=-1, keepdim=True)

# 稳定（PyTorch 内置已做）
F.softmax(x, dim=-1)
```

PyTorch 的 `softmax` 内部做了 `x - x.max()`，可放心用。**但你自己写时**记得这一步。

### 18.2.3 cross_entropy = log_softmax + nll_loss

直接：

```python
loss = F.cross_entropy(logits, target)
```

而不是：

```python
p = F.softmax(logits, dim=-1)        # 中间数值不稳
log_p = torch.log(p)
loss = F.nll_loss(log_p, target)
```

`cross_entropy` 内部用 logsumexp 形式，数值稳定。

### 18.2.4 BCEWithLogitsLoss vs Sigmoid + BCELoss

```python
# 推荐
loss = F.binary_cross_entropy_with_logits(logits, target)

# 不推荐
loss = F.binary_cross_entropy(torch.sigmoid(logits), target)
```

前者数值稳定，避免 log(sigmoid(x)) 的下溢。

### 18.2.5 epsilon 防 0

```python
# 不安全
y = x.log()                # x = 0 → -Inf
y = torch.sqrt(x)          # x < 0 → NaN
y = a / b                  # b = 0 → Inf

# 安全
eps = 1e-8
y = (x.clamp(min=eps)).log()
y = torch.sqrt(x.clamp(min=0) + eps)
y = a / (b.clamp(min=eps))
```

### 18.2.6 Gradient clipping

```python
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
```

防止梯度爆炸的最直接手段。Transformer 训练几乎必用。

### 18.2.7 weight initialization

不正确的初始化会让深层网络梯度爆炸或消失。常用：

```python
nn.init.kaiming_normal_(layer.weight, nonlinearity='relu')   # ReLU 系
nn.init.xavier_normal_(layer.weight, gain=...)               # tanh / sigmoid
nn.init.trunc_normal_(layer.weight, std=0.02)                # Transformer 标配
```

层 norm / BN 一般 weight=1, bias=0。

### 18.2.8 LayerNorm 优先于 BatchNorm（在大模型）

LayerNorm 不依赖 batch 统计，对小 batch / 序列长度可变的场景更稳定。Transformer 几乎全用 LayerNorm 或 RMSNorm。

## 18.3 attention 的数值技巧

### 18.3.1 scale 必加

```python
# Naive
attn = (q @ k.T).softmax(-1)

# 正确
attn = (q @ k.T / math.sqrt(d_k)).softmax(-1)
```

不 scale → softmax 进入饱和区 → 梯度极小。

### 18.3.2 Flash Attention 内置稳定性

Flash Attention 的 online softmax 算法天生稳定，并且省显存。用 `F.scaled_dot_product_attention` 即可：

```python
out = F.scaled_dot_product_attention(q, k, v, is_causal=True)
```

### 18.3.3 mask 位置用 -inf 还是大负数

```python
attn_scores.masked_fill(mask, float('-inf'))
```

大负数（-1e9）也行，但 fp16 下 -1e9 会被截断成 -65504。**fp16/bf16 下用** `-1e4` 量级或 `-inf`：

```python
attn_scores.masked_fill(mask, torch.finfo(attn_scores.dtype).min)
```

## 18.4 自定义 loss 的数值稳定

写自定义 loss 时注意：

```python
# 焦点损失（Focal Loss）— 不稳定写法
def focal(logits, target, gamma=2.0):
    p = torch.sigmoid(logits)              # 数值不稳
    ce = -(target * p.log() + (1-target) * (1-p).log())
    pt = target * p + (1-target) * (1-p)
    return ce * (1-pt).pow(gamma)

# 稳定写法
def focal(logits, target, gamma=2.0):
    bce = F.binary_cross_entropy_with_logits(logits, target, reduction='none')
    p = torch.sigmoid(logits)
    pt = target * p + (1-target) * (1-p)
    return bce * (1-pt).pow(gamma)
```

记住：**任何 sigmoid+log / softmax+log 都用稳定 API 替代**。

## 18.5 fp16 / bf16 训练的特殊问题

### 18.5.1 fp16 下溢

梯度小于 ~6e-5 在 fp16 下变成 0。用 GradScaler 解决（第 14 章）。

### 18.5.2 bf16 精度低

bf16 尾数仅 7 位，相对精度 ~1%。累加大量小值会丢精度。处理：

- LayerNorm 内部用 fp32（autocast 自动）
- 累加用 fp32（如 attention scores 的 softmax）
- 优化器状态用 fp32 master（AMP 默认）

### 18.5.3 BatchNorm 在 fp16 下

BN 的方差计算对 fp16 极敏感，autocast 会保 fp32。如果手动 `.half()` 整个模型，BN 会出问题 —— 改用 SyncBatchNorm 或换 LayerNorm。

### 18.5.4 cumsum / softmax 在低精度的差异

某些 reduction op 在 fp16 累积后误差大。如果调试发现 fp16 / bf16 vs fp32 结果差异异常大，定位到这些 op，改成 fp32。

## 18.6 量化的数值损失

INT8 / INT4 量化把浮点数映射到有限离散值：

- 范围（scale）选小 → 量化精细但 outlier 被截断
- 范围选大 → outlier 保留但小值精度低

LLM 中 outlier 是关键现象（特别是 attention 的某些 channel）：

| 方案 | 思路 |
|------|------|
| GPTQ | 分块 Hessian 校正 |
| AWQ | activation outlier-aware，保留关键 channel 高精度 |
| SmoothQuant | 把 activation 的 outlier "搬"到 weight |
| LLM.int8() | outlier 走 fp16，其余 int8 |

普通 PTQ 量化 LLM 损失大；用专门库才能保住精度。

## 18.7 调试工具：set_detect_anomaly

```python
torch.autograd.set_detect_anomaly(True)
# 任何 NaN/Inf 在反向时会立即抛异常
# 并打印 forward 时的栈
```

**极慢，仅调试用**。对于偶发 NaN，可以包到 try/except：

```python
try:
    with torch.autograd.detect_anomaly():
        loss.backward()
except RuntimeError as e:
    print('Got anomaly:', e)
    # 保存触发样本以分析
```

## 18.8 调试工具：register_hook

精准定位"第几层开始 NaN"：

```python
def detect_nan(name):
    def hook(grad):
        if torch.isnan(grad).any() or torch.isinf(grad).any():
            print(f'NaN/Inf grad at {name}')
            print(f'  shape={grad.shape}, max abs={grad.abs().max().item()}')
        return grad
    return hook

for name, p in model.named_parameters():
    if p.requires_grad:
        p.register_hook(detect_nan(name))
```

forward hook 也能用：

```python
def fwd_check(name):
    def hook(_, __, output):
        if isinstance(output, torch.Tensor) and (torch.isnan(output).any() or torch.isinf(output).any()):
            print(f'NaN/Inf in {name}')
    return hook

for name, m in model.named_modules():
    m.register_forward_hook(fwd_check(name))
```

## 18.9 通过最小复现定位 bug

最重要的调试技能：**把问题压缩到最小**。

1. 不报错？写一个"反复跑同一 batch"的循环
2. 报错？写一个"只跑出错那个 batch"的脚本
3. 复杂模型？用一个最小子模型复现
4. 复杂数据？用合成数据替代

```python
# Minimal Reproducible Example (MRE) 模板
import torch
import torch.nn as nn

torch.manual_seed(42)

# 最小模型
model = nn.Linear(10, 10).cuda()
# 合成数据
x = torch.randn(2, 10).cuda()
y = torch.randint(0, 10, (2,)).cuda()
# 复现
out = model(x)
loss = F.cross_entropy(out, y)
loss.backward()
```

把代码缩到 < 50 行能复现 → 你能自己 fix；缩不下来 → 至少能向社区求助。

## 18.11 调试中的"打印大法"

虽然朴素，但 90% 的 PyTorch bug 用合理打印就能定位。要打的内容：

| 阶段 | 打印 |
|------|------|
| 数据 | `x.shape`, `x.dtype`, `x.min().item()`, `x.max().item()`, `x.isnan().any().item()` |
| 模型输出 | 同上 |
| loss | `loss.item()` |
| 梯度 | `total_norm`, `grad.abs().max()` |
| 参数 | `param.norm()`, `param.abs().max()` |
| 学习率 | `optimizer.param_groups[0]['lr']` |

封装成一个 debug 函数：

```python
def stats(t, name=''):
    if t is None:
        print(f'{name}: None'); return
    print(f'{name}: shape={tuple(t.shape)} dtype={t.dtype} '
          f'min={t.min().item():.4g} max={t.max().item():.4g} '
          f'mean={t.float().mean().item():.4g} '
          f'has_nan={t.isnan().any().item()} has_inf={t.isinf().any().item()}')
```

## 18.12 验证模型实现的"sanity test"

新写 / 移植一个模型时，做以下测试：

```python
# 1. 输出 shape 正确
out = model(torch.randn(1, 3, 224, 224))
assert out.shape == (1, num_classes)

# 2. backward 不报错，梯度非 None
loss = out.sum()
loss.backward()
for p in model.parameters():
    assert p.grad is not None

# 3. overfit 单个样本
x, y = single_sample
for _ in range(500):
    optim.zero_grad()
    loss = criterion(model(x), y)
    loss.backward()
    optim.step()
assert loss.item() < 0.01

# 4. forward 与已知 reference 一致（如果 port 自其他实现）
torch.allclose(my_out, ref_out, atol=1e-4)

# 5. determinism
torch.manual_seed(0)
out1 = model(x)
torch.manual_seed(0)
out2 = model(x)
assert torch.allclose(out1, out2)
```

跑通这五条，模型实现基本可信。

## 18.13 性能调试的 micro-benchmark 模板

```python
import torch
from torch.utils.benchmark import Timer

def bench(fn, label, *args, **kw):
    t = Timer(stmt='fn(*args, **kw)', globals=locals())
    print(f'{label}: {t.timeit(100)}')

x = torch.randn(64, 1024, device='cuda')
y = torch.randn(64, 1024, device='cuda')

bench(lambda a, b: a + b, 'add', x, y)
bench(lambda a, b: torch.matmul(a, b.T), 'matmul', x, y)
```

`torch.utils.benchmark.Timer` 自动 warm up + sync + 多次取均值，比手写 time.time() 准。

## 18.14 一次完整调试故事（示例）

> "Transformer 训练 200 步后 loss 突然 NaN"

step 1：复现
- 设固定种子，确认每次都在 200 步左右出 NaN

step 2：找触发样本
- 在出 NaN 时打印 batch index、保存 batch
- 在该 batch 上单独跑

step 3：哪个 op
- 加 `set_detect_anomaly`
- 报告：attention 的 softmax 出 Inf

step 4：为什么
- 打印进入 softmax 前的 attention scores → 发现 max 值 > 1e4
- attention 输出在 fp16 下溢出

step 5：根因
- 没用 SDPA，朴素实现没 scale by sqrt(d) 或 scale 错了
- 或：序列变长，某个 batch 某个 head 的 score 异常大

step 6：修复
- 改用 `F.scaled_dot_product_attention`
- 或改 bf16
- 或加 attention score clipping

step 7：回归
- 再训 1000 步无 NaN，loss 曲线正常

## 18.15 本章小结

- 浮点精度的有限性是数值问题的根 —— 多用 `logsumexp`、`cross_entropy`、`bce_with_logits` 等稳定 API
- attention 的 scale、masking 大负数、Flash Attention 默认稳定
- fp16 易下溢用 GradScaler；bf16 精度低靠 LayerNorm fp32 / 优化器 fp32 兜底
- 量化 LLM 用专用工具（GPTQ/AWQ）保精度
- 调试三大杀器：`set_detect_anomaly` / 参数 hook / `_record_memory_history`
- 用最小可复现示例 (MRE) 压缩 bug，多数情况自己就能修
- 复现性的成本是性能；选择适合场景的严格度
