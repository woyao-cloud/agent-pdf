# 第15章 分布式训练

单卡放不下，单卡跑太慢，必须上多卡甚至多机。本章把 PyTorch 分布式训练的几条主路径讲清楚 —— DDP、FSDP / FSDP2、张量并行、流水线并行 —— 以及它们的适用边界与工程要点。

---

## 15.1 并行的四种轴

| 轴 | 切分什么 | 代表方案 |
|---|---------|---------|
| **数据并行（DP）** | 把 batch 切到多 GPU；每卡完整模型 | DDP |
| **完全分片数据并行（FSDP / ZeRO）** | 同上 + 把参数/梯度/优化器切片 | FSDP、DeepSpeed ZeRO |
| **张量并行（TP）** | 把单个权重矩阵切到多 GPU | Megatron-LM、tensor_parallel |
| **流水线并行（PP）** | 把不同层切到不同 GPU | torch.distributed.pipelining、DeepSpeed PP |

实际大模型训练通常是**3D 并行 = DP × TP × PP**。中小模型 DDP/FSDP 已足够。

## 15.2 DDP：标准数据并行

### 15.2.1 启动脚本

```bash
torchrun --nproc_per_node=4 train.py
# 多机
torchrun --nnodes=2 --nproc_per_node=8 \
         --rdzv_backend=c10d --rdzv_endpoint=master:29400 train.py
```

`torchrun` 是 PT 1.10+ 的统一启动器，取代了老的 `torch.distributed.launch`。

### 15.2.2 训练脚本骨架

```python
import torch
import torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel as DDP
import os

def main():
    dist.init_process_group(backend='nccl')
    local_rank = int(os.environ['LOCAL_RANK'])
    torch.cuda.set_device(local_rank)
    device = torch.device('cuda', local_rank)

    model = MyModel().to(device)
    model = DDP(model, device_ids=[local_rank])

    optim = torch.optim.AdamW(model.parameters(), lr=3e-4)

    sampler = DistributedSampler(dataset, shuffle=True)
    loader = DataLoader(dataset, batch_size=BSZ, sampler=sampler,
                        num_workers=4, pin_memory=True)

    for epoch in range(epochs):
        sampler.set_epoch(epoch)              # 关键
        for x, y in loader:
            x, y = x.to(device), y.to(device)
            out = model(x)
            loss = criterion(out, y)
            loss.backward()                   # all-reduce 自动发生
            optim.step()
            optim.zero_grad()

    dist.destroy_process_group()
```

### 15.2.3 DDP 内部机制

- 每张 GPU 有完整模型副本与完整优化器状态
- forward 各自跑（无通信）
- backward 时，每个梯度 ready 就触发 all-reduce（与计算重叠）
- optimizer.step() 各自执行（参数同步天然保持一致）

### 15.2.4 性能调优

```python
DDP(model,
    device_ids=[local_rank],
    bucket_cap_mb=25,                # 桶大小，越大通信越少但延迟到反向后期
    gradient_as_bucket_view=True,    # PT 1.8+ 默认；省内存
    find_unused_parameters=False,    # 模型有"未使用"参数时设 True，但慢
    static_graph=True,               # 图固定时进一步优化
)
```

**重要警告**：`find_unused_parameters=True` 极慢，仅在确实有动态分支跳过参数时用。多数情况能改模型避免（比如 always 走完所有层）。

### 15.2.5 DDP 常见 bug

- **没 set_epoch**：每个 epoch 数据顺序相同
- **batch norm 各卡独立**：精度可能差，用 `nn.SyncBatchNorm.convert_sync_batchnorm(model)`
- **在 DDP 包装前后访问参数不一致**：访问 `model.module.xxx` 而非 `model.xxx`
- **不同 rank 走不同代码路径**：导致挂起（某些 rank 等不来集合通信）
- **rank 0 写 ckpt 时其他 rank 抢资源**：用 `dist.barrier()` 或只在 rank 0 做 IO

## 15.3 FSDP：完全分片数据并行

### 15.3.1 为什么需要 FSDP

DDP 每张卡都有完整模型 + 完整优化器状态，**模型大小受限于单卡显存**。FSDP（PT 1.12+）/ DeepSpeed ZeRO 把：

| 切分 | 等价 |
|------|------|
| 优化器状态 | ZeRO Stage 1 |
| + 梯度 | ZeRO Stage 2 |
| + 参数 | ZeRO Stage 3 / FSDP 默认 |

forward/backward 时按需 all-gather 完整参数，算完即丢。**显存几乎线性减少**，通信成本上升。

### 15.3.2 FSDP 用法

```python
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP, ShardingStrategy
from torch.distributed.fsdp.wrap import transformer_auto_wrap_policy
import functools

auto_wrap_policy = functools.partial(
    transformer_auto_wrap_policy,
    transformer_layer_cls={MyTransformerBlock},   # 按 transformer block 包装
)

model = FSDP(
    model,
    sharding_strategy=ShardingStrategy.FULL_SHARD,   # ZeRO-3
    auto_wrap_policy=auto_wrap_policy,
    mixed_precision=...,                             # bf16 配置
    device_id=local_rank,
)
```

### 15.3.3 ShardingStrategy

| 策略 | 行为 | 等价 |
|------|------|------|
| `NO_SHARD` | 不切分（=DDP） | DDP |
| `SHARD_GRAD_OP` | 切梯度+优化器 | ZeRO-2 |
| `FULL_SHARD` | 切参数+梯度+优化器 | ZeRO-3 |
| `HYBRID_SHARD` | 节点内 FULL_SHARD + 节点间副本 | 中等通信、中等显存 |

### 15.3.4 mixed precision 配置

```python
from torch.distributed.fsdp import MixedPrecision
mp_policy = MixedPrecision(
    param_dtype=torch.bfloat16,
    reduce_dtype=torch.bfloat16,
    buffer_dtype=torch.bfloat16,
)
model = FSDP(model, mixed_precision=mp_policy, ...)
```

### 15.3.5 checkpoint 与 FSDP

FSDP 下每个 rank 只持有参数的一部分，保存有两种模式：

```python
from torch.distributed.fsdp import FullStateDictConfig, StateDictType

# Full state dict：rank 0 收集全部参数（可能 OOM）
with FSDP.state_dict_type(model, StateDictType.FULL_STATE_DICT,
                          FullStateDictConfig(rank0_only=True, offload_to_cpu=True)):
    state = model.state_dict()
    if dist.get_rank() == 0:
        torch.save(state, 'model.pt')

# Sharded state dict：每个 rank 存自己的分片
with FSDP.state_dict_type(model, StateDictType.SHARDED_STATE_DICT):
    ...
```

大模型必用 sharded checkpoint；用 PyTorch DCP（Distributed Checkpoint）API 更现代：

```python
import torch.distributed.checkpoint as dcp
dcp.save(state_dict, checkpoint_id='ckpt/step_1000')
```

### 15.3.6 FSDP2（PT 2.4+）

PT 2.4 起推出 FSDP2 设计，使用 `fully_shard` 函数式 API、更好的 compile 兼容性。新项目可优先尝试：

```python
from torch.distributed._composable.fsdp import fully_shard
fully_shard(model)
```

旧项目继续用 FSDP1（仍维护）。

## 15.4 张量并行（TP）

### 15.4.1 何时需要

模型单层就放不下单卡时（如 70B+ 全连接、Mixture of Experts）。把单个矩阵乘按行 / 列切到多 GPU。

### 15.4.2 PyTorch 原生 TP

PT 2.0+ 的 `torch.distributed.tensor.parallel`：

```python
from torch.distributed.tensor.parallel import (
    parallelize_module, ColwiseParallel, RowwiseParallel,
)

# 对一个 transformer block 应用 TP
parallelize_module(
    block,
    device_mesh=mesh,
    parallelize_plan={
        'attn.q_proj': ColwiseParallel(),
        'attn.k_proj': ColwiseParallel(),
        'attn.v_proj': ColwiseParallel(),
        'attn.o_proj': RowwiseParallel(),
        'mlp.gate_proj': ColwiseParallel(),
        'mlp.up_proj':   ColwiseParallel(),
        'mlp.down_proj': RowwiseParallel(),
    },
)
```

按 Megatron-LM 的经典切法：
- attention 的 QKV 列切（输入完整，输出按 head 分）
- attention 的 output 行切（输入按 head 分，输出 all-reduce）
- MLP 中间层按列切，最后层按行切

### 15.4.3 通信代价

每个 TP 块需要至少一次 all-reduce（行切的输出 / 列切的输入），跨 GPU 带宽要够。**只在 NVLink 域内做 TP**，跨节点性能崩溃。

### 15.4.4 与 DP 的组合

3D 并行：DP（节点间）× TP（节点内 GPU 间）× PP（节点链）：

```python
from torch.distributed.device_mesh import init_device_mesh
mesh = init_device_mesh('cuda', (DP, TP), mesh_dim_names=('dp', 'tp'))

# 在 tp 维上做 TP，在 dp 维上做 DDP/FSDP
```

DeviceMesh 是 PT 2.x 的统一抽象。

## 15.5 流水线并行（PP）

### 15.5.1 思想

把模型的不同层放到不同 GPU。每个 GPU 持有部分层；mini-batch 切成 micro-batch，前一个 micro-batch 在 stage 2 时下一个在 stage 1，形成流水线。

### 15.5.2 PyTorch torch.distributed.pipelining

```python
from torch.distributed.pipelining import pipeline, ScheduleGPipe, SplitPoint

# 标记切分点
split_spec = {
    'layer_4': SplitPoint.BEGINNING,
    'layer_8': SplitPoint.BEGINNING,
}
pipe = pipeline(model, mb_args=(example,), split_spec=split_spec)

# 在每个 rank 上获取自己的 stage
stage = pipe.build_stage(stage_idx, device, group)
schedule = ScheduleGPipe(stage, n_microbatches=8, loss_fn=criterion)

# 训练
schedule.step(x, target=y)
```

### 15.5.3 PP 的代价

- **气泡（pipeline bubble）**：流水线开头与结尾有 GPU 闲置；micro-batch 越多气泡比例越小但单 micro-batch 显存越大
- **调度复杂**：GPipe / 1F1B / Interleaved-1F1B 各有取舍
- **实现复杂**：层切分点、激活传递、loss 计算位置都要处理

PP 通常只在超大模型 + 跨节点必要时用。中等模型 FSDP 已够。

## 15.6 通信优化

### 15.6.1 NCCL 调优

```bash
export NCCL_DEBUG=INFO              # 看通信细节
export NCCL_IB_HCA=mlx5_0           # 指定 IB 网卡
export NCCL_SOCKET_IFNAME=eth0      # 指定 socket 接口
export NCCL_P2P_LEVEL=NVL           # 强制只用 NVLink
```

具体参数因集群而异。NCCL 有自动 topology detection，但偶尔需要手动 override。

### 15.6.2 重叠通信与计算

DDP 默认就在重叠（梯度 ready 即 all-reduce）。FSDP 通过 prefetch 重叠下一层参数 all-gather：

```python
FSDP(model, ..., backward_prefetch=BackwardPrefetch.BACKWARD_PRE)
```

### 15.6.3 梯度压缩

实验性：1bit Adam、PowerSGD 等。一般不用，除非通信极度受限。

## 15.7 多机训练的工程要点

### 15.7.1 节点间互通

- IB 或 RoCE 优于纯 TCP
- 防火墙开放 NCCL 端口
- `/etc/hosts` 一致；时间同步（NTP）

### 15.7.2 数据访问

- 共享存储（NFS / GPFS / Lustre）vs 本地拷贝
- ImageNet 这种大数据集，每节点本地一份是最稳的
- 流式数据（webdataset + S3）适合超大数据

### 15.7.3 故障容错

- `torchrun` 支持 elastic（节点挂了自动重启）
- 定期 checkpoint（FSDP sharded ckpt 速度可接受）
- 用 SLURM / Kubernetes 等编排

### 15.7.4 复现性

- 每个 rank 设不同 seed（避免所有卡生成相同噪声）
- DistributedSampler 必须 `set_epoch`
- 跨节点 RNG 同步在某些场景必要

## 15.8 选型决策

```
模型放得下单卡？
├── 是 → DDP（多卡 / 多机）
└── 否
    ├── 单节点能放 → FSDP FULL_SHARD（节点内）
    └── 单节点放不下
        ├── 中等模型（10B-70B） → FSDP HYBRID_SHARD 或 + TP
        └── 超大模型（100B+） → 3D 并行（DP × TP × PP）
            ├── 自研栈 → torch.distributed + DeviceMesh
            └── 用框架 → DeepSpeed / Megatron-LM / Megatron-Core
```

### 15.8.1 框架选型

| 框架 | 特点 |
|------|------|
| **Raw PyTorch (DDP/FSDP)** | 灵活、官方维护 |
| **Hugging Face Accelerate** | 配置简单，自动 DDP/FSDP/DeepSpeed |
| **DeepSpeed** | ZeRO 实现历史最成熟、Inference 加速 |
| **Megatron-LM / Megatron-Core** | LLM 预训练黄金标准（NVIDIA） |
| **PyTorch Lightning** | 训练循环抽象，多卡自动化 |
| **Colossal-AI** | 国产，并行策略丰富 |

中小项目 → Accelerate / Lightning；大模型预训练 → Megatron-Core；强自定义 → Raw PyTorch。

## 15.9 多卡训练易错清单

| 错误 | 后果 | 处理 |
|------|------|------|
| 忘记 `set_epoch` | 每 epoch 数据顺序相同 | 调用 sampler.set_epoch(epoch) |
| 不同 rank 走不同分支 | 集合通信挂起 | 保证所有 rank 走相同代码 |
| rank 0 才执行的代码遗漏 barrier | 其他 rank 提前进入下个 step | `dist.barrier()` |
| 用 print 而非 rank-aware logging | 输出混乱 | 只 rank 0 打印 |
| BN 各卡独立 | 精度下降 | SyncBatchNorm |
| ckpt 保存 OOM | full state dict 在大模型上集中 | sharded ckpt |
| dataloader workers 与 GPU 数没协调 | 总进程数爆 CPU | num_workers = ncpu / world_size |
| 启动脚本用 mp.spawn 与 torchrun 混用 | 多次初始化 | 选一种 |
| nccl backend 没选 | 退化到 gloo（慢） | `init_process_group(backend='nccl')` |
| init 时间长 / 节点不匹配 | 训练永远没开始 | 检查 host / 端口 / 防火墙 |

## 15.10 调试与观测

```python
# 仅 rank 0 打印
def is_main(): return dist.get_rank() == 0
def print0(*args, **kw):
    if is_main(): print(*args, **kw)

# barrier 同步检查点
dist.barrier()

# all-reduce 检查所有 rank 的 loss
loss_t = torch.tensor([loss.item()], device=device)
dist.all_reduce(loss_t, op=dist.ReduceOp.AVG)
print0(f'avg loss: {loss_t.item()}')
```

集群级监控：DCGM、Prometheus、Grafana。看每张卡的 throughput、温度、ECC error。一张坏卡能拉慢整个 job。

## 15.11 本章小结

- 单机多卡：DDP 是默认；模型大用 FSDP（全切分）
- FSDP2 / DCP / DeviceMesh 是 PT 2.x 的现代分布式抽象
- 张量并行只在 NVLink 域内做；流水并行只在超大模型用
- 3D 并行 = DP × TP × PP，是 100B+ 模型预训练的事实组合
- 中小项目用 Accelerate / Lightning 包一层；大模型用 Megatron-Core
- 多卡 bug 集中在分支不一致、sampler 没 set_epoch、checkpoint OOM
- NCCL 调优、IB 网络、共享存储、ckpt 存储是工程基础设施
