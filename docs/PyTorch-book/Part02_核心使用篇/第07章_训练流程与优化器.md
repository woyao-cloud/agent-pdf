# 第07章 训练流程与优化器

任何 PyTorch 训练脚本都遵循同一个骨架：前向 → 算 loss → 反向 → 优化器 step。这章把骨架里每一根骨头讲清楚 —— 不只是 API 用法，而是它们的**数学含义**与**实战细节**。

---

## 7.1 标准训练循环骨架

```python
model.train()
for epoch in range(num_epochs):
    for x, y in train_loader:
        x, y = x.to(device, non_blocking=True), y.to(device, non_blocking=True)

        optimizer.zero_grad(set_to_none=True)
        out = model(x)
        loss = criterion(out, y)
        loss.backward()
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        optimizer.step()
        scheduler.step()        # 每 step 调度（按 step 调度器）

    val_loss = evaluate(model, val_loader)
```

每行都有讲究。下面逐个剖析。

---

## 7.2 zero_grad：set_to_none 才是默认

```python
optimizer.zero_grad()                  # 旧默认：grad.fill_(0)
optimizer.zero_grad(set_to_none=True)  # PT 1.7+ 推荐，PT 2.0 起为默认
```

`set_to_none=True` 把 `param.grad` 直接置为 `None`，下次反向时 PyTorch 重新分配（写入而非累加）。优势：

1. 跳过加法（直接赋值）
2. 跳过 `grad` 张量的内存清零
3. 可让 PyTorch 优化掉部分 op

代价：自定义优化逻辑里访问 `param.grad` 时要判 `None`。

## 7.3 backward 前后的常见操作

### 7.3.1 梯度累积（gradient accumulation）

显存放不下大 batch 时，用累积模拟：

```python
accum_steps = 4
optimizer.zero_grad(set_to_none=True)
for i, (x, y) in enumerate(loader):
    out = model(x)
    loss = criterion(out, y) / accum_steps     # 除以累积步数
    loss.backward()
    if (i + 1) % accum_steps == 0:
        optimizer.step()
        optimizer.zero_grad(set_to_none=True)
```

注意：BatchNorm 的统计量仍按真实 batch 计算（不是累积后的），与真正大 batch 训练不完全等价。LayerNorm/RMSNorm 模型（Transformer）则等价。

### 7.3.2 梯度裁剪

防止梯度爆炸：

```python
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
```

按所有梯度的全局 L2 范数裁剪。常见值：1.0（Transformer）、5.0（旧 RNN）。

> 用 `clip_grad_value_` 是按值裁剪（每个梯度元素），通常**不推荐** —— 会破坏梯度方向。

混合精度训练时要在 `scaler.unscale_(optimizer)` 之后再裁剪（详见第 14 章）。

### 7.3.3 检查梯度健康

调试代码片段：

```python
total_norm = 0.0
for p in model.parameters():
    if p.grad is not None:
        total_norm += p.grad.data.norm(2) ** 2
print('grad norm:', total_norm ** 0.5)
```

或用 `torch.nn.utils.get_total_norm`（PT 2.4+）。

## 7.4 优化器全景

### 7.4.1 SGD 家族

```python
torch.optim.SGD(model.parameters(), lr=0.1, momentum=0.9,
                weight_decay=1e-4, nesterov=True)
```

经典视觉训练的默认选择。Nesterov momentum 在大多数情况略优于普通 momentum。

### 7.4.2 Adam 家族

```python
torch.optim.Adam(model.parameters(), lr=1e-3, betas=(0.9, 0.999),
                 eps=1e-8, weight_decay=0)

torch.optim.AdamW(model.parameters(), lr=3e-4, betas=(0.9, 0.999),
                  weight_decay=0.01)
```

**重要**：用 Transformer / 大模型时**几乎总用 AdamW**，不要用 Adam。

为什么？Adam 把 weight_decay 加进梯度里再被自适应缩放，导致大梯度参数 decay 弱、小梯度参数 decay 强 —— 与 L2 正则化不等价。AdamW 把 decay 单独应用于权重本身，恢复正确语义。

### 7.4.3 其他常用优化器

| 优化器 | 特点 | 适用 |
|------|------|------|
| `RMSprop` | Adam 前身 | 老 RNN 代码 |
| `Adagrad` | 历史梯度累积 | 稀疏特征 |
| `LBFGS` | 二阶 | 小批量、确定性 |
| `Adafactor` | 不存二阶 momentum，省显存 | 大模型预训练 |
| `Lion`（第三方） | 只用 sign | 大模型，省显存 |
| `Sophia`（研究） | 二阶近似 | LLM 预训练加速 |

### 7.4.4 fused 优化器

PT 2.0+ 提供 `fused=True`：把所有参数的更新融合成一个 CUDA kernel：

```python
torch.optim.AdamW(model.parameters(), lr=3e-4, fused=True)
```

省 launch overhead，对参数多但每个张量小的模型（如 LLM）加速明显（~10-30%）。

### 7.4.5 参数分组

不同层用不同超参（如 backbone 用低 lr）：

```python
optimizer = torch.optim.AdamW([
    {'params': model.backbone.parameters(), 'lr': 1e-5},
    {'params': model.head.parameters(),     'lr': 1e-3},
], weight_decay=0.01)
```

更精细：

```python
no_decay = ['bias', 'LayerNorm.weight']
params = [
    {
        'params': [p for n, p in model.named_parameters()
                   if not any(nd in n for nd in no_decay)],
        'weight_decay': 0.01
    },
    {
        'params': [p for n, p in model.named_parameters()
                   if any(nd in n for nd in no_decay)],
        'weight_decay': 0.0
    },
]
optimizer = torch.optim.AdamW(params, lr=3e-4)
```

bias 与 LayerNorm 不施加 weight decay 是 BERT/GPT 的默认实践。

## 7.5 学习率调度器

### 7.5.1 常用调度器

```python
from torch.optim.lr_scheduler import (
    StepLR, MultiStepLR, ExponentialLR,
    CosineAnnealingLR, OneCycleLR,
    ReduceLROnPlateau, LambdaLR,
)
```

| 调度器 | 含义 |
|------|------|
| `StepLR(step_size=30, gamma=0.1)` | 每 30 epoch 乘 0.1 |
| `MultiStepLR(milestones=[60,120], gamma=0.1)` | 在指定 epoch 衰减 |
| `CosineAnnealingLR(T_max=epochs)` | 余弦下降，常配 warmup |
| `OneCycleLR(max_lr=...)` | 三角 + 退火，超参敏感但效果好 |
| `ReduceLROnPlateau` | 验证指标停滞才衰减 |
| `LambdaLR(lr_lambda=fn)` | 自定义函数 |

### 7.5.2 warmup + 余弦：Transformer 标配

```python
import math

def lr_lambda(step):
    warmup_steps = 1000
    total_steps = 100000
    if step < warmup_steps:
        return step / warmup_steps
    progress = (step - warmup_steps) / (total_steps - warmup_steps)
    return 0.5 * (1 + math.cos(math.pi * progress))

scheduler = torch.optim.lr_scheduler.LambdaLR(optimizer, lr_lambda)
```

每个 step（不是 epoch）调用 `scheduler.step()`。

### 7.5.3 调度器调用顺序的坑

**PT 1.1+ 的规则**：先 `optimizer.step()`，再 `scheduler.step()`。

混合精度时：

```python
scaler.step(optimizer)
scaler.update()
scheduler.step()      # 必须在 scaler.step 之后
```

如果 `scaler.step()` 因为 NaN 跳过了优化器步进，仍要不要 step 调度器？官方建议：**仍然 step**（除非用 ReduceLROnPlateau 这种基于 val 的）。

## 7.6 损失函数

### 7.6.1 分类常用

```python
nn.CrossEntropyLoss()                 # 输入 logits，自动 log_softmax
nn.BCEWithLogitsLoss()                # 二分类 / 多标签，输入 logits
nn.NLLLoss()                          # 输入 log_softmax 后的概率，几乎不用单独用
```

**绝对不要**自己写 `softmax + log` 再传给 NLLLoss，会数值不稳。用 `CrossEntropyLoss`。

### 7.6.2 标签平滑

```python
nn.CrossEntropyLoss(label_smoothing=0.1)   # PT 1.10+
```

标签平滑等价于把真实分布从 one-hot `(0,...,1,...,0)` 改成 `(α,...,1-(K-1)α,...,α)`。视觉分类常用，对过拟合有正则作用。

### 7.6.3 类别不平衡的处理

```python
weights = torch.tensor([1.0, 5.0, 10.0])    # 类别样本越少权重越大
nn.CrossEntropyLoss(weight=weights.to(device))
```

或用 Focal Loss（自定义）。

### 7.6.4 回归

```python
nn.MSELoss()                          # 平方误差
nn.L1Loss()                           # 绝对误差，对离群值更鲁棒
nn.SmoothL1Loss(beta=1.0)             # Huber，组合两者
```

### 7.6.5 ignore_index

分割 / 序列任务常有 padding 或忽略类：

```python
nn.CrossEntropyLoss(ignore_index=-100)   # label==-100 的位置不计入 loss
```

`-100` 是 PyTorch 默认值（ignore_index）—— 在数据预处理时把要忽略的位置标成 -100 即可。

## 7.7 评估循环

```python
@torch.inference_mode()
def evaluate(model, loader):
    model.eval()
    total_loss, total, correct = 0.0, 0, 0
    for x, y in loader:
        x, y = x.cuda(), y.cuda()
        out = model(x)
        loss = criterion(out, y)
        total_loss += loss.item() * x.size(0)
        pred = out.argmax(dim=1)
        correct += (pred == y).sum().item()
        total += x.size(0)
    return total_loss / total, correct / total
```

注意点：

1. `@torch.inference_mode()` 比 `torch.no_grad()` 更省
2. 必须 `model.eval()` 切换 BN/Dropout
3. 评估完别忘 `model.train()` 切回去
4. `loss.item()` 是 GPU→CPU 同步点，每个 batch 调可接受，但**不要在每行**都调

## 7.8 checkpoint 管理

### 7.8.1 完整 checkpoint

```python
def save_ckpt(path, model, optimizer, scheduler, scaler, epoch, step):
    torch.save({
        'epoch': epoch,
        'step': step,
        'model': model.state_dict(),
        'optimizer': optimizer.state_dict(),
        'scheduler': scheduler.state_dict(),
        'scaler': scaler.state_dict() if scaler else None,
        'rng': torch.get_rng_state(),
        'cuda_rng': torch.cuda.get_rng_state(),
    }, path)
```

恢复训练必须保存 optimizer 和 scheduler 状态 —— 否则恢复后的训练动力学与原训练不同（Adam 的 momentum、scheduler 的 step 计数）。

### 7.8.2 加载

```python
ckpt = torch.load(path, map_location='cpu', weights_only=False)
model.load_state_dict(ckpt['model'])
optimizer.load_state_dict(ckpt['optimizer'])
scheduler.load_state_dict(ckpt['scheduler'])
if scaler and ckpt['scaler']:
    scaler.load_state_dict(ckpt['scaler'])
start_epoch = ckpt['epoch'] + 1
```

`weights_only=False` 是必要的 —— 因为我们存了非 Tensor 数据（dict、计数器）。**只在你信任来源时**用 `False`，因为它会用 pickle 加载，存在反序列化风险。

### 7.8.3 多卡训练保存

DDP 模式下只 rank 0 保存即可，避免多 rank 同时写：

```python
if dist.get_rank() == 0:
    save_ckpt(...)
dist.barrier()    # 等保存完再继续
```

FSDP 时各 rank 持有不同 shard，需要用 `FSDP.full_state_dict_type` 或 sharded checkpoint，详见第 15 章。

## 7.9 早停（early stopping）

```python
class EarlyStopping:
    def __init__(self, patience=5, min_delta=0.0):
        self.patience = patience
        self.min_delta = min_delta
        self.best = float('inf')
        self.counter = 0
    def step(self, val_loss):
        if val_loss < self.best - self.min_delta:
            self.best = val_loss
            self.counter = 0
            return False        # don't stop
        self.counter += 1
        return self.counter >= self.patience
```

注意：早停需要可靠的验证集；小数据 + 噪声大时容易"假早停"。

## 7.10 反思 vs 工业训练循环

上面的"标准循环"在小项目可用。工业大规模训练通常用框架：

| 框架 | 特点 |
|------|------|
| **PyTorch Lightning** | 把骨架抽象成 `LightningModule`，自动多卡、混合精度、ckpt | 
| **Hugging Face Trainer / Accelerate** | NLP / 大模型主流 |
| **Composer / FFCV / 各家自研** | 极致性能 |

直接从 raw PyTorch 起步的好处是看清每一步发生了什么；用框架的好处是把样板代码与工程基础设施剥离。**二者不矛盾，先掌握 raw 再迁移**。

## 7.11 完整训练脚本模板（含混合精度）

```python
import torch
from torch.cuda.amp import autocast, GradScaler

device = 'cuda'
model = MyModel().to(device)
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4, fused=True)
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=total_steps)
scaler = GradScaler()
criterion = torch.nn.CrossEntropyLoss(label_smoothing=0.1)

step = 0
model.train()
for epoch in range(num_epochs):
    for x, y in train_loader:
        x = x.to(device, non_blocking=True)
        y = y.to(device, non_blocking=True)

        optimizer.zero_grad(set_to_none=True)
        with autocast(dtype=torch.bfloat16):
            out = model(x)
            loss = criterion(out, y)

        scaler.scale(loss).backward()
        scaler.unscale_(optimizer)
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        scaler.step(optimizer)
        scaler.update()
        scheduler.step()

        if step % log_interval == 0:
            print(f'step {step} loss {loss.item():.4f}')
        step += 1

    if rank == 0:

```

## 7.12 本章小结

- `zero_grad(set_to_none=True)` 是新默认，省内存与时间
- 梯度累积模拟大 batch；BN 行为与真正大 batch 不同
- AdamW 是 Transformer 的默认；bias / LayerNorm 不加 weight decay
- 优化器要参数分组、scheduler 要每 step 调用、混精时调用顺序固定
- CrossEntropyLoss / BCEWithLogitsLoss **永远直接用**，不要手写 softmax+log
- checkpoint 必须保存 optimizer + scheduler + scaler + rng，恢复才一致
- 评估用 `inference_mode()`，记得 `model.eval()` 切换
