# 第06章 数据加载与预处理

数据加载是深度学习训练中**最容易被低估的瓶颈**。GPU 等数据时浪费的算力，比模型本身慢两倍还要可怕。本章拆解 PyTorch 的数据 pipeline：`Dataset`、`DataLoader`、`Sampler`、`collate_fn`、多进程模型，以及常见的性能陷阱。

---

## 6.1 Dataset 抽象

`torch.utils.data.Dataset` 只规定两个接口：

```python
from torch.utils.data import Dataset

class MyDataset(Dataset):
    def __len__(self):
        return self.n_samples

    def __getitem__(self, idx):
        return self.x[idx], self.y[idx]
```

`__getitem__` 应该返回**一个样本**，而不是 batch。batching 由 `DataLoader` 完成。

### 6.1.1 Map-style vs Iterable-style

| 类型 | 父类 | 适用 |
|------|------|------|
| Map-style | `Dataset` | 已知总长度，可随机索引 |
| Iterable-style | `IterableDataset` | 流式数据、超大数据集、Kafka/Webstream |

Iterable 例子：

```python
from torch.utils.data import IterableDataset

class StreamDataset(IterableDataset):
    def __iter__(self):
        for line in open('huge.jsonl'):
            yield self.parse(line)
```

注意：用 `IterableDataset` 配合 `num_workers > 1` 时要**手动避免重复**（每个 worker 应只迭代自己负责的分片，否则 N 个 worker 输出 N 倍数据）。`get_worker_info()` 拿到 worker 编号自行切分。

## 6.2 DataLoader 全貌

```python
from torch.utils.data import DataLoader

loader = DataLoader(
    dataset,
    batch_size=64,
    shuffle=True,
    num_workers=4,
    pin_memory=True,
    drop_last=True,
    persistent_workers=True,
    prefetch_factor=2,
    collate_fn=None,
)
```

每个参数都对性能/正确性有具体影响。

| 参数 | 作用 | 常见错误 |
|------|------|---------|
| `batch_size` | 一次组装多少样本 | 太大 OOM；太小 GPU 闲置 |
| `shuffle` | 随机打乱 | 验证集不要 shuffle |
| `num_workers` | 子进程数 | 0 = 主进程同步加载（DEBUG 用）；过多反而慢 |
| `pin_memory` | 用页锁定内存 | GPU 训练几乎必开 |
| `drop_last` | 丢弃最后不满 batch | 否则最后 batch 大小不一致影响 BN/分布式 |
| `persistent_workers` | worker 不在 epoch 间销毁 | 启动慢的 dataset 受益巨大 |
| `prefetch_factor` | 每 worker 预取多少 batch | 数据小就调大，memory tight 调小 |
| `collate_fn` | 把样本列表组装成 batch | 变长数据必须自定义 |

## 6.3 num_workers 的选择

经验法则：

- 小：`num_workers = 0`，所有数据加载在主进程（DataLoader 同步），GPU 一定会等
- 中：`num_workers = CPU 核数 / GPU 数`，对 ImageNet 之类 CPU 解码 + 增强较重的任务
- 大：超过 CPU 核数后通常没收益，反而增加进程切换成本

**多卡 DDP 训练时**：每个 GPU 有自己的进程，每个进程再开 N 个 worker → 总进程数 = num_gpus * num_workers。容易爆 CPU/RAM，按 `CPU核数 / num_gpus` 计算。

### 6.3.1 fork vs spawn

Linux 默认 `fork`：worker 继承父进程内存，启动快，但**不能与 CUDA 已初始化的状态共存**。所以 `DataLoader` 的 worker **不能在 worker 内部调用 CUDA**（除非用 `spawn`）。

Windows / macOS 默认 `spawn`：每个 worker 重新导入模块，启动慢但安全。

```python
import torch
torch.multiprocessing.set_start_method('spawn', force=True)
```

如果 worker 内必须用 GPU（罕见），切到 spawn。

## 6.4 collate_fn：组装 batch

默认 `collate_fn` 把 `[(x1,y1), (x2,y2), ...]` 转成 `(stack(x), stack(y))`。stack 要求所有样本 shape 一致。变长场景必须自定义：

### 6.4.1 NLP 变长序列

```python
from torch.nn.utils.rnn import pad_sequence

def collate_pad(batch):
    xs = [b['input_ids'] for b in batch]
    ys = [b['label'] for b in batch]
    xs = pad_sequence(xs, batch_first=True, padding_value=0)
    ys = torch.tensor(ys)
    lengths = torch.tensor([len(b['input_ids']) for b in batch])
    return xs, ys, lengths

loader = DataLoader(ds, batch_size=32, collate_fn=collate_pad)
```

### 6.4.2 检测/分割：变长 ground truth

```python
def collate_det(batch):
    images = torch.stack([b['image'] for b in batch])
    boxes = [b['boxes'] for b in batch]    # 每个样本 box 数量不同，保持 list
    return images, boxes
```

输入 GPU 时，list 中的张量要分别 `.to(device)`。模型 forward 也要适配 list 输入。

## 6.5 Sampler：控制采样顺序

`shuffle=True` 实际是 `RandomSampler`。其他常用：

| Sampler | 用途 |
|---------|------|
| `SequentialSampler` | 顺序遍历（验证默认） |
| `RandomSampler` | 随机（带或不带重复） |
| `WeightedRandomSampler` | 类别不平衡时按权重采样 |
| `SubsetRandomSampler` | 在指定子集中随机 |
| `DistributedSampler` | 多卡训练，每个 rank 看不同分片 |
| `BatchSampler` | 直接生成 batch 索引（自定义 batch 策略） |

### 6.5.1 类别不平衡

```python
from torch.utils.data import WeightedRandomSampler

class_counts = [100, 1000, 50]    # 三类样本数
weights_per_class = 1.0 / torch.tensor(class_counts, dtype=torch.float)
sample_weights = weights_per_class[labels]    # 每个样本的权重

sampler = WeightedRandomSampler(
    sample_weights, num_samples=len(labels), replacement=True
)
loader = DataLoader(ds, batch_size=32, sampler=sampler)  # 注意：不要再 shuffle=True
```

### 6.5.2 DistributedSampler

```python
from torch.utils.data.distributed import DistributedSampler

sampler = DistributedSampler(ds, num_replicas=world_size, rank=rank, shuffle=True)
loader = DataLoader(ds, sampler=sampler, batch_size=32)

for epoch in range(epochs):
    sampler.set_epoch(epoch)    # 关键：让每个 epoch 用不同随机种子
    for x, y in loader:
        ...
```

忘记 `set_epoch` 会导致每个 epoch 顺序完全相同 —— 模型可能记住顺序。

## 6.6 数据预处理：在哪里做

候选位置：

| 位置 | 优点 | 缺点 |
|------|------|------|
| 提前预处理写到磁盘 | 训练时 IO 最少 | 失去随机增强多样性 |
| `Dataset.__getitem__` 中 CPU 处理 | 灵活、可随机增强 | 受 CPU 速度限制，主流方案 |
| 在 worker 中处理 | 多进程并行 | 同上 |
| 在 GPU 上处理（如 DALI、torchvision v2） | 极快 | 占用 GPU 内存与算力 |

主流方案：CPU 多进程 worker + 随机增强。重型预处理（视频解码、3D 体素化）考虑 GPU 加速库。

### 6.6.1 torchvision transforms v2

PyTorch 官方推荐 `torchvision.transforms.v2`，比 v1 快、支持视频/box/mask 联动：

```python
from torchvision.transforms import v2

train_tf = v2.Compose([
    v2.RandomResizedCrop(224, antialias=True),
    v2.RandomHorizontalFlip(),
    v2.ToDtype(torch.float32, scale=True),
    v2.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]),
])
```

### 6.6.2 PIL vs OpenCV vs Pillow-SIMD

图像解码瓶颈不可忽视：

| 库 | 速度 | 特点 |
|------|------|------|
| PIL（默认） | 基线 | 兼容性最好 |
| Pillow-SIMD | ~3-4x | drop-in 替换 PIL |
| OpenCV | ~2x | API 不同（BGR、shape 顺序） |
| nvidia DALI | 5-10x | GPU 解码 + 预处理 pipeline |
| FFCV | 10x+ | 自定义二进制格式，最快 |

## 6.7 数据增强的常见模式

```python
# 训练增强
train_tf = v2.Compose([
    v2.RandomResizedCrop(224),
    v2.RandomHorizontalFlip(),
    v2.RandAugment(num_ops=2, magnitude=9),     # 随机选 2 个增强操作
    v2.ToDtype(torch.float32, scale=True),
    v2.Normalize(mean, std),
    v2.RandomErasing(p=0.25),
])

# 验证：仅必要变换
val_tf = v2.Compose([
    v2.Resize(256, antialias=True),
    v2.CenterCrop(224),
    v2.ToDtype(torch.float32, scale=True),
    v2.Normalize(mean, std),
])
```

注意：

- 验证集**不要**用随机增强
- Normalize 的 mean/std 要与预训练权重匹配（ImageNet 标准 vs 自定义）
- 多次同样的增强组合可考虑放进 `torch.compile` 内 GPU 化

## 6.8 数据加载性能调试

### 6.8.1 判断瓶颈在数据还是 GPU

```python
import time
torch.cuda.synchronize()
t0 = time.time()
for x, y in loader:
    x = x.cuda(non_blocking=True)
    y = y.cuda(non_blocking=True)
    torch.cuda.synchronize()       # 等数据搬完
    out = model(x)
    loss = criterion(out, y)
    loss.backward()
    optimizer.step()
    torch.cuda.synchronize()
    print(time.time() - t0)
    t0 = time.time()
```

更好的办法：用 `torch.profiler`（第 12 章详解），看 timeline 里 GPU 是否有空白。

### 6.8.2 prefetch_factor 与 persistent_workers

epoch 切换时如果发现 GPU 突然空转，是因为 worker 进程被销毁重建：

```python
DataLoader(..., persistent_workers=True, prefetch_factor=4)
```

对启动慢的 Dataset（如要打开数据库连接、加载大词典）效果显著。

### 6.8.3 fast_collate

如果 `collate_fn` 在 Python 里循环复制大量数据，可改成 NumPy 一次性 stack：

```python
def fast_collate(batch):
    images = np.stack([np.asarray(b[0]) for b in batch])  # 不必先转 PIL
    targets = torch.tensor([b[1] for b in batch])
    return torch.from_numpy(images).permute(0, 3, 1, 2).contiguous(), targets
```

## 6.9 大数据集存储格式

| 格式 | 适合 | 优缺点 |
|------|------|-------|
| 原始文件 + 索引 | 小到中 | 简单；目录大量小文件慢 |
| `.tar`/`tar.gz`（webdataset） | 大 | 顺序读快；需要 webdataset 库 |
| HDF5 / Zarr | 数值矩阵、医学影像 | 块状读取；多进程要小心锁 |
| LMDB | KV 形式 | 极快随机读；写一次读多次 |
| Parquet / Arrow | 表格数据 | 列存压缩；大数据生态友好 |
| FFCV `.beton` | 视觉训练 | 极致性能；需要预转换 |

> **经验**：训练样本超过几十万，强烈建议**打包**成 tar/lmdb/beton 之一。文件系统对成千上万的小文件 inode 操作非常慢，HDD 上尤甚。

def __getitem__(self, idx):

## 6.11 数据增强中的隐性 bug

### 6.11.1 多进程 worker 的随机数

每个 worker 进程会**继承相同的随机种子**，导致每个 worker 生成相同的随机数序列：

```python
# 训练 5 个 epoch，发现每个 epoch 内的"随机增强"都一样
```

PT 1.9+ 默认已在每个 worker 设置不同种子，但自定义 `worker_init_fn` 时容易覆盖：

```python
def worker_init_fn(worker_id):
    seed = torch.initial_seed() % 2**32
    np.random.seed(seed)        # NumPy 随机也要重置
    random.seed(seed)
```

如果增强用的是 NumPy / Python random，必须显式同步种子。

### 6.11.2 Tensor 在 worker 里被无意共享

`fork` 模式下，worker 共享父进程的 tensor 内存。如果你在 `__getitem__` 里**修改**一个共享的全局 tensor，会引发竞态。

规则：worker 内只读，不修改全局状态。

### 6.11.3 num_workers > 0 时 dataset 必须可 pickle

子进程通过 pickle 序列化传递 dataset 对象。如果 dataset 持有不可序列化的资源（lambda、open file handle、数据库连接），会报 pickle 错误。

正确做法：在 `__init__` 里只存路径与配置，在 `__getitem__` 里**懒加载**（首次访问才打开文件）。

```python
class LazyDataset(Dataset):
    def __init__(self, h5_path):
        self.h5_path = h5_path
        self.h5 = None
    def __getitem__(self, idx):
        if self.h5 is None:
            self.h5 = h5py.File(self.h5_path, 'r')   # worker 内首次打开
        return self.h5['data'][idx]
```

## 6.12 推荐数据 pipeline 模板

```python
import torch
from torch.utils.data import Dataset, DataLoader
from torch.utils.data.distributed import DistributedSampler

class ImgDataset(Dataset):
    def __init__(self, files, transform):
        self.files = files
        self.transform = transform
    def __len__(self):
        return len(self.files)
    def __getitem__(self, idx):
        img = self.transform(read_image(self.files[idx]))
        label = parse_label(self.files[idx])
        return img, label

def make_loader(ds, is_train, batch_size, world_size, rank):
    sampler = DistributedSampler(
        ds, num_replicas=world_size, rank=rank, shuffle=is_train
    ) if world_size > 1 else None

    return DataLoader(
        ds,
        batch_size=batch_size,
        sampler=sampler,
        shuffle=(sampler is None and is_train),
        num_workers=8,
        pin_memory=True,
        drop_last=is_train,
        persistent_workers=True,
        prefetch_factor=4,
    )
```

## 6.13 本章小结

- `Dataset` 实现 `__len__` / `__getitem__`，单样本粒度；`DataLoader` 负责 batch、shuffle、多进程
- `num_workers` 配 `pin_memory` + `non_blocking=True` 才能真正 overlap H2D 与计算
- `collate_fn` 处理变长数据；`Sampler` 处理类别不平衡和分布式
- 验证集**不要 shuffle、不要随机增强**；分布式必须 `set_epoch`
- worker 进程的随机数、CUDA 共存、pickle 兼容性是常见坑
- 大数据集打包（webdataset / lmdb / FFCV）能把 IO 提一个量级
- 用 profiler 判断瓶颈在数据还是 GPU，再决定优化方向
