# 第05章 nn.Module 与模型构建

`torch.nn.Module` 是 PyTorch 中**所有模型的基类**。它看似只是个普通 Python 类，但背后承担了：参数注册、子模块管理、设备搬迁、序列化、训练/评估状态切换、hook 系统。理解 `Module` 的内部机制能帮你写出"正确并且高效"的模型代码 —— 而不只是能跑的。

---

## 5.1 一个最小的 Module

```python
import torch
import torch.nn as nn

class MLP(nn.Module):
    def __init__(self, in_dim, hidden, out_dim):
        super().__init__()
        self.fc1 = nn.Linear(in_dim, hidden)
        self.fc2 = nn.Linear(hidden, out_dim)

    def forward(self, x):
        return self.fc2(torch.relu(self.fc1(x)))

model = MLP(784, 256, 10)
out = model(torch.randn(2, 784))
```

每行代码背后都有"魔法"：

- `super().__init__()`：初始化 `_parameters`、`_buffers`、`_modules` 三个字典
- `self.fc1 = nn.Linear(...)`：触发 `__setattr__`，自动注册到 `_modules`
- `model(input)`：实际调用 `__call__`，它在 `forward` 前后插入 hook

---

## 5.2 Module 的内部结构

`Module` 维护几个核心字典：

| 属性 | 内容 | 注册方式 |
|------|------|---------|
| `_parameters` | `nn.Parameter` 对象 | 直接赋值或 `register_parameter` |
| `_buffers` | 不参与梯度但要随模型迁移的张量 | `register_buffer` |
| `_modules` | 子 Module | 直接赋值或 `add_module` |

```python
class Foo(nn.Module):
    def __init__(self):
        super().__init__()
        self.weight = nn.Parameter(torch.randn(3, 3))   # → _parameters
        self.register_buffer('mean', torch.zeros(3))    # → _buffers
        self.fc = nn.Linear(3, 3)                       # → _modules
        self.note = "hello"                             # 不进任何字典，普通属性

f = Foo()
print(list(f.named_parameters()))   # weight + fc.weight + fc.bias
print(list(f.named_buffers()))      # mean
print(list(f.named_modules()))      # 自身 + fc
```

### 5.2.1 Parameter 与普通 Tensor 的关键区别

```python
self.x = torch.randn(3, 3, requires_grad=True)         # 不会被 model.parameters() 收到
self.x = nn.Parameter(torch.randn(3, 3))               # 自动注册为参数
```

`nn.Parameter` 是 Tensor 的子类，专门用于让 `Module` 识别"这是要训练的权重"。常见 bug：用普通 tensor 存权重 → optimizer 拿不到 → 永远不更新。

### 5.2.2 buffer 是什么

不是参数，但又要随模型保存、加载、`.to(device)`、`state_dict()` 一起走的张量：

- BatchNorm 的 `running_mean` / `running_var`
- 位置编码表（如果不可学习）
- mask 表

```python
self.register_buffer('pos_emb', torch.zeros(seq_len, dim))
# state_dict 包含；保存/加载会带上；不出现在 parameters() 里
```

`persistent=False` 可注册"临时 buffer"，不进入 state_dict。

## 5.3 forward 不能直接调

```python
model.forward(x)   # ❌ 不要这么写
model(x)           # ✅ 触发 __call__，会运行 hook
```

`__call__` 比 `forward` 多做的：

1. 调用所有 `forward_pre_hook`
2. 真正调用 `forward`
3. 调用所有 `forward_hook`
4. 反向时调用 `backward_hook`

直接调 `forward` 会绕过 hook，破坏调试工具、`torch.compile`、量化等基础设施。

## 5.4 nn.Sequential、nn.ModuleList、nn.ModuleDict

### 5.4.1 Sequential：线性堆叠

```python
net = nn.Sequential(
    nn.Linear(10, 32),
    nn.ReLU(),
    nn.Linear(32, 1),
)
out = net(x)        # 自动按顺序前向
```

适合：纯线性堆叠。如有跳跃连接、控制流，不要用。

### 5.4.2 ModuleList：可索引的子模块容器

```python
class DeepMLP(nn.Module):
    def __init__(self, n_layers):
        super().__init__()
        self.layers = nn.ModuleList(
            [nn.Linear(64, 64) for _ in range(n_layers)]
        )

    def forward(self, x):
        for layer in self.layers:
            x = torch.relu(layer(x))
        return x
```

**陷阱**：用普通 Python list 存 Module 会**不被注册**：

```python
self.layers = [nn.Linear(64, 64) for _ in range(n)]   # ❌ 不会注册参数
self.layers = nn.ModuleList([...])                    # ✅
```

### 5.4.3 ModuleDict：按名称访问

```python
self.heads = nn.ModuleDict({
    'classifier': nn.Linear(64, 10),
    'regressor': nn.Linear(64, 1),
})
```

多任务场景常用。同样不能用普通 dict。

## 5.5 train() 与 eval() —— 状态切换的语义

```python
model.train()     # 训练模式
model.eval()      # 评估模式
```

只影响那些**行为依赖训练状态**的子模块：

- **Dropout**：train 时随机丢弃；eval 时直接传过
- **BatchNorm**：train 时更新 running stats、用 batch stats 归一化；eval 时用 running stats
- 自定义模块：通过 `self.training` 标志区分

```python
class MyDropout(nn.Module):
    def __init__(self, p):
        super().__init__()
        self.p = p

    def forward(self, x):
        if self.training:
            mask = (torch.rand_like(x) > self.p).float()
            return x * mask / (1 - self.p)
        return x
```

> **极常见 bug**：评估时忘记 `model.eval()`，BatchNorm 在每个验证 batch 上更新 running stats，验证集"污染"训练统计；Dropout 还在丢弃 → 验证 loss 偏高且不稳定。

## 5.6 设备与 dtype 迁移

`Module.to(device, dtype)` 会**递归地**把所有 parameter 与 buffer 搬到目标设备/类型：

```python
model.to('cuda')              # 全搬到 GPU
model.to(torch.bfloat16)      # 全转成 bf16
model.to('cuda', torch.bf16)  # 同时
```

注意：

- 输入张量**不会被自动迁移**，要手动 `x.to('cuda')`
- 在 `__init__` 里创建的临时常量 tensor（不是 buffer）不会被迁移 —— 用 `register_buffer` 或在 forward 里用 `x.new_zeros(...)`

错误示例：

```python
class Bad(nn.Module):
    def __init__(self):
        super().__init__()
        self.const = torch.zeros(3)   # 不会迁移
    def forward(self, x):
        return x + self.const          # x 在 cuda, const 在 cpu → 报错
```

正确：

```python
self.register_buffer('const', torch.zeros(3))
```

## 5.7 参数初始化

PyTorch 默认初始化对常见层（Linear、Conv）是 Kaiming uniform，多数情况够用。但需要重新初始化时：

```python
def init_weights(m):
    if isinstance(m, nn.Linear):
        nn.init.kaiming_normal_(m.weight, nonlinearity='relu')
        if m.bias is not None:
            nn.init.zeros_(m.bias)
    elif isinstance(m, nn.LayerNorm):
        nn.init.ones_(m.weight)
        nn.init.zeros_(m.bias)

model.apply(init_weights)
```

`apply()` 递归到所有子模块（包括自己）。

常用初始化：

| 函数 | 适用 |
|------|------|
| `kaiming_normal_` / `kaiming_uniform_` | ReLU 系激活 |
| `xavier_normal_` / `xavier_uniform_` | tanh / sigmoid |
| `trunc_normal_` | Transformer / ViT 标配 |
| `orthogonal_` | RNN |
| `zeros_` / `ones_` | bias / norm |

## 5.8 state_dict 与 load_state_dict

`state_dict()` 返回 `OrderedDict[str, Tensor]`，键是参数/buffer 的层级名：

```python
model.state_dict().keys()
# odict_keys(['fc1.weight', 'fc1.bias', 'fc2.weight', 'fc2.bias'])

torch.save(model.state_dict(), 'model.pt')

# 加载
model = MLP(784, 256, 10)
model.load_state_dict(torch.load('model.pt', map_location='cpu'))
```

### 5.8.1 strict=False 的应用

```python
missing, unexpected = model.load_state_dict(state_dict, strict=False)
print(missing)      # 模型有但 ckpt 没有
print(unexpected)   # ckpt 有但模型没有
```

迁移学习时常用：从大模型 checkpoint 中加载部分权重。注意 missing/unexpected 的处理 —— 静默失败比报错更危险。

### 5.8.2 不要 `torch.save(model)` —— 保存整个对象

```python
torch.save(model, 'model.pt')           # ❌ 会序列化类定义和路径
torch.save(model.state_dict(), 'm.pt')  # ✅ 只存张量字典
```

直接保存模型对象会绑定到当时的代码路径（pickle 类引用），换文件结构后**完全无法加载**。这是新手常踩的坑。

PT 2.x 推荐用更安全的 `torch.save(state_dict, ...)` + `weights_only=True` 加载（默认 True），防止反序列化漏洞。

## 5.9 freeze / unfreeze 参数

冻结部分参数（迁移学习常用）：

```python
for p in model.backbone.parameters():
    p.requires_grad = False

# 优化器只接收要更新的参数
optimizer = torch.optim.Adam(
    filter(lambda p: p.requires_grad, model.parameters()),
    lr=1e-4
)
```

注意：

- BatchNorm 即使冻结了 weight/bias，运行时仍可能更新 `running_mean/var` —— 配合 `module.eval()` 阻止更新
- 完全冻结的 backbone 可以包在 `torch.no_grad()` 里前向，节省激活显存

```python
class FineTune(nn.Module):
    def forward(self, x):
        with torch.no_grad():
            features = self.backbone(x)
        return self.head(features)
```

## 5.10 hook 的实战用法

### 5.10.1 提取中间层特征

```python
features = {}
def hook(name):
    def fn(_, __, output):
        features[name] = output
    return fn

handle = model.layer3.register_forward_hook(hook('layer3'))
out = model(x)
print(features['layer3'].shape)
handle.remove()           # 用完务必移除，避免内存泄漏
```

### 5.10.2 调试梯度

```python
def grad_print(name):
    def fn(grad):
        print(f"{name} grad norm = {grad.norm()}")
    return fn

for name, p in model.named_parameters():
    if p.requires_grad:
        p.register_hook(grad_print(name))
```

## 5.11 Functional API vs Module API

很多操作既有 `nn.X` 又有 `nn.functional.X`：

```python
# Module 风格
self.relu = nn.ReLU()
self.dropout = nn.Dropout(0.5)
y = self.dropout(self.relu(x))

# Functional 风格
import torch.nn.functional as F
y = F.dropout(F.relu(x), p=0.5, training=self.training)
```

选择原则：

- **有可训练参数 / 有内部状态 → Module 形式**：Linear、Conv、BatchNorm、Dropout 大多场景都用 Module
- **纯函数（无参数无状态）→ Functional 形式**：relu、softmax、log_softmax、cross_entropy 等

特别注意：`F.dropout` 必须显式传 `training=self.training`，否则永远在 dropout 或永远不 dropout。Module 形式自动同步训练状态。

## 5.13 一个完整示例：可复用的 Transformer Block

```python
class TransformerBlock(nn.Module):
    def __init__(self, dim, heads, mlp_ratio=4.0, dropout=0.0):
        super().__init__()
        self.norm1 = nn.LayerNorm(dim)
        self.attn = nn.MultiheadAttention(
            dim, heads, dropout=dropout, batch_first=True
        )
        self.norm2 = nn.LayerNorm(dim)
        self.mlp = nn.Sequential(
            nn.Linear(dim, int(dim * mlp_ratio)),
            nn.GELU(),
            nn.Dropout(dropout),
            nn.Linear(int(dim * mlp_ratio), dim),
            nn.Dropout(dropout),
        )

    def forward(self, x, attn_mask=None):
        h = self.norm1(x)
        h, _ = self.attn(h, h, h, attn_mask=attn_mask, need_weights=False)
        x = x + h
        x = x + self.mlp(self.norm2(x))
        return x
```

要点：

- pre-norm（先 norm 再算 attention）—— 训练稳定
- residual connection 直接 `x + ...` —— 不要写成 `x.add_()`，会破坏 autograd
- attention dropout 与 MLP dropout 分开传

## 5.14 本章小结

- `Module` 通过 `__setattr__` 自动注册子模块、参数、buffer
- 训练参数必须用 `nn.Parameter`；要随模型走的非梯度张量用 `register_buffer`
- 调用模型用 `model(x)` 而非 `model.forward(x)`
- `train()` / `eval()` 切换 Dropout/BatchNorm 行为，评估时极易遗漏
- `state_dict` 保存张量字典，不要序列化整个 Module
- 迁移学习冻结参数后要让 optimizer 也只看到可训练参数
- hook 是调试与特征提取利器，但用完必须 remove
