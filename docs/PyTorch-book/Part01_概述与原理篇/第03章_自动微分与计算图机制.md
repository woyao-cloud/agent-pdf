# 第03章 自动微分与计算图机制

PyTorch 之所以能用一行 `loss.backward()` 算出整个网络的梯度，靠的是 **Autograd 引擎**。理解 Autograd 不是炫技 —— 它直接关系到你能否解释：
- "为什么我的 `requires_grad=True` 没生效？"
- "为什么显存爆炸 —— 中间变量在哪里？"
- "为什么二阶导报错？"
- "为什么 `with torch.no_grad()` 能省一半显存？"

本章把 Autograd 拆解到能写自定义算子的程度。

---

## 3.1 自动微分的三种范式

| 范式 | 代表 | 何时构图 |
|------|------|---------|
| 符号微分 | SymPy、早期 Theano | 编译期，由表达式推导出梯度公式 |
| 数值微分 | finite difference | 运行期，对每个参数加 ε 计算差分 |
| 自动微分（AD） | PyTorch、JAX、TF | 运行期，按链式法则反向传播 |

数值微分简单但 O(n) 慢且不精确；符号微分难处理控制流；AD 兼顾速度与正确性，是所有现代框架的选择。

AD 又分两种模式：

- **Forward mode**：和前向同时计算 `(value, tangent)` 对，适合输入维度小、输出维度大的场景
- **Reverse mode**（PyTorch 默认）：先前向缓存中间值，再反向计算梯度，适合**深度学习常见场景：标量 loss + 海量参数**

PyTorch 主要使用 reverse mode；通过 `torch.func.jvp` 也能做 forward mode（详见第 11 章）。

## 3.2 PyTorch 的反向计算图

### 3.2.1 一个最小例子

```python
import torch

x = torch.tensor(2.0, requires_grad=True)
y = x * 3 + 1
z = y ** 2

z.backward()
print(x.grad)   # 2 * (2*3+1) * 3 = 42
```

发生了什么：

1. `requires_grad=True` 的 leaf tensor 被标记
2. 每次运算（`*`、`+`、`**`）都会**记录**一个 `grad_fn`，指向反向函数节点
3. `z.backward()` 从 z 出发，沿 `grad_fn` 链反向遍历，按链式法则累加梯度到 leaf

```python
print(z.grad_fn)            # <PowBackward0>
print(z.grad_fn.next_functions)  # 指向 y 的 grad_fn
```

### 3.2.2 计算图的"动态"含义

每次前向都**重新构建**一张图：

```python
for i in range(10):
    y = x * (i + 1)         # 每次构造的图都不同
    y.backward()
    x.grad.zero_()
```

这正是动态图与静态图的本质区别 —— 前者把图绑定在 Python 执行流上，后者要预先声明。

### 3.2.3 leaf tensor 与 non-leaf tensor

**leaf**：图的叶子节点，通常是模型参数或输入。`x.is_leaf == True`。
**non-leaf**：运算结果，`y = x * 3` 中的 `y`。

只有 leaf tensor 的 `.grad` 会保留；中间结果默认不保留（节省显存）。如果要查看中间梯度：

```python
y = x * 3
y.retain_grad()       # 显式保留
z = y ** 2
z.backward()
print(y.grad)         # OK
```

## 3.3 backward 的执行流程

`backward()` 的内部步骤（简化版）：

1. 从被调用 Tensor 的 `grad_fn` 入队
2. 维护拓扑顺序，逐个弹出反向节点
3. 对每个节点：
   - 取它的输入梯度（来自后续节点）
   - 调用反向函数，算出对它输入的梯度
   - **累加**到下游节点（注意：是 `+=` 不是 `=`）
4. 抵达 leaf 时，将梯度写入 `.grad`

关键点：

### 3.3.1 梯度累积

```python
x = torch.tensor(2.0, requires_grad=True)
y = x * 3
y.backward()
print(x.grad)   # 3
y2 = x * 5
y2.backward()
print(x.grad)   # 8 = 3 + 5  累加！
```

这是为什么训练循环里要 `optimizer.zero_grad()`。

### 3.3.2 一次前向只能反传一次

默认情况下，反向后中间张量被释放：

```python
y = x * 3
z = y ** 2
z.backward()
z.backward()    # RuntimeError: Trying to backward through the graph a second time
```

如要多次反传：

```python
z.backward(retain_graph=True)   # 保留计算图
z.backward()
```

代价：中间张量不释放，显存占用增加。绝大多数场景**不需要**这个标志，看到它一般是别的问题（多 loss 没合并、错误的训练循环等）。

### 3.3.3 非标量反传需要 grad_outputs

```python
y = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)
y.backward()    # RuntimeError: grad can be implicitly created only for scalar outputs

# 解法 1：对 sum 反传
y.sum().backward()

# 解法 2：显式提供向量
y.backward(torch.ones_like(y))   # 等价于上面
```

物理含义：对向量输出 y，`y.backward(v)` 计算的是 `v^T · ∂y/∂x`，即 Vector-Jacobian Product (VJP)。Autograd 本质是 VJP。

## 3.4 grad_fn 与自定义 Function

每个 PyTorch 算子背后都有一个 `Function`（`torch.autograd.Function`），定义了 forward 与 backward。可自定义：

```python
class MyReLU(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):
        ctx.save_for_backward(x)
        return x.clamp(min=0)

    @staticmethod
    def backward(ctx, grad_output):
        (x,) = ctx.saved_tensors
        grad_input = grad_output.clone()
        grad_input[x < 0] = 0
        return grad_input

x = torch.randn(5, requires_grad=True)
y = MyReLU.apply(x)
y.sum().backward()
```

要点：

- `ctx.save_for_backward()` 用于保存反向需要的张量；不要直接存 `self.x = x`，会破坏图依赖
- forward 与 backward 的输入输出维度必须**对偶**：forward 的每个输入对应 backward 的一个返回梯度

### 3.4.1 何时需要自定义 Function

- 已有算子组合无法表达的数学运算
- 需要数值稳定的特殊反向（如 log-sum-exp、softmax 自己的稳定实现）
- 需要直接调用 CUDA kernel 而又要参与 Autograd
- "stop gradient" 的特殊变体（如 GRL 梯度反转层）

### 3.4.2 检查梯度正确性

`torch.autograd.gradcheck` 用数值微分验证你的 backward：

```python
x = torch.randn(5, dtype=torch.double, requires_grad=True)
torch.autograd.gradcheck(MyReLU.apply, (x,))   # 通过则梯度正确
```

> gradcheck 必须用 `double` 精度，否则数值差分误差大。

## 3.5 控制梯度流的常用 API

| API | 作用 | 何时用 |
|-----|------|-------|
| `torch.no_grad()` 上下文 | 不构建计算图 | 推理、评估、不需要反传时 |
| `torch.inference_mode()` 上下文 | 比 `no_grad` 更激进的优化 | 纯推理（不能再次启用 autograd） |
| `tensor.detach()` | 从图中分离一份新视图 | 需要数值但切断梯度流 |
| `tensor.requires_grad_(False)` | 原地修改属性 | 冻结某个参数 |
| `with torch.set_grad_enabled(flag)` | 动态切换 | 训练/评估混合代码 |
| `@torch.no_grad()` 装饰器 | 函数级 | 评估函数 |

### 3.5.1 no_grad vs inference_mode

```python
with torch.no_grad():
    y = model(x)             # 不构图，但 y 仍是普通 tensor

with torch.inference_mode():
    y = model(x)             # 不构图，且做了更激进的优化（version counter 跳过等）
    # y 不能再用于训练
```

`inference_mode` 比 `no_grad` 在很多场景快 5-10%，但 y 之后无法被 autograd 重新启用。**纯推理服务首选**。

### 3.5.2 detach 的常见用法

```python
# 用模型 A 的输出作为模型 B 的输入，但不让梯度回传到 A
features = model_A(x).detach()
out = model_B(features)
loss = criterion(out, y)
loss.backward()    # 只更新 model_B
```

GAN 训练判别器时同样关键：

```python
fake = generator(z).detach()      # 别让 D 的梯度污染 G
d_loss = criterion(D(fake), 0) + criterion(D(real), 1)
d_loss.backward()
```

## 3.6 高阶导数

PyTorch 支持任意阶导数，原理是反向图也可微分：

```python
x = torch.tensor(2.0, requires_grad=True)
y = x ** 3
dy_dx = torch.autograd.grad(y, x, create_graph=True)[0]   # 3x^2 = 12
d2y_dx2 = torch.autograd.grad(dy_dx, x)[0]                # 6x = 12
```

`create_graph=True` 让一阶导本身参与新的计算图，从而可对其再求导。**显存代价巨大**：每阶都要保留前一阶的中间张量。物理 PINN、元学习（MAML）等场景必须用。

## 3.7 Autograd 与显存

每次前向构图时，PyTorch 默认**保留前向所有中间激活**用于反向。这是训练显存的主要来源（不是参数本身）。

经验估计（fp16 混精训练）：

```
模型显存 ≈ 参数 * 6 字节 (fp16 + master fp32 + 优化器状态)
激活显存 ≈ batch * seq * hidden * num_layers * 2 字节
```

对 transformer 训练而言，激活往往**远大于**参数显存。

### 3.7.1 Gradient Checkpointing

牺牲计算换显存：前向**只缓存检查点**，反向时重新算被丢弃的中间值。

```python
from torch.utils.checkpoint import checkpoint

def block(x):
    return some_complex_subnet(x)

y = checkpoint(block, x, use_reentrant=False)   # 不缓存内部激活
```

实际效果：对 LLM 训练通常省 30-50% 激活显存，多 30% 计算时间。详见第 13 章。

### 3.7.2 Autograd 与原地操作

原地操作（`x += y`、`x.relu_()`）破坏 Autograd 历史：

```python
x = torch.randn(3, requires_grad=True)
y = x * 2
x += 1                # 改变 x，破坏了 y = x*2 的历史
y.sum().backward()    # RuntimeError: ... has been modified by an inplace operation
```

PyTorch 用 **version counter** 检测：每个 Storage 都记录版本号，任何 inplace 都会自增；反向时核对版本，不一致就报错。

> **建议**：在训练循环中除了 `optimizer.step()` 内部、`torch.add_` 这类显式优化，**避免对带梯度的 tensor 做原地操作**。可读性提升远大于那点显存。

## 3.8 hooks：监听梯度流

```python
def grad_hook(grad):
    print('grad:', grad)
    return grad * 2          # 也可以返回修改后的梯度

x = torch.randn(3, requires_grad=True)
x.register_hook(grad_hook)

y = (x ** 2).sum()
y.backward()
```

应用场景：

- 调试梯度爆炸/消失：在每层注册 hook 打印 grad norm
- 实现梯度反转层（GRL）：返回 `-grad`
- 梯度裁剪的细粒度版本

模块级 hook：

```python
def fwd_hook(module, input, output): ...
def bwd_hook(module, grad_input, grad_output): ...

linear.register_forward_hook(fwd_hook)
linear.register_full_backward_hook(bwd_hook)
```

注意 hook 引用计数容易造成内存泄漏 —— 用完调 `handle.remove()`。

## 3.9 torch.func：函数式 Autograd

PT 2.0+ 内置 `torch.func`（前身 `functorch`），借鉴 JAX 提供 `vmap` / `grad` / `jacrev` 等函数变换：

```python
from torch.func import grad, vmap

def f(x):
    return (x ** 2).sum()

# 函数式求梯度（不需要 requires_grad）
grad_f = grad(f)
print(grad_f(torch.tensor([1.0, 2.0, 3.0])))   # [2., 4., 6.]

# 自动批量化
batched_grad_f = vmap(grad_f)
print(batched_grad_f(torch.randn(10, 3)))      # 一次算 10 个
```

适合：per-sample gradient（差分隐私）、雅可比矩阵显式构造、Hessian-vector 积、元学习等。

## 3.10 常见 Autograd 陷阱

| 现象 | 原因 | 解法 |
|------|------|------|
| `RuntimeError: element 0 ... does not require grad` | 在 detach / no_grad 之后又调 backward | 检查 detach 位置 |
| `RuntimeError: leaf variable has been moved into a non-leaf node` | 把 leaf tensor 包了一层运算 | 用 `nn.Parameter` 或保留原 leaf |
| `loss.backward()` 后 `param.grad is None` | 该参数未参与计算 / dtype 不匹配 | 打印图、确认调用路径 |
| 二阶导得不到 / 报错 | 一阶时未 `create_graph=True` | 加上 `create_graph=True` |
| 显存随 epoch 增长 | 梯度未 zero / 累积了 retain_graph | 检查 `zero_grad()`、删除多余 `retain_graph` |
| `inplace operation detected` | 对带梯度 tensor 做了原地修改 | 改成非原地版本 |

第 17 章会给出完整的 Autograd 故障排查流程。

## 3.11 本章小结

- Autograd 是 reverse-mode 自动微分的引擎，本质是 Vector-Jacobian Product
- 计算图按 Python 执行流即时构建，每次反向后默认释放中间激活
- 自定义运算用 `torch.autograd.Function`；用 `gradcheck` 验证正确性
- `no_grad` / `inference_mode` / `detach` 用于精细控制梯度流，对显存和性能影响巨大
- 高阶导数靠 `create_graph=True`，显存代价高
- 训练显存的"幕后凶手"通常是激活而非参数；gradient checkpointing 是杠杆
