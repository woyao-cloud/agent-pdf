# 第11章 推荐、时序、强化学习、生成模型

PyTorch 的应用远不止视觉与 NLP。本章把另外四类常见但风格各异的场景压缩到一章：**推荐系统、时序预测、强化学习、生成模型**。每节给出典型 pipeline、PyTorch 生态、关键陷阱。

## 11.1 推荐系统

### 11.1.1 任务类型

| 任务 | 典型问题 |
|------|---------|
| CTR / CVR 预估 | 点击率、转化率（二分类） |
| 评分预测 | 1-5 星预测（回归） |
| Top-K 推荐 | 给用户 N 个候选 |
| 序列推荐 | 基于行为序列的下一步 |

### 11.1.2 模型脉络

```
传统：       LR / FM
深度：       Wide & Deep / DeepFM / DCN
序列：       DIN / DIEN / SASRec / BERT4Rec
两塔：       DSSM 系列（召回）
图：         GraphSAGE / PinSage（候选/embedding）
LLM 时代：   LLM4Rec（用 LLM 做 ranker / 改写）
```

### 11.1.3 PyTorch 推荐生态

| 库 | 角色 |
|------|------|
| **TorchRec** | Meta 官方，超大规模 embedding 表 |
| **RecBole** | 学术、模型最全 |
| **Merlin / NVTabular** | NVIDIA，端到端 GPU |
| **FuxiCTR** | 工业 CTR baseline 集 |

### 11.1.4 核心难点：超大 embedding 表

推荐系统的最大特征：sparse feature 表巨大 —— 用户 / 物品 / 上下文等 ID 维度可达**数十亿**，单个 embedding 表可超过单卡显存。

PyTorch 的标准 `nn.Embedding` 不够用。解决：

- **分片 embedding**（TorchRec 的核心）：把表按行 / 列切到多个 GPU
- **混合并行**：embedding 用 model parallel，dense 部分用 data parallel
- **CPU offload**：访问稀疏，CPU/SSD 存储 + 按需取

### 11.1.5 一个最小 DeepFM 示例

```python
import torch.nn as nn

class DeepFM(nn.Module):
    def __init__(self, feat_sizes, emb_dim=16, dnn_hidden=[128,64]):
        super().__init__()
        self.embeddings = nn.ModuleList(
            [nn.Embedding(s, emb_dim) for s in feat_sizes]
        )
        self.first_order = nn.ModuleList(
            [nn.Embedding(s, 1) for s in feat_sizes]
        )
        n_feat = len(feat_sizes)
        layers = []
        in_dim = n_feat * emb_dim
        for h in dnn_hidden:
            layers += [nn.Linear(in_dim, h), nn.ReLU()]
            in_dim = h
        layers.append(nn.Linear(in_dim, 1))
        self.dnn = nn.Sequential(*layers)

    def forward(self, x):
        # x: (B, n_feat) long
        emb = [e(x[:, i]) for i, e in enumerate(self.embeddings)]      # n_feat * (B, D)
        emb_stack = torch.stack(emb, dim=1)                            # (B, n_feat, D)
        # FM 二阶交叉
        sum_sq = emb_stack.sum(dim=1) ** 2
        sq_sum = (emb_stack ** 2).sum(dim=1)
        fm_2nd = 0.5 * (sum_sq - sq_sum).sum(dim=1, keepdim=True)
        # 一阶
        fm_1st = sum(e(x[:, i]) for i, e in enumerate(self.first_order))
        # DNN
        dnn_out = self.dnn(emb_stack.flatten(1))
        return torch.sigmoid(fm_1st + fm_2nd + dnn_out)
```

### 11.1.6 推荐场景的特殊风险

- **数据穿越**：用了未来信息（label leakage） → 离线很高，上线崩
- **特征不一致**：训练时按某种规则编码 ID，上线时编码不一致
- **冷启动**：新用户/新物品的 embedding 没训练
- **样本不平衡**：CTR 数据正例 0.1-5%，需要 negative sampling 或 focal-like loss
- **A/B 偏差**：离线 AUC 提升 ≠ 线上指标提升

## 11.2 时序预测

### 11.2.1 模型路径

```
统计：    ARIMA / ETS / Prophet
经典 DL： RNN / LSTM / GRU
近期：    TCN / Temporal Fusion Transformer / N-BEATS / N-HiTS
现代：    PatchTST / TimesNet / iTransformer / Time-LLM
```

### 11.2.2 PyTorch 生态

| 库 | 用途 |
|------|------|
| `pytorch-forecasting` | TFT / N-BEATS / DeepAR |
| `darts` | 多模型 + scikit-learn 风格 API |
| `neuralforecast`（Nixtla） | 大量神经预测模型 |

### 11.2.3 序列建模常见 PyTorch 写法

```python
class LSTMForecast(nn.Module):
    def __init__(self, in_dim, hidden, horizon):
        super().__init__()
        self.lstm = nn.LSTM(in_dim, hidden, num_layers=2,
                            batch_first=True, dropout=0.1)
        self.head = nn.Linear(hidden, horizon)

    def forward(self, x):       # x: (B, T, F)
        h, _ = self.lstm(x)
        return self.head(h[:, -1])    # (B, horizon)
```

### 11.2.4 时序数据处理要点

- **窗口切分**：滑动窗口生成 (input, target) 对；窗口大小 / 步长是关键超参
- **归一化**：必须按训练集统计，验证 / 测试用相同 mean/std；做 z-score 后预测要逆变换
- **泄漏防护**：归一化、特征工程不能用未来信息
- **频率对齐**：缺失值插值 vs mask；高频与低频特征对齐
- **多变量 / 多时序**：iTransformer 等模型把"变量"作为序列 token

### 11.2.5 评估指标

MAE、MAPE、SMAPE、RMSE、MASE。**业务往往不关心 RMSE，关心 P50/P95 误差或某些定向区间**。和业务方对齐再选指标。

## 11.3 强化学习


### 11.3.2 PyTorch RL 生态

| 库 | 特点 |
|------|------|
| **TorchRL**（PyTorch 官方） | 模块化、tensordict 抽象 |
| **Stable-Baselines3** | 经典实现，最易上手 |

### 11.3.3 PPO 训练循环骨架

```python
for iteration in range(N):
    # 1. rollout：收集 trajectories
    obs, actions, log_probs, rewards, values = rollout(env, policy, value, steps)
    # 2. 计算 advantage（GAE）
    advs, returns = compute_gae(rewards, values, gamma, lam)
    # 3. 多 epoch 优化
    for epoch in range(K):
        for batch in sample(trajectories, batch_size):
            new_log_probs, new_values = policy.evaluate(batch.obs, batch.actions)
            ratio = (new_log_probs - batch.log_probs).exp()
            surr1 = ratio * batch.advs
            surr2 = ratio.clamp(1-eps, 1+eps) * batch.advs
            policy_loss = -torch.min(surr1, surr2).mean()
            value_loss = (new_values - batch.returns).pow(2).mean()
            entropy = policy.entropy(batch.obs).mean()
            loss = policy_loss + 0.5*value_loss - 0.01*entropy
            loss.backward()
            optimizer.step()
            optimizer.zero_grad()
```

### 11.3.4 RL 实战陷阱

- **环境不确定性**：随机种子、并行 env 同步状态、wrapper 顺序敏感
- **reward 量级**：reward 是 1 还是 1000 影响很大；常做 normalization
- **observation normalization**：running mean/std 必须保存
- **超参敏感**：lr、γ、λ、clip_eps 改一点效果天差地别
- **CPU/GPU 抢调度**：env 在 CPU 跑，模型在 GPU；过多 H2D 拷贝拖慢
- **action discretization**：连续动作离散化损失精度
- **稀疏 reward**：要 reward shaping、curiosity、HER 等
- **梯度方差大**：不稳定时换 SAC 或加 entropy

### 11.3.5 LLM 中的 RL：GRPO / DPO

DeepSeek-R1 / 推理模型常用 GRPO（Group Relative Policy Optimization）：

- 一个 prompt 生成多个回答
- 用 reward model（或规则）打分
- 同组内相对优势（advantage = reward - group_mean / group_std）
- PPO 风格更新

不需要 critic，省一半显存。trl 已支持。

### 11.4.1 GAN

PyTorch 经典 DCGAN 模板：

```python
# Generator
class G(nn.Module):
    def __init__(self, z_dim, img_ch):
        super().__init__()
        self.net = nn.Sequential(
            nn.ConvTranspose2d(z_dim, 512, 4, 1, 0), nn.BatchNorm2d(512), nn.ReLU(),
            nn.ConvTranspose2d(512, 256, 4, 2, 1), nn.BatchNorm2d(256), nn.ReLU(),
            nn.ConvTranspose2d(256, 128, 4, 2, 1), nn.BatchNorm2d(128), nn.ReLU(),
            nn.ConvTranspose2d(128, img_ch, 4, 2, 1), nn.Tanh(),
        )
    def forward(self, z): return self.net(z)

# Discriminator (略)

# 训练循环关键
for real, _ in loader:
    z = torch.randn(B, z_dim, 1, 1, device=device)
    fake = G(z)

    # train D
    d_loss = bce(D(real), 1) + bce(D(fake.detach()), 0)
    d_loss.backward(); opt_d.step(); opt_d.zero_grad()

    # train G
    g_loss = bce(D(fake), 1)
    g_loss.backward(); opt_g.step(); opt_g.zero_grad()
```

GAN 训练**极不稳定**，常见症状：

- mode collapse（G 只生成一种样本）
- D 太强导致 G 梯度消失
- 训练发散

缓解：WGAN-GP、SpectralNorm、TTUR（D/G 不同 lr）、EMA。但 2023 后 Diffusion 已基本取代 GAN 在大多数生成任务的位置。

### 11.4.2 VAE

```python
class VAE(nn.Module):
    def __init__(self, in_dim, h, z):
        super().__init__()
        self.enc = nn.Sequential(nn.Linear(in_dim, h), nn.ReLU(), nn.Linear(h, 2*z))
        self.dec = nn.Sequential(nn.Linear(z, h), nn.ReLU(), nn.Linear(h, in_dim))

    def forward(self, x):
        mu_logvar = self.enc(x.flatten(1))
        mu, logvar = mu_logvar.chunk(2, dim=-1)
        z = mu + (0.5 * logvar).exp() * torch.randn_like(mu)    # reparam
        return self.dec(z), mu, logvar

def vae_loss(recon, x, mu, logvar):
    bce = F.binary_cross_entropy(recon, x.flatten(1), reduction='sum')
    kld = -0.5 * (1 + logvar - mu.pow(2) - logvar.exp()).sum()
    return bce + kld
```

VAE 当前主要作为更大系统的子模块（Stable Diffusion 的 VAE encoder/decoder、世界模型）。

### 11.4.3 Flow / Score-based / Consistency Models

近年的发展：

- **Normalizing Flow**：精确似然（医学、物理）
- **Score-based / EDM**：Diffusion 的统一视角

工业落地仍以 Diffusion 为主，其他多见于研究。

## 11.5 跨场景共性陷阱

虽然这四类场景差异大，但共性陷阱不少：

| 陷阱 | 表现 |
|------|------|
| 训练-推理数据分布不一致 | 离线指标好，上线崩 |
| 评估集泄漏 | 离奇高的指标 |
| reward / loss 量级失衡 | 训练发散 |
| running stats 没保存（BN、normalizer） | 推理时输出乱 |
| 随机性未控制 | 复现失败 |
| H2D 频繁拷贝 | GPU 利用率 < 30% |
| 单卡瓶颈但没用 DDP/FSDP | 训练慢 |
| 模型太大 OOM 后强行减 batch | 训练效果差 → 应该用混精/checkpoint/FSDP |

## 11.6 选择 PyTorch 还是别的？

| 场景 | PyTorch 是否首选 |
|------|---------------|
| 研究、原型迭代 | 是 |
| 视觉 / NLP / 多模态 工业落地 | 是 |
| 推荐系统超大表 | TorchRec 可，但 TF / 自研框架仍是主流 |
| 时序经典统计 | 用 Prophet / statsmodels 更好；DL 才用 PyTorch |
| 强化学习研究 | 是 |
| 强化学习游戏引擎集成 | C++ 引擎 + ONNX 推理 更合适 |
| 移动端低功耗 | 慎重，TFLite/CoreML 仍领先 |
| 端到端自动驾驶训练 | 是（特斯拉、Wayve 都是 PyTorch） |

## 11.7 本章小结

- 推荐系统的核心是巨型 embedding 表 —— TorchRec 是 PyTorch 阵营答案
- 时序模型从 LSTM 进入 Transformer 时代；用 `pytorch-forecasting` / `neuralforecast`
- RL 的工程难度大于模型本身；首选 Stable-Baselines3 / TorchRL；LLM 上看 trl
- 生成模型：Diffusion 主流，GAN 退场，VAE 作为组件，Flow/Consistency 在演进
- 不论哪类场景，离线 vs 在线一致性、随机性控制、normalizer 保存都是隐形风险
