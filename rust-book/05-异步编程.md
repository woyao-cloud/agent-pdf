# 第 5 章 异步编程
> **本章导读**：async/await、Future、Tokio 运行时。Rust 的异步编程模型与 Go 类似，但更强调零成本抽象和编译期检查。
## 1. 异步编程基础
### 1.1 为什么需要异步
- **I/O 密集型任务**：网络请求、文件读写、数据库查询
- **高并发**：同时处理大量连接
- **性能**：避免阻塞等待， 提高资源利用率
### 1.2 同步 vs 异步
```rust
// 同步：阻塞等待
fn sync_request(url: &str) -> String {
    // 调用会阻塞当前线程
    blocking_http_get(url)}

// 异步：非阻塞
async fn async_request(url: &str) -> String {    // 调用不阻塞，返回 Future    reqwest::get(url).await.unwrap().text().unwrap()}
```
## 2. async/await 语法
### 2.1 async 函数
```rust
async fn fetch_data() -> String {    // 这些是异步调用
    let data = get_from_network().await;    process_data(data).await}
```### 2.2 await
`await` 暂停当前 Future， 等待另一个 Future 完成：
```rust
async fn example() {    let a = async_operation_1().await;    let b = async_operation_2().await;    println!("{} {}", a, b);
}
```### 2.3 async 块
```rust
fn main() {    // 运行时创建 Future    let future = async {        let result = some_async_func().await;
        result    };    // 需要运行时执行    block_on(future);
}
```
## 3. Future trait
### 3.1 Future 定义
```rust
pub trait Future {    type Output;    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
}pub enum Poll<T> {    Ready(T),    Pending,}
```- `poll` 方法：轮询 Future 是否完成- `Pending`：还未完成，需要稍后再次轮询- `Ready`：已完成，返回结果### 3.2 Future 执行
```rust
use futures::executor::block_on;

fn main() {    let future = async {        42    };    let result = block_on(future);    println!("{}", result);}
```
## 4. Tokio 运行时
### 4.1 Tokio 简介
Tokio 是 Rust 最流行的异步运行时：- 多线程工作窃取调度器
- 生态丰富（HTTP、数据库、gRPC）
- 生产级可靠
```rust
// Cargo.toml
// [dependencies]
// tokio = { version = "1", features = ["full"] }
```### 4.2 Tokio 使用
```rust
#[tokio::main]
async fn main() {    // 这是异步 main 函数    let result = say_hello().await;
    println!("{}", result);}

async fn say_hello() -> String {    "Hello, World!".to_string()}
```### 4.3 多任务
```rust
#[tokio::main]
async fn main() {
    // 并发执行多个任务    let (a, b) = tokio::join!(        task_a(),        task_b(),    );    println!("Results: {} {}", a, b);}async fn task_a() -> String {    "A".to_string()}async fn task_b() -> String {    "B".to_string()}
```> ✅ **join!** 等待多个 Future 同时完成。## 5. Pin 和 Unpin
### 5.1 为什么需要 Pin
Rust 需要保证 `self` 指针不会移动，用于自引用结构：```rust
// 自引用结构需要 Pinstruct MyStruct {    data: String,    ptr: *const String,  // 指向 data}// 如果不 Pin，data 移动后 ptr 就失效了
```### 5.2 Pin 使用
```rust
use std::pin::Pin;use std::future::Future;

async fn example() {    // 在 async 块中，生成的 Future 会被 Pin    let future = async {        // 代码    };}
```> 💡 **进阶**：大多数情况下你不需要手动处理 Pin，编译器自动处理。
## 6. 异步并发模式
### 6.1 并发执行
```rust
use tokio::task;#[tokio::main]
async fn main() {    // spawn 创建新任务    let handle1 = task::spawn(async {        do_something().await    });    let handle2 = task::spawn(async {        do_something_else().await    });    let (r1, r2) = tokio::join!(handle1, handle2);    println!("{} {}", r1.unwrap(), r2.unwrap());}async fn do_something() -> String { "first".to_string() }
async fn do_something_else() -> String { "second".to_string() }
```
### 6.2 Select
同时等待多个 Future，先完成的执行：```rust
use tokio::time::{sleep, Duration};#[tokio::main]async fn main() {    tokio::select! {        result = fast_operation() => {            println!("Fast: {}", result);        }        result = slow_operation() => {            println!("Slow: {}", result);        }        _ = sleep(Duration::from_secs(1)) => {            println!("Timeout");        }    }}async fn fast_operation() -> String {    "fast".to_string()}async fn slow_operation() -> String {    tokio::time::sleep(Duration::from_secs(2)).await;    "slow".to_string()
}
```### 6.3 Stream
异步迭代器：
```rust
use tokio::sync::mpsc;use tokio_stream::StreamExt;

#[tokio::main]
async fn main() {    let (tx, mut rx) = mpsc::channel(10);        tokio::spawn(async move {        for i in 0..5 {            tx.send(i).await.unwrap();        }    });        while let Some(v) = rx.recv().await {        println!("Got: {}", v);    }
}
```
## 7. 异步生态
### 7.1 常用库
| 库 | 用途 |
|----|------| | tokio | 运行时 |
| async-std | 运行时（更轻量） |
| reqwest | HTTP 客户端 |
| hyper | HTTP 服务器 |
| sqlx | 异步 SQL |
| tokio-postgres | PostgreSQL |
| redis | Redis 客户端 |
| tonic | gRPC |
| tower | 网络库 |
| async-trait | async fn in trait |
### 7.2 常见模式：Spawning
```rust
// 长时间运行的任务
async fn server() {    loop {        // 处理连接        tokio::select! {            result = accept_connection() => {                if let Ok(stream) = result {                    tokio::spawn(handle_connection(stream));                }            }            _ = shutdown_signal() => {                break;            }        }    }}
```
## 8. 异步 vs 线程
| 维度 | 异步 | 线程 |
|------|------|------| | 资源占用 | 极低（每任务约 1-2KB） | 高（每线程 ~1MB） | | 上下文切换 | 用户态（快） | 内核态（慢） | | 编程模型 | 手动 await | 自动切换 | | 适用场景 | I/O 密集 | CPU 密集 |
| 生态成熟度 | 较新 | 成熟 |
