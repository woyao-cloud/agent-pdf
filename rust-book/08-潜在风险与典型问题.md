# 第 8 章 潜在风险与典型问题
> **本章导读**：Rust 使用中的常见风险、陷阱、以及系统化的调试方法。帮助你在生产环境中避开 Rust 的"坑"。
## 1. unsafe 代码
### 1.1 何时使用 unsafe
- 调用 C 库
- 原始指针操作
- 手动实现 unsafe trait
- 性能关键代码（绕过检查）
- 自引用结构（Pin）
### 1.2 unsafe 职责
```rust
unsafe fn dangerous() {    // 编译器不检查这些操作    // 1. 解引用裸指针    let ptr = 0x1234 as *mut i32;    *ptr = 42;        // 2. 调用 unsafe 函数    dangerous_function();        // 3. 实现 unsafe trait    unsafe trait Dangerous {}        // 4. 访问或修改可变静态变量    static mut COUNTER: i32 = 0;    unsafe { COUNTER += 1; }}```### 1.3 安全原则
> ⚠️ **黄金法则**： unsafe 代码应该尽可能小，被安全代码包围。
```rust
// ✅ 好：安全的封装
pub fn safe_access(data: &[i32]) -> Option<i32> {    data.get(0).copied()}// ❌ 坏：把 unsafe 暴露给用户// pub unsafe fn get_unchecked(data: &[i32]) -> i32 { ... }```## 2. 内存问题
### 2.1 循环引用（内存泄漏）
```rust
use std::rc::{Rc, RefCell};use std::cell::RefCell;struct Node {    value: i32,    children: RefCell<Vec<Rc<RefCell<Node>>>>,}// 循环引用导致无法释放let a = Rc::new(RefCell::new(Node {    value: 1,    children: RefCell::new(vec![]),}));let b = Rc::new(RefCell::new(Node {    value: 2,    children: RefCell::new(vec![]),}));a.borrow_mut().children.push(Rc::clone(&b));b.borrow_mut().children.push(Rc::clone(&a));// a 和 b 相互引用，引用计数永远 > 0```> ✅ **解决方案**：使用 `Weak` 打破循环。### 2.2 避免循环引用
```rust
use std::rc::{Rc, Weak};use std::cell::RefCell;struct Node {    value: i32,    parent: RefCell<Weak<Node>>,    // 用 Weak    children: RefCell<Vec<Rc<Node>>>,}```### 2.3 栈溢出（Stack Overflow）
```rust
// 递归导致栈溢出
fn recursive_sum(n: u64) -> u64 {    if n == 0 { return 0; }    n + recursive_sum(n - 1)}// ✅ 解决方案：改用迭代
fn iterative_sum(n: u64) -> u64 {    (1..=n).sum()}```> ⚠️ **注意**：Rust 默认栈大小约 8MB，递归深度有限。## 3. 并发陷阱
### 3.1 死锁
```rust
use std::sync::Mutex;fn main() {    let a = Mutex::new(1);    let b = Mutex::new(2);        let handle1 = std::thread::spawn(move || {        let _ = a.lock().unwrap();        std::thread::sleep(std::time::Duration::from_millis(10));        let _ = b.lock().unwrap();  // 可能死锁    });        let handle2 = std::thread::spawn(move || {        let _ = b.lock().unwrap();        std::thread::sleep(std::time::Duration::from_millis(10));        let _ = a.lock().unwrap();  // 可能死锁    });        handle1.join().unwrap();    handle2.join().unwrap();}```> ✅ **解决方案**：固定加锁顺序，或使用 `try_lock`。### 3.2 异步死锁
```rust
async fn deadlock() {    let lock = tokio::sync::Mutex::new(1);        let _ = lock.lock().await;    // 获取锁    // 如果在持有锁时 await，其他任务无法获取锁    // tokio::time::sleep(Duration::from_secs(1)).await;    let _ = lock.lock().await;  // 死锁！}```> ⚠️ **注意**：在异步中持有锁时不要 await。## 4. 生命周期陷阱
### 4.1 悬垂引用
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {    if x.len() > y.len() { x } else { y }}fn main() {    let string1 = String::from("hello");    let result;    {        let string2 = String::from("world!");        result = longest(&string1, &string2);        // result 指向 string2    }    // string2 销毁，但 result 仍指向它！    // println!("{}", result);  // ❌ 悬垂引用！}```### 4.2 生命周期收缩
```rust
struct Parser<'a> {    input: &'a str,}impl<'a> Parser<'a> {    fn parse<'b>(&'b self) -> &'b str {  // 'b 可以不同于 'a        &self.input[..5]    }}```## 5. 性能陷阱
### 5.1 隐式克隆
```rust
fn slow(parts: &[String]) -> String {    parts.join(", ")}  // 隐式 clonefn fast(parts: &[String]) -> String {    let mut s = String::new();    for (i, p) in parts.iter().enumerate() {        if i > 0 { s.push_str(", "); }        s.push_str(p);    }    s}```### 5.2 过度使用 Box
```rust// 过度使用 Box
let boxed = Box::new(42);  // 堆分配// 不需要时用引用
let reference = &42;        // 栈分配```### 5.3 字符串拼接
```rust
// 低效：多次分配
let mut s = String::new();for _ in 0..100 {    s.push_str("a");}// 高效：预分配
let mut s = String::with_capacity(100);for _ in 0..100 {    s.push_str("a");}```## 6. 常见编译错误
### 6.1 借用错误
```rust
let mut v = vec![1, 2, 3];let first = &v[0];v.push(4);  // ❌ 借用后修改println!("{}", first);  // 悬垂引用风险```### 6.2 生命周期不匹配
```rust
fn factory() -> &str {  // ❌ 缺少生命周期标注    let s = String::from("hello");    &s  // 返回局部变量引用}```### 6.3 类型推断失败
```rust
