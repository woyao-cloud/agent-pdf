# 第 1 章 引言与定位
> **本章导读**：理解 Rust 想解决什么问题、它的历史脉络与核心理念。读完后你能回答：Rust 适合什么场景？它解决了什么痛点？

## 1. Rust 解决什么问题

### 1.1 传统系统编程的痛点

在 C/C++ 开发中，你可能遇到过以下问题：

| 痛点 | 描述 | 后果 |
|------|------|------|
| **空指针/野指针** | 指针未初始化或已释放后仍使用 | 段错误、安全漏洞 |
| **内存泄漏** | 分配内存未释放 | 长期运行内存耗尽 |
| **数据竞争** | 多线程同时修改同一数据 | 数据损坏、崩溃 |
| **缓冲区溢出** | 写入超过数组边界 | 安全漏洞、崩溃 |
| **释放后使用** | use-after-free | 未定义行为 |
| **双重释放** | free 两次同一内存 | 崩溃 |

这些问题被称为 **"内存安全"** 问题，在 C/C++ 中只能靠程序员手动注意，编译器爱莫能助。

### 1.2 Rust 的解决方案

Rust 通过**所有权系统（Ownership）** 在编译期检查这些问题：

```rust
// Rust：编译期检查，拒斥有问题的代码
fn main() {
    let s1 = String::from("hello");
    let s2 = s1;  // s1 移动到 s2，s1 不再有效
    
    // println!("{}", s1);  // ❌ 编译错误！s1 已移动
    println!("{}", s2);    // ✅ 正常
}
```

对比 C++（可以编译，但危险）：

```cpp
// C++：可以编译，但有 use-after-free 风险
#include <iostream>
#include <string>
int main() {
    std::string s1 = "hello";
    std::string s2 = std::move(s1);  // s1 变为空
    // std::cout << s1 << std::endl;  // UB！未定义行为
    std::cout << s2 << std::endl;    // OK
}
```

### 1.3 核心特性一览

| 特性 | 作用 | 效果 |
|------|------|------|
| **所有权系统** | 每个值有唯一所有者 | 编译期防止内存问题 |
| **借用检查** | 引用必须遵守规则 | 防止数据竞争 |
| **生命周期** | 引用必须有效 | 防止悬垂指针 |
| **类型系统** | 高度表达力 | 编译期发现逻辑错误 |
| **RAII** | 资源获取即初始化 | 自动释放资源 |
| **模式匹配** | 强大的解构能力 | 减少 bug |

## 2. Rust 的核心优势

### 2.1 内存安全 + 零成本抽象

```rust
// 高层抽象，但无运行时开销
fn sum(vec: &[i32]) -> i32 {
    vec.iter().sum()  // 编译后接近手写循环
}
```
编译时检查 = 运行时零开销

### 2.2 并发安全

```rust
use std::thread;
use std::sync::Mutex;

fn main() {
    let data = Mutex::new(0);
    
    let handles: Vec<_> = (0..10).map(|_| {
        thread::spawn(|| {
            let mut guard = data.lock().unwrap();
            *guard += 1;
        })
    }).collect();
    
    for h in handles { h.join().unwrap(); }
    
    println!("{}", *data.lock().unwrap());  // 10
}
```
数据竞争在编译期被阻止！

### 2.3 表达力强的类型系统

```rust
// 编译期保证不可能的状态
enum Message {
    Quit,
    Move { x: i32, y: i32 },
    Write(String),
    ChangeColor(i32, i32, i32),
}

// Result 类型强制错误处理
fn read_file(path: &str) -> Result<String, io::Error> {
    fs::read_to_string(path)?  // 传播错误
}
```

### 2.4 生产力工具

## 4. Rust 的应用场景

### 4.1 适合使用 Rust 的场景

| 场景 | 原因 |
|------|------|
| **系统编程** | 操作系统、驱动、嵌入式（无 GC，接近 C 性能） |
| **WebAssembly** | 浏览器端高性能计算（游戏、物理引擎） |
| **命令行工具** | 高性能 + 跨平台 |
| **网络服务** | 高并发 + 内存安全（TiKV、Deno） |
| **区块链** | 安全性关键（Solana, Polkadot） |
| **游戏引擎** | 性能 + 内存控制 |
| **数据库** | Rust 实现 RocksDB（比 C++ 更安全） |

### 4.2 不适合使用 Rust 的场景

| 场景 | 原因 |
|------|------|
| **简单脚本** | 编写成本高于 Python/Bash |
| **GUI 应用** | 生态不如 Electron/Qt/C# |
| **快速原型** | 编译时间影响迭代速度 |
| **机器学习** | Python 生态更强（PyTorch/TensorFlow） |
| **Android/iOS** | 生态不如 Kotlin/Swift |

### 4.3 著名项目

| 项目 | 领域 | 说明 |
|------|------|------|
| **Firefox** | 浏览器 | 部分组件使用 Rust |
| **Chrome** | 浏览器 | 已用 Rust 重写关键组件 |
| **Linux 内核** | 操作系统 | 2022 年开始支持 Rust |
| **Windows** | 操作系统 | 2023 年开始用 Rust 重写组件 |
| **TiKV** | 数据库 | 分布式键值存储 |
| **Deno** | 运行时 | JS/TS 运行时 |
| **Brave** | 浏览器 | 基于 Chromium + Rust |
| **Alacritty** | 终端 | 最快的终端模拟器 |
| **ripgrep** | 工具 | 比 grep 快 10 倍 |

## 7. 小结与延伸阅读

**关键回顾**：
- Rust 通过**所有权系统**在编译期防止内存安全问题
- 核心优势：**内存安全 + 零成本抽象 + 并发安全 + 表达力强**

- 学习曲线：所有权是最大门槛，但值得投入
