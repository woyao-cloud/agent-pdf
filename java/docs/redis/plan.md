## 第二部分：核心应用场景实战（原理、风险、优化与代码）
*本部分针对6大典型业务场景，剖析实现原理，重点揭示潜在风险并提供优化方案与生产级代码/配置示例。*

### 第3章 分布式缓存（Cache）场景
* **3.1 实现原理**：旁路缓存模式（Cache Aside）与读写链路设计
* **3.2 潜在风险**：
  * 缓存穿透（恶意查询不存在的数据）
  * 缓存击穿（热点Key突然过期导致DB被打挂）
  * 缓存雪崩（大量Key同时过期或Redis宕机）
* **3.3 优化与应对方案**：
  * 布隆过滤器（Bloom Filter）与空值缓存防穿透
  * 逻辑过期与互斥锁（Mutex Lock）防击穿
  * 随机过期时间与多级缓存架构防雪崩
* **3.4 示例代码与配置**：
  * 附：基于Redisson的防击穿分布式锁代码示例
  * 附：Caffeine + Redis 多级缓存Spring Boot配置

### 第4章 分布式锁（Distributed Lock）场景
* **4.1 实现原理**：`SETNX`、`PEXPIRE` 与 Lua脚本原子性保障
* **4.2 潜在风险**：
  * 锁过期但业务未执行完（死锁/并发问题）
  * 主从异步复制导致的主从切换锁丢失（Redlock算法的争议与局限）
  * 客户端长时间GC停顿导致的锁误删
* **4.3 优化与应对方案**：
  * 引入“看门狗（Watch Dog）”机制自动续期
  * 锁的唯一标识（UUID+ThreadId）与Lua原子删除验证
  * 跨机房多活架构下的锁选型（Zookeeper vs Redis）
* **4.4 示例代码与配置**：
  * 附：Redisson `RLock` 看门狗机制源码级解析与实战代码
  * 附：原生Lua脚本实现安全释放锁代码示例

### 第5章 消息队列与延迟任务（MQ & Delay Queue）场景
* **5.1 实现原理**：
  * 基于 `List` 的阻塞队列（BRPOP）
  * 基于 `Pub/Sub` 的发布订阅
  * 基于 `ZSet` 的延迟队列（Score存执行时间戳）
  * 基于 `Stream` 的企业级消息队列（Consumer Group、ACK机制）
* **5.2 潜在风险**：
  * 消息丢失（客户端宕机、未ACK）
  * 消息堆积导致内存OOM
  * 轮询延迟队列带来的CPU空转与性能损耗
* **5.3 优化与应对方案**：
  * 使用 `XACK` 与 `Pending Entries List (PEL)` 保证消息可靠性
  * 延迟队列优化：时间轮算法结合Redis或改用RabbitMQ/RocketMQ
* **5.4 示例代码与配置**：
  * 附：基于 `Redis Stream` 实现带重试机制的消费者组代码
  * 附：基于 `ZSet` + Lua 的轻量级延迟任务调度代码

### 第6章 高并发限流与计数器（Rate Limiting）场景
* **6.1 实现原理**：`INCR` 原子递增、滑动窗口与令牌桶/漏桶算法
* **6.2 潜在风险**：
  * 边界并发突刺问题（固定窗口缺陷）
  * 分布式环境下的时钟漂移与精度丢失
  * 高频限流导致Redis网络I/O成为瓶颈
* **6.3 优化与应对方案**：
  * 基于Lua脚本实现原子化的滑动窗口与令牌桶算法
  * 客户端本地令牌桶 + Redis全局令牌桶的二级限流架构
* **6.4 示例代码与配置**：
  * 附：Redis+Lua实现精准滑动窗口限流代码
  * 附：网关层（如Spring Cloud Gateway）集成Redis限流配置

### 第7章 排行榜与社交Feed流（Leaderboard & Feed）场景
* **7.1 实现原理**：`ZSet` 的跳跃表特性与 `Pipeline` 批量操作
* **7.2 潜在风险**：

## 第四部分：典型生产问题排查与性能调优
*本部分提供“老中医”级别的 troubleshooting 指南，直击生产环境痛点。*

### 第11章 生产环境“四大杀手”排查与解决
* **11.1 大Key（BigKey）问题**
  * 危害：阻塞主线程、网络拥塞、内存不均
  * 排查：`redis-cli --bigkeys`、`MEMORY USAGE`、RDB离线分析工具
  * 解决：Hash分片、压缩存储、异步删除（`UNLINK`）
* **11.2 热Key（HotKey）问题**
  * 危害：单节点CPU/网络打满，集群负载失衡
  * 排查：`redis-cli --hotkeys`（需开启LFU）、客户端埋点监控
  * 解决：本地缓存（Caffeine/Guava）、Key加随机后缀打散、读写分离
* **11.3 缓存雪崩/穿透/击穿的监控与自愈**
* **11.4 内存暴涨与OOM排查**
  * 内存淘汰策略（LRU/LFU/TTL）的正确选择
  * 客户端缓冲区溢出排查（`client-output-buffer-limit`）

### 第12章 性能监控、诊断与调优
* **12.1 核心监控指标体系**：命中率、内存碎片率、Evicted/Expired Keys、连接数、网络吞吐
* **12.2 慢查询日志（Slowlog）分析**：定位耗时命令与不合理的数据结构使用
* **12.3 核心参数调优指南**：
  * `tcp-backlog` 与 `somaxconn` 的协同配置
  * `hz` 参数对过期键清理与CPU占用的平衡
  * `maxmemory` 与操作系统的内存预留
