# 第11章 架构模式选择与最佳实践
## 11.1 如何选择架构模式
### 11.1.1 决策因素
| 因素 | 问题 |
|------|------|
| 团队规模 | 3-5人单体，10人以上微服务 |
| 业务复杂度 | 简单三层，复杂微服务 |
| 伸缩需求 | 无要求单体，需要弹性云原生 |
| 迭代速度 | 慢单体，快微服务 |
| 运维能力 | 弱单体，强微服务 |
### 11.1.2 架构演进路线
```
单体 → 三层架构 → SOA → 微服务 → 云原生
```
## 11.2 典型问题处理
### 11.2.1 性能问题
- 瓶颈分析
- 缓存策略
- 异步处理
- 负载均衡
### 11.2.2 可用性问题
- 冗余部署
- 自动故障转移
- 多活架构
### 11.2.3 一致性问题
- 强一致性：分布式事务
- 最终一致性：消息队列+Saga
### 11.2.4 安全性问题
- 身份认证
- 权限控制
- 数据加密
- 安全审计
## 11.3 架构重构
### 11.3.1 何时重构
- 技术债务累积
- 业务快速变化
- 性能瓶颈
### 11.3.2 重构策略
-  strangler fig模式
- 特征切换
- 并行运行
- 逐步迁移
## 11.4 本章小结
架构模式选择没有最佳答案， 只有最适合。 需要根据业务、 技术、 团队等多方面因素综合决策。
