# 第2章 前序知识——学深度学习需要什么基础？

## 2.1 数学基础：你不需要成为数学家

听到"深度学习"四个字，很多人第一反应是："数学要求很高吧？"确实，深度学习论文中充满了数学符号。但好消息是：**你不需要理解所有数学，也能用好深度学习框架**。这就像你不需要理解汽车发动机的每个零件的功能，也能开车。

你真正需要的数学知识只有三个，而且都只需要"理解概念"的程度：

**线性代数：理解"数据是表格"就够了。**

线性代数中最核心的概念是"矩阵"——也就是一张行和列组成的表格。在深度学习中，你的所有数据都是矩阵。一张图片是一个矩阵（或几个矩阵叠在一起），一段文字也可以变成一个矩阵，一个批量的数据是一个大矩阵。你不需要知道矩阵的"特征值分解"或"奇异值分解"，但你需要知道"矩阵乘法"——它是神经网络中最基本的运算。

可以这样理解矩阵乘法：矩阵 A 的每一行代表一个样本（比如一个商品），矩阵 B 的每一列代表一个特征提取器（比如"是否是电子产品"）。A 乘以 B 的结果告诉了你每个商品在每种特征上的得分。这个得分就是"神经网络的一层"在做的事情。

**微积分：理解"梯度"就是下山的方向。**

你只需要理解一个概念：**偏导数**。偏导数回答的问题是"如果我把某个参数调大一点点，输出会变大还是变小？变化多少？"

用下山来比喻。想象你站在一座山的某个位置，目标是走到山脚（最低点）。你蒙着眼睛，只能靠脚去感觉哪个方向是下坡。这个"下坡的方向"就是"梯度"。深度学习中的"梯度下降"就是沿着梯度的反方向（下坡方向）调整参数，一步一小步地走向最低点。

你不需要自己推导导数——框架会自动计算。你只需要理解"梯度告诉我参数该怎么调"这个逻辑就够了。

**概率统计：理解"平均值"和"概率"就够了。**

损失函数（用来衡量模型好坏的指标）本质上就是"模型犯了多少错"的平均值。准确率就是"模型答对的百分比"。你不需要懂假设检验或置信区间——那些是数据分析师需要的，不是深度学习需要的。

总结一句话：**大学理工科的大一数学水平完全够用。** 如果你已经工作了几年、忘记了数学知识，也不用担心。碰到不理解的概念时，花 10 分钟搜索一下，理解基本概念后继续往前走即可。大多数深度学习框架的用户并没有扎实的数学背景，但这不影响他们做出好的产品。

## 2.2 编程基础：需要 Python，不需要 C++

学习 PyTorch 或 TensorFlow 需要 Python 基础。具体来说，你需要知道以下内容：

**需要掌握的内容：**

Python 的基本语法——变量、列表、字典、函数、类、条件判断、循环。这些是日常写深度学习代码时最常用的。特别是"类"（class）——PyTorch 的模型都是通过定义 Python 类来构建的。

NumPy 的基本操作——这是本章的重点（见 2.3 节）。你不需要成为 NumPy 专家，但需要理解"数组"的概念以及常见的数组运算。

**不需要掌握的内容：**

你不需要学 C++——虽然 PyTorch 和 TensorFlow 的底层是用 C++ 编写的，但它们对外提供的是 Python 接口。你写 Python 就够了。

你不需要学 CUDA——GPU 编程是框架自动处理的。你只需要调用 `.cuda()` 或指定设备名称，框架会负责把计算分配到 GPU 上。

你不需要学系统编程——内存管理、多线程、网络编程等知识在深度学习框架中已经被封装好了。

总结一句话：**如果你能用 Python 写一个简单的类并调用它的方法，你就已经具备学习深度学习框架的编程基础了。**

## 2.3 NumPy 基础详解

### 2.3.1 NumPy 是什么——Python 的"数据容器升级版"

NumPy 是 Python 中最重要的科学计算库。它的名字来源于"Numerical Python"（数值计算 Python）。可以把它理解为**Python 原生列表的全面升级版**。

但在深度学习领域，NumPy 的地位远比"一个科学计算库"要高——**它是 PyTorch 和 TensorFlow 的"祖先"**。这两个框架的张量（Tensor）操作 API，几乎完全模仿了 NumPy。学会了 NumPy 的数组操作，你就学会了两个深度学习框架的一半。

#### 为什么深度学习不用 Python 列表？

想象一下，你有一张 1000×1000 像素的彩色照片。在计算机中，这张照片被表示为一个三维数组：1000（高度）× 1000（宽度）× 3（红绿蓝三个颜色通道）。也就是说，这张照片里有 300 万个数字。

如果你用 Python 原生的列表来存储这 300 万个数字，会遇到两个严重问题：

**问题一：速度极慢。** Python 列表的每个元素都是一个 Python 对象（有类型信息、引用计数等额外开销）。当你需要对这 300 万个数字做"每个都加 1"这种最简单的操作时，Python 需要用 for 循环逐个处理每个元素。这个循环本身会带来巨大的性能开销。实际上，Python 的 for 循环比 C 语言的 for 循环慢几十倍。

**问题二：内存浪费。** 一个 Python 整数对象大约占用 28 个字节。300 万个整数 × 28 字节 ≈ 84 MB。而同样这些数用 NumPy 数组存储，每个数只占 4 或 8 个字节，总内存不到 12 MB。差距接近 7 倍。

NumPy 解决这两个问题的思路是：**放弃 Python 对象的灵活性，采用 C 语言风格的连续内存布局**。简单来说，NumPy 在底层用 C 语言处理数据，只把计算结果返回给 Python。这意味着，你写的是 Python 代码，但实际执行速度接近 C 语言。

可以这样理解：如果你有一万个数要相加，Python 列表的做法是"让一个人跑一万次把两个数加起来"，而 NumPy 的做法是"让一万个人同时加"。前者需要一万步，后者只需要一步。

### 2.3.2 核心概念：标量、向量、矩阵、张量

NumPy 中最核心的概念是"ndarray"（N 维数组）。它表示的是一系列不同"维度"的数据容器。

**标量（0 维数组）**：一个单独的数字。比如你的年龄、今天的温度。

**向量（1 维数组）**：一串按顺序排列的数字。比如你一周七天的每日步数：[8000, 9500, 7200, 11000, 8900, 6500, 10200]。在深度学习中，一条数据通常表示为一个向量。比如一个房子的特征："面积 120 平米、卧室 3 个、房龄 5 年、价格 350 万"——这 4 个数字就组成了一个 4 维向量。

**矩阵（2 维数组）**：一个由行和列组成的"表格"。比如一个班级里 30 个学生的考试成绩，每个学生考了 5 门课——这就是一个 30 行 5 列的矩阵。在深度学习中，一个批量（batch）的数据就是用矩阵表示的。如果你的批大小是 32 张图片，每张图片展平为 784 个像素，那么这 32 张图片就是一个 32 行 784 列的矩阵。

**张量（3 维及以上数组）**：当维度超过 2 时，统称为张量。一张彩色图片就是一个 3 维张量（高度 × 宽度 × 颜色通道）。一段视频是一个 4 维张量（帧数 × 高度 × 宽度 × 颜色通道）。PyTorch 和 TensorFlow 的名字里的"Tensor"指的就是这个——它们是用来"操作张量"的框架。

举个例子，一张 640×480 像素的彩色照片的"形状"是 (480, 640, 3)。480 是高度，640 是宽度，3 是 RGB 三个颜色通道。这个"形状"（shape）是张量最重要的属性——它告诉你有多少个数字以及它们是怎么排列的。

### 2.3.3 NumPy 的三种核心运算

NumPy 提供了大量运算功能，但最核心的只有三种。

**第一种：逐元素运算。**

假设你有两个数组，分别存储了"一月每天的最高温度"和"一月每天的最低温度"。如果你想求每天的"平均温度"，你需要把两个数组对应位置的数字相加再除以 2。

用 Python 列表做，你需要写 for 循环逐个相加。用 NumPy，只需要一次加法——它对两个数组的对应位置逐元素相加。

更常见的用法是：你有一批商品的价格，现在所有商品打八折。你需要把每个价格乘以 0.8。在 NumPy 中，就是数组乘以一个标量——一次操作完成所有元素的乘法。

**第二种：广播机制——让形状不同的数组也能相加。**

广播是 NumPy 中最巧妙但最初让人困惑的概念。它允许形状不同的数组进行运算。

用一个例子来理解。你有一个 4 行 3 列的矩阵，存储了 4 个学生在 3 门课上的成绩。你想给每个学生的每门成绩加 5 分的"平时分加分"。你需要把矩阵的每个元素都加 5。这个 5 可以看作一个标量。根据广播机制，标量会"扩展"成一个 4×3 的矩阵，每个位置都是 5，然后和原矩阵相加。

另一个实际例子：你有一个 100 行 10 列的矩阵，存储了 100 个商品在 10 个销售渠道上的销售额。你想从每个商品的 10 个渠道销售额中减去这个商品的"平均销售额"。每个商品的平均销售额是一个 100 个数字的向量（100 行 1 列）。广播机制让这个 100×1 的向量自动"复制"到 10 列，变成一个 100×10 的矩阵，然后执行减法。这个过程完全自动。

广播的直观理解就是"复印"。你有一张 4×3 的"原始图案"和一张 1×3 的"贴纸"。你把贴纸复印了 4 份，沿着行方向贴到原始图案上。贴纸自动扩展到和原始图案一样大小，然后逐位置运算。

**第三种：规约运算——把一堆数变成一个数。**

规约运算指的是"把数组沿某个方向压缩"。最常用的规约运算包括求和、求平均值、求最大值。

用成绩表来理解。4 行（4 个学生）3 列（3 门课）的成绩矩阵：

"全班数学的总分是多少？"——沿着行方向压缩，对每一列求和，得到 3 个数字（每科总分）。
"每个学生三科的总分是多少？"——沿着列方向压缩，对每一行求和，得到 4 个数字（每个学生总分）。
"全班数学的最高分是多少？"——在对应列中找最大值。

这个"沿着哪个方向压缩"的概念，在深度学习框架中叫做"维度"（dimension 或 axis）。一个简单的记忆方法：沿着第 0 维求和，就是把行压缩掉（按列求和）；沿着第 1 维求和，就是把列压缩掉（按行求和）。

### 2.3.4 为什么深度学习离不开 NumPy？

如果你理解了 NumPy 的数组、逐元素运算、广播和规约，你就已经掌握了深度学习框架中最核心的部分。原因在于：**PyTorch 和 TensorFlow 的张量都是 NumPy 数组的"GPU 升级版"**。

具体来说，两种框架在 NumPy 的基础上做了三件事：

第一，它们把 NumPy 数组的操作原封不动地搬到了 GPU 上。在 NumPy 中你写"两个数组相加"的思维方式，在 PyTorch 中完全一样——只是换了一个名称（从"数组"变成了"张量"）。唯一的区别是 PyTorch 的张量可以放在 GPU 上。

第二，它们在 NumPy 的基础上增加了"自动求导"功能。NumPy 数组做加法后，你只知道结果，不知道结果相对于每一个输入的"变化率"。PyTorch 的张量在做加法时，会记录这个操作，以便将来计算梯度。这是 NumPy 没有的能力，也是深度学习框架的核心价值。

第三，它们增加了一些 NumPy 中没有的运算——卷积、循环、注意力机制——但这些都是基于 NumPy 风格的数组 API 构建的。你只要理解了"对数组做运算"这个思维模式，新运算的学习成本就大大降低了。

用类比来总结：NumPy 对深度学习框架的关系，就像"手动挡汽车"对"自动挡汽车"的关系。学会了手动挡，你理解汽车的基本原理。学会了 NumPy，你理解数据运算的基本原理（形状、维度、广播）。然后开自动挡（PyTorch/TensorFlow）就变得非常自然——你只是少了一些手动操作，多了一些自动功能。

对于本书来说，你不需要成为 NumPy 专家。你只需要知道：

- 深度学习中的数据是用"张量"（即多维数组）表示的
- 对张量的操作分为"逐元素"、"广播"和"规约"三种
- PyTorch 和 TensorFlow 的张量 API 都是模仿 NumPy 设计的
- 你写 NumPy 的思维方式，可以直接迁移到两个深度学习框架中

有了这个基础，后面章节中当我们提到"张量"、"形状"、"维度"、"广播"这些概念时，你就知道它们在说什么了。
