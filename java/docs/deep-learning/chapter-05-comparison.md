# 第5章 核心维度对比——从 8 个角度看清楚

## 5.1 学习曲线

### PyTorch：先易后难

PyTorch 的入门非常直观。你只需要理解三个概念——张量（Tensor）、自动求导（Autograd）、模型（nn.Module）——就能写一个完整的训练脚本。这三个概念的命名和用法都贴近 Python 的习惯。学完基础后，你可以在简单的数据集上训练一个简单的模型，马上获得正向反馈。

但随着任务复杂度的提升，你需要逐步理解更多概念。比如分布式训练（DDP）、自定义 autograd 函数、torch.compile 编译优化等。这些进阶内容需要花时间去理解，但好消息是——你不需要一开始就学他们。PyTorch 的设计是"按需学习"：在需要的时候再去了解。

### TensorFlow：先难后易

TensorFlow 的学习曲线比较曲折。理解 Keras 的高级 API 很容易——几行代码就能训练一个模型。但一旦需要跳出标准模式（比如自定义训练循环、处理特殊的输入格式、调试性能问题），你就需要理解 TensorFlow 的底层机制。

特别是在部署阶段，TensorFlow 的优势开始体现。如果你需要部署模型，TF Serving 和 TFLite 有大量现成的文档和最佳实践。对于常见场景，你可以直接复制 config 文件，基本上不需要太多修改。

所以 TensorFlow 的学习曲线是"浅入深出"——入门简单（Keras），深入难（底层机制），但用到部署阶段反而又有成熟工具可循。

## 5.2 调试体验

调试是 PyTorch 和 TensorFlow 最显著的区别之一。

在 PyTorch 中，你可以在任何位置打印任意张量的值和形状。你可以在 `forward` 方法中加入断点，一步一步地观察数据流过每一层时的变化。你可以在训练循环中的任何位置添加调试代码。

在 TensorFlow 中，默认情况下也是 eager 模式，可以打印。但当你的模型被 `@tf.function` 包装后，这个函数内部的代码就变成了一个静态图的节点，你无法在函数内部打断点、无法打印中间变量。这意味着——你改成 `@tf.function` 后，突然就不能调试了。

`@tf.function` 的编译错误也很令人头疼。当一个函数因为某些原因（比如使用了 TensorFlow 不支持的数据类型）无法编译时，错误信息往往指向编译过程的内部，而不是指向你的源代码。定位这些问题需要经验。

总结一下：如果你经常需要调试、尝试新结构、修改模型代码，PyTorch 的调试体验明显更好。

## 5.3 模型部署

### PyTorch 的部署生态

TorchServe 是 PyTorch 官方的模型部署方案。它支持 REST 和 gRPC 协议，支持模型版本管理，支持批处理。TorchServe 的配置相对简单，一个模型归档文件（.mar）包含了模型权重、推理代码和依赖配置。

PyTorch 还支持 TorchScript——一种将 PyTorch 模型编译成跨平台可执行文件的技术。TorchScript 模型可以脱离 Python 环境运行，你可以在 C++ 程序中直接加载和执行。

### TensorFlow 的部署生态

TF Serving 已经运行了多年，在生产环境中的稳定性和成熟度都已经得到了充分验证。TF Serving 的自动批处理功能非常成熟——当同时有多个推理请求时，TF Serving 自动将它们合并成一个批次，送 GPU 一次处理，然后再把结果拆开返回给各个请求。

TFLite 是移动端部署的成熟方案。它支持硬件加速（通过 GPU 和神经网络处理单元），支持模型量化（浮点转整数，缩小 4 倍），支持 Android 和 iOS。

### 对比总结

如果你的部署目标是服务器端在线推理，两种框架都有成熟的方案。TF Serving 更成熟，TorchServe 正在追赶。如果你的部署目标是移动端（特别是 Android），TFLite 是更好的选择。如果你的部署环境只有 C++ 而没有 Python，两种框架都支持（TensorFlow 的 C++ API 更成熟一些，PyTorch 的 TorchScript C++ API 也在不断完善）。

## 5.8 八个维度速查表

| 维度 | PyTorch | TensorFlow |
|------|---------|-----------|
| 学习曲线 | 先易后难，Pythonic | Keras 简单，深入复杂 |
| 调试体验 | 原生 Python，可打断点 | eager 可调试，但 @tf.function 不能 |
| 模型部署 | TorchServe（后起之秀） | TF Serving（成熟稳定） |
| 学术生态 | 90% 论文用 | < 10%，论文代码需翻译 |
| 移动端 | PyTorch Mobile（成长中） | TFLite（最佳选择） |
| 分布式训练 | DDP 简洁 | 多种 Strategy |
| 时间线策略 | 研究/原型首选 | 生产/移动端首选 |
| 社区资源 | 教程友好，问答丰富 | 文档完善，但新技术更新慢 |

没有绝对"更好"的框架，只有"更适合当前场景"的框架。
