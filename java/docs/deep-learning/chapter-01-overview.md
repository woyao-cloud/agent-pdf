# 第1章 深度学习框架概览——它们解决什么问题？

## 1.1 为什么需要深度学习框架？

### 从"手写梯度"的故事说起

2012 年，Alex Krizhevsky 用 GPU 训练了一个深度卷积网络（AlexNet），在 ImageNet 图像识别比赛中以压倒性优势夺冠。这件事被公认为深度学习"文艺复兴"的起点。

但很少人知道的是：AlexNet 的整个训练代码是用 C++ 和 CUDA 手写的。每一层的前向传播要手写（卷积怎么算？池化怎么算？），每一层的反向传播也要手写（每个参数对最终结果的偏导数是多少？）。如果一个 8 层的网络，每一层都有多个参数，光是把梯度公式写对就可能花掉好几天。

更痛苦的是：**你无法验证梯度对不对**。loss 确实下降了——但你真的确定梯度是对的吗？也许梯度写错了，但凑巧能让 loss 下降，只是需要多花 10 倍的时间才能收敛。当时检查梯度的唯一方法是"数值梯度法"——把每个参数微调一点点，看 loss 的变化是否与手写的梯度公式一致。对于一个有 6000 万个参数的 AlexNet，这几乎不可能。

这就是深度学习框架要解决的核心问题：**你只需要写前向传播，反向传播（梯度计算）框架自动完成。** 这就是"自动求导"。

### 框架的三大核心价值

深度学习框架做了三件最重要的事：

**第一：自动求导。** 你定义一个数学表达式（比如 y = wx + b），框架自动记录每一步操作。当你调用"反向传播"时，框架自动从后往前计算每个参数的偏导数。你不需要推导任何数学公式，不需要手写任何梯度代码。

**第二：GPU 加速。** 深度学习模型需要在 GPU 上训练才能有合理的速度。但直接写 GPU 代码（CUDA）极其复杂。框架封装了这一层——你只需要告诉框架"把这个计算放到 GPU 上"，剩下的事情框架自动完成。PyTorch 中就是一行 `.cuda()`；TensorFlow 中通常自动分配。

**第三：模型组件库。** 没有人从零开始写一个卷积层。框架提供了大量预构建的组件——卷积层、池化层、循环层、各种优化器、各种损失函数。你只需要像搭积木一样把这些组件组合起来，而不是从零开始写每一个数学运算。

### 一个直观的对比

在没有框架的时代训练一个神经网络，大致需要做这些事情：推导梯度公式、编写前向传播的 CUDA 代码、编写反向传播的 CUDA 代码、调试梯度是否正确、把数据从 CPU 拷贝到 GPU、手动实现优化器来更新参数。整个过程可能需要数周。

有了深度学习框架后，你只需要做这些事情：选择网络结构（比如"我要一个 3 层卷积 + 2 层全连接的网络"）、加载数据、调用训练函数。框架自动处理梯度、GPU 加速、参数更新。整个过程可能只需要几小时。

这个效率提升——从数周降到几小时——就是深度学习框架存在的意义。

## 1.2 当前主流框架格局

### PyTorch、TensorFlow、JAX 的定位

截至 2024-2025 年，深度学习框架的格局已经非常清晰，大致可以分成三个梯队：

**第一梯队：PyTorch。** 学术界绝对主导，工业界快速增长。如果你去看 2024 年的机器学习顶级会议（NeurIPS、ICML、ICLR），大约 90% 的论文使用 PyTorch。这意味着新模型、新算法几乎都会先出 PyTorch 版本。如果你做研究或想复现最新论文，PyTorch 是必然选择。

**第二梯队：TensorFlow。** 工业界存量巨大，但新增项目在减少。TensorFlow 的强项是生产部署——它的 TF Serving 是业界最成熟的模型部署方案之一。很多大公司（特别是 Google 生态内的公司）有大量的 TensorFlow 存量代码。但在学术界，TensorFlow 的使用率已经降到了个位数。

**第三梯队：JAX。** Google 的新一代框架，在研究者中小众但快速增长。JAX 的设计理念和 PyTorch、TensorFlow 都不同——它采用函数式编程风格，强调"纯函数"和"不可变状态"。JAX 的使用者主要是对性能有极致要求的研究者，以及一些前沿的 AI 实验室。JAX 的学习曲线比 PyTorch 陡峭，但一旦掌握，在某些任务上可以写出更高效、更灵活的代码。

### 学术界与工业界的偏好差异

学术界偏好 PyTorch 的原因很简单：**快**。这里说的不是运行速度，而是**实验速度**。研究者需要不断尝试新想法，如果每试一个新想法都要等半小时建图、debug 还不方便，研究的效率会大幅下降。PyTorch 的动态图让研究者可以快速试错——像写普通 Python 一样写模型，随时打断点查看中间结果。

工业界的情况更复杂。一部分老项目仍然基于 TensorFlow，切换成本太高；另一部分新项目已经在用 PyTorch，因为招人更容易（新一代工程师几乎只学过 PyTorch）。还有一部分公司采用了混合策略：用 PyTorch 训练模型，然后通过 ONNX（一个中间格式）转换到 TensorFlow Serving 或 ONNX Runtime 部署。

### 一句话总结

如果你问"我应该学哪个"——在 2024-2025 年这个时间点，答案几乎总是 **PyTorch**。不是因为它全面优于 TensorFlow，而是因为它在学术界的主导地位使得它成为了深度学习的事实标准。TensorFlow 仍然有它的优势场景（特别是移动端部署），但你可以在掌握了 PyTorch 之后再了解 TensorFlow。
