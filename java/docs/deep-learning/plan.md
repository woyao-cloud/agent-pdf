# 《深度学习框架对比与实践：PyTorch 与 TensorFlow》大纲

## 本书定位

纯自然语言为主，极少代码。面向**有编程基础但想系统了解深度学习框架**的读者。不教深度学习算法本身，而是教"两个框架是什么、怎么选、各自优缺点、学习路径"。

## 全书结构

### 第1章 深度学习框架概览——它们解决什么问题？（无代码）

  * 从"手写梯度"到"自动求导"的演化故事
  * 框架的核心价值：自动求导 + GPU 加速 + 模型组件库
* 1.2 当前主流框架格局
  * PyTorch、TensorFlow、JAX 的定位
  * 学术界 vs 工业界的偏好差异
  * 市场份额和趋势数据

### 第2章 前序知识——学这两个框架需要什么基础？（无代码）
* 2.1 数学基础（需要到什么程度）
  * 线性代数：矩阵乘法、向量空间、转置（大学工科水平就够）
  * 微积分：偏导数、链式法则（理解"梯度"的概念）
  * 概率统计：均值、方差、概率分布（理解"损失函数"）
  * 例子说明：用"下山"比喻解释梯度下降
* 2.2 编程基础
  * Python：列表推导、函数、类
  * 不需要：C++、CUDA、系统编程
* 2.3 NumPy 基础详解（本章重点）
  * 2.3.1 NumPy 是什么——Python 的"数据容器升级版"
    * 从 Python 列表到 NumPy 数组：为什么深度学习不用 Python 列表？
    * 例子：用 Python 列表存 100 万个数需要多少内存 vs 用 NumPy 数组
  * 2.3.2 核心概念：数组 vs 向量 vs 矩阵 vs 张量
    * 0 维数组（标量）、1 维数组（向量）、2 维数组（矩阵）、多维数组（张量）
    * 例子：一张彩色图片在 NumPy 中是什么形状？
  * 2.3.3 NumPy 的三种核心运算
    * 逐元素运算：加法、乘法（和 Python 列表的区别）
    * 广播机制：形状不同的数组怎么相加？（用"复印"比喻）
    * 规约运算：求和、求平均、求最大值（把一堆数变成一个数）
  * 2.3.4 为什么深度学习离不开 NumPy？
    * NumPy 是 PyTorch Tensor 和 TensorFlow Tensor 的"原型"
    * 两种框架的张量操作 API 都模仿了 NumPy
    * 学会了 NumPy = 学会了两个框架的一半
    * 例子：PyTorch/TensorFlow 中的"张量"和 NumPy 的"数组"的对应关系
* 2.3 深度学习基础概念
  * 神经网络是什么？（用"函数拟合器"比喻）
  * 训练 = 找最好的参数（用"调收音机旋钮"比喻）
  * 过拟合 = 背答案而不是学规律

### 第3章 PyTorch 全景——特点、优点与缺点（极少代码）
* 3.1 PyTorch 的核心理念
  * 动态图：写 Python 就是在建图，建图就是在执行
  * Pythonic：代码像 Python，不像 DSL
  * 例子：对比"用 PyTorch 写一个条件分支" vs "用 TF 1.x 写同样的逻辑"
* 3.2 PyTorch 的优点
  * 调试体验极佳：print 任意中间结果，pdb 打断点
  * 模型定义灵活：可以在 forward() 中用 if/for
  * 学术生态第一：90% 的新论文用 PyTorch
  * HuggingFace 默认后端：所有预训练模型原生支持 PyTorch
  * 例子：研究者想尝试一个新想法，PyTorch 下只需要改几行代码
* 3.3 PyTorch 的缺点
  * 部署工具链不如 TF 成熟
  * 移动端支持（PyTorch Mobile）起步较晚
  * 生产环境下的监控和运维工具相对较少
  * 例子：一个团队想在生产环境部署模型，发现 TensorFlow Serving 比 TorchServe 更成熟

### 第4章 TensorFlow 全景——特点、优点与缺点（极少代码）
* 4.1 TensorFlow 的核心理念
  * 从静态图到动态图的演进
  * Keras：让 TF 变得易用的高级 API
  * 端到端平台：从训练到部署的完整工具链
* 4.2 TensorFlow 的优点
  * TF Serving 是工业部署的成熟方案（gRPC + REST，自动批处理，版本管理）
  * TFLite 是移动端部署的成熟方案（Android 首选）
  * TFX 提供了完整的 ML 流水线管理
  * Google 背书，企业级支持
  * 例子：一个需要部署到数百万 Android 手机的 AI 应用，TFLite 是唯一成熟选择
* 4.3 TensorFlow 的缺点
  * 调试体验不如 PyTorch（即使是 eager 模式）
  * 学术论文支持度低（新模型通常先出 PyTorch 版本）
  * API 变更频繁，兼容性历史包袱重
  * 例子：研究者发现一篇新论文的官方实现是 PyTorch，需要花时间"翻译"成 TF

### 第5章 核心维度对比——从 8 个角度看清楚（无代码）
* 5.1 对比维度一：学习曲线
  * PyTorch：先易后难（入门简单，高级用法需要理解更多概念）
  * TensorFlow：先难后易（Keras 简化后入门尚可，但深入需要理解 graph 模式）
* 5.2 对比维度二：调试体验
  * PyTorch：可以用 print、pdb、if/for——原生 Python 体验
  * TensorFlow：eager 模式下可以调试，但 tf.function 编译后不能打断点
* 5.3 对比维度三：模型部署
  * PyTorch：TorchServe（较新），TorchScript + C++ API
  * TensorFlow：TF Serving（成熟稳定），TFLite（移动端首选）
* 5.4 对比维度四：生态与社区
  * PyTorch：学术界主导，HuggingFace 生态，论文复现首选
  * TensorFlow：工业界存量巨大，Google 产品线深度集成
* 5.5 对比维度五：分布式训练
  * PyTorch：DDP（DistributedDataParallel）是事实标准
  * TensorFlow：MirroredStrategy、MultiWorkerMirroredStrategy
* 5.6 对比维度六：移动端与边缘
  * PyTorch：PyTorch Mobile（成长中）
  * TensorFlow：TFLite（成熟，Android 官方推荐）
* 5.7 对比维度七：时间线——你的项目生命周期
  * 研究/原型阶段 → PyTorch 更合适
  * 生产/大规模部署 → TF 的部署工具更成熟
  * 混合策略：PyTorch 训练 + ONNX 转换 + TF 部署
* 5.8 对比维度八：学习资源与社区
  * PyTorch：官方教程友好，论文代码多，论坛活跃
  * TensorFlow：官方文档完善，Google 资源多，但新技术更新慢

### 第6章 如何选择——6 个典型决策场景（无代码）
* 6.1 场景一：你是在校研究生/科研人员
  * 建议：PyTorch
  * 理由：发表论文的主流框架，复现他人工作方便，灵活试错
* 6.2 场景二：你在创业公司做 MVP
  * 建议：PyTorch
  * 理由：快速迭代验证，社区资源丰富，招人更容易
* 6.3 场景三：你在大型企业做生产部署
  * 建议：TensorFlow（如有存量）或 PyTorch（新项目）
* 6.4 场景四：你要做移动端 AI
  * 建议：TensorFlow（TFLite 更成熟）
* 6.5 场景五：你想找深度学习的工作
  * 建议：主学 PyTorch，了解 TensorFlow
* 6.6 场景六：你是企业技术选型决策者
  * 建议：优先 PyTorch（趋势向上），评估部署需求

### 第7章 学习路径建议——按阶段规划（无代码）
* 7.1 第一阶段：深度学习基础（不看框架）
  * 推荐资源
  * 需要理解的核心概念（梯度下降、反向传播、损失函数、过拟合）
* 7.2 第二阶段：选择一个框架入门
  * PyTorch 路径：官方 tutorial → 一个完整项目 → 进阶
  * TensorFlow 路径：Keras 入门 → 理解底层 → 部署
* 7.3 第三阶段：框架对比与迁移
  * 理解两个框架的思维差异
  * 学会看对方的代码并"翻译"
* 7.4 第四阶段：生产化技能
  * 部署、监控、A/B 测试、模型版本管理

## 写作风格说明

1. **每节都有例子**——用一个具体的场景故事说明抽象概念
2. **自然语言为主**——公式用文字描述，代码控制在全书的 5% 以内
3. **对比思维贯穿全书**——不是孤立介绍每个框架，而是放在一起对比
4. **适合零基础读者**——不需要先学深度学习，但有一章讲"前序知识"
