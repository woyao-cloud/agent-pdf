# 第7章 学习路径建议——按阶段规划

## 7.1 第一阶段：深度学习基础（不看框架）

在接触任何框架之前，先理解深度学习的核心概念。这个阶段的目标不是成为理论专家，而是建立基本的认知框架。

**需要理解的 4 个核心概念：**

**概念一：神经网络是一个"万能函数拟合器"。** 从本质上说，神经网络做的事情是"给定输入，预测输出"。一张图片是输入，图片的类别是输出。一段文字是输入，文字的情感是输出。一个房子的特征是输入，房子的价格是输出。神经网络通过学习大量"输入-输出"的对应关系，学会一个函数 f，使得 f(输入) ≈ 输出。

**概念二：训练就是"找最好的参数"。** 神经网络中有大量参数（几百万到几千亿个）。训练的过程就是不断调整这些参数，使得 f(输入) 和真实的输出之间的差距越来越小。这个"差距"叫做损失（loss）。损失越小，模型越好。可以想象你在调收音机的旋钮——你要找到那个让声音最清晰的"最佳旋钮位置"。

**概念三：梯度下降是"找最佳参数"的方法。** 梯度告诉你"往哪个方向调参数，loss 会下降"。梯度下降就是沿着梯度的反方向一小步一小步地调整参数。这个过程很慢但很稳定——只要你每一步都往下走，最终总能走到山脚。梯度是框架自动计算的，你不需要理解它的数学细节。

**概念四：过拟合就是"背答案而不是学规律"。** 如果一个模型在训练数据上表现很好，但在新数据上表现很差，这就是过拟合。相当于学生背下了所有习题的答案，但考试时题目稍作变化就不会做了。防止过拟合的方法包括：增加数据量、简化模型、使用正则化技术。

**推荐资源（按顺序）：** 3Blue1Brown 的"神经网络"系列视频（最直观的入门）、《动手学深度学习》（李沐，免费在线版）、fast.ai 的实践课程。不要一开始就啃《深度学习》（花书）——那是参考书，不是入门书。

## 7.2 第二阶段：选择一个框架入门

### PyTorch 路径

**第 1 步：官方教程的 60 分钟速成。** PyTorch 官网有一个 "PyTorch in 60 Minutes" 教程，涵盖了 Tensor、Autograd、神经网络构建等核心概念。跟着做完这个教程，你就知道了 PyTorch 的基本用法。

**第 2 步：完成一个完整项目。** 找一个经典的入门数据集（如 CIFAR-10 或 Fashion-MNIST），从头到尾完成数据加载、模型训练、评估、保存的完整流程。这个阶段的目标是理解整个训练流程，而不是追求准确率。

**第 3 步：学习迁移学习。** 用 `torchvision` 加载一个预训练模型（如 ResNet-18），在你的数据集上微调。迁移学习能让你在很少的数据上获得不错的性能，是实际项目中最常用的技术之一。

**第 4 步：深入学习一个领域。** 根据你的兴趣选择一个方向——计算机视觉（torchvision）、自然语言处理（HuggingFace Transformers）、时序预测——然后深入学习这个领域的常见模型和技术。

### TensorFlow 路径

**第 1 步：Keras 入门。** Google 的 "TensorFlow Fundamentals" 教程。用 Keras Sequential API 构建模型，用 fit 训练模型。这个阶段的目标是让代码跑起来。

**第 2 步：理解 tf.data 和数据流水线。** TensorFlow 的数据加载组件 `tf.data` 与其他框架不同，理解它的工作方式对你后续提高训练效率很重要。

**第 3 步：自定义训练和 tf.function。** 当你需要超出 Keras 标准训练模式时，自定义训练循环和 `tf.function` 是必须理解的。这是 TensorFlow 学习曲线中比较陡峭的部分。

**第 4 步：部署。** 尝试用 TF Serving 部署一个模型。这是 TensorFlow 的核心优势之一。

## 7.3 第三阶段：框架对比与迁移

当你掌握了其中一个框架后，学习另一个框架会快很多——因为核心概念是通用的。

理解两个框架的思维差异是关键。PyTorch 的思维是"Python 优先"——模型是一个类，训练是一个循环，一切都可以通过 Python 控制。TensorFlow 的思维是"图式执行"——即使默认是 eager 模式，底层的执行模型仍然是图，理解图的执行方式对理解 TensorFlow 的很多行为很重要。

学会看对方的代码并"翻译"成你熟悉的框架。当你看到一篇论文的官方实现用的是另一个框架时，你需要能理解它在做什么，然后用自己的框架重写。

## 7.4 第四阶段：生产化技能

当你能够在单机单卡上训练模型后，下一步是让模型能够在真实环境中工作。

**分布式训练**——当数据量或模型大到单卡放不下时，需要把训练分布到多张 GPU 或多个机器上。PyTorch 的 DDP 是事实标准。TensorFlow 的 MirroredStrategy。

**模型部署**——把训练好的模型变成在线推理服务。理解 TF Serving 或 TorchServe 的配置和调优。

**监控与运维**——部署后的模型需要监控：推理延迟、吞吐量、预测分布漂移（数据分布变了，模型精度可能下降）。这些是生产环境中常会遇到的问题。

**A/B 测试**——新版本模型上线前，需要验证它确实比旧版本好。理解如何进行流量分割和效果对比。

**模型版本管理**——当模型频繁更新时，如何管理不同版本的模型文件、如何回滚。
