## 详细章节内容

### 第1篇：基础篇 — RAG 与 LightRAG 概述

**第1章 RAG 技术演进与 LightRAG 定位**
- 1.1 RAG 技术发展简史
  - 朴素 RAG：向量检索 + LLM
  - 高级 RAG：重排序、查询重写、HyDE
  - 模块化 RAG：路由、多模态、Agent
- 1.2 传统 RAG 的局限性
  - 语义鸿沟：向量相似度 ≠ 语义相关性
  - 关系缺失：无法捕捉实体间关系
  - 全局理解差：难以回答需要综合多文档的问题
- 1.3 图增强 RAG 的兴起
  - GraphRAG（微软）：全局摘要 + 社区检测
  - LightRAG（HKU）：轻量级图索引 + 双级检索
  - 其他方案：KAG、HippoRAG
- 1.4 LightRAG 在 RAG 生态中的定位

**第2章 LightRAG 核心优势与解决的问题**
- 2.1 LightRAG 核心优势
  - 轻量级：相比 GraphRAG 减少 50-80% Token 消耗
  - 双级检索：低层具体事实 + 高层抽象摘要
  - 增量更新：无需重建索引即可添加新文档
  - 关系感知：自动提取实体间关系
- 2.2 LightRAG 解决的核心问题
  - 多跳推理：需要跨多个文档关联信息
  - 关系查询：实体间的关系是什么
  - 全局概览：文档集的整体主题和结构
  - 增量知识：知识库持续更新
- 2.3 适用场景与局限性
- 2.4 潜在风险总览

**第3章 LightRAG vs 微软 GraphRAG 深度对比**
- 3.1 架构对比
  - GraphRAG：全局摘要 → 社区检测 → 分层摘要
  - LightRAG：图索引 → 双级检索 → 直接生成
- 3.2 索引构建对比
  - GraphRAG：需要 LLM 生成摘要，Token 消耗大
  - LightRAG：仅提取实体和关系，Token 消耗小
- 3.3 查询性能对比
  - 全局查询：GraphRAG 社区摘要 vs LightRAG 高层检索
  - 局部查询：GraphRAG 实体搜索 vs LightRAG 低层检索
- 3.4 Token 消耗对比
- 3.5 适用场景对比
- 3.6 选型建议
