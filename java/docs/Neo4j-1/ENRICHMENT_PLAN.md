## 二、增强原则

1. **故事驱动** — 每章用一个真实场景故事开场，让读者先理解"为什么要学这个"
2. **类比优先** — 用读者已有的知识（SQL、文件系统、社交网络）类比新概念
3. **预期管理** — 每个查询/操作都说明"执行后你会看到什么"
4. **常见误区** — 每个知识点配"新手常犯的错误"
5. **渐进式复杂度** — 从简单到复杂，每一步都建立在已学知识上

## 五、风格示例

### 当前风格（太简练）：
```
## 核心概念
- **节点（Node）**：表示实体
- **关系（Relationship）**：表示连接
```

### 增强后风格：
```
## 核心概念

### 🎯 节点（Node）— 图中的"名词"
想象你在画一张社交网络图。你要把"张三"画成一个圆圈，把"李四"画成另一个圆圈。
这些圆圈就是**节点**。在Neo4j中，节点就是"实体"——可以是人、公司、商品、订单，
任何你想记录的东西。

💡 **类比**：在关系型数据库中，节点相当于"表中的一行记录"。
但区别在于：节点可以同时属于多个类别（标签），而一行只能属于一个表。

🎬 **例子**：在电影数据库中：
- `(:Actor {name: "Keanu Reeves"})` — 一个演员节点
- `(:Movie {title: "The Matrix"})` — 一部电影节点
- `(:Director {name: "Lana Wachowski"})` — 一个导演节点

它们都是"节点"，但通过不同的**标签**（Actor、Movie、Director）来区分类型。
```
