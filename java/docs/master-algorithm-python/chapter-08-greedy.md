# 第8章 贪心算法

> **核心问题**：如何在每一步都做出局部最优选择，最终得到全局最优解？

贪心算法（Greedy Algorithm）是最直观的算法设计范式之一——它在每个决策点上选择当前最优的选项，期望通过一系列局部最优选择聚合出全局最优解。它不像 DP 那样保留所有选择路径，而是只走一条路，因此效率极高。

---

## 8.1 贪心算法基本思想

### 解决的问题

贪心算法适用于满足以下性质的问题：

- **贪心选择性质（Greedy Choice Property）**：整体最优解可以通过一系列局部最优选择（即贪心选择）来构造。一旦做出贪心选择，后续只需要求解剩余的子问题。
- **最优子结构（Optimal Substructure）**：一个问题的最优解包含其子问题的最优解。这意味着在做出贪心选择后，剩余的子问题也必须能独立求出最优解。

> **❓ 贪心 vs DP**：两者都要求最优子结构，但贪心额外要求贪心选择性质——即"每一步的局部最优就是全局最优的一部分"。DP 不需要这个性质，所以 DP 更通用但更慢。

### 贪心策略的分类

| 策略 | 思路 | 典型问题 |
|------|------|---------|
| **最小/最大优先** | 每步选当前最小或最大的元素 | 活动选择（最早结束）、Dijkstra |
| **最小代价优先** | 每步选代价最小的操作 | Huffman 编码、Prim 最小生成树 |
| **单位价值优先** | 按单位收益排序，优先选最高效的 | 分数背包 |
| **最近邻优先** | 每步选最近的未访问节点 | 最近邻 TSP（近似解） |

### 贪心算法通用框架

```
贪心(Greedy) 算法通用框架：

① 确定贪心策略
   └→ 如何定义"当前最好"？
② 按贪心策略排序或选择
   └→ 通常对输入排序（O(n log n)），然后线性扫描
③ 逐步构造解
   └→ 维护当前已选集合，每步决定是否加入新元素
④ 验证解的正确性
   └→ 贪心需要证明！直觉不够，需要严格证明
```

### 贪心 vs 穷举

```
问题规模 n:        10        50        100       1000
穷举 (2^n):      1024      ~10^15     ~10^30    ≈∞
贪心 (n log n):   ~10      ~50        ~100      ~1000

贪心放弃了"保证最优"的可能性，换取了极高的效率。
```

### 使用场景

| 应用领域 | 经典问题 | 贪心策略 |
|---------|---------|---------|
| 调度 | 活动选择 | 最早结束时间优先 |
| 调度 | 区间调度 | 最早结束 / 最多重叠 |
| 压缩 | Huffman 编码 | 最小频率合并 |
| 图论 | Dijkstra 最短路 | 当前最短距离优先 |
| 图论 | Prim / Kruskal | 最小边优先 |
| 图论 | 分数背包 | 单位价值最高优先 |
| 路由 | 负载均衡 | 最小负载优先 |
| 缓存 | LRU / LFU | 最近最少使用 |

### 潜在风险与问题

- **贪心不一定最优**：需要严格证明贪心选择性质。直觉上"选当前最好"并不总能得到全局最优。
- **依赖输入排序**：贪心通常需要预排序，排序开销 O(n log n) 可能是瓶颈。
- **无法回溯**：贪心一旦做出选择就不会改变，因此错误的选择无法修正。
- **对数据敏感**：某些贪心策略对数据的分布非常敏感（如最近邻 TSP）。

## 8.2 贪心 vs 动态规划

贪心和 DP 都利用最优子结构，但它们在多个关键维度上截然不同：

| 维度 | 贪心算法（Greedy） | 动态规划（DP） |
|------|-------------------|--------------|
| **选择方式** | 每步做出一个不可撤销的选择 | 保留所有可能的选择路径 |
| **决策空间** | 每步只考虑一个候选 | 每步考虑所有子问题 |
| **子问题依赖** | 每步只留下一个子问题 | 依赖大量重叠的子问题 |
| **正确性条件** | 贪心选择性质 + 最优子结构 | 最优子结构 + 重叠子问题 |
| **证明难度** | 需要证明贪心选择性质 | 相对直观（状态转移） |
| **时间复杂度** | 通常 O(n log n) 或 O(n) | 通常 O(n²) 或更高 |
| **空间复杂度** | 通常 O(1) | 通常 O(n) 或更高 |
| **典型实现** | 排序 + 一次扫描 | 填表 + 回溯 |
| **保证最优解** | 仅对特定问题保证 | 总是保证最优解 |
| **调试难度** | 结果错误时难以定位 | DP 表可逐格检查 |

**选择标准**：
- 当问题符合贪心选择性质时，优先选择贪心——更快、更简单
- 当不确定贪心是否有效时，DP 是安全的选择
- 如果输入规模极大（>10^6），只能考虑贪心或近似算法

## 8.3 经典问题

### 活动选择（Activity Selection）

问题：给定 N 个活动的开始和结束时间 `[start_i, end_i]`，同一时间只能参加一个活动，求能参加的最大活动数量。

**贪心策略**：**每次选结束时间最早的活动**。这为剩余活动留下最多的空余时间。

```
活动:        A ---- B --------- C ---- D ---- E
时间轴:  0----1----2----3----4----5----6----7----8
开始/结束: (1,3) (2,4) (3,5) (4,6) (5,7)

贪心过程（按结束时间排序后）：
  ① 候选：[(1,3), (2,4), (3,5), (4,6), (5,7)]
  ② 选 (1,3): 最早结束，留下时间 ≥3
  ③ 从 ≥3 的活动里，最早结束是 (3,5) → 选
  ④ 从 ≥5 的活动里，最早结束是 (5,7) → 选
  结果：选 3 个活动 [(1,3), (3,5), (5,7)]
```

**复杂度**：排序 O(n log n)，选择 O(n)，总体 O(n log n)。

**正确性证明（Exchange Argument）**：
1. 设贪心解为 G = {g₁, g₂, ..., gₖ}，最优解为 O = {o₁, o₂, ..., oₘ}
2. 假设 m > k（最优解包含更多活动）
3. 考虑第一个不同的选择：g₁ 的结束时间 ≤ o₁ 的结束时间（因为贪心选最早结束）
4. 将 O 中的 o₁ 替换为 g₁，得到的 O' 仍然是可行解且活动数不变
5. 不断用贪心选择替换最优解中的活动，最终将 O 转化为贪心解 G
6. 因此 G 也是最优解（|G| = |O|）

### 区间调度（Interval Scheduling）—— 最大不相交区间数

问题：给定 N 个区间 `[l_i, r_i]`，求最大不相交区间数。

这与活动选择本质相同：按右端点排序，贪心选取不重叠的区间。

```
区间:    [1,3]  [2,4]  [3,5]  [4,6]  [5,7]
排序后:  [1,3]  [2,4]  [3,5]  [4,6]  [5,7]

贪心：
  选 [1,3] → 下一个不重叠的是 [3,5] → 下一个是 [5,7]
  结果：3 个区间
```

**变体问题**：

- **最少区间覆盖点**（用最少的点覆盖所有区间）：贪心选区间最右端点
- **最小移除区间数**（使得剩余区间互不相交）：等价于总区间数 − 最大不相交区间数
- **会议室 II**（最少需要多少会议室）：扫描线 + 优先队列

### Huffman 编码

问题：给定字符及其出现频率，构造最优前缀码（Prefix Code），使得编码后字符串总长度最短。

**贪心策略**：**每次合并两个频率最小的节点**，构造一棵二叉树，使得高频字符用短编码，低频字符用长编码。

```
字符与频率:  A:5  B:9  C:12  D:13  E:16  F:45

构造过程：
  步骤1: 合并 A(5) 和 B(9) → 14
  步骤2: 合并 C(12) 和 D(13) → 25
  步骤3: 合并 14 和 E(16) → 30
  步骤4: 合并 25 和 30 → 55
  步骤5: 合并 45 和 55 → 100

特征树结构：
               [0/1]
              /     \
           F(45)   [55]
                  /    \
              [30]     [25]
             /    \    /   \
          [14]   E(16) C(12) D(13)
         /    \
       A(5)  B(9)

编码结果：
  F: 0      (1 bit)
  C: 100    (3 bits)
  D: 101    (3 bits)
  A: 1100   (4 bits)
  B: 1101   (4 bits)
  E: 111    (3 bits)

总位数 = 45×1 + 12×3 + 13×3 + 5×4 + 9×4 + 16×3 = 224
定长编码（3 bits/char 需 96×3 = 288 bits）
节省 = 288 - 224 = 64 bits (22%)
```

**复杂度**：使用优先队列 O(n log n)，建树 O(n)，编码表生成 O(n)。

**正确性证明（Greedy Stays Ahead + Exchange Argument）**：

1. **贪心选择性质**：存在一个最优前缀码，其中频率最小的两个字符在树的最深层且为兄弟节点。
   - 如果这两个字符不是兄弟，可以通过交换得到同样优的编码
2. **最优子结构**：合并最小频率的两个字符后，原问题转化为 N-1 个字符的新问题
   - 合并后的节点频率 = 两者之和，被视为一个"虚拟字符"
   - 新问题的最优解 + 合并步骤 = 原问题的最优解
3. 归纳法：从 N=2 开始归纳，每一步合并最小频率保持了最优性

## 8.4 贪心算法的正确性证明

贪心算法"看起来正确"不等于"确实正确"。必须通过严格的数学证明来验证。

### 两大证明方法

#### 1. Greedy Stays Ahead（贪心领先）

**思路**：证明贪心算法在每一步都**不落后于**任何最优解。如果贪心解在每一步都保持领先（或持平），那么最终结果至少和最优解一样好。

**模板**：
```
1. 定义衡量指标 mᵢ（贪婪在第 i 步后达到的值）
2. 定义 m*ᵢ（任意最优解在第 i 步后达到的值）
3. 证明对 ∀i，mᵢ ≥ m*ᵢ（或 mᵢ ≤ m*ᵢ，视问题而定）
4. 由归纳法可得：贪心算法达到的值 ≥ 最优解的值
```

**示例：活动选择**——证明贪心选的结束时间 ≤ 最优解同一步结束时间。

**示例：Dijkstra**——证明每步选出的节点距离就是它的最短距离。

#### 2. Exchange Argument（交换论证）

**思路**：任给一个最优解 O，通过一系列**交换操作**在不破坏最优性的前提下逐步将 O 转化为贪心解 G，从而证明 G 也是最优的。

**模板**：
```
1. 设贪心解 G = (g₁, g₂, ..., gₖ)
2. 设最优解 O = (o₁, o₂, ..., oₘ)，且 m ≥ k（或 m ≤ k）
3. 找到第一个位置 t 使 gₜ ≠ oₜ
4. 证明可以用 gₜ 替换 oₜ 而不降低 O 的质量
5. 重复替换直到 O 变为 G
6. 因此 |G| = |O|，贪心解是最优的
```

### 贪心何时失败？—— 反例分析

**硬币找零的反例**：
```
面值: [1, 3, 4]
金额: 6

贪心策略：每次选最大面值
  贪心: 4 + 1 + 1 = 3 枚硬币
  最优: 3 + 3 = 2 枚硬币

贪心失败！因为选 4 导致剩余金额 2 只能用两个 1，
而两个 3 的组合更优。
```

**分析为什么失败**：贪心选择性质不成立。当前最大面值 4 的"性价比"和它在整体中的角色不匹配。在这个硬币系统中，3 是更关键的中间面值。

### 判断贪心是否有效的实用技巧

| 条件 | 说明 |
|------|------|
| **问题的结构是"找最大/最小集合"** | 通常可以尝试贪心 |
| **问题可以用"matroid"描述** | 贪心一定有效（matroid 理论中，贪心在所有 matroid 上最优） |
| **每步选择不受之前选择的顺序影响** | 贪心是一个好的候选 |
| **问题有明确的"度量"可以比较** | 可以设计贪心策略 |
| **一个反例就能证伪** | 尝试构造反例测试策略 |

**常见可证明贪心的问题**：
- 活动选择、区间调度
- Huffman 编码
- Dijkstra 最短路
- Prim 和 Kruskal 最小生成树
- 分数背包（Fractional Knapsack）
- 任务调度（最小化延迟）

**常见贪心不保证最优的问题**：
- 0/1 背包（贪心只能得到近似解）
- 旅行商问题（TSP）
- 图着色
- 子集和问题
- 硬币找零（某些面值）
