# 第3章 算法思维模式

> **核心问题**：拿到一个问题后，如何选择最合适的算法策略？不同算法模式之间有什么区别与联系？

算法思维模式（Algorithm Thinking Patterns）是解决问题的高层策略框架。理解这些模式，能帮你在面对一个新问题时快速定位到合适的方法论，而不是每次都从头摸索。

## 3.1 分治法（Divide and Conquer）

### 解决的问题
将一个复杂的大问题分解为若干个规模更小、结构相似的子问题，递归求解后再合并结果。适用于具有**最优子结构**且子问题**相互独立**的场景。

### 实现原理

**三步流程**：
```
        原始问题
           │
    ┌──────┴──────┐
    ▼             ▼
   子问题1       子问题2    ← Divide：将问题分解为更小的子问题
    │             │
    ▼             ▼
   子问题1解     子问题2解   ← Conquer：递归求解子问题
    │             │
    └──────┬──────┘
           ▼
        合并结果              ← Combine：合并子问题的解
```

**复杂度分析**：
- 递推公式：`T(n) = a·T(n/b) + f(n)`
- 主定理（Master Theorem）是分析分治复杂度的核心工具：
  - 若 `f(n) = O(n^c)` 且 `c < log_b a`，则 `T(n) = Θ(n^{log_b a})`
  - 若 `f(n) = Θ(n^c)` 且 `c = log_b a`，则 `T(n) = Θ(n^c log n)`
  - 若 `f(n) = Ω(n^c)` 且 `c > log_b a`，则 `T(n) = Θ(f(n))`

### 代码实现

见 `demos/ch03/demo_divide_conquer.py` — 以归并排序演示完整的分治三步过程。

**核心骨架**（伪代码）：
```python
def divide_conquer(problem):
    # 1. 基本情况：问题足够小，直接求解
    if is_trivial(problem):
        return solve_directly(problem)

    # 2. Divide：拆分为子问题
    subproblems = split(problem)

    # 3. Conquer：递归求解
    sub_results = [divide_conquer(sub) for sub in subproblems]

    # 4. Combine：合并结果
    return combine(sub_results)
```

### 使用场景

| 应用领域 | 经典算法 | 分治维度 |
|---------|---------|---------|
| 排序 | 归并排序、快速排序 | 按位置或基准分割 |
| 查找 | 二分查找 | 按大小关系分割 |
| 矩阵运算 | Strassen 矩阵乘法 | 按分块分割 |
| 几何 | 最近点对 | 按坐标分割 |
| 数值计算 | 快速傅里叶变换(FFT) | 按奇偶分割 |

### 潜在风险与问题

- **分解开销**：如果分解和合并的代价过高（如 `f(n)` 接近 `O(n^2)`），分治可能不如暴力
- **递归深度**：对于 Python，默认递归深度限制约 1000，需注意栈溢出
- **子问题重叠**：如果子问题不独立（有重叠），分治会导致重复计算，应改用 DP

### 优化策略

- **阈值切换**：当子问题规模小于某个阈值时，切换到迭代或暴力算法，减少递归开销
- **尾递归消除**：将递归转为迭代（如归并排序的遍历合并阶段）
- **并行化**：分治天然适合并行，子问题可分配到不同处理器

```python
def merge_sort_hybrid(arr, threshold=16):
    """当子数组长度小于 threshold 时切换为插入排序"""
    if len(arr) <= threshold:
        return insertion_sort(arr)  # 小规模用简单排序
    mid = len(arr) // 2
    left = merge_sort_hybrid(arr[:mid], threshold)
    right = merge_sort_hybrid(arr[mid:], threshold)
    return merge(left, right)
```

## 3.2 贪心算法（Greedy）

### 解决的问题
通过每一步都选择当前最优（局部最优），期望最终得到全局最优解。适用于具有**贪心选择性质**和**最优子结构**的问题。

### 实现原理

**贪心 vs 最优解**：
```
贪心决策过程（以找零为例）：
  金额: 63  硬币面值: [25, 10, 5, 1]
  Step 1: 选 25 (剩余 38)  ✓ 局部最优
  Step 2: 选 25 (剩余 13)  ✓
  Step 3: 选 10 (剩余 3)   ✓
  Step 4: 选 1  (剩余 2)    ✓
  Step 5: 选 1  (剩余 1)    ✓
  Step 6: 选 1  (剩余 0)    ✓
  结果: 6 枚硬币

但在某些面值组合下贪心会失败（见 demo_greedy_vs_dp.py）
```

**正确性证明方法**：
- **交换论证（Exchange Argument）**：证明任意最优解都可以通过一系列不劣化结果的交换变为贪心解
- **数学归纳法**：证明贪心选择后，剩余子问题仍然可以应用贪心策略

### 代码实现

见 `demos/ch03/demo_greedy_vs_dp.py` — 通过硬币找零问题对比贪心与动态规划。

**核心骨架**：
```python
def greedy(items, constraint):
    result = []
    # 按贪心策略排序
    sorted_items = sort_by_greedy_criterion(items)
    for item in sorted_items:
        if meets_constraint(item, constraint):
            result.append(item)
            constraint = update(constraint, item)
    return result
```

### 使用场景

| 应用领域 | 经典算法 | 贪心策略 |
|---------|---------|---------|
| 调度 | 活动选择 | 按结束时间最早 |
| 压缩 | Huffman 编码 | 频率最低的优先合并 |
| 图论 | Prim / Kruskal (MST) | 最小权重边优先 |
| 图论 | Dijkstra 最短路径 | 当前距离最短优先 |
| 缓存 | LRU / LFU 缓存淘汰 | 最近最少/最不经常使用 |

### 潜在风险与问题

- **贪心失效**：并非所有问题都有贪心选择性质。例如带面值 [1, 3, 4] 的找零问题，贪心选 4+1+1=3 枚，最优解 3+3=2 枚
- **证明困难**：贪心正确性往往需要严谨证明，直觉判断不可靠
- **局部最优 ≠ 全局最优**：背包问题（0-1 背包）贪心就经常失败

### 优化策略

- **结合其他策略**：贪心 + 动态规划（如贪心做预处理缩小状态空间）
- **贪心启发式**：在 NP-难问题中，贪心常用作近似算法的基础
- **识别贪心适用性**：
  - 问题是否可以在局部做选择而不影响后续？→ 可能是贪心
  - 是否有反例能推翻贪心？→ 尝试构造反例验证

## 3.3 动态规划（Dynamic Programming）

### 解决的问题
通过将原问题分解为**重叠子问题**，记录子问题的解避免重复计算，从而高效求得最优解。适用于具有**最优子结构**和**重叠子问题**的性质的问题。

### 实现原理

> **❓ 分治 vs DP**：分治的子问题是**独立**的，DP 的子问题是**重叠**的。这是选择的关键分水岭。

**两种实现范式**：

```
┌──────────────────────────────────────────────────┐
│                 动态规划                          │
│                                                   │
│  方式一：Memoization（自顶向下 + 记忆化）          │
│  ┌────────────────────────────────────────┐       │
│  │ fib(5)                                 │       │
│  │ ├── fib(4)                             │       │
│  │ │   ├── fib(3)                         │       │
│  │ │   │   ├── fib(2)                     │       │
│  │ │   │   └── fib(1) fib(0)  ← 缓存      │       │
│  │ │   └── fib(2)  ← 命中缓存             │       │
│  │ └── fib(3)  ← 命中缓存                 │       │
│  └────────────────────────────────────────┘       │
│                                                   │
│  方式二：Tabulation（自底向上 + 表格）              │
│  ┌────────────────────────────────────────┐       │
│  │ dp[0] → dp[1] → dp[2] → ... → dp[n]   │       │
│  │ 每个状态只依赖前面已计算的状态           │       │
│  └────────────────────────────────────────┘       │
└──────────────────────────────────────────────────┘
```

| 维度 | Memoization（记忆化） | Tabulation（表格法） |
|------|---------------------|--------------------|
| 方向 | 自顶向下（递归） | 自底向上（迭代） |
| 实现 | 递归 + 缓存字典/数组 | 循环填充表格 |
| 计算量 | 只计算需要的状态 | 计算所有状态 |
| 空间 | 递归栈 + 缓存 | 表格数组 |
| 调试 | 相对复杂 | 直观清晰 |

### 代码实现

见 `demos/ch03/demo_greedy_vs_dp.py`（DP 版本硬币找零）。

**Fibonacci with Memoization（简洁示例）**：
```python
def fib_memo(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib_memo(n-1, memo) + fib_memo(n-2, memo)
    return memo[n]
```

**Fibonacci with Tabulation**：
```python
def fib_tab(n):
    if n <= 1:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i-1] + dp[i-2]
    return dp[n]
```

**DP 通用三步法**：
1. **定义状态** `dp[i]`：表示"前 i 个元素中……"的最优解
2. **状态转移方程**：`dp[i] = f(dp[i-1], dp[i-2], ...)`
3. **初始条件 + 边界**：`dp[0]`, `dp[1]` 等基础值

### 使用场景

| 应用领域 | 经典问题 | 状态定义 |
|---------|---------|---------|
| 序列 | 最长公共子序列 (LCS) | `dp[i][j]`: A[0..i] 与 B[0..j] 的 LCS |
| 序列 | 最长递增子序列 (LIS) | `dp[i]`: 以 A[i] 结尾的 LIS |
| 背包 | 0-1 背包 | `dp[i][w]`: 前 i 个物品容量 w 的最大价值 |
| 编辑 | 编辑距离 | `dp[i][j]`: A[0..i] 到 B[0..j] 的最小编辑 |
| 路径 | 网格路径数 | `dp[i][j]`: 到达 (i,j) 的路径数 |

### 潜在风险与问题

- **状态定义错误**：DP 最大的坑 — 状态定义不当会导致转移方程无法正确写出
- **维度爆炸**：状态维度过高（如三维、四维）导致空间和计算量过大
- **顺序依赖**：Tabulation 需要确保状态按拓扑顺序计算

### 优化策略

- **空间压缩（Rolling Array）**：当 `dp[i]` 只依赖 `dp[i-1]` 时，可以用滚动数组将 `O(n)` 降为 `O(1)`
- **状态压缩 DP**：用位掩码表示集合状态，适用于小规模 NP-难问题
- **四边形不等式**：对某些区间 DP 问题，可用决策单调性优化到 `O(n^2)`

```python
# 空间压缩的 Fibonacci
def fib_compressed(n):
    if n <= 1:
        return n
    prev2, prev1 = 0, 1
    for _ in range(2, n + 1):
        prev2, prev1 = prev1, prev1 + prev2
    return prev1
```

## 3.4 回溯法（Backtracking）

### 解决的问题
通过尝试所有可能的候选解来求解问题，并在发现当前路径不可能达到可行解时进行**回溯（撤销选择）**。适用于组合搜索、约束满足问题。

### 实现原理

> **❓ DP vs 回溯**：DP 求的是**最优解**，利用重叠子问题剪枝；回溯求的是**所有可行解**（或特定约束下的解），利用约束条件剪枝。

**搜索树与剪枝**：
```
               root
           /    |    \          ← 做出选择
          a     b     c
         /|\   /|\   /|\        ← 递归进入下一层
        ...  ...  ...
           \
            ✗ 剪枝：此路径不满足约束
             \
              backtrack → 撤销选择，尝试另一分支
```

**核心框架（选/不选模式）**：
```python
def backtrack(路径, 选择列表):
    if 满足结束条件:
        记录结果
        return

    for 选择 in 选择列表:
        if 不满足约束条件:    ← 剪枝
            continue
        做选择 (将选择加入路径)
        backtrack(路径, 更新后的选择列表)
        撤销选择 (从路径移除)
```

### 代码实现

见 `demos/ch03/demo_backtracking.py` — 全排列生成与剪枝可视化。

**N-Queens 骨架**：
```python
def solve_n_queens(n):
    def is_safe(board, row, col):
        # 检查列冲突和斜线冲突
        for i in range(row):
            if board[i] == col or \
               board[i] - i == col - row or \
               board[i] + i == col + row:
                return False
        return True

    def backtrack(row, board):
        if row == n:
            solutions.append(board[:])
            return
        for col in range(n):
            if is_safe(board, row, col):
                board.append(col)      # 做选择
                backtrack(row + 1, board)
                board.pop()            # 撤销选择

    solutions = []
    backtrack(0, [])
    return solutions
```

### 使用场景

| 应用领域 | 经典问题 | 约束条件 |
|---------|---------|---------|
| 排列组合 | 全排列、子集生成 | 元素不重复等 |
| 博弈 | N-Queens、数独 | 行列斜线不冲突 |
| 图论 | 哈密顿路径、图着色 | 相邻节点约束 |
| 组合优化 | 组合求和 | 目标和约束 |
| 约束求解 | SAT、CSP | 逻辑约束 |

### 潜在风险与问题

- **指数爆炸**：最坏情况下时间复杂度为 `O(n!)` 或 `O(2^n)`，问题规模稍大就会超时
- **缺少有效剪枝**：剪枝策略不好时，搜索空间几乎无法缩减
- **重复解**：不注意去重会导致大量重复搜索

### 优化策略

- **有效剪枝**：剪枝函数应尽早排除不可能的分支
- **排序预处理**：先处理约束最强的变量（如数独中先填可选值最少的格子）
- **对称破缺（Symmetry Breaking）**：利用问题对称性减少搜索空间
- **记忆化搜索**：对相同的子状态缓存结果，避免重复搜索
- **并行搜索**：将搜索树的顶层分支分配到不同线程/进程

## 3.5 分支限界法（Branch and Bound）

### 解决的问题
在解空间树中搜索最优解时，通过维护**上下界**来剪掉不可能产生更优解的分支。与回溯法类似但以**优化**为目标。

### 实现原理

**回溯 vs 分支限界**：

| 维度 | 回溯法 | 分支限界法 |
|------|-------|-----------|
| 目标 | 找所有解 / 可行解 | 找最优解 |
| 搜索方式 | 深度优先 (DFS) | 广度优先 (BFS) / 最小代价优先 |
| 剪枝依据 | 约束条件 | 约束条件 + 界限（上界/下界） |
| 数据结构 | 递归栈 | 队列 / 优先队列 |
| 典型应用 | N-Queens、数独 | TSP、背包问题 |

**工作原理**：
```
初始状态（根节点）
    │
    ▼
扩展节点 → 计算界限 → 如果 bound ≤ best_so_far → 剪枝
    │                             否则继续扩展
    ▼
生成子节点 → 重复上述过程
```

- **上界/下界**：对当前分支可能达到的最优解进行估算
- **剪枝条件**：
  - 最小化问题：如果当前下界 ≥ 已知最优解 → 剪枝
  - 最大化问题：如果当前上界 ≤ 已知最优解 → 剪枝

### 使用场景

| 应用领域 | 经典问题 | 界限策略 |
|---------|---------|---------|
| 路径优化 | 旅行商问题 (TSP) | 最小生成树下界 + 路径长度上界 |
| 组合优化 | 0-1 背包 | 贪心上界（分数背包） |
| 调度 | 作业车间调度 | 松弛下界 |
| 布局 | 电路板布线 | 曼哈顿距离下界 |

### 潜在风险与问题

- **界限质量**：界限越紧剪枝效果越好，但计算界限本身也有成本
- **内存消耗**：BFS 方式可能产生大量节点，需要较大内存
- **退化情况**：界限质量差时退化为暴力搜索

### 优化策略

- **优先队列**：使用最小/最大堆优先扩展最有希望的节点
- **对称性去除**：利用问题对称结构减少冗余分支
- **启发式初始解**：先用贪心或近似算法得到一个较好的初始解，提高剪枝效率
- **松弛**：通过松弛约束得到更紧的界限（如 LP 松弛）

## 3.6 枚举与启发式

### 3.6.1 暴力枚举（Brute Force）

**适用场景**：
- 问题规模非常小（如 n ≤ 15），枚举可行
- 需要验证其他算法的正确性（作为基准）
- 输入空间有限（如密码暴力破解）

**风险**：指数级时间复杂度，在工程中几乎不可用。

### 3.6.2 启发式方法（Heuristic）

**核心思想**：放弃求解最优解，用可接受的时间找到一个"足够好"的解。

**常见启发式**：

| 方法 | 原理 | 适用场景 |
|------|------|---------|
| 爬山法 | 在邻域中选最优方向移动 | 局部搜索问题 |
| 模拟退火 | 以一定概率接受劣解，避免陷入局部最优 | 组合优化 |
| 遗传算法 | 模拟自然选择，交叉变异产生新解 | 复杂函数优化 |
| 蚁群算法 | 模拟蚂蚁觅食的信息素机制 | 路径规划 |
| 近似算法 | 可证明的解质量保证（如 2-近似） | NP-难问题 |

**使用建议**：
- **首选精确算法**（分治/DP/回溯），只有无法求解时才考虑启发式
- **近似算法** > 启发式：近似算法有理论保证，启发式没有
- **结合使用**：启发式提供初始解 → 分支限界或精确算法精细化

## 决策流程：选择思维模式

```
问题来了
    │
    ▼
┌─────────────────────────────────────────────────────┐
│  ① 需求的解的类型？                                  │
├─────────────────────────────────────────────────────┤
│  A) 求"是否存在/是否可行" → 回溯法                    │
│  B) 求"最优解" → 看 ②                                │
│  C) 求"所有解" → 回溯法                               │
└─────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────┐
│  ② 问题是否具备最优子结构？                            │
├─────────────────────────────────────────────────────┤
│  否 → 考虑分支限界 / 启发式 / 枚举                     │
│  是 → 看 ③                                           │
└─────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────┐
│  ③ 子问题是否重叠？                                   │
├─────────────────────────────────────────────────────┤
│  独立（子问题不重叠）→ 分治法                          │
│  重叠（子问题重复出现）→ 看 ④                          │
└─────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────┐
│  ④ 是否有贪心选择性质？                                │
├─────────────────────────────────────────────────────┤
│  是 → 贪心算法（最简单高效）                           │
│  否 → 动态规划（通用但可能更复杂）                     │
│  不确定 → 先尝试贪心构造反例，不行再上 DP              │
└─────────────────────────────────────────────────────┘
```

### 快速参考表

| 问题特征 | 推荐模式 | 原因 |
|---------|---------|------|
| 排序、大规模数据分治 | 分治法 | 子问题独立，可高效合并 |
| 每一步局部最优 → 全局最优 | 贪心算法 | 最简、最快、无状态 |
| 重叠子问题、求最优解 | 动态规划 | 避免重复计算 |
| 需要遍历所有可能性 | 回溯法 | 系统化搜索 |
| 约束 + 优化目标 | 分支限界 | 界限剪枝加速搜索 |
| n < 15 的小规模 | 暴力枚举 | 实现简单、不易出错 |
| 超大问题、无精确解 | 启发式/近似 | 只能"够好" |

---

## 小结

本章介绍了六种核心算法思维模式：

| 模式 | 核心策略 | 关键词 | 如何选择 |
|------|---------|-------|---------|
| **分治法** | 分解 → 递归 → 合并 | 独立子问题 | 问题可拆分为独立子问题 |
| **贪心算法** | 局部最优 → 全局最优 | 贪心选择性质 | 每一步最优不影响后续选择 |
| **动态规划** | 状态 + 转移 + 缓存 | 重叠子问题 | 子问题重复、求最优解 |
| **回溯法** | 探索 → 约束 → 回溯 | 系统化搜索 | 需要枚举所有可能性 |
| **分支限界** | 搜索 + 上下界剪枝 | 优化 + 界限 | 优化问题 + 需要剪枝 |
| **枚举/启发式** | 枚举或近似 | 暴力 / 近似 | 容量极小或极大时 |

**关键能力**：不是记住每个模式的细节，而是面对问题时能**快速识别出应使用哪种模式**。这需要大量做题和实践，建议配合第 7-9 章（DP、贪心、回溯的深入案例）一起学习。
