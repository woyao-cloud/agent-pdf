# 第4章 排序算法

> **核心问题**：面对一组杂乱无序的数据，如何高效地将其变为有序序列？不同的排序算法在时间复杂度、空间复杂度、稳定性上各有何优劣？如何在实际场景中做出最优选择？

排序（Sorting）是计算机科学中最基础、研究最透彻的问题之一。几乎所有数据处理的流程中都能找到排序的影子——搜索引擎对结果按相关性排序、数据库 `ORDER BY` 操作、推荐系统按分值排序。理解排序算法，是理解算法设计的绝佳窗口。

---

## 4.1 排序算法分类与对比

### 解决的问题

面对一个无序数组，你有一大堆排序算法可选。但不同的算法有不同的性格——有的快但不稳定，有的稳定但费内存，有的对几乎有序的数据特别高效。分类的目的是帮你在面对具体问题时，快速缩小选择范围。

### 实现原理

排序算法可以从三个维度分类：

**1. 比较排序 vs 非比较排序**

| 类别 | 原理 | 下界 | 代表算法 |
|------|------|------|---------|
| **比较排序 (Comparison Sort)** | 通过两两比较决定顺序 | Ω(n log n) | 快速排序、归并排序、堆排序 |
| **非比较排序 (Non-Comparison Sort)** | 利用数据本身的特殊性质（如整数范围、位数） | O(n+k) | 计数排序、桶排序、基数排序 |

比较排序有一个重要的理论下界：**任何基于比较的排序算法在最坏情况下至少需要 Ω(n log n) 次比较**。也就是说，不可能有比 O(n log n) 更快的通用比较排序算法。非比较排序通过利用数据的额外信息（如键的范围、分布）来突破这个下界。

**2. 稳定排序 vs 不稳定排序**

稳定排序保持相等元素的原始相对顺序。这在按多关键字排序时至关重要——例如先按姓名字典序排序，再按年龄排序，稳定排序能保证年龄相同的人仍然保持按姓名排序的顺序。

| 性质 | 含义 |
|------|------|
| **稳定 (Stable)** | 相等元素排序后相对位置不变 | 插入排序、归并排序、计数排序、冒泡排序 |
| **不稳定 (Unstable)** | 相等元素排序后相对位置可能改变 | 快速排序、选择排序、堆排序、希尔排序 |

**3. 原地排序 vs 非原地排序**

| 性质 | 额外空间 | 代表算法 |
|------|---------|---------|
| **原地 (In-place)** | O(1) 或 O(log n) | 冒泡排序、快速排序、堆排序、插入排序 |
| **非原地 (Out-of-place)** | O(n) 或更多 | 归并排序、计数排序、桶排序 |

### Master 对比表

| 算法 | 平均时间 | 最坏时间 | 最好时间 | 空间 | 稳定 | 原地 | 数据敏感 |
|------|---------|---------|---------|------|:----:|:----:|:--------:|
| 冒泡排序 (Bubble) | O(n²) | O(n²) | O(n) | O(1) | ✓ | ✓ | 已排序时最优 |
| 快速排序 (Quick) | O(n log n) | O(n²) | O(n log n) | O(log n) | ✗ | ✓ | 取决于 pivot |
| 插入排序 (Insertion) | O(n²) | O(n²) | O(n) | O(1) | ✓ | ✓ | 几乎有序时近似 O(n) |
| 希尔排序 (Shell) | O(n log² n) | O(n log² n) | O(n log n) | O(1) | ✗ | ✓ | 取决于 gap 序列 |
| 选择排序 (Selection) | O(n²) | O(n²) | O(n²) | O(1) | ✗ | ✓ | 不敏感（总是 n²） |
| 堆排序 (Heap) | O(n log n) | O(n log n) | O(n log n) | O(1) | ✗ | ✓ | 不敏感 |
| 归并排序 (Merge) | O(n log n) | O(n log n) | O(n log n) | O(n) | ✓ | ✗ | 不敏感 |
| 计数排序 (Counting) | O(n+k) | O(n+k) | O(n+k) | O(k) | ✓ | ✗ | 整数范围 k 小则快 |
| 桶排序 (Bucket) | O(n+k) | O(n²) | O(n+k) | O(n) | ✓ | ✗ | 均匀分布时最优 |
| 基数排序 (Radix) | O(d·(n+k)) | O(d·(n+k)) | O(d·(n+k)) | O(n+k) | ✓ | ✗ | 位数 d 小则快 |

> 注：k 表示键的取值范围大小，d 表示数字的位数。

### 使用场景

- **面试和竞赛**：快速排序和归并排序是最常被问到的算法
- **生产代码**：Python 的 `list.sort()` 使用 TimSort（归并+插入混合），Java 的 `Arrays.sort()` 使用 Dual-Pivot QuickSort
- **大数据**：外部排序（External Sort）用归并排序处理内存放不下的数据
- **特殊数据**：整数用基数排序，范围有限的整数用计数排序，均匀分布浮点数用桶排序

### 潜在风险

- **忽略稳定性需求**：多关键字排序时不使用稳定排序会导致"看似正确实则错误"的结果
- **误解 O(n log n)**：理论上同样复杂度的算法，实际常数因子可能差 2-3 倍
- **快速排序的最坏情况**：对已排序数组使用固定 pivot 的快速排序退化到 O(n²)

### 优化策略

1. **混合策略**：小规模数据用插入排序，大规模用快速排序或归并排序
2. **三路切分 (3-Way Partition)**：处理大量重复元素时，将数组分为 `< pivot`、`= pivot`、`> pivot` 三部分
3. **尾递归优化**：快速排序中优先处理较小的子数组，减少递归深度

## 4.2 交换排序（冒泡、快速排序）

### 解决的问题

交换排序的核心思想是：通过不断交换逆序的元素对，使整个数组逐步变得有序。两个最经典的交换排序分别是"慢而稳"的冒泡排序和"快而不稳"的快速排序。

### 实现原理

#### 冒泡排序 (Bubble Sort)

**原理**：从左到右遍历数组，比较相邻元素，如果前 > 后就交换。每轮遍历会将当前未排序部分的最大元素"冒泡"到最右端。

```
初始: [5, 3, 8, 6, 4]

第1轮（将最大值 8 冒泡到末尾）:
  比较 5 和 3 → 交换 → [3, 5, 8, 6, 4]
  比较 5 和 8 → 不交换
  比较 8 和 6 → 交换 → [3, 5, 6, 8, 4]
  比较 8 和 4 → 交换 → [3, 5, 6, 4, 8]  ← 8 就位

第2轮（将次大值 6 冒泡到倒数第二）:
  比较 3 和 5 → 不交换
  比较 5 和 6 → 不交换
  比较 6 和 4 → 交换 → [3, 5, 4, 6, 8]  ← 6 就位

... 继续直到完全有序
```

**优化**：如果某一轮没有发生任何交换，说明数组已经有序，可以提前终止。

**复杂度**：最好 O(n)（已排序），最坏/平均 O(n²)。

#### 快速排序 (Quick Sort)

**原理**：选择一个 pivot（基准），将数组分为"小于 pivot"和"大于 pivot"两部分，然后递归地对两部分排序。

```
pivot=5  [3, 4, 2, 5, 8, 7, 9]
            ↓     ↓  ↓
       小于部分 │ 大于部分
         ↓     │    ↓
      [3,4,2] 5  [8,7,9]
         ↓          ↓
      [2,3,4]    [7,8,9]
         ↓          ↓
      [2,3,4,5,7,8,9]
```

**Pivot 选择策略**：

| 策略 | 方法 | 优缺点 |
|------|------|--------|
| 固定 pivot | 取第一个或最后一个元素 | 简单但已排序数组退化为 O(n²) |
| 随机 pivot | 随机选一个元素 | 避免最坏情况（概率极低） |
| 三数取中 (Median-of-Three) | 取首、中、尾三个元素的中位数 | 工程上最常用，几乎避免退化 |

**关键操作：Lomuto partition**：
遍历数组，将小于 pivot 的元素交换到左端，最后将 pivot 放到中间位置。

### 代码实现

见 `demos/ch04/demo_sorting.py` — `bubble_sort()` 和 `quick_sort()`。

```python
def quick_sort(arr, low, high):
    if low < high:
        pi = partition(arr, low, high)  # 切分
        quick_sort(arr, low, pi - 1)    # 排序左半
        quick_sort(arr, pi + 1, high)   # 排序右半

def partition(arr, low, high):
    pivot = arr[high]   # 选最后一个元素为 pivot
    i = low - 1         # i 指向"小于区域的末尾"
    for j in range(low, high):
        if arr[j] <= pivot:
            i += 1
            arr[i], arr[j] = arr[j], arr[i]
    arr[i + 1], arr[high] = arr[high], arr[i + 1]
    return i + 1
```

### 使用场景

- **冒泡排序**：几乎只用于教学和非常小的数据集（n < 50）
- **快速排序**：通用排序的首选之一，各大语言标准库的默认实现

### 潜在风险

- 快速排序的递归实现可能导致栈溢出（可用迭代或尾递归优化）
- 快速排序是不稳定的——如果必须稳定，请用归并排序

### 优化策略

- **小数组切换**：当子数组长度 < 10-20 时，切换到插入排序
- **三路切分**：处理大量重复元素（见 `demos/ch04/demo_sorting.py` 中的 `quick_sort_3way`）

## 4.3 插入排序（直接插入、希尔排序）

### 解决的问题

插入排序类算法的核心思想是：将待排序的元素逐个插入到已排序序列的正确位置。对于几乎有序的数据，插入排序极其高效。

### 实现原理

#### 直接插入排序 (Insertion Sort)

**原理**：将数组视为"已排序部分"和"未排序部分"。每次从未排序部分取第一个元素，在已排序部分中找到它的正确位置并插入。

```
[5 | 3, 8, 6, 4]    ← | 左侧为已排序
  ↓ 插入 3
[3, 5 | 8, 6, 4]    ← 3 插入到 5 之前
     ↓ 插入 8
[3, 5, 8 | 6, 4]    ← 8 已经在正确位置
        ↓ 插入 6
[3, 5, 6, 8 | 4]    ← 6 插入到 5 和 8 之间
           ↓ 插入 4
[3, 4, 5, 6, 8]
```

**复杂度**：最好 O(n)（已排序），最坏/平均 O(n²)。但在"几乎有序"的数据上，插入排序的实际运行时间接近 O(n)，因为大多数元素只需比较很少几次就能找到正确位置。

#### 希尔排序 (Shell Sort)

希尔排序是插入排序的改进版。它通过"间隔"（gap）将原数组分成若干子序列，对每个子序列进行插入排序，然后逐步缩小 gap 直到 1。

```
初始数组: [9, 8, 3, 7, 5, 6, 4, 1]
gap=4: 分成 4 组 → 分别插入排序
  组1: [9, 5] → [5, 9]
  组2: [8, 6] → [6, 8]
  组3: [3, 4] → [3, 4]
  组4: [7, 1] → [1, 7]
  结果: [5, 6, 3, 1, 9, 8, 4, 7]

gap=2: 分成 2 组 → 分别插入排序
  组1: [5, 3, 9, 4] → [3, 4, 5, 9]
  组2: [6, 1, 8, 7] → [1, 6, 7, 8]
  结果: [3, 1, 4, 6, 5, 7, 9, 8]

gap=1: 对整个数组做插入排序
  结果: [1, 3, 4, 5, 6, 7, 8, 9]
```

**Gap 序列对比**：

| Gap 序列 | 示例 | 平均复杂度 |
|---------|------|-----------|
| Shell 原始 | n/2, n/4, ..., 1 | O(n²) |
| Hibbard | 2^k - 1 | O(n^(3/2)) |
| Sedgewick | 4^k + 3·2^(k-1) + 1 | O(n^(4/3)) |
| Knuth | (3^k - 1)/2 | O(n^(3/2)) |

### 代码实现

见 `demos/ch04/demo_sorting.py` — `insertion_sort()` 和 `shell_sort()`。

### 使用场景

- **插入排序**：小规模数据（n < 50）、几乎有序的数据、作为 TimSort 的组件
- **希尔排序**：中等规模数据（n < 5000）、嵌入式系统（代码量少，不需要额外空间）

### 潜在风险

- 插入排序的 O(n²) 在大规模数据上不可接受
- 希尔排序的 gap 选择对性能影响巨大，不合适的 gap 序列可能退化到 O(n²)

### 优化策略

- **二分插入**：使用二分查找确定插入位置，将比较次数从 O(n) 降到 O(log n)（但移动次数仍为 O(n)）
- **希尔排序的 gap 序列**：优先选择 Sedgewick 或 Knuth 序列

## 4.4 选择排序（简单选择、堆排序）

### 解决的问题

选择排序类的核心思想是：每轮从未排序部分选出最小（或最大）元素，放到已排序部分的末尾。"选择"的思路非常直观。

### 实现原理

#### 简单选择排序 (Selection Sort)

**原理**：每轮遍历找到未排序部分的最小值，与未排序部分的第一个元素交换。

```
初始: [5, 3, 8, 6, 4]

第1轮：从 [5, 3, 8, 6, 4] 选最小 3 → 与 5 交换 → [3, 5, 8, 6, 4]
第2轮：从 [5, 8, 6, 4] 选最小 4 → 与 5 交换 → [3, 4, 8, 6, 5]
第3轮：从 [8, 6, 5] 选最小 5 → 与 8 交换 → [3, 4, 5, 6, 8]
第4轮：从 [6, 8] 选最小 6 → 已在位     → [3, 4, 5, 6, 8]
```

**复杂度**：O(n²) — 无论数据是否有序，每轮都必须遍历全部未排序部分找到最小值。

**不稳定性举例**：`[5a, 5b, 3]` — 第 1 轮选 3，与 5a 交换 → `[3, 5b, 5a]`，两个 5 的相对顺序变了。

#### 堆排序 (Heap Sort)

堆排序利用**最大堆**（Max Heap）数据结构。最大堆是一棵完全二叉树，每个节点的值 ≥ 其子节点的值。

```
构建最大堆（以数组 [3, 5, 8, 6, 4] 为例）:
  初始数组:  [3, 5, 8, 6, 4]
            3
          /   \
         5     8
        / \
       6   4

  堆化（heapify）后:
            8
          /   \
         6     5
        / \
       3   4
  数组表示: [8, 6, 5, 3, 4]

排序阶段（反复取出堆顶）:
  取 8 → 放末尾 → 堆调整为 [6, 4, 5, 3 | 8]
  取 6 → 放末尾 → 堆调整为 [5, 4, 3 | 6, 8]
  取 5 → 放末尾 → 堆调整为 [4, 3 | 5, 6, 8]
  取 4 → 放末尾 → 堆调整为 [3 | 4, 5, 6, 8]
  取 3 → 完成     → [3, 4, 5, 6, 8]
```

**复杂度**：建堆 O(n)，每次取堆顶 O(log n)，共 O(n log n)。最坏情况也是 O(n log n)，这是堆排序相比快速排序最大的优势——没有退化风险。

### 代码实现

见 `demos/ch04/demo_sorting.py` — `selection_sort()` 和 `heap_sort()`。

### 使用场景

- **选择排序**：仅用于教学，实际中几乎不用
- **堆排序**：需要 O(n log n) 最坏时间且不能使用额外空间的场景（如嵌入式系统）

### 潜在风险

- 堆排序不稳定，且常数因子比快速排序大，实际中通常比快速排序慢
- 堆排序的局部性较差（cache-unfriendly），因为它跳着访问数组元素

### 优化策略

- **堆排序 vs 快速排序**：当内存紧张（不允许 O(n) 空间）且不能接受 O(n²) 退化时，堆排序是安全的选择
- **混合使用**：Python 的 `heapq` 模块中的 `nsmallest` / `nlargest` 使用堆来选择 Top-K 元素

## 4.5 归并排序与分布式排序

### 解决的问题

当数据量大到无法全部载入内存（比如对 100 GB 的日志文件排序），或者你需要一个稳定的 O(n log n) 排序时，归并排序是理想选择。

### 实现原理

#### 归并排序 (Merge Sort)

归并排序采用经典的分治（Divide and Conquer）策略：

```
                        [5, 3, 8, 6, 4, 1, 9, 2]
                           /                \
                    [5, 3, 8, 6]          [4, 1, 9, 2]
                     /        \             /        \
                 [5, 3]      [8, 6]      [4, 1]     [9, 2]
                  /   \       /   \       /   \       /   \
                [5]   [3]   [8]   [6]   [4]   [1]   [9]   [2]   ← 分到单元素
                  \   /       \   /       \   /       \   /
                 [3, 5]      [6, 8]      [1, 4]      [2, 9]    ← 合并排序
                     \         /             \         /
                    [3, 5, 6, 8]           [1, 2, 4, 9]
                        \                      /
                     [1, 2, 3, 4, 5, 6, 8, 9]               ← 最终合并
```

**合并 (Merge)** 操作（关键步骤）：
同时遍历两个已排序子数组，每次取较小的元素放入结果数组。

```python
def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    # 收尾
    result.extend(left[i:])
    result.extend(right[j:])
    return result
```

**复杂度**：O(n log n) 时间，O(n) 空间（需要额外数组存储合并结果）。

**稳定性**：稳定——当 left[i] == right[j] 时，取左子数组的元素，保持了原始顺序。

#### 外部排序 (External Sorting)

当数据量 > 内存容量时，需要使用外部排序：

```
阶段1 — 分割与排序（产生归并段/runs）:
  100 GB 数据 → 分成 100 个 1 GB 的块 → 每块在内存中排序后写回磁盘

阶段2 — 多路归并:
  打开 100 个有序文件的句柄 → 使用最小堆（败者树）选择当前最小值 → 写入输出文件
```

**复杂度**：排序阶段 O(n log n)，归并阶段 I/O 次数 = O(log_k (n/M)) 其中 k 是归并路数，M 是内存大小。

### 代码实现

见 `demos/ch04/demo_sorting.py` — `merge_sort()`。

### 使用场景

- **通用排序**：需要稳定排序时的首选
- **外部排序**：处理无法载入内存的大规模数据
- **多路归并**：数据库的排序归并连接（Sort-Merge Join）

### 潜在风险

- O(n) 的额外空间在内存受限时是致命缺陷
- 递归实现的归并排序同样有栈溢出风险

### 优化策略

- **小数组切换**：当子数组长度 < 32 时使用插入排序（TimSort 的核心优化）
- **原地归并**：有 O(n log n) 时间的原地归并算法，但常数很大，实际中不常用
- **自底向上 (Bottom-up)**：用迭代替代递归，消除栈空间消耗

## 4.6 线性排序（计数、桶、基数）

### 解决的问题

比较排序的下界是 Ω(n log n)。但如果我们知道数据的特殊性质（比如数据是整数，范围有限，或者符合某种分布），就可以突破这个下界，达到 O(n) 时间。这就是**线性排序**的价值所在。

### 实现原理

#### 计数排序 (Counting Sort)

**原理**：统计每个值出现的次数，然后根据计数重建有序序列。

```
数组 [4, 2, 2, 8, 3, 3, 1]，元素范围 1-8

1. 计数：
  值:    1  2  3  4  5  6  7  8
  计数: [1, 2, 2, 1, 0, 0, 0, 1]

2. 累加（确定每个元素的位置）：
  累加: [1, 3, 5, 6, 6, 6, 6, 7]

3. 从后往前遍历原数组，根据累加计数将元素放到输出数组中
  最终输出: [1, 2, 2, 3, 3, 4, 8]
```

**复杂度**：O(n + k)，其中 k 是数据范围。当 k = O(n) 时，即 O(n)。

**限制**：只能用于整数或可以映射为整数的数据，且 k 不能太大（否则空间浪费严重）。

#### 桶排序 (Bucket Sort)

**原理**：将数据均匀分到若干"桶"中，对每个桶内部排序，然后按桶顺序合并。

```
数组 [0.42, 0.32, 0.78, 0.12, 0.94, 0.53, 0.21, 0.67]
                                    ↓
分成 4 个桶（范围 0-0.25, 0.25-0.5, 0.5-0.75, 0.75-1.0）:
  桶0 [0.12, 0.21]
  桶1 [0.42, 0.32]
  桶2 [0.78, 0.53, 0.67]
  桶3 [0.94]
                                    ↓
每个桶内排序（可用插入排序或其他）：
  桶0 [0.12, 0.21]
  桶1 [0.32, 0.42]
  桶2 [0.53, 0.67, 0.78]
  桶3 [0.94]
                                    ↓
按桶顺序连接:
[0.12, 0.21, 0.32, 0.42, 0.53, 0.67, 0.78, 0.94]
```

**复杂度**：平均 O(n + k)，最坏 O(n²)（所有元素落入同一个桶时退化为内部排序的复杂度）。

**关键**：输入数据需要**均匀分布**，否则桶的分配不平衡。

#### 基数排序 (Radix Sort)

**原理**：按位排序——从最低有效位（LSD）到最高有效位，依次对每一位进行稳定排序（通常使用计数排序作为子程序）。

```
数组 [329, 457, 657, 839, 436, 720, 355]

按个位排序（使用稳定的计数排序）:
  [720, 329, 436, 839, 355, 457, 657]
按十位排序:
  [720, 329, 436, 839, 355, 457, 657]  →  [329, 720, 436, 839, 355, 457, 657]
按百位排序:
  [329, 355, 436, 457, 657, 720, 839]  →  有序！
```

**复杂度**：O(d·(n + k))，其中 d 是位数，k 是基数（如 10 进制为 10，2 进制为 2）。当 d 是常数且 k = O(n) 时，整体为 O(n)。

### 代码实现

见 `demos/ch04/demo_sorting.py` — `counting_sort()`、`bucket_sort()`、`radix_sort()`。

### 使用场景

| 算法 | 适用场景 | 典型示例 |
|------|---------|---------|
| 计数排序 | 整数范围有限（如成绩、年龄） | 考试分数排序 |
| 桶排序 | 数据均匀分布 | 浮点数[0,1) 排序 |
| 基数排序 | 定长整数或字符串 | 电话号码、学号排序 |

### 潜在风险

- 计数排序：k 远大于 n 时空间浪费巨大，甚至不可用
- 桶排序：数据分布不均匀时退化严重
- 基数排序：对负数和浮点数需要额外处理

### 优化策略

- **MSD 基数排序**：从最高位开始，可用于字符串排序
- **混合基数排序**：位数多时，当前几位分出很少元素后就切换到插入排序
- 在处理负整数时，可以将所有数加上偏移量转为非负

## 4.7 典型排序源码解析：Python TimSort

### 解决的问题

Python 的内置排序 `list.sort()` 和 `sorted()` 使用一种叫做 **TimSort** 的混合排序算法（以创造者 Tim Peters 命名）。TimSort 的核心思路是：**归并排序保证 O(n log n) 最坏时间，插入排序处理小数组和"几乎有序"的数据**。TimSort 在真实世界的数据（往往含有天然的"有序片段"——runs）上表现极其优异。

### 实现原理

TimSort 的工作流程：

```
1. 识别天然有序段 (runs)：
   [3, 5, 8 | 6, 4, 1, 2, 7 | 9]
    ↑ 升序run      ↑ 降序run(反转)    ↑ 升序run

2. 如果 run 长度 < min_run（通常 32-64），则用插入排序扩展：

3. 维护 run 栈，当栈顶两个 run 的长度比例 > 某个阈值时，合并它们：

4. 使用 Galloping Mode（飞奔模式）优化合并：
   ┌─────────────────────────────────────┐
   │ 普通合并                           │
   │ left: [1, 3, 4, 5, 7]             │
   │ right: [2, 6, 8, 9]               │
   │ 比较: 1vs2 → 取1                  │
   │       3vs2 → 取2                  │
   │       3vs6 → 取3                  │
   │       4vs6 → 取4                  │
   │       5vs6 → 取5                  │
   │       ...一个一个比                │
   └─────────────────────────────────────┘

   ┌─────────────────────────────────────┐
   │ Galloping Mode                     │
   │ 连续从 left 取了 4 个 → 猜 right    │
   │ 还有更大的 → 用二分查找一次找  │
   │ 到 right 中应插入的位置，批量复制  │
   └─────────────────────────────────────┘
```

**关键数据结构**：

| 组件 | 作用 |
|------|------|
| **run** | 天然有序的连续子序列 |
| **min_run** | 最小 run 长度（32-64），太短的 run 用插入排序扩充 |
| **run stack** | 存储待合并的 runs，合并条件控制平衡性 |
| **gallop** | 当一方连续胜出时，加速合并过程 |

**时间复杂度**：最好 O(n)（已排序或逆序），平均/最坏 O(n log n)。

**空间复杂度**：O(n) 临时空间（但比归并排序节省了一些常数因子）。

**稳定性**：稳定。

### 代码实现

见 `demos/ch04/demo_timsort.py` — 简化版 TimSort 实现。

### 使用场景

- **所有 Python 排序**：`list.sort()` 和 `sorted()` 都使用 TimSort
- **Java 的 Arrays.sort(Object[])**：JDK 7+ 也使用 TimSort（称为 ComparableTimSort）
- **Android、Apache Harmony**：也采用了 TimSort

### 潜在风险

- TimSort 的实现相当复杂（约 1000 行 C 代码），有潜在的 bug 风险（2015 年曾发现一个整数溢出 bug）
- Galloping Mode 在某些极端数据上反而会变慢

### 优化策略

- **动态 min_run**：根据数组长度动态计算合适的 min_run
- **合并阈值**：严格的栈不变式（`len(stack[-3]) > len(stack[-2]) + len(stack[-1])` 且 `len(stack[-2]) > len(stack[-1])`）保证合并效率

## 4.8 排序算法选择策略

### 解决的问题

面对一个具体的排序任务，有十几种算法可用。如何根据**数据特征**和**需求约束**快速做出最优选择？本节提供一个系统的决策框架。

### 实现原理

#### 决策树

以下决策树帮助你在实际场景中选择合适的排序算法：

```
输入数据
  │
  ├─ 数据量非常大（> 内存容量）？
  │   └──→ 外部归并排序
  │
  ├─ 数据是整数且范围有限（k ≤ 10·n）？
  │   └──→ 计数排序
  │
  ├─ 数据是浮点数且在 [0,1) 内均匀分布？
  │   └──→ 桶排序
  │
  ├─ 数据是定长整数或短字符串？
  │   └──→ 基数排序
  │
  ├─ 需要稳定排序？
  │   ├─ 数据几乎有序？
  │   │   └──→ 插入排序（或 TimSort）
  │   └─ 不关心数据分布？
  │       └──→ 归并排序（或 TimSort）
  │
  ├─ 内存极度受限（不能 O(n) 额外空间）？
  │   ├─ 可以接受偶尔 O(n²)？
  │   │   └──→ 快速排序（三数取中 pivot）
  │   └─ 必须保证 O(n log n)？
  │       └──→ 堆排序
  │
  └─ 默认选择？
      └──→ TimSort（Python）/ Dual-Pivot QuickSort（Java）
```

#### 按场景速查

| 场景 | 推荐算法 | 理由 |
|------|---------|------|
| 排序 10 个元素 | 插入排序 | 代码简单，小数据上常数极小 |
| 排序 10⁶ 个随机整数 | 快速排序 | O(n log n) 平均时间，常数小 |
| 排序 10⁶ 个[0,100]的整数 | 计数排序 | O(n)，线性时间 |
| 排序 10⁹ 个整数（内存不够） | 外部归并排序 | 将数据分块排序后再归并 |
| 排序几乎有序的数据 | 插入排序 / TimSort | 接近 O(n) |
| 排序包含大量重复值的数据 | 三路快排 / 计数排序 | 三路切分大幅减少比较次数 |
| 需要稳定排序 | 归并排序 / TimSort | 稳定且高效 |
| 嵌入式低内存环境 | 堆排序 | O(1) 空间，稳定 O(n log n) 时间 |

#### 综合排序排行榜

在**没有特殊约束**的通用场景下，以下排序算法的工程实用性排序：

```
第 1 梯队（实际使用）:
  TimSort           — Python/Java 内置，真实数据表现最佳
  快速排序(三路)     — C/C++ 标准库，常数最小
  归并排序          — 稳定性的不二之选

第 2 梯队（特定场景）:
  基数排序          — 整数/定长字符串
  计数排序          — 范围有限的整数
  桶排序            — 均匀分布的浮点数
  堆排序            — 安全但慢（常数大）

第 3 梯队（理论价值 > 实用价值）:
  希尔排序          — 简单但不如 TimSort
  冒泡排序          — 教学用途
  选择排序          — 教学用途
```

### 使用场景

- **面试**：快速排序和归并排序是最高频考点
- **工程**：能使用内置排序（`list.sort()`）就不要自己写
- **竞赛**：通常用 C++ 的 `std::sort()` 或自己实现快速排序

### 潜在风险

- **过早优化**：对于 n < 10⁴ 的数据，任何 O(n log n) 排序的性能差异都在毫秒级
- **忽略常数**：堆排序 O(n log n) 在 n=10⁶ 时通常比快速排序慢 2-3 倍
- **稳定性陷阱**：多关键字排序中不稳定排序会导致看似正确的结果

### 优化策略

1. **用内置排序**：Python 的 `list.sort()` 已实现高度优化，除非你有特殊需求（如线性排序），否则用它
2. **预处理**：了解数据的分布特性（范围？是否几乎有序？是否有大量重复值？）——这是选择算法的最重要信息
3. **混合策略**：不要只用一种排序——Python 的 TimSort 和 Java 的 Dual-Pivot QuickSort 都是混合算法，这是一个重要的设计模式
4. **验证**：任何排序实现，务必测试边界情况（空数组、单元素、已排序、逆序、全部相等）
