## 第七篇：开发者核心素养与必备技能图谱（🌟 核心新增）
*本篇跳出语法层面，系统梳理高级开发人员在真实企业级项目中必须掌握的 TS 相关工程技能。*

### 第22章 技能一：类型驱动的 API 设计能力 (Type-Driven Design)
* **22.1 调用者体验优先**：如何写出对调用者友好的类型？（利用函数签名自动推导，避免让调用者手动传入复杂的泛型参数）。
* **22.2 防御性 API 设计**：利用 `readonly`、`Omit` 和私有品牌类型（Branded Types），限制外部对内部状态的非法篡改。
* **22.3 避免“类型体操”滥用**：区分“必要的类型抽象”与“炫技”。（原则：如果一个类型推导需要超过 3 层 `infer` 且严重影响 IDE 性能，请果断放弃，改用显式声明）。

### 第23章 技能二：跨越静态与运行时的鸿沟（边界防御技能）
* **23.1 核心认知**：深刻理解“TS 类型在边界处（网络请求、用户输入、Localstorage）一定会失效”。
* **23.2 必备工具链**：熟练掌握 **Zod / Valibot / TypeBox** 等运行时校验库。
* **23.3 实战技能**：编写一次 Schema，同时生成 TS 静态类型（`z.infer`）与运行时校验逻辑；在 API 网关层强制校验外部数据，将“运行时的 `undefined` 灾难”转化为“可控的业务异常”。

### 第24章 技能三：IDE 高级调试与类型探查技能
* **24.1 悬停与跳转**：熟练使用 VSCode 的“悬停（Hover）”查看推断类型，使用“转到类型定义”追踪第三方库源码。
* **24.2 类型沙盒隔离**：使用 TS 官方提供的 [TypeScript Playground](https://www.typescriptlang.org/play) 隔离并复现复杂的类型推导问题，方便向社区提问。
* **24.3 辅助工具**：使用 `tsd` 或 `expect-type` 进行**类型级测试（Type-Level Testing）**，确保重构后复杂的工具类型推导依然正确。

### 第25章 技能四：大型项目 TS 编译性能监控与调优
* **25.1 识别性能瓶颈**：当 IDE 代码提示变慢、保存时类型检查卡顿时，如何定位问题？
* **25.2 调优手段**：
  * 减少深层交叉类型（`&`）与复杂的递归条件类型。
  * 合理使用 `interface` 替代 `type` 以利用编译器的对象缓存机制。
  * 配置 `tsconfig.json` 中的 `incremental` 和 `composite` 开启增量编译。
* **25.3 监控体系**：在 CI/CD 流水线中集成 `tsc --diagnostics`，监控每次提交的类型检查耗时，防止“类型污染”拖慢整个团队的开发效率。

### 第26章 技能五：平滑迁移与渐进式重构技能
* **26.1 遗留项目改造**：如何在不中断业务的情况下，将几十万行的 JS 项目逐步迁移到 TS？
* **26.2 迁移策略**：
  * 开启 `allowJs` 和 `checkJs`。
  * 从边缘工具函数开始，逐步向核心业务逻辑推进。
  * 巧用 `// @ts-expect-error` 标记未处理的类型错误，并定期清理技术债。

### 💡 本手册特色设计说明：

1. **“比喻式”教学（浅出）**：
   * 讲**泛型**时，用“月饼模具（泛型）与月饼（具体类型）”来比喻。
   * 讲**联合类型收窄**时，用“安检门（类型守卫）”来比喻 TS 如何在运行时排除错误选项。
2. **“对比式”排坑（深入）**：
   * 每一章都有 **“Bad Code vs Good Code”** 对比，不仅告诉你怎么写，更告诉你**为什么不能那么写**（例如：为什么 `interface` 继承比 `type` 交叉在编译性能上更好）。
3. **“全栈化”视野（完全）**：
   * 打破“TS 只是前端语言”的偏见，专门开辟 **Node.js 后端、ORM、tRPC 全栈共享** 章节，契合现代全栈工程师的需求。
4. **“工程化”闭环（必备技能）**：
   * 新增的**第七篇**是本书的灵魂升华。它补齐了大多数 TS 教程缺失的“工程落地”环节，教导开发者如何设计好用的 API、如何防御运行时边界数据、如何监控编译性能，真正将 TS 转化为团队的生产力工具。
