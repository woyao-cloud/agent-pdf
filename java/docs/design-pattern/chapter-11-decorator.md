# 第11章 装饰器模式（Decorator）
+**装饰器模式**动态地给一个对象添加额外的职责，比生成子类更灵活。它是一种结构型设计模式，用于在不修改原有类的情况下增强功能。
+## 11.1 解决的问题与应用场景
+### 11.1.1 问题分析
+在软件系统中，经常需要给对象添加额外的功能：```java
+// 假设有一个基础咖啡类Coffee// 需求：+// - 加牛奶 -> 牛奶咖啡+// - 加糖 -> 加糖咖啡+// - 加牛奶和糖 -> 牛奶糖咖啡+// - 加奶油 -> 奶油咖啡+// - ...+// 问题：如果用继承实现// class MilkCoffee extends Coffee { }// class SugarCoffee extends Coffee { }// class MilkSugarCoffee extends Coffee { }// class MilkCreamCoffee extends Coffee { }// class MilkSugarCreamCoffee extends Coffee { }+// 类数量爆炸！并且咖啡和配料可以任意组合```+### 11.1.2 典型应用场景
++**1. IO流（Java经典应用）**```java+FileInputStream fis = new FileInputStream("file.txt");BufferedInputStream bis = new BufferedInputStream(fis);DataInputStream dis = new DataInputStream(bis);```++**2. 图形界面增强**```java+Component button = new Button();Component bordered = new BorderDecorator(button);Component clickable = new ClickDecorator(bordered);```++**3. 缓存装饰**```java+DataSource realDataSource = new DatabaseDataSource();DataSource cachedDataSource = new CacheDecorator(realDataSource);```++**4. 日志增强**```java+Logger logger = new ConsoleLogger();Logger timed = new TimedLogger(logger);Logger logged = new FileLogger(timed);```+## 11.2 实现原理与UML
+### 11.2.1 核心思想
+装饰器模式的核心是**包装一个对象，在不改变其接口的前提下，增强其功能**。装饰器与原对象实现相同的接口，可以在方法调用前后添加额外的逻辑。+### 11.2.2 UML类图+```┌─────────────────────┐        ┌─────────────────────┐│       Client       │        │     Component      ││                     │        │    (抽象组件)       │├─────────────────────┤        ├─────────────────────┤│                     │        │ + operation()      │└─────────────────────┘        └──────────┬──────────┘                                    │                                    │                         ┌──────────┴──────────┐                         │                     │                         ▼                     ▼              ┌─────────────────┐   ┌─────────────────────┐              │ConcreteComponent│   │    Decorator      │              │   (具体组件)     │   │    (装饰器)       │              ├─────────────────┤   ├─────────────────────┤              │ + operation()   │   │ - component      │──────►        └─────────────────┘   │ + operation()   │                         └──────────┬──────────┘                                    │                         ┌────────────┴────────────┐                         ▼                         ┌─────────────────────────┐                         │   ConcreteDecorator    │                         │    (具体装饰器)         │                         ├─────────────────────────┤                         │ + operation()          │                         └─────────────────────────┘```++### 11.2.3 角色分析+- **Component（抽象组件）**：定义一个对象接口，可以给这些对象动态地添加职责- **ConcreteComponent（具体组件）**：定义一个具体的组件对象，可以给这个对象添加职责- **Decorator（装饰器）**：维持一个Component对象的引用，并定义一个与Component接口一致的接口- **ConcreteDecorator（具体装饰器）**：负责给组件对象添加额外的职责+### 11.2.4 时序图+```Client           Component        Decorator      ConcreteDecorator   ConcreteComponent
   │                 │                │                  │                  │   │ operation()      │                │                  │                  │   │ ───────────────►│                │                  │                  │   │                 │                │                  │                  │   │                 │  operation()    │                  │                  │   │                 │ ───────────────►│                  │                  │   │                 │                │                  │                  │   │                 │                │  operation()     │                  │   │                 │                │ ─────────────────►│                  │   │                 │                │                  │  (添加额外逻辑)   │   │                 │                │                  │                  │   │                 │                │    result         │                  │   │                 │                │ ◄─────────────────│                  │   │                 │                │                  │   │                 │   result         │                  │   │                 │ ◄─────────────────│                  │   │                 │                  │                  │   │  result         │                  │                  │   │ ◄───────────────│                  │                  │   │```++## 11.3 代码实现
+### 11.3.1 基础实现（咖啡系统）++**抽象组件 - 饮料**```java+public abstract class Beverage {    protected String description = "未知饮料";        public String getDescription() {        return description;    }        public abstract double cost();}```++**具体组件 - 咖啡**```java+public class Coffee extends Beverage {    public Coffee() {        this.description = "咖啡";    }        @Override    public double cost() {        return 10.0;  // 基础咖啡10元    }}```++**抽象装饰器**```java+public abstract class CondimentDecorator extends Beverage {    // 持有被装饰对象的引用    protected Beverage beverage;    }        @Override    public String getDescription() {        return beverage.getDescription() + ", 牛奶";    }        @Override    public double cost() {        return beverage.cost() + 3.0;  // 牛奶3元    }}```++**具体装饰器 - 糖**```java+public class Sugar extends CondimentDecorator {    public Sugar(Beverage beverage) {        super(beverage);    }        @Override    public String getDescription() {        return beverage.getDescription() + ", 糖";    }        @Override    public double cost() {        return beverage.cost() + 1.5;  // 糖1.5元    }}```++**具体装饰器 - 奶油**```java+public class Cream extends CondimentDecorator {    public Cream(Beverage beverage) {        super(beverage);    }        @Override    public String getDescription() {        return beverage.getDescription() + ", 奶油";    }        @Override    public double cost() {        return beverage.cost() + 5.0;  // 奶油5元    }}```++**使用**```java+public class Main {    public static void main(String[] args) {        // 基础咖啡        Beverage coffee = new Coffee();        System.ou t. println(coffee.getDescription() + " = " + coffee.cost());        // 输出: 咖啡 = 10.0+        // 加牛奶        Beverage milkCoffee = new Milk(new Coffee());        System.ou t. println(milkCoffee.getDescription() + " = " + milkCoffee.cost());        // 输出: 咖啡, 牛奶 = 13.0+        // 加牛奶和糖        Beverage sweetMilkCoffee = new Sugar(new Milk(new Coffee()));        System.ou t. println(sweetMilkCoffee.getDescription() + " = " + sweetMilkCoffee.cost());        // 输出: 咖啡, 牛奶, 糖 = 14.5+        // 任意组合        Beverage fancyCoffee = new Cream(new Sugar(new Milk(new Coffee())));        System.ou t. println(fancyCoffee.getDescription() + " = " + fancyCoffee.cost());    void write(String key, String value);}++// 真实数据源+public class FileDataSource implements DataSource {    private String filename;        public FileDataSource(String filename) {        this.filename = filename;    }        @Override    public String read(String key) {        System.ou t. println("从文件读取: " + key);        return "file data";  // 简化    }        @Override    public void write(String key, String value) {        System.ou t. println("写入文件: " + key + " = " + value);    }}++// 缓存装饰器+public class CacheDecorator implements DataSource {    private DataSource source;    private Map<String, String> cache = new HashMap<>();    private Map<String, Long> timestamps = new HashMap<>();    private long expiration;        public CacheDecorator(DataSource source, long expiration) {        this.source = source;        this.expiration = expiration;    }        @Override    public String read(String key) {        if (isExpired(key)) {            cache.remove(key);            timestamps.remove(key);        }        return cache.computeIfAbsent(key, k -> source.read(k));    }        @Override    public void write(String key, String value) {        source.write(key, value);        cache.put(key, value);        timestamps.put(key, System.currentTimeMillis());    }        private boolean isExpired(String key) {        Long ts = timestamps.get(key);        return ts == null || (System.currentTimeMillis() - ts) > expiration;    }}++// 日志装饰器+public class LoggingDecorator implements DataSource {    private DataSource source;        public LoggingDecorator(DataSource source) {        this.source = source;    }        @Override    public String read(String key) {        System.ou t. println("[READ] " + key);        String result = source.read(key);        System.ou t. println("[READ] Result: " + result);        return result;    }        @Override       public void write(String key, String value) {        System.ou t. println("[WRITE] " + key + " = " + value);        source.write(key, value);    }}++// 使用+public class Main {    public static void main(String[] args) {        DataSource source = new FileDataSource("data.txt");+        // 添加缓存和日志装饰        DataSource cached = new CacheDecorator(source, 60000);  // 60秒过期+        DataSource logged = new LoggingDecorator(cached);+        // 读取数据        String data = logged.read("user:1");  // 有缓存        data = logged.read("user:1");  // 无缓存    }}```+### 11.3.4 加密装饰器+```java+// 加密装饰器+public class EncryptionDecorator implements DataSource {    private DataSource source;        public EncryptionDecorator(DataSource source) {        this.source = source;    }        @Override    public String read(String key) {        String encrypted = source.read(key);        return decrypt(encrypted);    }        @Override    public void write(String key, String value) {        String encrypted = encrypt(value);        source.write(key, encrypted);    }        private String encrypt(String data) {        // 简化加密        return "ENC(" + data + ")";    }        private String decrypt(String data) {        // 简化解密        if (data.startsWith("ENC(") && data.endsWith(")")) {            return data.substring(4, data.length() - 1);        }        return data;    }}```+## 11.4 JDK/框架源码解析

+### 11.6.1 装饰器顺序敏感+装饰器的顺序会影响最终结果：```java+// 加糖再加热 = 12元+Beverage a = new Sugar(new Coffee());+// 加热再加糖 = 12元（但描述不同）+Beverage b = new Sugar(new Coffee());+// 但对于某些装饰器，顺序可能影响行为+// 比如加密后压缩 vs 压缩后加密```+### 11.6.2 对象识别困难+使用装饰器后，对象的确切类型变得复杂：```java+Beverage coffee = new Milk(new Sugar(new Coffee()));+// coffee instanceof Milk -> true+// coffee instanceof Sugar -> false（装饰器包装后无法直接判断）+// coffee.getDescription() -> "咖啡, 糖, 牛奶"```+### 11.6.3 过度装饰+过度使用装饰器可能导致：- 代码可读性下降- 调试困难- 性能开销+**解决方案**：- 适可而止- 提供简化构造方法+### 11.6.4 与继承的区别+| 特征 | 继承 | 装饰器 | |------|------|--------| | 时机 | 编译时 | 运行时 | | 灵活性 | 低 | 高 | | 类数量 | 多（子类爆炸） | 少（可复用） | | 对象类型 | 固定 | 可动态改变 | | 组合 | 单一继承 | 任意组合 |+## 11.7 优化策略
