# 第14章 享元模式（Flyweight）
+**享元模式**运用共享技术有效地支持大量细粒度对象。它是一种结构型设计模式，通过共享对象来减少内存消耗。
+
+## 14.1 解决的问题与应用场景
+
+### 14.1.1 问题分析
+在软件系统中，经常需要创建大量相似的对象：+```java+// 例如：游戏中创建成千上万的子弹、敌人、小兵// 如果每个对象都占用独立内存，会导致内存爆炸// 1000个子弹对象 × 每个100字节 = 100KB// 10000个 = 1MB// 100000个 = 10MB
+// 加上其他对象，内存很快就耗尽了```++问题：+- 大量相似对象占用大量内存+- 创建对象耗时，性能下降+- 垃圾回收压力增大+### 14.1.2 典型应用场景++**1. 游戏开发**```java+// 子弹共享Image flyweight = BulletImage.get("normal_bullet");Bullet bullet1 = new Bullet(flyweight);Bullet bullet2 = new Bullet(flyweight);  // 复用图像```++**2. 文本编辑器**```java+// 字符享元Character a = CharacterFactory.get('a');Character a2 = CharacterFactory.get('a');// a 和 a2 是同一个对象！```++**3. 图形系统**```java+// 图形享元Shape circle = ShapeFactory.get("circle");// 相同的圆共享同一个Shape对象```++**4. 线程池、连接池**```java+// 连接池 - 共享数据库连接Connection pool = ConnectionPool.getInstance();Connection conn1 = pool.getConnection();Connection conn2 = pool.getConnection();```+## 14.2 实现原理与UML
+### 14.2.1 核心思想
+享元模式的核心是**将对象的状态分为内部状态和外部状态**：- **内部状态**：可以共享的部分，存储在享元对象内部- **外部状态**：不能共享的部分，由客户端在调用时传入++### 14.2.2 UML类图+```┌─────────────────────┐        ┌─────────────────────┐│      Client        │        │    FlyweightFactory││                     │        │    (享元工厂)       │├─────────────────────┤        ├─────────────────────┤│                     │        │ - flyweights       ││                     │        │ + getFlyweight()   │└─────────────────────┘        └──────────┬──────────┘                                   │                              │                         ▼+┌─────────────────────┐        ┌─────────────────────┐│   Flyweight        │        │   ConcreteFlyweight││   (抽象享元)        │        │    (具体享元)       │├─────────────────────┤        ├─────────────────────┤│ + operation(state) │        │ + operation(state) │└─────────────────────┘        └─────────────────────┘+           ▲                                   │                                   │           │                                   ▼+┌─────────────────────┐        ┌─────────────────────┐│    Unshared        │        │   Context          ││    ConcreteFlyweight│        │   (外部状态)        │├─────────────────────┤        ├─────────────────────┤│ + operation(state) │        │                    │└─────────────────────┘        └─────────────────────┘
```+++### 14.2.3 角色分析+- **Flyweight（抽象享元）**：定义享元对象的接口- **ConcreteFlyweight（具体享元）**：实现享元接口，存储内部状态- **UnsharedConcreteFlyweight（非共享具体享元）**：不能被共享的具体享元类- **FlyweightFactory（享元工厂）**：创建和管理享元对象- **Context（外部状态）**：存储在享元外部的状态信息+### 14.2.4 时序图+```Client          FlyweightFactory      Flyweight          Flyweight+   │                  │                    │                 │   │   getFlyweight() │                    │                 │   │ ──────────────► │                    │                 │   │                 │                    │                 │   │                 │  (查找或创建)      │                 │   │                 │                    │                 │   │                 │   flyweight       │                 │   │ ◄────────────── │                    │                 │   │                 │                    │                 │   │   operation(extrinsicState)                    │   │ ─────────────────────────────────────────────► │   │                  │                    │                 │   │                  │      result         │                 │   │ ◄─────────────────────────────────────────────│   │                  │                    │                 │```++## 14.3 代码实现

+### 14.6.1 线程安全问题++```java
+// 享元工厂必须是线程安全的public class UnsafeFactory {    private static Map<String, Flyweight> cache = new HashMap<>();        public static Flyweight get(String key) {        if (!cache.containsKey(key)) {            // 竞态条件！多个线程可能同时创建        }        return cache.get(key);    }}```++**解决方案**：使用ConcurrentHashMap++### 14.6.2 外部状态管理++外部状态的管理变得复杂：+- 需要在客户端维护外部状态+- 容易造成内存泄漏+- 调试困难+### 14.6.3 对象细粒度设计++不是所有对象都适合使用享元模式：+- 对象较大，状态较少：不值得共享+- 对象经常变化：共享反而复杂+- 维护开销大于节省的内存：不需要使用+### 14.6.4 享元 vs 单例+| 特性 | 享元模式 | 单例模式 | |------|----------|----------| | 数量 | 多个可共享 | 只有一个 | | 状态 | 有内部/外部状态 | 无状态 | | 目的 | 节省内存 | 唯一实例 |+## 14.7 优化策略
