# 第3章 算法思维模式

> "算法不是背出来的，是想出来的。" —— 掌握几种核心的算法思维模式，你就拥有了解决绝大多数算法问题的"武功招式"。

---

## 3.1 分治法（Divide and Conquer）

### 核心思想：分而治之

分治法的思想古已有之——"分而治之"本身就是一条著名的政治和军事策略。在算法领域，它的含义是：

> 将一个难以直接解决的大问题，**分割**成若干个规模更小但结构相同的子问题，**递归**地解决这些子问题，然后**合并**子问题的解得到原问题的解。

分治法包含三个步骤：

| 步骤 | 英文 | 说明 |
|------|------|------|
| **分解（Divide）** | Divide | 将原问题分解为若干个规模较小的子问题 |
| **解决（Conquer）** | Conquer | 递归地解决每个子问题。当子问题足够小时，直接求解 |
| **合并（Combine）** | Combine | 将子问题的解合并为原问题的解 |

### 经典案例一：归并排序（Merge Sort）

归并排序是分治法最经典的体现：

- **分解**：将长度为 `n` 的数组从中间分成两个长度各为 `n/2` 的子数组
- **解决**：递归地对两个子数组进行归并排序
- **合并**：将两个有序的子数组合并为一个有序数组

```
原始数组：[38, 27, 43, 3, 9, 82, 10]
            /                    \
     [38, 27, 43, 3]        [9, 82, 10]
      /         \            /        \
  [38, 27]   [43, 3]     [9, 82]    [10]
   /    \      /   \      /    \      |
 [38]  [27]  [43]  [3]  [9]  [82]   [10]
   \    /      \   /      \    /      |
  [27,38]    [3,43]     [9,82]     [10]
      \        /            \       /
    [3,27,38,43]          [9,10,82]
          \                  /
        [3,9,10,27,38,43,82]
```

**时间复杂度**：$O(n \log n)$
- 分解的层数：$\log n$（每次将规模减半）
- 合并每层：$O(n)$（需要遍历所有元素）
- 总计：$O(n \log n)$

### 经典案例二：快速排序（Quick Sort）

快速排序同样是分治法的代表：

- **分解**：选择一个基准（pivot），将数组分为两部分——左部分都小于基准，右部分都大于基准（称为 partition 操作）
- **解决**：递归地对左右两部分进行快速排序
- **合并**：无需合并操作（因为 partition 已经将元素放到了正确的位置上）

快速排序的平均时间复杂度也是 $O(n \log n)$，但最坏情况下会退化到 $O(n^2)$（当每次选择的基准都是最大或最小元素时）。

### 经典案例三：二分查找（Binary Search）

二分查找将分治法用在查找问题上：

- **分解**：将有序数组从中间分为左右两半
- **解决**：比较目标值与中间元素，如果相等则返回；如果目标值小于中间元素，在左半部分递归查找；否则在右半部分递归查找
- **合并**：无需合并，直接返回结果

**时间复杂度**：$O(\log n)$

### 进阶案例：计算数组中的逆序对

逆序对问题是分治法的一个非平凡应用。给定一个数组，如果 `i < j` 且 `arr[i] > arr[j]`，则 `(i, j)` 称为一个逆序对。问题是：计算数组中逆序对的总数。

暴力解法需要 $O(n^2)$ 的时间——枚举所有 `(i, j)` 对并检查是否逆序。

利用归并排序，我们可以在 $O(n \log n)$ 时间内解决：在合并两个有序子数组的过程中，每当从右半部分取一个元素时，左半部分剩余的所有元素都大于该元素，因此这些元素都与该元素构成逆序对。

```
左半部分：[1, 3, 5]   右半部分：[2, 4, 6]   合并中...
取左 1 → 不产生逆序
取左 3 → 不产生逆序
取右 2 → 左半部分的 [3, 5] 都与 2 构成逆序，计数 +2
取左 5 → 不产生逆序
取右 4 → 左半部分的 [5] 与 4 构成逆序，计数 +1
取右 6 → 不产生逆序
总计逆序对：3
```

## 3.2 贪心算法（Greedy）

### 核心思想：只看眼前

贪心算法的哲学很简单：

> 在每一步都做出当前看起来最优的选择，期望最终得到全局最优解。

贪心算法不回溯，不做全局规划，走一步看一步。这种策略虽然简单高效，但并不总能保证全局最优——它只适用于具有"贪心选择性"的问题。

### 贪心算法的要素

一个适合贪心算法的问题必须满足：

1. **贪心选择性质**：问题的全局最优解可以通过一系列局部最优的选择来达到
2. **最优子结构**：问题的最优解包含子问题的最优解

### 经典案例一：找零问题——用美元硬币

假设你有面值为 25、10、5、1 美分的硬币（美元硬币系统），要支付 63 美分，如何用最少的硬币？

贪心策略：每次都选面值最大的硬币。
```
63 → 选 25（剩余 38）→ 选 25（剩余 13）
   → 选 10（剩余 3）→ 选 1（剩余 2）→ 选 1（剩余 1）→ 选 1（剩余 0）
结果：25 + 25 + 10 + 1 + 1 + 1 = 6 枚硬币
```

在美元硬币系统中，贪心算法总能得到最优解（硬币面值相互成倍数关系）。

### 经典案例二：活动选择问题

假设你有多个活动，每个活动有开始时间和结束时间，你希望安排尽可能多的不冲突的活动。

```
活动：  |-----A1-----|
           |-----A2-----|
  |-----A3-----|
              |-----A4-----|
```

贪心策略：每次选择结束时间最早且与已选活动不冲突的活动。这个贪心策略能得到全局最优解。

### 贪心算法的局限性

贪心算法并不总是有效。考虑一个自定义面值的硬币系统：面值为 1、3、4，需要凑出 6。

- **贪心**：先选 4，再选 1，再选 1 → 3 枚硬币
- **最优**：3 + 3 → 2 枚硬币

这个反例说明：贪心算法虽然快，但需要问题本身具备贪心选择性才能保证正确。

## 3.3 动态规划（Dynamic Programming）

### 核心思想：记住过去，避免重复

动态规划（DP）与分治法类似，都是将大问题分解为子问题。但关键区别在于：动态规划处理的子问题之间存在**重叠**——同一个子问题会被多次求解。

> 动态规划通过"记住"子问题的解来避免重复计算，以空间换时间。

### 适用条件

1. **最优子结构**：问题的最优解包含子问题的最优解（与贪心相同）
2. **重叠子问题**：子问题会被重复求解，因此值得缓存结果（与分治不同）

### 分治法 vs 动态规划 vs 贪心

| 特征 | 分治法 | 动态规划 | 贪心算法 |
|------|--------|---------|---------|
| 子问题关系 | 相互独立 | 相互重叠 | 相互独立 |
| 决策方式 | 分解+合并 | 状态转移 | 局部最优 |
| 回溯 | 不需要 | 查表 | 不回溯 |
| 保证最优 | 是 | 是 | 否 |
| 典型应用 | 归并排序 | 背包问题 | 最小生成树 |

### 简单示例：斐波那契数列

斐波那契数列的定义：
- F(0) = 0, F(1) = 1
- F(n) = F(n-1) + F(n-2), n ≥ 2

**朴素递归**（指数级）：
```java
int fib(int n) {
    if (n <= 1) return n;
    return fib(n-1) + fib(n-2);
}
```
这个实现会反复计算相同的子问题——`fib(5)` 需要计算 `fib(4)` 和 `fib(3)`，而 `fib(4)` 又需要计算 `fib(3)` 和 `fib(2)`——`fib(3)` 被重复计算了两次。

**记忆化递归（自顶向下 DP）**：
```java
int fib(int n, int[] memo) {
    if (n <= 1) return n;
    if (memo[n] != 0) return memo[n];
    memo[n] = fib(n-1, memo) + fib(n-2, memo);
    return memo[n];
}
```

**递推（自底向上 DP）**：
```java
int fib(int n) {
    if (n <= 1) return n;
    int[] dp = new int[n+1];
    dp[0] = 0; dp[1] = 1;
    for (int i = 2; i <= n; i++)
        dp[i] = dp[i-1] + dp[i-2];
    return dp[n];
}
```

DP 将时间复杂度从 $O(2^n)$ 降到 $O(n)$，空间复杂度为 $O(n)$（还可以优化到 $O(1)$）。

## 3.4 回溯法（Backtracking）

### 核心思想：尝试-撤销-再尝试

回溯法是一种系统的**试错**方法：

> 逐步构建解，当发现当前选择不能通向有效解时，撤销该选择（回溯），尝试其他选择。

可以将回溯法的执行过程想象为深度优先遍历一棵"状态空间树"，在遍历过程中进行剪枝。

```
                根（空解）
              /    |    \
           选1    选2    选3
          /  \      \
       选2  选3    选1
        |     |
      选3   选2
```

回溯法的通用模板：

```java
void backtrack(当前状态) {
    if (当前状态是有效解) {
        记录解;
        return;
    }
    for (每个可选的选择) {
        做选择（更新状态）;
        backtrack(新状态);
        撤销选择（恢复状态）;
    }
}
```

### 经典案例：生成所有子集（幂集）

给定集合 `{1, 2, 3}`，生成所有子集：

```
{} → {1} → {1,2} → {1,2,3} → {1,3} → {2} → {2,3} → {3}
```

对于每个元素，回溯法面临两个选择：选或不选。因此状态空间树是一个二叉树，最终生成 $2^n$ 个叶子节点（所有子集）。

回溯法在组合数搜索问题中非常有用：子集、排列、组合、八皇后、数独、图的着色等。

## 3.5 分支限界法（Branch and Bound）

### 核心思想：剪掉不可能的分支

分支限界法与回溯法类似，都遍历状态空间树。但分支限界法比回溯法多了一个**界限（bound）** 的概念。

> 分支限界法在遍历过程中维护一个"当前最优解"，并为每个节点计算一个"乐观估计值"。如果某个节点的乐观估计值比当前最优解还差，就剪掉该分支——因为沿着这个分支走，不可能得到比当前更好的解。

### 回溯 vs 分支限界

| 方面 | 回溯法 | 分支限界法 |
|------|--------|-----------|
| 遍历方式 | 深度优先 | 可以是广度优先、最佳优先 |
| 剪枝依据 | 约束条件（不可行则剪） | 约束条件 + 界限估计（不可能更优则剪） |
| 适用场景 | 搜索所有可行解 | 搜索最优解 |
| 典型应用 | 八皇后、子集生成 | 旅行商问题、0-1背包 |

### 示例：0-1背包问题

- 物品：重量 [2, 3, 4, 5]，价值 [3, 4, 5, 6]，背包容量 8
- 每个物品选或不选

分支限界法的界限计算：对于当前节点，已经选了某些物品，剩余容量先用**分数背包**（物品可以分割）的贪心解作为上界。

```
根（已选：无，价值：0，容量剩余：8）
上界（乐观估计）≈ 3 + 4 + 5 + 6 = 18（全部装入）
├── 选物品1（已选：{1}，价值：3，容量剩余：5）
│   上界 = 3 + (4 + 5 + 6) = 18
│   ├── 选物品2（已选：{1,2}，价值：7，容量剩余：2）
│   │   上界 = 7 + (5) = 12（只能再装物品3的一部分）
│   │   ├── 选物品3（容量不足，不可能）
│   │   └── 不选物品3（已选：{1,2}，价值：7，容量剩余：2）
│   │       上界 = 7 + (6) = 13
│   │       └── ...
│   └── 不选物品2 ...
└── 不选物品1 ...
```

当某个节点的上界 ≤ 当前已找到的最优解时，该分支被剪掉，无需继续探索。

## 3.6 枚举法与启发式算法

### 枚举法（Exhaustive Search）

枚举法是最直接、最朴素的算法设计方法：

> 列出所有可能的候选解，逐一检查是否为有效解。

枚举法也称为**暴力法（Brute Force）**，它不依赖任何技巧或洞察，只是"老实"地遍历所有可能性。

**优点**：
- 总是能找出正确解
- 实现简单，不易出错
- 非常适合验证其他优化算法的正确性

**缺点**：
- 计算复杂度极高（通常是阶乘或指数级）
- 只适用于问题规模非常小的情况

#### 什么时候使用枚举法？

1. **问题规模保证很小**（如 n ≤ 10 的旅行商问题）
2. **作为正确性基准**，验证更优算法的结果
3. **没有已知的高效算法**（NP-hard 问题在小规模时）
4. **输入规模极度受限的场景**（如密码破解中的短密钥）

### 启发式算法（Heuristic Algorithm）

当问题规模太大，精确算法无法在合理时间内求解时，我们需要**启发式算法**：

> 启发式算法基于经验法则（rule of thumb），在合理的时间内给出一个"足够好"的近似解，但不保证最优性和正确性。

| 方面 | 枚举法 | 启发式算法 |
|------|--------|-----------|
| 解的质量 | 保证最优 | 近似最优 |
| 时间复杂度 | 极高 | 较低 |
| 适用范围 | 极小规模 | 大规模 |
| 正确性保证 | 有 | 无 |

#### 常见的启发式算法

1. **模拟退火（Simulated Annealing）**：模拟物理退火过程，以一定概率接受更差的解以跳出局部最优
2. **遗传算法（Genetic Algorithm）**：模拟自然选择，通过选择、交叉、变异来进化出更好的解
3. **禁忌搜索（Tabu Search）**：维护一个禁忌表，避免走回最近探索过的区域
4. **蚁群算法（Ant Colony Optimization）**：模拟蚂蚁觅食的路径选择行为

#### 何时使用启发式？

- 问题规模极大（如 n > 1000 的旅行商问题）
- 不需要精确最优解，只需要"够用"的解
- 实时性要求高，无法等待精确算法的计算时间

## 本章小结

- **分治法**：分解 → 解决 → 合并。核心是子问题相互独立。代表：归并排序、快速排序、二分查找
- **贪心算法**：每一步做局部最优选择。思想简单高效，但只在满足贪心选择性质时才能保证最优
- **动态规划**：记住子问题的解以避免重复计算。核心是重叠子问题和最优子结构。比贪心更普适，但有空间开销
- **回溯法**：系统的试错过程——做选择、递归、撤销选择。适合搜索所有可行解
- **分支限界法**：在回溯的基础上增加界限剪枝——当某个分支不可能产生更优解时提前终止
- **枚举与启发式**：枚举精确但慢，启发式快但不精确。根据问题规模和需求选择
