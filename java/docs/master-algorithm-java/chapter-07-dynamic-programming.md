# 第7章 动态规划

> "Those who cannot remember the past are condemned to repeat it." —— George Santayana。动态规划正是避免重复计算的艺术——它通过记住子问题的解，将指数级暴力搜索转化为多项式时间的高效算法。

---

## 7.1 动态规划基本思想

### 7.1.1 从递归到动态规划

动态规划（Dynamic Programming, DP）适用于具有以下两个特征的问题：

| 特征 | 描述 | 举例 |
|------|------|------|
| **最优子结构（Optimal Substructure）** | 问题的最优解包含子问题的最优解 | 最短路径的子路径也是最短的 |
| **重叠子问题（Overlapping Subproblems）** | 子问题被重复求解多次 | 斐波那契中 fib(3) 被多次计算 |

不具备重叠子问题时，分治法（如归并排序）更合适；不具备最优子结构时，贪心或搜索更合适。

### 7.1.2 两种实现方式

**自顶向下（Top-Down）+ 记忆化（Memoization）：**

```
fib(5) 的递归树（朴素递归）：
                    fib(5)
                  /        \
             fib(4)        fib(3)
            /      \       /    \
        fib(3)   fib(2) fib(2) fib(1)
        /    \
    fib(2) fib(1)

→ fib(3) 被计算了 2 次，fib(2) 被计算了 3 次
→ 记忆化缓存后，每个子问题只计算一次
```

**自底向上（Bottom-Up）+ 表格（Tabulation）：**

```java
// 斐波那契：自底向上
int fib(int n) {
    if (n <= 1) return n;
    int[] dp = new int[n + 1];
    dp[0] = 0; dp[1] = 1;
    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }
    return dp[n];
}
```

| 对比维度 | 自顶向下（记忆化） | 自底向上（表格） |
|---------|-------------------|-----------------|
| 思考方式 | 递归 + 缓存，更直观 | 迭代填表，需要确定顺序 |
| 空间 | 递归栈 + 缓存表 | 仅缓存表（可优化） |
| 性能 | 有递归开销 | 通常更快 |
| 子问题遍历 | 只计算需要的子问题 | 计算所有子问题 |

### 7.1.3 DP 解题五步框架

```
┌─────────────────────────────────────────────────────┐
│  ① 定义状态（State Definition）                      │
│  dp[i][j] 代表什么含义？                             │
├─────────────────────────────────────────────────────┤
│  ② 状态转移方程（Transition Equation）                │
│  dp[i][j] = f(dp[i-1][j], dp[i][j-1], ...)          │
├─────────────────────────────────────────────────────┤
│  ③ 初始化（Initialization）                          │
│  base case: dp[0][...], dp[...][0]                   │
├─────────────────────────────────────────────────────┤
│  ④ 遍历顺序（Iteration Order）                       │
│  确保计算 dp[i][j] 时，依赖的子问题已计算完毕          │
├─────────────────────────────────────────────────────┤
│  ⑤ 返回结果（Result Extraction）                     │
│  答案可能在 dp[n][m] 或 max(dp[...]) 中             │
└─────────────────────────────────────────────────────┘
```

## 7.2 状态定义与转移方程

### 7.2.1 状态是 DP 的灵魂

状态定义决定了问题的解法难度。好的状态定义让转移方程自然清晰；不好的状态定义让问题变得复杂甚至不可解。

**一维状态（1D DP）：**

```java
// 状态: dp[i] = 前 i 个元素的最优解
// 示例: 最大子数组和
dp[i] = Math.max(nums[i], dp[i - 1] + nums[i]);
```

**二维状态（2D DP）：**

```java
// 状态: dp[i][j] = 前 i 个物品在容量 j 下的最优值
// 示例: 0/1 背包
dp[i][j] = Math.max(dp[i-1][j], dp[i-1][j - w[i]] + v[i]);
```

**区间状态（Interval DP）：**

```java
// 状态: dp[i][j] = 区间 [i, j] 上的最优解
// 示例: 矩阵链乘
dp[i][j] = min(dp[i][k] + dp[k+1][j] + cost(i,k,j));
```

**树形状态（Tree DP）：**

```java
// 状态: dp[node][state] = 以 node 为根的子树在 state 下的最值
// 示例: 最大独立集
dp[node][0] = sum(max(dp[child][0], dp[child][1]));
dp[node][1] = val[node] + sum(dp[child][0]);
```

### 7.2.2 从暴力搜索到 DP 的转化流程

```
暴力递归 → 识别重叠子问题 → 加记忆化 → 改自底向上 → 空间优化

例：0/1 背包
Step 1: 暴力枚举每个物品选或不选 → O(2^n)
Step 2: 发现 (i, capacity) 的组合被重复计算
Step 3: 加 memo[i][capacity] 缓存 → O(n×W)
Step 4: 改为自底向上填二维表 → 仍 O(n×W)
Step 5: 空间优化为一维数组 → O(W)
```

## 7.3 经典问题

### 7.3.1 斐波那契数列（DP 视角回顾）

从 DP 框架重新审视斐波那契：

```
① 状态定义: dp[i] = 第 i 个斐波那契数
② 转移方程: dp[i] = dp[i-1] + dp[i-2]
③ 初始化:   dp[0] = 0, dp[1] = 1
④ 遍历顺序: i 从 2 到 n
⑤ 返回结果: dp[n]

空间优化: 只需要两个变量，无需整个数组
```

```java
// 空间复杂度 O(1) 的斐波那契
public int fib(int n) {
    if (n <= 1) return n;
    int prev2 = 0, prev1 = 1;
    for (int i = 2; i <= n; i++) {
        int cur = prev1 + prev2;
        prev2 = prev1;
        prev1 = cur;
    }
    return prev1;
}
```

### 7.3.2 0/1 背包问题

**问题：** 给定 n 个物品，每个物品有重量 w[i] 和价值 v[i]，背包容量为 W，求能装入的最大价值。

**二维 DP：**

```
状态: dp[i][j] = 前 i 个物品，容量为 j 时的最大价值
转移:
         ┌ dp[i-1][j]                     (不选物品 i)
dp[i][j] = ┤
         └ max(dp[i-1][j], dp[i-1][j-w[i]] + v[i])   (选物品 i, j ≥ w[i])

初始化: dp[0][*] = 0
返回:   dp[n][W]
```

**空间优化为一维（滚动数组）：**

```
dp[j] = max(dp[j], dp[j - w[i]] + v[i])   // j 从 W 递减遍历！
```

**为什么 j 要逆序？** 保证每个物品只选一次。如果正序，dp[j - w[i]] 可能已经包含了当前物品 i，导致物品被重复选择（这正是完全背包的解法）。

### 7.3.3 最长公共子序列（LCS）

**问题：** 给定两个字符串 text1 和 text2，返回最长公共子序列的长度。

```
状态: dp[i][j] = text1[0..i-1] 和 text2[0..j-1] 的 LCS 长度
转移:
         ┌ dp[i-1][j-1] + 1,               text1[i-1] == text2[j-1]
dp[i][j] = ┤
         └ max(dp[i-1][j], dp[i][j-1]),     text1[i-1] != text2[j-1]

初始化: dp[0][*] = 0, dp[*][0] = 0
返回:   dp[m][n]
```

**回溯重构 LCS 序列：** 从 dp[m][n] 开始，根据转移方向反向追踪。

### 7.3.4 最长递增子序列（LIS）

**方法一：DP O(n²)**

```
状态: dp[i] = 以 nums[i] 结尾的最长递增子序列长度
转移: dp[i] = max(dp[j] + 1)  for all j < i and nums[j] < nums[i]
初始化: dp[i] = 1 (每个元素自身构成一个长度为 1 的递增序列)
返回: max(dp)
```

**方法二：贪心 + 二分 O(n log n)（耐心排序 Patience Sorting）**

维护数组 tails，tails[k] 表示长度为 k+1 的递增子序列的最小末尾元素。

```java
int lisLength(int[] nums) {
    int[] tails = new int[nums.length];
    int len = 0;
    for (int x : nums) {
        int i = Arrays.binarySearch(tails, 0, len, x);
        if (i < 0) i = -(i + 1);
        tails[i] = x;
        if (i == len) len++;
    }
    return len;
}
```

该算法不直接得到 LIS 序列，但能正确计算长度。

## 7.4 状态压缩与空间优化

### 7.4.1 滚动数组（Rolling Array）

当 dp[i] 只依赖于 dp[i-1]（或有限的前几项）时，可以用滚动数组节省空间。

```
0/1 背包优化前:   dp[n+1][W+1]    →   O(nW) 空间
0/1 背包优化后:   dp[W+1]         →   O(W) 空间
LCS 优化前:       dp[m+1][n+1]    →   O(mn) 空间
LCS 优化后:       dp[2][n+1]      →   O(n) 空间
```

### 7.4.2 位掩码 DP（Bitmask DP）

当状态集是一个有限集合的子集时，可以用二进制位表示状态。

```
n 个元素的任意子集 → 0 到 2^n - 1 的整数
状态: dp[mask] = 在 mask 表示的子集上的最优解
转移: dp[mask | (1 << k)] = f(dp[mask], ...)
```

典型应用：TSP（旅行商问题）、集合划分、任务分配。

### 7.4.3 空间优化实践指南

| 原始维度 | 依赖关系 | 优化方式 |
|---------|---------|---------|
| 1D | dp[i] 依赖 dp[i-1] | 单变量滚动 |
| 2D | dp[i][j] 依赖 dp[i-1][*] | 一维滚动数组 |
| 2D | dp[i][j] 依赖 dp[i-1][j] 和 dp[i][j-1] | 一维 + 临时变量 |
| 3D | 依赖前一层 | 二维滚动数组 |

## 7.5 树形 DP 与区间 DP

### 7.5.1 树形 DP

树形 DP 的基本模式：后序遍历（先处理子树，再处理当前节点）。

**最大独立集（Maximum Independent Set on Tree）：**

```
状态: dp[node][0] = 不选 node 时，子树的最大独立集大小
      dp[node][1] = 选 node 时，子树的最大独立集大小

转移: dp[node][0] = sum(max(dp[child][0], dp[child][1]))   // 不选 node，孩子可选可不选
      dp[node][1] = 1 + sum(dp[child][0])                   // 选 node，孩子都不选

返回: max(dp[root][0], dp[root][1])
```

**树的直径（Tree Diameter）：** 树上最远两个节点的距离。

```
DFS 求直径:
1. 从任意节点出发，找到最远的节点 u
2. 从 u 出发，找到最远的节点 v
3. u 到 v 的路径即为直径

DP 求直径（一次 DFS）:
对每个节点，计算经过该节点的最长路径（子树最大深度 + 次大深度）
所有节点的最长路径的最大值即为直径
```

### 7.5.2 区间 DP

区间 DP 的套路：先枚举区间长度，再枚举区间起点，最后枚举分割点。

**矩阵链乘（Matrix Chain Multiplication）：**

```
状态: dp[i][j] = 合并矩阵 i..j 的最小乘法次数
转移: dp[i][j] = min(dp[i][k] + dp[k+1][j] + p[i]*p[k+1]*p[j+1])
                  其中 i ≤ k < j
初始化: dp[i][i] = 0
遍历顺序: 区间长度 len 从 2 到 n
```

**回文分割（Palindrome Partitioning - Minimum Cuts）：**

```
状态: dp[i] = 前缀 s[0..i] 的最小分割次数
      isPal[i][j] = s[i..j] 是否为回文

转移: if (isPal[j][i]) dp[i] = min(dp[i], dp[j-1] + 1)
      其中 0 ≤ j ≤ i
初始化: dp[i] = i (最坏情况每个字符切一刀)
返回: dp[n-1]
```

## 7.6 动态规划进阶

### 7.6.1 完全背包（Unbounded Knapsack）

与 0/1 背包的区别：每种物品有无限件，可以重复选取。

```
0/1 背包: dp[j] = max(dp[j], dp[j - w[i]] + v[i])   // j 逆序
完全背包: dp[j] = max(dp[j], dp[j - w[i]] + v[i])   // j 正序！
```

为什么完全背包正序？因为正序遍历时，dp[j - w[i]] 已经包含了当前物品可能被多次选取的情况。

### 7.6.2 多维背包（Multi-dimensional Knapsack）

背包有多个容量约束（如重量和体积），状态维度相应增加。

```
状态: dp[j][k] = 使用重量 j、体积 k 时的最大价值
转移: dp[j][k] = max(dp[j][k], dp[j-w[i]][k-v[i]] + val[i])
```

### 7.6.3 数位 DP（Digit DP）

用于解决"在 [L, R] 范围内满足某种条件的数的个数"问题。

```
状态: dp[pos][tight][leadZero][...] = 处理到第 pos 位时的计数
       pos: 当前处理到第几位
       tight: 前缀是否与上限严格一致
       leadZero: 是否有前导零

模板（记忆化搜索）:
1. 将数字转换为数位数组 digits[]
2. DFS(pos, tight, leadZero, ...) 递归处理每一位
3. 用 memo 缓存已计算的状态
```

### 7.6.4 位掩码 DP 求解 TSP

**旅行商问题：** 给定 n 个城市和城市间距离，求经过每个城市恰好一次并回到起点的最短路径。

```
状态: dp[mask][v] = 从起点出发，经过 mask 集合中的城市，最后到达 v 的最短距离
      mask 的二进制第 i 位为 1 表示城市 i 已访问

转移: dp[mask | (1 << u)][u] = min(dp[mask][v] + dist[v][u])
      其中 v 在 mask 中，u 不在 mask 中

初始化: dp[1 << start][start] = 0
返回: min(dp[(1<<n)-1][v] + dist[v][start])   // 回到起点

复杂度: O(n² × 2ⁿ)，相比 n! 的暴力枚举有质的飞跃
```

## 本章小结

| 概念 | 要点 |
|------|------|
| DP 本质 | 最优子结构 + 重叠子问题 |
| 实现方式 | 自顶向下（记忆化）vs 自底向上（填表） |
| 解题框架 | 状态 → 转移 → 初始化 → 遍历 → 返回 |
| 经典问题 | 背包、LCS、LIS、编辑距离 |
| 优化技巧 | 滚动数组、状态压缩、位掩码 |
| 特殊类型 | 树形 DP、区间 DP、数位 DP |

动态规划的学习路径：**理解原理 → 手写经典 → 识别模式 → 灵活应用 → 触类旁通**。每一个 DP 问题都是三个要素的组合：状态定义、转移方程、遍历顺序。掌握这三者，就能驾驭绝大多数 DP 问题。
