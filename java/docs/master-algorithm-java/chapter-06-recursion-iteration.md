# 第6章 递归与迭代

> "理解递归，你就理解了计算；理解迭代，你就理解了效率。" 递归是描述复杂问题的优雅方式，迭代是解决性能问题的务实手段。两者的关系，正如数学归纳法与循环的关系——同一枚硬币的两面。

---

## 6.1 递归的基本原理

### 6.1.1 递归的三个定律

所有正确的递归算法都遵循三个定律：

1. **基准情形（Base Case）**：递归必须有一个或多个不再递归调用的情形——即可以直接求解的最小子问题。
2. **递归情形（Recursive Case）**：递归调用必须朝着基准情形推进。
3. **向基准推进**：每次递归调用都必须使问题规模缩小，最终到达基准情形。

```
阶乘 n! 的递归定义：

          ┌ 1,               n = 0   ← 基准情形
    n! =  ┤
          └ n × (n-1)!,      n > 0   ← 递归情形，每次减少 1
```

违反这三个定律中的任意一个，都会导致无限递归或错误结果。

### 6.1.2 调用栈可视化

Java 的每次方法调用都会在 **调用栈（Call Stack）** 上分配一个 **栈帧（Stack Frame）**，其中包含：

| 栈帧内容 | 说明 |
|---------|------|
| 返回地址 | 方法执行完毕后返回的位置 |
| 局部变量 | 方法中声明的所有局部变量和参数 |
| 操作数栈 | 进行表达式求值的临时存储区 |

以 `factorial(4)` 为例，调用栈的变化如下：

```
Step 1: factorial(4) 入栈
          ┌─────────────┐
          │ factorial(4)│  n=4, 等待 n*factorial(3)
          └─────────────┘

Step 2: factorial(3) 入栈
          ┌─────────────┐
          │ factorial(4)│  n=4
          ├─────────────┤
          │ factorial(3)│  n=3, 等待 n*factorial(2)
          └─────────────┘

Step 3: factorial(2) 入栈
          ┌─────────────┐
          │ factorial(4)│  n=4
          ├─────────────┤
          │ factorial(3)│  n=3
          ├─────────────┤
          │ factorial(2)│  n=2, 等待 n*factorial(1)
          └─────────────┘

Step 4: factorial(1) 入栈
          ┌─────────────┐
          │ factorial(4)│  n=4
          ├─────────────┤
          │ factorial(3)│  n=3
          ├─────────────┤
          │ factorial(2)│  n=2
          ├─────────────┤
          │ factorial(1)│  n=1, 基准情形，返回 1
          └─────────────┘

Step 5-7: 逐层出栈，每层将结果乘以 n 后返回上一层
          factorial(1) → 1
          factorial(2) → 2*1 = 2
          factorial(3) → 3*2 = 6
          factorial(4) → 4*6 = 24
```

**关键观察**：递归调用在"递推"阶段（入栈）逐步调用，在"回归"阶段（出栈）逐步返回。非尾递归的乘法运算是在回归阶段执行的。

### 6.1.3 Java 的递归调用机制

Java 虚拟机（JVM）对每个线程维护一个独立的调用栈，栈的大小由 JVM 参数 `-Xss` 控制（通常为 512KB~1MB）。

```java
// 递归深度限制演示
public static void deepRecursion(int depth) {
    System.out.println("当前深度: " + depth);
    deepRecursion(depth + 1);  // 无限递归，最终 StackOverflowError
}
```

**Java 默认栈大小与可达到的递归深度：**

| 栈大小 (-Xss) | 约可达到的递归深度 | 说明 |
|--------------|-----------------|------|
| 256KB | ~2000 层 | 最小栈配置，适合受限环境 |
| 512KB | ~5000 层 | 默认值（部分系统） |
| 1MB | ~10000 层 | JVM 默认值（多数系统） |
| 8MB | ~80000 层 | 显式配置的较大栈 |

> **注意**：实际深度取决于局部变量的数量和类型（每个栈帧的大小不同）。包含数组参数或大量局部变量的方法，每个栈帧更大，可达到的深度更小。

**栈溢出（StackOverflowError）** 是递归最容易踩的坑：

```java
public static long factorial(long n) {
    return n == 0 ? 1 : n * factorial(n - 1);
}

// factorial(100000) → StackOverflowError！
// 因为需要 100000 个栈帧，远超 JVM 默认限制
```

Java 无法恢复 `StackOverflowError`（它是 `Error` 而非 `Exception`），因此预防远比补救重要。

## 6.2 递归 vs 迭代

### 6.2.1 全面对比

| 维度 | 递归 | 迭代 |
|------|------|------|
| **代码可读性** | 高——直接对应数学定义 | 中等——需要手动管理状态 |
| **性能（时间）** | 较低——函数调用有额外开销 | 高——单纯循环无函数调用开销 |
| **内存使用** | $O(n)$ 栈空间（非尾递归） | $O(1)$ 额外空间 |
| **风险** | 栈溢出、无限递归 | 无限循环（通常更容易排查） |
| **适用问题** | 树、图、分治、回溯 | 线性遍历、累计计算 |
| **状态管理** | 由调用栈自动维护 | 需要手动维护循环变量 |
| **可调试性** | 栈追踪丰富但信息量大 | 简单直接 |

### 6.2.2 何时使用递归

**适合递归的场景**（递归的"舒适区"）：

1. **问题的数学定义本身就是递归的**：树的高度、阶乘、斐波那契数列
2. **需要回溯的分支搜索**：N 皇后、迷宫求解、全排列
3. **嵌套数据结构**：JSON 解析、XML DOM 遍历、目录树遍历
4. **分治策略**：归并排序、快速排序

**何时应该避免递归**：

1. **深度不确定或可能很大**：几千层的递归在 Java 中就是栈溢出
2. **性能敏感的内循环**：函数调用开销在大量重复时被放大
3. **每个递归分支很小但数量巨大**：如从 1 累加到 n
4. **状态需要在调用之间共享**：递归让共享状态的管理复杂化

### 6.2.3 所有递归都可以转换为迭代

这是一个重要的理论结论：**任何递归算法都可以转换为等价的迭代算法**，方法是使用显式的栈数据结构来模拟调用栈。

```
递归 → 迭代的转换策略：

1. 确定哪些状态是"挂起"的（需要在递归返回后继续执行）
2. 将这些状态封装为"帧"对象
3. 使用显式的栈（Stack 或 Deque）来管理这些帧
4. 用循环替代递归调用
5. 手动控制"回归"阶段的执行
```

**转换示例**（递归版 → 迭代版）：

```java
// 递归版：简洁，由 JVM 管理栈
public static int factorialRecursive(int n) {
    if (n <= 1) return 1;
    return n * factorialRecursive(n - 1);
}

// 迭代版：高效，手动管理
public static int factorialIterative(int n) {
    int result = 1;
    for (int i = 2; i <= n; i++) {
        result *= i;
    }
    return result;
}
```

阶乘的转换是特例——它如此简单以至于不需要显式栈。更复杂的递归（如树的遍历）需要显式栈，这在 Demo2 中演示。

## 6.3 递归优化

### 6.3.1 尾递归（Tail Recursion）

#### 什么是尾递归？

**尾递归**是指递归调用是函数中 **最后一个执行的操作**，且该调用的结果 **直接返回**，不参与任何后续计算。

```java
// 非尾递归：乘法在递归返回后执行
int factorialNormal(int n) {
    if (n <= 1) return 1;
    return n * factorialNormal(n - 1);  // ← 递归返回后还要做乘法
}

// 尾递归：递归调用就是最后一个操作
int factorialTail(int n, int accumulator) {
    if (n <= 1) return accumulator;
    return factorialTail(n - 1, n * accumulator);  // ← 直接返回递归结果
}
```

在非尾递归中，每个栈帧必须在返回后继续执行（乘法），因此不能释放。在尾递归中，如果编译器支持优化，当前栈帧可以被复用。

#### 为什么 Java 不优化尾递归

这是一个经常被问到的问题。答案是：**Java 语言规范没有要求尾递归优化**，主要原因是：

1. **安全性问题**：尾递归优化会改变栈追踪（stack trace）信息，使调试变得困难。
2. **JVM 架构限制**：JVM 的安全模型需要精确的栈帧信息用于权限检查，复用栈帧会破坏这一模型。
3. **历史原因**：Java 设计时并未将函数式编程作为首要目标，Scala/Kotlin 等 JVM 语言通过编译器层面实现了尾递归优化。

```java
// 在 Scala 中，@tailrec 注解强制编译器进行尾递归优化
// 在 Java 中，相同的代码不会得到优化

// Java: factorialTail(100000, 1) → StackOverflowError
// Scala: factorialTail(100000, 1) → 正常工作（被优化为循环）
```

**底线**：在 Java 中，尾递归不会带来性能优势。它的价值在于为 **可读性** 和 **后续迁移** 做准备。

**尾递归的变通方案**：将尾递归手动改写为循环：

```java
// 尾递归 → 循环转换
int factorialLoop(int n) {
    int acc = 1;
    while (n > 1) {
        acc *= n;
        n--;
    }
    return acc;
}
```

### 6.3.2 记忆化（Memoization）

**记忆化**是一种通过缓存子问题的解来避免重复计算的技术。它本质上是 **空间换时间** 的典型应用。

#### 核心思想

以斐波那契数列为例：

```
fib(5) = fib(4) + fib(3)
       = (fib(3) + fib(2)) + (fib(2) + fib(1))
       = ((fib(2) + fib(1)) + fib(2)) + (fib(2) + fib(1))
```

注意 `fib(2)` 被重复计算了 **3 次**，`fib(3)` 被重复计算了 **2 次**。当 n 增大时，重复计算呈指数级增长。

```
fib(5) 的递归树：

              fib(5)
             /      \
        fib(4)      fib(3)
        /    \      /    \
    fib(3) fib(2) fib(2) fib(1)
    /    \
fib(2) fib(1)

→ fib(2) 被计算了 3 次！
→ fib(3) 被计算了 2 次！
```

#### 实现模式

```java
// 记忆化实现——使用缓存数组
public static long fibMemoized(int n, long[] memo) {
    if (n <= 1) return n;
    if (memo[n] != 0) return memo[n];     // 命中缓存
    memo[n] = fibMemoized(n - 1, memo) + fibMemoized(n - 2, memo);
    return memo[n];
}
```

| 版本 | 时间复杂度 | 空间复杂度 | n=50 的性能 |
|------|-----------|-----------|------------|
| 朴素递归 | $O(2^n)$ | $O(n)$ | 永远算不完 |
| 记忆化递归 | $O(n)$ | $O(n)$ | 微秒级 |
| 迭代（DP） | $O(n)$ | $O(1)$ | 微秒级 |

**适用条件**：记忆化要求问题具有 **重叠子问题** 性质——即不同的子问题会共享相同的子子问题。

### 6.3.3 蹦床模式（Trampoline Pattern）

当递归深度很深且无法轻易转化为循环时，**蹦床模式** 是一种实用的技术。它通过将递归调用包装为惰性操作，在循环中逐步执行，从而避免栈溢出。

#### 工作原理

蹦床模式的核心思想是：每个"递归调用"不再真正调用自身，而是返回一个 **表示"下一步做什么"的对象**。一个外层循环负责反复执行这些"下一步"，直到得到最终结果。

```java
// 蹦床模式的核心抽象
interface Trampoline<T> {
    T get();                                           // 获取结果
    default boolean isComplete() { return true; }      // 是否已完成
    default Trampoline<T> bounce() { return this; }    // 下一步计算
}
```

```
递归 vs 蹦床的流程对比：

递归：
  fib(5) → 调用 fib(4) → 调用 fib(3) → ... → JVM 栈溢出风险

蹦床：
  loop:
    fib(5) → 返回 fib(4) + fib(3) 的计算描述（不执行）
    fib(4) → 返回 fib(3) + fib(2) 的计算描述
    ... → 最终得到结果
  整个过程中 JVM 栈深度始终为 1（只有循环帧）
```

**坑点**：蹦床模式虽然解决了栈溢出问题，但可能比普通递归慢 2-10 倍，因为每次"下一步"都需要创建新的对象。它适用于 **深度大但分支少** 的场景，不适合性能敏感路径。

## 6.4 经典递归问题

### 6.4.1 斐波那契数列（Fibonacci）

斐波那契数列是递归的经典入门问题，也是展示不同优化层次的绝佳示例。

```
定义：F(0) = 0, F(1) = 1, F(n) = F(n-1) + F(n-2)
```

**三种实现方式的演进：**

| 版本 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 朴素递归 | $O(2^n)$ | $O(n)$ | 存在大量重叠子问题 |
| 记忆化递归 | $O(n)$ | $O(n)$ | 缓存已计算结果 |
| 迭代 | $O(n)$ | $O(1)$ | 只保留前两个值 |

```java
// 版本1：朴素递归——简洁但指数级性能
int fibNaive(int n) {
    if (n <= 1) return n;
    return fibNaive(n - 1) + fibNaive(n - 2);
    // fibNaive(50) ≈ 2^50 次调用 → 永远算不完
}

// 版本2：记忆化递归——线性时间
int fibMemo(int n, int[] memo) {
    if (n <= 1) return n;
    if (memo[n] != 0) return memo[n];
    memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
    return memo[n];
}

// 版本3：迭代——最优解
int fibIterative(int n) {
    if (n <= 1) return n;
    int a = 0, b = 1;
    for (int i = 2; i <= n; i++) {
        int c = a + b;
        a = b;
        b = c;
    }
    return b;
}
```

**调用次数对比**（计算 fib(n) 所需的递归调用次数）：

| n | 朴素递归调用次数 | 记忆化递归调用次数 |
|---|----------------|-----------------|
| 10 | 177 | 19 |
| 20 | 21891 | 39 |
| 30 | 2692537 | 59 |
| 40 | 331160281 | 79 |
| 50 | 约 $2.5 \times 10^{10}$ | 99 |

**关键洞察**：朴素递归的调用次数约等于 $2 \times \text{fib}(n+1) - 1$，是指数级爆炸。记忆化后降至 $2n - 1$，是线性级。

### 6.4.2 阶乘（Factorial）

阶乘是最简单的递归问题，也是理解递归与迭代对比的最佳起点。

```
定义：0! = 1, n! = n × (n-1)!
```

```java
// 递归版
int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}

// 迭代版（一维递推）
int factorialIterative(int n) {
    int result = 1;
    for (int i = 2; i <= n; i++) result *= i;
    return result;
}
```

阶乘的递归转迭代是最简单的——因为递归结构是一维线性链，没有分支。

### 6.4.3 汉诺塔（Tower of Hanoi）

汉诺塔问题是"分治 + 递归"的完美示例：

**问题**：有三根柱子 A、B、C，A 上有 n 个大小不同的圆盘（小的在上、大的在下）。目标是将所有圆盘从 A 移到 C，每次只能移动一个，且大盘不能放在小盘上。

**递归解法**：

```
要将 n 个圆盘从 A 移到 C（借助 B）：
1. 将 n-1 个圆盘从 A 移到 B（借助 C）  ← 子问题
2. 将第 n 个圆盘从 A 移到 C             ← 直接操作
3. 将 n-1 个圆盘从 B 移到 C（借助 A）  ← 子问题
```

```java
void hanoi(int n, char from, char to, char aux) {
    if (n == 1) {
        System.out.println("移动圆盘 1: " + from + " → " + to);
        return;
    }
    hanoi(n - 1, from, aux, to);      // 步骤1
    System.out.println("移动圆盘 " + n + ": " + from + " → " + to); // 步骤2
    hanoi(n - 1, aux, to, from);      // 步骤3
}
```

**复杂度分析**：

- 移动次数：$T(n) = 2T(n-1) + 1 = 2^n - 1$
- 时间复杂度：$O(2^n)$
- 空间复杂度：$O(n)$（递归深度 = n）

**直观理解**：n=64 时，需要 $2^{64}-1$ 步。如果每秒移动一次，需要约 5849 亿年——比宇宙的年龄还长。

### 6.4.4 树遍历（Tree Traversal）

树的三种遍历方式是"分支递归"的典型例子——每个递归调用有两个分支（左子树和右子树）。

**二叉树节点定义：**

```java
class TreeNode {
    int val;
    TreeNode left, right;
    TreeNode(int x) { val = x; }
}
```

**三种遍历的递归实现：**

```
前序（Preorder）：  根 → 左 → 右
中序（Inorder）：   左 → 根 → 右
后序（Postorder）： 左 → 右 → 根
```

```java
// 前序遍历
void preorder(TreeNode root) {
    if (root == null) return;
    System.out.print(root.val + " ");  // 访问根节点
    preorder(root.left);               // 递归左子树
    preorder(root.right);              // 递归右子树
}

// 中序遍历
void inorder(TreeNode root) {
    if (root == null) return;
    inorder(root.left);                // 递归左子树
    System.out.print(root.val + " ");  // 访问根节点
    inorder(root.right);               // 递归右子树
}

// 后序遍历
void postorder(TreeNode root) {
    if (root == null) return;
    postorder(root.left);              // 递归左子树
    postorder(root.right);             // 递归右子树
    System.out.print(root.val + " ");  // 访问根节点
}
```

**遍历示例**（以下树结构）：

```
        1
       / \
      2   3
     / \
    4   5

前序：1 2 4 5 3     → 用于复制树结构
中序：4 2 5 1 3     → 二叉搜索树中输出有序序列
后序：4 5 2 3 1     → 用于删除树（先处理子节点）
```

**迭代版树遍历**在 Demo2 中详细实现。核心思路是用显式栈手动模拟递归过程。

### 6.4.5 迷宫求解（Maze Solving）

迷宫求解是 **回溯法 + 递归** 的典型应用。它在每个位置尝试四个方向，走不通就回退。

**问题**：给定一个二维迷宫矩阵，0 表示通路，1 表示障碍。从起点 `(0,0)` 出发，找到到终点 `(n-1, n-1)` 的路径。

```java
boolean solveMaze(int[][] maze, int x, int y, int[][] solution) {
    int n = maze.length;
    // 到达终点
    if (x == n - 1 && y == n - 1) {
        solution[x][y] = 1;
        return true;
    }
    // 检查当前位置是否有效
    if (x < 0 || x >= n || y < 0 || y >= n) return false;
    if (maze[x][y] == 0 || solution[x][y] == 1) return false;

    solution[x][y] = 1; // 标记已访问

    // 尝试四个方向（下、右、上、左）
    if (solveMaze(maze, x + 1, y, solution) ||  // 下
        solveMaze(maze, x, y + 1, solution) ||  // 右
        solveMaze(maze, x - 1, y, solution) ||  // 上
        solveMaze(maze, x, y - 1, solution)) {  // 左
        return true;
    }

    solution[x][y] = 0; // 回溯：撤销选择
    return false;
}
```

**回溯法的核心模式：**

```
做选择 → 递归 → 撤销选择

每个回溯问题都遵循这个模式：
1. 在当前步骤做出一个选择
2. 递归地解决剩余问题
3. 如果递归失败，撤销当前选择，尝试下一个选择
```

## 本章小结

| 概念 | 核心要点 | 一句话总结 |
|------|---------|-----------|
| 递归三定律 | 基准情形 + 递归情形 + 向基准推进 | 必须有终止条件，每次调用的规模必须减小 |
| 调用栈 | 每次递归调用分配一个栈帧 | 递归深度 = 栈空间占用 |
| 栈溢出 | 递归过深超过 JVM 栈限制 | Java 中不可恢复的 Error |
| 递归 vs 迭代 | 可读性 vs 性能 | 递归优雅，迭代高效 |
| 递归转迭代 | 用显式栈模拟调用栈 | 理论上所有递归都可以转换 |
| 尾递归 | 递归调用是最后一个操作 | Java 不优化，但对代码组织有意义 |
| 记忆化 | 缓存子问题的解避免重复计算 | 将指数爆炸降为线性 |
| 蹦床模式 | 用循环模拟递归，每个步骤返回惰性操作 | 解决 Java 深度递归的实用方案 |
| 经典问题 | 斐波那契、阶乘、汉诺塔、树遍历、迷宫 | 掌握这些 = 掌握递归思维 |

**一图胜千言**（递归优化的演进路径）：

```
朴素递归         →  记忆化递归      →  迭代
O(2^n) 时间       O(n) 时间         O(n) 时间
O(n) 空间         O(n) 空间         O(1) 空间
（指数爆炸）      （缓存冗余）      （最优解）
                                    ↑
                              这是工程实践中的目标

深度递归问题      →  蹦床模式
栈溢出风险          栈安全但稍慢
```
