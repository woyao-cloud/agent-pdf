# 第19章 算法设计能力

> "好的算法不是写出来的，是设计出来的。设计意味着有方法、有步骤、有取舍。"

---

## 19.1 如何分析问题

分析问题是算法设计的第一步。面对一个陌生问题时，不要急着写代码，先回答以下几个问题。

### 理解输入输出约束

拿到题目后的第一件事：

- **输入规模有多大？** n = 10² 还是 10⁶？这将直接决定 O(n²) 是否可行
- **数据类型是什么？** 整数？浮点数？字符串？图？
- **范围约束？** 值域是 [0, 10⁹] 吗？需要考虑大数溢出吗？
- **时间限制？** 通常 1-2 秒，对应 Java 约 10⁷-10⁸ 次基本运算
- **空间限制？** 通常 256MB-512MB

**规模速查表：**

| n 的大小 | 允许的复杂度 | 典型算法 |
|---------|------------|---------|
| n ≤ 10 | O(n!), O(2ⁿ) | 暴力枚举、回溯 |
| n ≤ 20 | O(2ⁿ), O(n·2ⁿ) | 状态压缩 DP |
| n ≤ 10³ | O(n²), O(n²logn) | 双层循环、Floyd |
| n ≤ 10⁵ | O(n), O(nlogn) | 排序+扫描、线段树 |
| n ≤ 10⁶ | O(n), O(nlogn) | 线性扫描、二分 |
| n ≤ 10⁸ | O(logn), O(1) | 数学公式、哈希表 |

### 识别子问题

将大问题拆解成小问题，是算法设计的核心能力：

```
大问题 → 子问题1 → 子问题2 → ... → 可直接求解的基元
```

**拆解方法：**
- **分治法**：将问题分成独立的子问题，分别求解后合并（如归并排序）
- **减治法**：每次减少一个元素，将 n 的问题转化为 n-1 的问题（如插入排序）
- **变治法**：将问题转化为已知的更容易求解的形式（如 AVL 树通过旋转保持平衡）

### 画例子

不要只在脑子里想，画出来。画例子能帮助你发现规律。

**画例子的要点：**
- 从小规模开始（n=3, n=4）
- 画出所有中间状态
- 标注关键决策点
- 寻找重复模式

例如，理解动态规划时，画出 DP 表格的填充过程远比看公式有效。

### 归约到已知问题

这是最强大的技巧之一。将未知问题归约到已知问题：

```
新问题 → 发现与已知问题的相似性 → 直接套用算法
```

**常见归约模式：**
- 求"最长..." → 可能是 DP
- 求"是否存在..." → 可能是 DFS/BFS 或二分图匹配
- 求"最小代价..." → 可能是最短路径、最小割或 DP
- 求"排列方式..." → 可能是回溯或贪心

### 问题分解模式

**归纳法（Induction）：** 证明 P(1) 成立，假设 P(k) 成立，证明 P(k+1) 成立。对应到算法：先解决最小规模问题，然后假设能解决规模 k 的问题，推导出规模 k+1 的解法。

**递归法（Recursion）：** 函数调用自身，每次调用缩小问题规模。核心是找到递归关系和终止条件。

**归约法（Reduction）：** 将问题 A 转换为问题 B，如果 B 有高效算法，则 A 也能高效求解。例如，将最大流问题归约为线性规划。

## 19.2 如何选择算法策略

面对一个问题时，如何从众多算法中选出最合适的？

### 决策流程图

```
输入规模小（n ≤ 20）？
├── 是 → 回溯/暴力枚举可行吗？
│       ├── 是 → 用回溯/位运算枚举
│       └── 否 → 考虑状态压缩 DP
└── 否 → 继续↓

有最优子结构？
├── 是 → 动态规划
│       └── 状态维度是否爆炸？
│               ├── 是 → 考虑贪心近似
│               └── 否 → DP 是正解
└── 否 → 继续↓

需要全局最优？
├── 是 → 搜索（BFS/DFS/A*）或网络流
└── 否 → 贪心是否可行？
        ├── 是 → 贪心（证明正确性！）
        └── 否 → 启发式算法

数据有什么特殊性质？
├── 已排序 → 二分查找/双指针
├── 有重复 → 哈希表/排序去重
├── 有周期性 → 数学分析
├── 有范围限制 → 计数排序/桶排序
└── 有图结构 → 图的算法
```

### 时间 vs 空间权衡

| 场景 | 策略 | 典型例子 |
|------|------|---------|
| 时间敏感，内存充足 | 用空间换时间 | 哈希缓存、预计算 |
| 内存紧张，时间宽裕 | 用时间换空间 | 流式处理、分块计算 |
| 两者都紧张 | 需要最佳平衡 | 缓存+LRU淘汰 |

**案例：斐波那契数列**
- 递归（时间 O(2ⁿ)，空间 O(n)）→ 极慢
- DP 数组（时间 O(n)，空间 O(n)）→ 标准解法
- 滚动变量（时间 O(n)，空间 O(1)）→ 最优
- 矩阵快速幂（时间 O(logn)，空间 O(1)）→ 数学最优

### 策略映射表

当看到特定关键词时，联想对应的策略：

| 问题特征 | 推荐算法策略 |
|---------|------------|
| 已排序的数组/查找 | 二分查找 |
| 有序数组中的两数之和 | 双指针 |
| 连续子数组/子串 | 滑动窗口、前缀和、DP |
| 最值问题（最大/最小） | DP、贪心、二分答案 |
| 存在性问题 | DFS、BFS、并查集 |
| 计数问题 | DP、组合数学、容斥 |
| 所有解/路径 | 回溯、DFS |
| 最优解（有限决策） | DP |
| 最优解（无限决策） | 贪心（需证明） |
| 区间问题 | 线段树、树状数组、扫描线 |
| 字符串匹配 | KMP、RK、Trie、AC自动机 |
| 图的最短路径 | Dijkstra、Bellman-Ford、Floyd |
| 图的连通性 | 并查集、Tarjan |
| 图的环检测 | DFS 染色、拓扑排序 |
| 拓扑关系 | 拓扑排序（Kahn / DFS） |
| 最大匹配/流 | 匈牙利算法、Dinic |
| 大数据的 top-K | 堆、快速选择、计数 |
| 数据范围小但数据量大 | 计数排序、桶排序 |
| 随机化需求 | 洗牌算法、蓄水池抽样 |

## 19.3 算法正确性证明

写对算法比写快算法更重要。本节介绍非正式的证明技巧。

### 循环不变式法

循环不变式是在循环的每次迭代前后都保持为真的断言。用不变式证明算法正确需要三步：

1. **初始化**：循环开始前，不变式为真
2. **保持**：如果某次迭代前不变式为真，那么下次迭代前仍然为真
3. **终止**：循环终止时，不变式提供了有用的性质，证明算法正确

**示例：插入排序的不变式证明**

```
不变式：每次迭代开始前，子数组 A[0..i-1] 是有序的
初始化：i=1 时，A[0..0] 只有一个元素，自然有序 ✓
保持：假设 A[0..i-1] 有序，将 A[i] 插入到正确位置后
      A[0..i] 有序 ✓
终止：i=n 时，A[0..n-1] 有序，排序完成 ✓
```

**示例：二分查找的不变式证明**

```
不变式：如果目标值在数组中，它一定在区间 [low, high] 内
初始化：low=0, high=n-1，整个数组包含目标（如果存在） ✓
保持：根据 A[mid] 与 target 的比较，缩小区间到正确的一半 ✓
终止：low > high 时，区间为空，说明目标不存在；
      或 mid 找到目标，直接返回 ✓
```

### 交换论证法（Exchange Argument）

用于证明贪心算法的正确性。核心思想：**任意最优解都可以通过一系列不劣化结果的交换，转变为贪心解。**

**步骤：**
1. 假设存在一个最优解 OPT
2. 找到 OPT 与贪心解的第一个不同之处
3. 证明可以交换 OPT 中的元素使其更接近贪心解而不劣化结果
4. 重复交换，最终 OPT 变为贪心解，说明贪心解也是最优的

**示例：活动选择问题**
- 贪心策略：每次选择结束时间最早的活动
- 交换论证：假设最优解中第一个活动不是结束最早的，则可以用最早结束的活动替换它，不会减少可选活动数，因此贪心解等价于最优解

### 剪切-粘贴法（Cut-and-Paste）

用于证明 DP 的最优子结构性质。核心思想：**如果问题的最优解包含子问题的解，那么这个子问题的解也一定是最优的。**

**步骤：**
1. 假设原问题的最优解为 OPT
2. 从 OPT 中「剪切」出一个子问题的解
3. 如果这个子问题的解不是最优的，可以「粘贴」一个更优的解
4. 这样会得到一个比 OPT 更优的原问题解，矛盾

**示例：最短路径**
- 假设 s→t 的最短路径经过中间节点 k
- 则 s→k 的子路径一定也是 s→k 的最短路径
- 否则可以剪掉 s→k 的子路径，粘贴更短的路径，得到更优的 s→t 路径

### 反例生成

当你怀疑一个算法不正确时，试着构造反例：

**反例构造技巧：**
- 从最简单的边界开始（n=1, n=2）
- 尝试对称结构
- 尝试极端值（最大/最小）
- 尝试"陷阱"场景（相等值、重复值）
- 用计算机随机生成样例并暴力验证

**反例生成清单：**

| 算法类型 | 可能的反例 |
|---------|-----------|
| 排序算法 | 已排序数组、逆序数组、全部相同元素 |
| 贪心算法 | 局部最优≠全局最优的案例 |
| DP 状态定义 | 状态不满足无后效性 |
| 二分查找 | 重复元素、旋转数组、查找不存在元素 |
| 图算法 | 负权边、零权边、自环、重边 |

## 19.4 算法复杂度分析技巧

### Master Theorem 的变体

标准的主定理可以求解形如 `T(n) = aT(n/b) + f(n)` 的递推式。

但实际中会遇到各种变体：

**变体1：非齐次项**
```
T(n) = aT(n/b) + f(n) + g(n)
```
分别分析 f(n) 和 g(n)，取复杂度更高的结果。

**变体2：分数部分**
```
T(n) = aT(⌊n/b⌋) + f(n) 或 T(n) = aT(⌈n/b⌉) + f(n)
```
向下/向上取整不影响渐进结果，直接套用主定理。

**变体3：不等分**
```
T(n) = T(n-1) + T(n-2) + O(1)
```
这是斐波那契递推，结果是 O(2ⁿ)。不符合主定理形式，需要用递归树或生成函数。

### Akra-Bazzi 方法

当分治的子问题规模不同时（如 `T(n) = T(⌊n/3⌋) + T(⌊2n/3⌋) + n`），主定理不适用。Akra-Bazzi 方法能处理这类非均匀分治：

```
T(n) = Σaᵢ·T(bᵢ·n + hᵢ(n)) + g(n), for large n

其中，bᵢ ∈ (0,1)，hᵢ(n) 是较小扰动项
```

求解步骤：
1. 找到 p 使得 Σaᵢ·bᵢᵖ = 1
2. 计算 T(n) = Θ(nᵖ·(1 + ∫₁ⁿ g(u)/uᵖ⁺¹ du))

**示例：**
```
T(n) = T(n/3) + T(2n/3) + n

求 p: (1/3)ᵖ + (2/3)ᵖ = 1 → p ≈ 1

T(n) = Θ(n·(1 + ∫₁ⁿ 1/u du))
     = Θ(n·(1 + lnn))
     = Θ(n·logn)
```

这与快速排序的平均复杂度一致。

### 摊还分析

摊还分析用于分析一系列操作的平均时间复杂度，即使个别操作代价很高。

**聚合法（Aggregate Method）：** 计算 n 次操作的总耗时 T(n)，摊还代价 = T(n)/n。

**记账法（Accounting Method）：** 为廉价操作"存款"，昂贵操作从存款中扣除。

**势能法（Potential Method）：** 定义势能函数 Φ(Dᵢ) 表示数据结构的状态。摊还代价 = 实际代价 + Φ(Dᵢ) - Φ(Dᵢ₋₁)。

**势能法分析 Union-Find（按秩合并+路径压缩）：**

```
势能函数：Φ(S) = Σ rank(x)
操作分析：
  - MakeSet(x): Φ 增加 O(1)，摊还 O(1)
  - Find(x) 的路径压缩: 势能释放支付压缩成本，摊还 O(α(n))
  - Union(x,y): O(1) 实际 + O(1) 势能变化
总摊还：接近 O(m·α(n))
```

**记账法分析伸展树（Splay Tree）：**

```
存款策略：每个节点存款 = 3(rank after - rank before) + 1
zig/zag 步骤消耗 1 单位存款
zig-zig/zig-zag 步骤消耗剩余的存款
所有操作摊还后为 O(logn)
```

### P vs NP 与 NP-完全性

**复杂度类的基本概念：**

| 类 | 含义 | 特点 |
|----|------|------|
| P | 多项式时间可解 | 排序、查找、最短路径 |
| NP | 多项式时间可验证 | 数独解是否正确、哈密顿路径验证 |
| NP-Complete | NP 中最难的问题 | 3-SAT、TSP、背包、图着色 |
| NP-Hard | 至少和 NP 问题一样难 | 停机问题、最优 TSP |

**归约证明 NP-完全性：**

如果要证明问题 A 是 NP-完全的，需要：
1. 证明 A ∈ NP（能在多项式时间验证解）
2. 将一个已知的 NP-完全问题 B 归约到 A（B ≤ₚ A）

**常用归约链：**

```
SAT → 3-SAT → 独立集 → 顶点覆盖 → 团
                              ↓
                          哈密顿路径 → TSP
                              ↓
                          子集和 → 背包
```

NP-完全性的实践意义：
- 如果证明问题是 NP-完全的，不要试图找多项式精确解
- 转而寻找：近似算法、启发式算法、参数化算法、对特殊情况的限制
