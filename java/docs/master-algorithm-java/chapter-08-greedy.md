# 第8章 贪心算法

> "Think globally, act locally." —— 贪心算法的哲学正是"局部最优推导全局最优"。它简单、高效，但只在特定问题上有效。懂得何时使用贪心，比懂得如何实现贪心更重要。

---

## 8.1 贪心算法基本思想

### 8.1.1 什么是贪心

贪心算法（Greedy Algorithm）在每一步都做出当前看来最优的选择，期望这些局部最优选择能够累积出全局最优解。

```
贪心算法的通用框架：

result = 初始状态
while (未达到目标) {
    做出当前最优的选择   ← 贪心策略（Greedy Choice）
    更新状态
}
return result
```

与动态规划不同，贪心不做全局搜索，不回溯，不保存子问题的解。它"走一步看一步"，决策一旦做出就不更改。

### 8.1.2 贪心算法的两个要素

一个问题适合用贪心算法求解，必须同时满足以下两个性质：

| 性质 | 描述 | 类比 |
|------|------|------|
| **贪心选择性质** | 全局最优解可以通过一系列局部最优选择来达成 | 每一步都选最好的，最终就是最好的 |
| **最优子结构** | 问题的最优解包含子问题的最优解 | 去掉第一步，剩下的仍然是子问题的最优解 |

**贪心选择性质**区别于动态规划的关键。DP 允许你"试错"——选择之后可以后悔，通过状态转移保证全局最优。贪心一旦选择就锁定，所以必须证明当前选择一定在某个全局最优解中。

### 8.1.3 贪心策略的设计

贪心策略的核心是确定"什么是最优选择"：

| 问题 | 贪心策略 | 是否有效 |
|------|---------|---------|
| 活动选择 | 选结束时间最早的 | ✔ 总是有效 |
| 找零（美元硬币） | 选面值最大的 | ✔ 有效 |
| 找零（任意硬币） | 选面值最大的 | ✘ 可能失败 |
| 0/1 背包 | 选价值/重量比最高的 | ✘ 可能失败 |
| 分数背包 | 选价值/重量比最高的 | ✔ 总是有效 |
| Huffman 编码 | 合并频率最低的 | ✔ 总是有效 |
| 最小生成树 | 选权重最小的边 | ✔ 总是有效 |
| Dijkstra 最短路径 | 选距离最短的 | ✔ 有效（无负边） |

### 8.1.4 贪心的直觉与陷阱

贪心算法看似简单，但最容易犯错——因为直觉上"最优"的选择可能是错的。

**经典陷阱：硬币找零**

```
硬币面值：{1, 3, 4}，目标金额：6

贪心策略（选最大面值）：
  选 4 → 剩余 2 → 选 1 → 选 1 → 共 3 枚

最优解：
  选 3 → 选 3 → 共 2 枚

结论：贪心失败！面值 4 不是 3 的倍数，局部最优 ≠ 全局最优
```

**正确的态度**：先用直觉猜测贪心策略，再用数学证明或反例验证。不要假设贪心总是正确的。

## 8.2 贪心 vs 动态规划

### 8.2.1 核心区别

贪心和 DP 都要求最优子结构，但贪心多了一个"贪心选择性质"的要求。

| 对比维度 | 贪心算法 | 动态规划 |
|---------|---------|---------|
| **决策方式** | 当前最优，一步到位 | 试错，保留所有可能性 |
| **子问题求解** | 只求解一个子问题 | 求解所有子问题 |
| **选择后能否后悔** | 不能 | 可以通过状态转移"后悔" |
| **状态空间** | 无（或极简） | 完整的状态表 |
| **正确性** | 需要证明贪心选择性质 | 由 DP 框架保证 |
| **时间复杂度** | 通常 O(n) 或 O(n log n) | 通常 O(n²) 或 O(n×W) |
| **空间复杂度** | O(1) | O(状态数) |
| **适用场景** | 贪心选择性质成立的问题 | 任何最优子结构问题 |

### 8.2.2 同一问题两种解法：活动选择

**问题**：多个活动，每个有 `[start, end]`，选择最大数量的不重叠活动。

**贪心解法**（总是正确）：

```
策略：每次选结束时间最早且与已选不冲突的活动
1. 按 end 排序
2. 选第一个活动
3. 跳过所有与已选冲突的活动，重复

复杂度：O(n log n)
```

**DP 解法**（也能正确，但更复杂）：

```
状态：dp[i] = 前 i 个活动（按结束时间排序）能选的最大数量
转移：dp[i] = max(dp[i-1], dp[prev[i]] + 1)
      prev[i] = 与活动 i 不冲突的最近一个活动

复杂度：O(n log n) 用于排序 + O(n) 用于 DP
```

```
决策树对比（活动: A(1,3), B(2,5), C(4,6), D(5,7)）：

贪心（只走一条路径）：
  ┌─ 选 A (1,3) ──→ 跳过 B ──→ 选 C (4,6) ──→ 跳过 D ──→ 结束，共 2 个

DP（探索多条路径）：
  ┌─ 选 A (1,3) ──→ 选 C (4,6) ──→ 共 2 个
  │            └──→ 选 D (5,7) ──→ 共 2 个
  ├─ 选 B (2,5) ──→ 选 D (5,7) ──→ 共 2 个
  └─ 不选 A ──────→ ...各种组合...

结论：两者结果一致，但贪心高效得多
```

### 8.2.3 同一问题两种解法：背包问题

**分数背包**（贪心有效）：

| 物品 | 重量 | 价值 | 价值/重量 |
|:----:|:----:|:----:|:---------:|
| A    | 10   | 60   | 6         |
| B    | 20   | 100  | 5         |
| C    | 30   | 120  | 4         |

背包容量 = 50

```
贪心（按价值/重量比从高到低）：
  选 A (全拿)：重量 10/10，价值 60，剩余容量 40
  选 B (全拿)：重量 20/20，价值 100，剩余容量 20
  选 C (拿 20/30)：重量 20/30，价值 80，剩余容量 0
  总价值 = 60 + 100 + 80 = 240  ← 全局最优
```

**0/1 背包**（贪心无效）：

```
同样的数据，但物品不能分割

贪心：选 A + B = 160（容量 30/50，浪费 20）
最优：选 B + C = 220（容量满）
```

为什么分数背包贪心有效而 0/1 背包无效？因为分数背包可以"取一部分"，使得贪心的选择不会浪费容量；而 0/1 背包一旦选了一个物品，剩余容量可能无法被最优利用。

## 8.3 经典问题

### 8.3.1 活动选择（Activity Selection）

**问题描述**：给定 n 个活动，每个活动 i 有开始时间 s[i] 和结束时间 f[i]（s[i] < f[i]）。同一时间只能进行一个活动，求能参加的最大活动数量。

**贪心策略**：按结束时间排序，每次选结束时间最早且不冲突的活动。

```
证明概要（交换论证）：
  假设贪心选了活动 a₁（结束最早），最优解第一个选的是 b₁。
  因为 a₁ 的结束时间 ≤ b₁ 的结束时间，所以 a₁ 与 b₁ 之后的活动也不冲突。
  因此可以安全地用 a₁ 替换 b₁，得到一个不差的最优解。
  以此类推，贪心选择的每个活动都可以替换最优解中对应位置的活动。
```

```java
// 伪代码
Arrays.sort(activities, (a, b) -> a.end - b.end);
int count = 1, lastEnd = activities[0].end;
for (int i = 1; i < n; i++) {
    if (activities[i].start >= lastEnd) {
        count++;
        lastEnd = activities[i].end;
    }
}
```

**时间复杂度**：O(n log n)（排序）+ O(n)（选择）= O(n log n)

### 8.3.2 Huffman 编码

**问题描述**：给定一组字符及其出现频率，构造最优前缀码（Prefix Code），使得编码后的总长度最短。

**贪心策略**：每次从优先队列中取出频率最小的两个节点合并，直到剩下一个根节点。

```
示例：字符 A(45), B(13), C(12), D(16), E(9), F(5)

Huffman 树构建过程：

Step 1:  最小的两个是 F(5) 和 E(9) → 合并为内部节点 (14)
Step 2:  当前最小: C(12) 和 B(13) → 合并为 (25)
Step 3:  当前最小: (14) 和 D(16) → 合并为 (30)
Step 4:  当前最小: (25) 和 (30) → 合并为 (55)
Step 5:  最后合并 (55) 和 A(45) → 根节点 (100)

最终 Huffman 树：
                  (100)
                 /     \
              A(45)    (55)
                      /    \
                   (25)    (30)
                  /    \   /   \
                C(12) B(13) (14) D(16)
                           /    \
                         F(5)  E(9)

编码：
  A: 0
  C: 100
  B: 101
  F: 1100
  E: 1101
  D: 111

加权长度 = 45×1 + 13×3 + 12×3 + 16×3 + 9×4 + 5×4 = 224 位
（定长编码需要 3 位 × 100 = 300 位，节省 25%）
```

**时间复杂度**：O(n log n)（优先队列操作）

**贪心选择性质证明**：对于任意频率集合，存在一个最优前缀码，其中频率最小的两个字符是兄弟节点且在树的最深层。这个性质保证了"合并最小两个"的操作是正确的。

### 8.3.3 分数背包（Fractional Knapsack）

**问题描述**：n 个物品，每个有重量 w[i] 和价值 v[i]，背包容量 W。物品可以分割（取一部分），求最大价值。

**贪心策略**：按价值/重量比（单位价值）降序排列，先拿单位价值最高的。

```
证明概要：
  假设最优解在某个步骤没有选择单位价值最高的物品。
  那么可以用单位价值最高的物品替换该步骤中价值密度较低的物品，
  总价值不变或增加。因此贪心策略不会比最优解差。
```

详细实现见 Demo。

### 8.3.4 最小生成树（Minimum Spanning Tree）

**问题描述**：给定一个带权无向连通图，求一棵包含所有顶点的树，使得所有边的权重之和最小。

**Prim 算法**（类似 Dijkstra）：

```
策略：从一个顶点开始，不断选择连接"已访问集合"和"未访问集合"的最小权重边

1. 任选起点，标记为已访问
2. 维护所有已访问顶点到未访问顶点的最小边
3. 选最小边，将对应的未访问顶点加入已访问集合
4. 更新新顶点带来的边
5. 重复直到所有顶点都访问

复杂度: O(V²) 或 O(E log V)（用优先队列）
```

**Kruskal 算法**（基于边排序）：

```
策略：将所有边按权重排序，从小到大添加，如果加入后不形成环则保留

1. 按权重对所有边排序
2. 初始化 Union-Find 数据结构
3. 遍历每条边 (u, v, w)
4.   find(u) ≠ find(v) → 加入 MST，union(u, v)
5. 重复直到 MST 有 V-1 条边

复杂度: O(E log E) = O(E log V)（排序为主）
```

```
示例图：
      2       3
  A ----- B ----- C
  |       |       |
 1|      4|      5
  |       |       |
  D ----- E ----- F
      6       7

Prim (从 A 开始):
  选 A-D(1) → 选 D-B(4)...（边权重不同结果可能不同）
  
Kruskal:
  排序: A-D(1), A-B(2), B-C(3), B-E(4), C-F(5), D-E(6), E-F(7)
  加 A-D(1) ✔ → 加 A-B(2) ✔ → 加 B-C(3) ✔
  加 B-E(4) ✔ → 加 C-F(5) ✔ → MST 完成，权重 = 1+2+3+4+5 = 15
```

两种算法的选择：
| 场景 | 推荐算法 |
|------|---------|
| 稠密图（E ≈ V²） | Prim（优先队列） |
| 稀疏图（E ≈ V） | Kruskal（Union-Find） |
| 需要流式处理边 | Kruskal（边排序后增量处理） |

## 8.4 贪心算法的正确性证明

### 8.4.1 为什么需要证明

贪心算法是"直觉驱动"的——直觉可能对，也可能错。务必证明贪心策略的正确性，否则就是赌博。

三种主流证明方法：

| 方法 | 核心思路 | 最佳适用 |
|------|---------|---------|
| **交换论证** | 将最优解逐步转换为贪心解，转换过程中不降低解的质量 | 活动选择、最小生成树 |
| **贪心领先** | 证明贪心算法在每一步都不比最优解"差" | 区间调度、调度问题 |
| **结构归纳** | 证明问题结构保证贪心选择永远正确 | Huffman 编码、分数背包 |

### 8.4.2 交换论证法（Exchange Argument）

**核心思想**：任意最优解都可以通过一系列"交换"操作，在不降低解质量的前提下，逐步变为贪心算法产生的解。因此贪心解也是最优解。

**应用：活动选择**

```
最优解 O = {o₁, o₂, ..., oₖ}，按结束时间排序
贪心解 G = {g₁, g₂, ..., gₘ}

证明步骤：
1. g₁ 的结束时间 ≤ o₁ 的结束时间（贪心选结束最早）
2. 将 o₁ 替换为 g₁，得到 O' = {g₁, o₂, ..., oₖ}
   - g₁ 与 o₂ 不冲突（因为 g₁ 结束时间 ≤ o₁ 结束时间 ≤ o₂ 开始时间）
3. O' 仍然是可行解，且 |O'| = |O| = k
4. 对剩余的区间重复此过程
5. 最终 O 被转换为 G，且 |G| = |O| = k，所以 m = k
```

**应用：分数背包**

```
最优解 O 在某个步骤选择了物品 B 而非物品 A，其中 A 的单位价值 > B 的单位价值
交换：用 A 替换 B 的一部分，直到 B 被完全替换或 A 被用完
结果：总价值不降 → 贪心最优
```

### 8.4.3 贪心领先法（Greedy Stays Ahead）

**核心思想**：证明贪心算法在每一步的"度量指标"都不比任何最优解差，从而最终结果也不差。

**应用：区间调度**（选最多不相交区间）

```
定义：经过 k 步后，贪心选择的第 k 个区间的结束时间为 Gₖ
最优解的第 k 个区间的结束时间为 Oₖ

归纳假设：Gₖ ≤ Oₖ

基例（k=1）：贪心选结束最早的区间 → G₁ ≤ O₁ ✓

归纳步：假设 Gₖ₋₁ ≤ Oₖ₋₁
  贪心在第 k 步选的是"结束最早且与 Gₖ₋₁ 不冲突的区间"
  最优解在第 k 步选的是"与 Oₖ₋₁ 不冲突的某个区间"
  由于 Gₖ₋₁ ≤ Oₖ₋₁，贪心的候选集 ≥ 最优解的候选集
  因此 Gₖ ≤ Oₖ

结论：贪心选择了至少和最优解一样多的区间
```

### 8.4.4 结构归纳法（Structural Proof）

**核心思想**：直接分析问题的数学结构，证明贪心选择总是安全的。

**应用：Huffman 编码**

```
引理：对于任意字符频率集合，存在一个最优前缀码，
      其中频率最小的两个字符是兄弟节点且在树的最深层。

证明：
  设 x 和 y 是频率最小的两个字符。
  在最优前缀码树 T 中，设最深层的两个兄弟节点为 a 和 b（频率 f(a)、f(b)）。
  交换：将 x 与 a 交换，y 与 b 交换（或相反）。
  由于 f(x) ≤ f(a) 且 f(y) ≤ f(b)，交换后编码总长度不增加。
  因此存在最优解让 x 和 y 在最深层成为兄弟 → 贪心合并最小两个是正确的。

归纳：合并 x 和 y 为一个新节点（频率 f(x)+f(y)），问题规模减少 1。
      递归应用相同策略 → 贪心构建的树是最优的。
```

**应用：分数背包**（按单位价值排序的正确性）

```
任何不按单位价值降序选择的解都可以被"优化"：
  如果选了单位价值低的物品而没选单位价值高的物品，
  将低价值物品替换为高价值物品必然增加总价值。
  因此按单位价值降序选取是最优的。
```

### 8.4.5 证明方法选择指南

| 问题特征 | 推荐方法 | 典型问题 |
|---------|---------|---------|
| 解是一组元素 | 交换论证 | 活动选择、Kruskal、MST |
| 度量指标可追踪 | 贪心领先 | 区间调度、任务调度 |
| 问题有递归结构 | 结构归纳 | Huffman、分数背包 |

## 本章小结

| 概念 | 要点 |
|------|------|
| 贪心本质 | 局部最优推导全局最优 |
| 两个要素 | 贪心选择性质 + 最优子结构 |
| 适用场景 | 活动选择、Huffman、分数背包、MST |
| 与 DP 区别 | 贪心不后悔、不存表、更快但不通用 |
| 正确性证明 | 交换论证 / 贪心领先 / 结构归纳 |
| 常见错误 | 假设贪心总是对的（一定要证明或验证！） |

贪心算法的学习路径：**理解思想 → 辨别适用场景 → 设计贪心策略 → 证明正确性 → 对比 DP 加深理解**。贪心是算法设计中"最危险也最优美"的策略——危险在于看似正确实则错误，优美在于当它有效时，它给出的是最简单、最优雅的解法。
