# 第4章 排序算法

> "排序是计算机科学中最基本也最优雅的问题之一。理解了排序，你就理解了算法设计的精髓。" —— 从冒泡排序到TimSort，排序算法的演进史就是一部算法优化史。

---

## 4.1 排序算法分类与对比

### 排序算法的分类维度

排序算法可以从多个维度进行分类：

**按比较方式分：**
- **比较排序（Comparison-based）**：通过元素之间的比较来确定顺序。任何比较排序在最坏情况下至少需要 $O(n \log n)$ 次比较。包括冒泡排序、快速排序、归并排序、堆排序等。
- **非比较排序（Non-comparison / Linear-time）**：不通过比较来确定顺序，而是利用元素本身的特殊性质（如整数值的范围、位数等）。时间复杂度可以突破 $O(n \log n)$ 的下界，达到 $O(n)$。包括计数排序、桶排序、基数排序。

**按稳定性分：**
- **稳定排序（Stable）**：相等的元素在排序后保持它们在原数组中的相对顺序。当需要按多个关键字排序时，稳定性非常重要。
- **不稳定排序（Unstable）**：相等的元素可能改变相对顺序。

**按空间复杂度分：**
- **原地排序（In-place）**：额外空间复杂度为 $O(1)$ 或 $O(\log n)$。
- **非原地排序（Out-of-place）**：需要 $O(n)$ 或更多的额外空间。

**按适应性分：**
- **自适应排序（Adaptive）**：对已经部分有序的数据表现更好。
- **非自适应排序（Non-adaptive）**：对输入数据的初始顺序不敏感。

### 所有排序算法对比一览

| 算法 | 平均时间 | 最坏时间 | 最好时间 | 空间 | 稳定 | 原地 | 自适应 |
|------|---------|---------|---------|------|:----:|:----:|:------:|
| 冒泡排序 | $O(n^2)$ | $O(n^2)$ | $O(n)$ | $O(1)$ | ✅ | ✅ | ✅ |
| 快速排序 | $O(n \log n)$ | $O(n^2)$ | $O(n \log n)$ | $O(\log n)$ | ❌ | ✅ | ❌ |
| 直接插入排序 | $O(n^2)$ | $O(n^2)$ | $O(n)$ | $O(1)$ | ✅ | ✅ | ✅ |
| 希尔排序 | $O(n^{1.3})$ | $O(n^{4/3})$ | $O(n \log n)$ | $O(1)$ | ❌ | ✅ | ❌ |
| 简单选择排序 | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | ❌ | ✅ | ❌ |
| 堆排序 | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(1)$ | ❌ | ✅ | ❌ |
| 归并排序 | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n)$ | ✅ | ❌ | ❌ |
| 计数排序 | $O(n + k)$ | $O(n + k)$ | $O(n + k)$ | $O(k)$ | ✅ | ❌ | ❌ |
| 桶排序 | $O(n + k)$ | $O(n^2)$ | $O(n + k)$ | $O(n)$ | ✅ | ❌ | ✅ |
| 基数排序 | $O(d \cdot (n + k))$ | $O(d \cdot (n + k))$ | $O(d \cdot (n + k))$ | $O(n + k)$ | ✅ | ❌ | ❌ |

> 注：$n$ 是待排序元素个数，$k$ 是值域范围，$d$ 是数字位数。希尔排序的时间复杂度与 gap 序列有关，表中为 Hibbard 增量序列的典型表现。

## 4.2 交换排序

### 4.2.1 冒泡排序（Bubble Sort）

#### 原理

冒泡排序得名于它的工作方式——较大的元素像气泡一样逐渐"浮"到数组的顶端。它的核心思想是：

> 重复遍历数组，依次比较相邻的两个元素，如果顺序错误就交换。每轮遍历后，最大的元素会"冒泡"到末尾。

#### 基本实现

```java
void bubbleSort(int[] arr) {
    int n = arr.length;
    for (int i = 0; i < n - 1; i++) {
        for (int j = 0; j < n - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                swap(arr, j, j + 1);
            }
        }
    }
}
```

#### 优化：提前终止

如果某轮遍历中没有发生任何交换，说明数组已经有序，可以提前终止。这个优化使冒泡排序在最好情况下达到 $O(n)$。

```java
void bubbleSortOptimized(int[] arr) {
    int n = arr.length;
    for (int i = 0; i < n - 1; i++) {
        boolean swapped = false;
        for (int j = 0; j < n - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                swap(arr, j, j + 1);
                swapped = true;
            }
        }
        if (!swapped) break;
    }
}
```

#### 复杂度分析

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | $O(n)$ | 数组已有序，一轮遍历后提前终止 |
| 最坏 | $O(n^2)$ | 数组逆序，需要 $n(n-1)/2$ 次比较 |
| 平均 | $O(n^2)$ | 随机排列 |

冒泡排序虽然效率低下，但它的简单性和稳定性使其成为教学中的经典入门算法。

### 4.2.2 快速排序（Quick Sort）

#### 原理

快速排序是实践中最快的通用排序算法之一，由 C. A. R. Hoare 于 1960 年提出。它采用分治策略：

1. **选择基准（Pivot Selection）**：从数组中选出一个元素作为基准。
2. **分区（Partition）**：将数组重新排列，使得所有小于基准的元素都在基准左边，大于基准的都在右边。
3. **递归排序**：递归地对基准左右两个子数组进行快速排序。

快速排序的"分治"与归并排序不同——归并排序的难点在"合"，快速排序的难点在"分"。

#### Pivot 选择策略

Pivot 的选择直接决定了快速排序的性能：

| 策略 | 方法 | 优点 | 缺点 |
|------|------|------|------|
| 固定选择 | 选择第一个或最后一个元素 | 实现简单 | 对有序数组退化为 $O(n^2)$ |
| 随机选择 | 随机选一个元素 | 避免最坏情况的概率极低 | 随机数有开销 |
| 三数取中 | 选首、中、尾三个元素的中位数 | 有效避免退化，实践中常用 | 额外比较 |

**三数取中（Median-of-Three）** 是工业界最常用的策略。它选择 `arr[left]`、`arr[mid]`、`arr[right]` 三个元素的中位数作为 pivot，能显著减少最坏情况发生的概率。

#### 分区方案：Lomuto vs Hoare

##### Lomuto 分区（简单易懂）

Lomuto 分区由 Nico Lomuto 提出，逻辑直观，适合教学：

```java
int lomutoPartition(int[] arr, int low, int high) {
    int pivot = arr[high];  // 选择最后一个元素为 pivot
    int i = low - 1;        // i 指向小于 pivot 的区域的最后一个元素
    for (int j = low; j < high; j++) {
        if (arr[j] <= pivot) {
            i++;
            swap(arr, i, j);
        }
    }
    swap(arr, i + 1, high);  // 将 pivot 放到正确位置
    return i + 1;            // 返回 pivot 的最终位置
}
```

**特点：**
- 实现简单，容易理解
- 每次 partition 只做一次 swap（加上循环内的交换）
- **但当所有元素都相等时，退化为 $O(n^2)$**（因为将相等元素全部归到左边）
- 执行约 $n$ 次交换，效率略低于 Hoare

##### Hoare 分区（效率更高）

Hoare 分区是快速排序发明者 C. A. R. Hoare 提出的原始方案：

```java
int hoarePartition(int[] arr, int low, int high) {
    int pivot = arr[low + (high - low) / 2];  // 选择中间元素为 pivot
    int i = low - 1;
    int j = high + 1;
    while (true) {
        do { i++; } while (arr[i] < pivot);
        do { j--; } while (arr[j] > pivot);
        if (i >= j) return j;
        swap(arr, i, j);
    }
}
```

**特点：**
- 双向扫描，平均交换次数只有 Lomuto 的 $1/3$
- 所有元素相等时不会退化（因为 `arr[i] < pivot` 和 `arr[j] > pivot` 条件在相等时不触发，指针各自向中间移动）
- 返回的 `j` 不一定是 pivot 的准确位置，需要递归 `[low, j]` 和 `[j+1, high]`

**两种方案对比：**

| 特性 | Lomuto | Hoare |
|------|--------|-------|
| 实现复杂度 | 简单 | 稍复杂 |
| 平均交换次数 | 约 $n$ 次 | 约 $n/3$ 次 |
| 相等元素退化 | 是（$O(n^2)$） | 否 |
| pivot 选取 | 通常选最后一个 | 通常选中间元素 |
| 返回值语义 | pivot 的最终位置 | 分区边界（非 pivot 位置） |

#### 最坏情况分析

快速排序的最坏情况发生在每次 partition 都将一个大小为 $n$ 的数组分成 $n-1$ 和 $0$ 两部分，此时递归深度为 $n$，时间复杂度为 $O(n^2)$。

**什么情况下发生最坏情况？**
- Lomuto + 固定选最后一个 pivot：数组已有序或逆序时（每次 select 到最大/最小元素）
- 三数取中 + 随机数据：概率极低（约为 $2/n!$）

**为什么实践中仍用快速排序？**
1. 最坏情况概率极低（尤其是结合随机化或三数取中）
2. 常数因子小，平均情况下比其他 $O(n \log n)$ 排序快 2~3 倍
3. 良好的缓存局部性（顺序访问）
4. 原地排序，空间复杂度 $O(\log n)$

## 4.3 插入排序

### 4.3.1 直接插入排序（Insertion Sort）

#### 原理

插入排序的工作原理类似于整理扑克牌——将每张牌插入到已排序的手牌中的正确位置。

> 将数组分为已排序区和未排序区，每次从未排序区取出第一个元素，在已排序区中找到合适的位置插入。

```java
void insertionSort(int[] arr) {
    for (int i = 1; i < arr.length; i++) {
        int key = arr[i];
        int j = i - 1;
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];  // 将大于 key 的元素右移
            j--;
        }
        arr[j + 1] = key;  // 将 key 插入正确位置
    }
}
```

#### 特点
- **自适应**：对近乎有序的数据，内层循环很快退出，接近 $O(n)$
- **稳定**：插入时相等元素不会交换位置
- **原地排序**
- 当 $n$ 较小时（通常 $\le 47$），插入排序比 $O(n \log n)$ 排序更快（常数因子小）

#### 复杂度

| 情况 | 时间复杂度 | 场景 |
|------|-----------|------|
| 最好 | $O(n)$ | 数组已有序，每个元素只需比较一次 |
| 最坏 | $O(n^2)$ | 数组逆序，每个元素都需要移动到最前面 |
| 平均 | $O(n^2)$ | 随机排列 |

### 4.3.2 希尔排序（Shell Sort）

#### 原理

希尔排序是插入排序的改进版本，由 Donald Shell 于 1959 年提出。它通过**分组插入**来解决插入排序"每次只能移动一位"的低效问题：

> 先将整个数组按一定的间隔（gap）分成若干子序列，对每个子序列进行插入排序；然后逐步缩小 gap，直到 gap=1 时进行最后一次插入排序。

```java
void shellSort(int[] arr) {
    int n = arr.length;
    // 使用 Knuth 增量序列：gap = gap * 3 + 1
    int gap = 1;
    while (gap < n / 3) gap = gap * 3 + 1;

    while (gap >= 1) {
        for (int i = gap; i < n; i++) {
            int key = arr[i];
            int j = i;
            while (j >= gap && arr[j - gap] > key) {
                arr[j] = arr[j - gap];
                j -= gap;
            }
            arr[j] = key;
        }
        gap /= 3;
    }
}
```

#### Gap 序列的影响

希尔排序的性能**高度依赖 gap 序列的选择**：

| Gap 序列 | 递推公式 | 平均时间 | 最坏时间 |
|----------|---------|---------|---------|
| Shell 原始 | $n/2, n/4, ..., 1$ | $O(n^{1.5})$ | $O(n^2)$ |
| Hibbard | $2^k - 1$ | $O(n^{1.25})$ | $O(n^{1.5})$ |
| Knuth | $(3^k - 1)/2$ | $O(n^{1.3})$ | $O(n^{1.5})$ |
| Sedgewick | $4^k + 3 \cdot 2^{k-1} + 1$ | $O(n^{1.25})$ | $O(n^{4/3})$ |

希尔排序的时间复杂度分析非常复杂，至今仍是开放研究问题。实践中 Knuth 或 Sedgewick 序列已经足够好。

> **注意**：希尔排序是不稳定的——因为在分组排序过程中，等值元素可能被分配到不同的组，从而改变相对顺序。

## 4.4 选择排序

### 4.4.1 简单选择排序（Selection Sort）

#### 原理

选择排序的思路非常直观：

> 每次从待排序区间中选出最小的元素，放到已排序区间的末尾。

```java
void selectionSort(int[] arr) {
    for (int i = 0; i < arr.length - 1; i++) {
        int minIdx = i;
        for (int j = i + 1; j < arr.length; j++) {
            if (arr[j] < arr[minIdx]) {
                minIdx = j;
            }
        }
        swap(arr, i, minIdx);
    }
}
```

#### 特点

- **不稳定**（常见实现中，交换可能打乱相等元素的顺序）。例如 `[3a, 3b, 1]` → 第一次选择后 `[1, 3b, 3a]`，`3a` 和 `3b` 的相对顺序改变了。
- **非自适应**：无论输入数据是否有序，比较次数始终是 $n(n-1)/2$
- **原地排序**
- **交换次数少**：最多 $n-1$ 次交换，适合交换成本高的场景

#### 复杂度

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | $O(n^2)$ | 无论有序与否，都需要扫描所有剩余元素 |
| 最坏 | $O(n^2)$ | 同上 |
| 平均 | $O(n^2)$ | 同上 |

### 4.4.2 堆排序（Heap Sort）

#### 原理

堆排序利用**二叉堆**（最大堆）的数据结构来进行排序。核心思想：

1. **建堆（Build Heap）**：将无序数组构建成一个最大堆
2. **排序**：反复将堆顶元素（最大值）与堆的最后一个元素交换，堆大小减 1，然后对新的堆顶进行下沉（sift down）操作以恢复堆性质

#### 关键操作

**下沉（Sift Down）**：从某个节点开始，如果它比子节点小，就与较大的子节点交换，直到满足堆性质。

```java
/**
 * 下沉操作：将索引 i 处的元素下沉到正确位置
 * @param n 当前堆的有效大小
 */
void siftDown(int[] arr, int n, int i) {
    while (true) {
        int largest = i;         // 当前节点
        int left = 2 * i + 1;    // 左子节点
        int right = 2 * i + 2;   // 右子节点

        if (left < n && arr[left] > arr[largest]) {
            largest = left;
        }
        if (right < n && arr[right] > arr[largest]) {
            largest = right;
        }
        if (largest == i) break; // 已经满足堆性质

        swap(arr, i, largest);
        i = largest;             // 继续向下检查
    }
}
```

**建堆（Building the Heap）**：从最后一个非叶子节点开始，逐个向上做下沉操作。这种方式的时间复杂度为 $O(n)$（不是 $O(n \log n)$）。

```java
void buildMaxHeap(int[] arr) {
    int n = arr.length;
    // 最后一个非叶子节点索引为 n/2 - 1
    for (int i = n / 2 - 1; i >= 0; i--) {
        siftDown(arr, n, i);
    }
}
```

**完整排序：**

```java
void heapSort(int[] arr) {
    int n = arr.length;
    // 1. 建堆 O(n)
    for (int i = n / 2 - 1; i >= 0; i--) {
        siftDown(arr, n, i);
    }
    // 2. 排序 O(n log n)
    for (int i = n - 1; i > 0; i--) {
        swap(arr, 0, i);        // 将堆顶（最大值）交换到末尾
        siftDown(arr, i, 0);    // 对新的堆顶做下沉
    }
}
```

#### 复杂度分析

| 操作 | 时间复杂度 | 说明 |
|------|-----------|------|
| 建堆 | $O(n)$ | 从最后一个非叶子节点向上做下沉，精确计算为 $\sum_{h=0}^{\log n} \frac{n}{2^{h+1}} \cdot O(h) = O(n)$ |
| 每次下沉 | $O(\log n)$ | 堆的高度为 $\log n$ |
| 总排序 | $O(n \log n)$ | 需要进行 $n-1$ 次下沉 |
| 空间 | $O(1)$ | 完全原地排序 |

#### 堆排序 vs 快速排序

| 对比项 | 堆排序 | 快速排序 |
|--------|-------|---------|
| 最坏情况 | $O(n \log n)$，稳定 | $O(n^2)$（可优化） |
| 平均情况 | $O(n \log n)$ | $O(n \log n)$，但常数小得多 |
| 常数因子 | 大（约 2~3 倍于快排） | 小 |
| 缓存性能 | 差（跳跃式访问，不连续） | 好（顺序访问） |
| 原地排序 | 是 | 是 |
| 稳定性 | 否 | 否 |

堆排序虽然最坏情况也是 $O(n \log n)$，但由于常数因子大和缓存性能差，在实践中**通常慢于快速排序**。

## 4.5 归并排序与分布式排序

### 4.5.1 归并排序（Merge Sort）

#### 原理

归并排序是分治法的经典应用。它将数组分成两半，分别排序后合并：

```
分解：[38, 27, 43, 3, 9, 82, 10]
         /                    \
  [38, 27, 43, 3]        [9, 82, 10]
   /         \            /        \
[38, 27]   [43, 3]     [9, 82]    [10]
  /    \      /   \      /    \      |
[38]  [27]  [43]  [3]  [9]  [82]   [10]
  \    /      \   /      \    /      |
[27, 38]    [3, 43]     [9, 82]   [10]
    \        /            \       /
  [3, 27, 38, 43]      [9, 10, 82]
        \                  /
      [3, 9, 10, 27, 38, 43, 82]
```

#### 自顶向下（Top-down） vs 自底向上（Bottom-up）

**自顶向下（递归）：**

```java
void mergeSort(int[] arr, int left, int right) {
    if (left >= right) return;
    int mid = left + (right - left) / 2;
    mergeSort(arr, left, mid);
    mergeSort(arr, mid + 1, right);
    merge(arr, left, mid, right);
}
```

**自底向上（迭代）：**

```java
void mergeSortBottomUp(int[] arr) {
    int n = arr.length;
    for (int size = 1; size < n; size *= 2) {
        for (int left = 0; left < n - size; left += 2 * size) {
            int mid = left + size - 1;
            int right = Math.min(left + 2 * size - 1, n - 1);
            merge(arr, left, mid, right);
        }
    }
}
```

两种方式的时间复杂度相同，但自底向上避免了递归调用开销，且更易于并行化。

#### 复杂度

| 情况 | 时间复杂度 | 空间复杂度 |
|------|-----------|-----------|
| 全部 | $O(n \log n)$ | $O(n)$（需要临时数组） |

归并排序是**稳定**的，这是它相对于快速排序和堆排序的重要优势。

### 4.5.2 外部排序（External Sorting）

#### 问题背景

当数据量超出内存容量时（例如对 100GB 的文件排序），内部排序算法不再适用。外部排序解决了这一问题。

#### 核心思想：归并排序的扩展

外部排序通常采用**多路归并**策略：

1. **分割阶段**：将大文件分成多个小块，每块大小刚好能读入内存。对每个小块在内存中排序后写回磁盘。
2. **归并阶段**：使用多路归并（k-way merge）将多个有序块合并为一个有序文件。

```
原始大文件（100GB）
    ↓ 分割成 M 个 1GB 的块
[块1] [块2] [块3] ... [块M]
    ↓ 每块内部排序（内存中）
[有序块1] [有序块2] ... [有序块M]
    ↓ 多路归并（每次从 M 个块中取最小值）
[有序大文件]
```

#### 多路归并的优化——败者树（Loser Tree）

传统的 k 路归并中，每次从 k 个候选者中选择最小值需要 $O(k)$ 的比较。使用**败者树**可以将选择代价降低到 $O(\log k)$。

败者树是一棵完全二叉树，叶子节点是 k 个输入序列的当前元素，内部节点记录两个子节点中"败者"（较大者）的序号，"胜者"（较小者）向上传递到根节点。根节点就是全局最小值的来源。

#### 性能考量

外部排序的瓶颈主要是 **I/O 次数**，而不是 CPU 计算。因此优化的重点是减少磁盘读写：

- 使用更大的内存缓冲区
- 使用更快的磁盘（SSD）
- 使用多路归并减少归并轮数（k 越大，归并轮数越少）
- 使用双缓冲技术，让 I/O 和计算重叠

## 4.6 线性排序

线性排序（Linear-time Sorting）突破了比较排序 $O(n \log n)$ 的下界，但它们对输入数据有特殊要求——必须利用数据本身的数值特性。

### 4.6.1 计数排序（Counting Sort）

#### 原理

计数排序适用于**值域范围较小**的整数数组。它通过统计每个值出现的次数，然后根据统计信息重建有序序列。

```java
void countingSort(int[] arr) {
    if (arr.length == 0) return;

    // 1. 找出值域范围
    int max = arr[0], min = arr[0];
    for (int v : arr) {
        if (v > max) max = v;
        if (v < min) min = v;
    }
    int range = max - min + 1;

    // 2. 计数
    int[] count = new int[range];
    for (int v : arr) count[v - min]++;

    // 3. 累加（使 count 成为"每个值最后出现位置"的索引）
    for (int i = 1; i < range; i++) count[i] += count[i - 1];

    // 4. 从后向前遍历原数组，放入输出数组（保证稳定性）
    int[] output = new int[arr.length];
    for (int i = arr.length - 1; i >= 0; i--) {
        int idx = --count[arr[i] - min];
        output[idx] = arr[i];
    }

    // 5. 复制回原数组
    System.arraycopy(output, 0, arr, 0, arr.length);
}
```

#### 复杂度分析

| 指标 | 值 |
|------|-----|
| 时间复杂度 | $O(n + k)$，其中 $k$ 是值域范围 |
| 空间复杂度 | $O(k)$，用于计数数组 |
| 稳定性 | 稳定 |

**适用条件：** 值域范围 $k$ 不能太大，否则空间和时间开销都会剧增。当 $k = O(n)$ 时，计数排序是完美的线性排序。

### 4.6.2 桶排序（Bucket Sort）

#### 原理

桶排序将数据分到有限数量的"桶"中，每个桶内部独立排序，然后依次输出所有桶。

```java
void bucketSort(float[] arr) {
    if (arr.length <= 1) return;

    // 1. 创建 n 个桶
    int n = arr.length;
    List<List<Float>> buckets = new ArrayList<>(n);
    for (int i = 0; i < n; i++) buckets.add(new ArrayList<>());

    // 2. 将元素放入桶中（假设数据服从 [0,1) 均匀分布）
    for (float v : arr) {
        int bucketIdx = (int) (v * n);
        buckets.get(bucketIdx).add(v);
    }

    // 3. 每个桶内部排序
    for (List<Float> bucket : buckets) Collections.sort(bucket);

    // 4. 合并所有桶
    int idx = 0;
    for (List<Float> bucket : buckets) {
        for (float v : bucket) arr[idx++] = v;
    }
}
```

#### 复杂度分析

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | $O(n + k)$ | 数据均匀分布，每个桶只有少量元素 |
| 最坏 | $O(n^2)$ | 所有数据进入同一个桶 |
| 平均 | $O(n + k)$ | 假设数据服从均匀分布 |

**适用条件：** 数据服从均匀分布。当数据分布极不均匀时，桶排序退化为 $O(n^2)$。

### 4.6.3 基数排序（Radix Sort）

#### 原理

基数排序按数字的每一位进行排序。有两种变体：

- **LSD（Least Significant Digit）**：从最低位开始排序，逐位向高位进行。需要稳定排序作为子程序（通常使用计数排序）。
- **MSD（Most Significant Digit）**：从最高位开始排序，递归地对每个桶排序。可以用插入排序处理小桶。

#### LSD 基数排序

```java
void radixSort(int[] arr) {
    // 找到最大值决定位数
    int max = arr[0];
    for (int v : arr) if (v > max) max = v;

    // 逐位排序（使用计数排序作为稳定子排序）
    for (int exp = 1; max / exp > 0; exp *= 10) {
        countingSortByDigit(arr, exp);
    }
}

void countingSortByDigit(int[] arr, int exp) {
    int n = arr.length;
    int[] output = new int[n];
    int[] count = new int[10];  // 0-9 共 10 个数字

    for (int v : arr) count[(v / exp) % 10]++;
    for (int i = 1; i < 10; i++) count[i] += count[i - 1];

    for (int i = n - 1; i >= 0; i--) {
        int digit = (arr[i] / exp) % 10;
        output[--count[digit]] = arr[i];
    }

    System.arraycopy(output, 0, arr, 0, n);
}
```

#### 复杂度分析

| 指标 | LSD 基数排序 | MSD 基数排序 |
|------|-------------|-------------|
| 时间复杂度 | $O(d \cdot (n + k))$ | $O(d \cdot (n + k))$ |
| 空间复杂度 | $O(n + k)$ | $O(n + k)$（或更少，如果递归处理） |
| 稳定性 | 稳定（子排序必须稳定） | 稳定 |

其中 $d$ 是最大数字的位数，$k$ 是进制基数（通常为 10）。

### 线性排序总结

| 算法 | 适用场景 | 数据要求 | 典型 $n$ 下的性能 |
|------|---------|---------|-----------------|
| 计数排序 | 整数，值域小 | $k = O(n)$ | 最快，但 $k$ 大时不可用 |
| 桶排序 | 浮点数，均匀分布 | 知道分布特性 | 均匀时很快 |
| 基数排序 | 整数或定长字符串 | 位数 $d$ 较小 | 适合 $d \ll \log n$ |

## 4.7 JDK 排序源码解析

Java 的 `Arrays.sort()` 和 `Collections.sort()` 是工程中最高频使用的排序方法。JDK 为它们选择了**两种不同的排序算法**，体现了对基本类型和引用类型不同特性的深刻考量。

### 4.7.1 基本类型排序：Dual-Pivot QuickSort

`Arrays.sort(int[])` 等方法对**基本类型数组**使用**双轴快速排序（Dual-Pivot Quicksort）**。

#### 双轴快速排序的原理

双轴快速排序是 Vladimir Yaroslavskiy 于 2009 年提出的改进版快速排序。它与经典快速排序的关键区别在于：

- 经典快速排序：选 **1 个 pivot**，将数组分成 **3 段**（小于、等于、大于）
- 双轴快速排序：选 **2 个 pivot**（要求 pivot1 ≤ pivot2），将数组分成 **4 段**

```
经典快排：
[ < pivot | = pivot | > pivot ]

双轴快排：
[ < p1 | p1 ≤ ... ≤ p2 | = p2 | > p2 ]
         [  中间段   ]
```

#### 双轴的优势

1. **减少递归深度**：一次划分产生 3 个子问题（中间段也不等于 pivot）
2. **更好的缓存局部性**：一次遍历可以处理更多元素
3. **整体性能比经典快排提升约 10-20%**（JDK 官方数据）

#### JDK 的优化细节

JDK 的 `DualPivotQuicksort` 类包含大量精心调优的细节：

- **小数组阈值**：当数组长度 < 47 时，改用插入排序（插入排序在小规模下更快）
- **接近有序**：当数组接近有序时，切换到归并排序
- **几乎有序**：检测到数组几乎有序时，使用经过优化的**成对插入排序（pair insertion sort）**
- **递归深度控制**：限制递归深度，超过阈值时使用堆排序（防止栈溢出）

```java
// JDK 源码中的排序策略（简化示意）
static void sort(int[] a, int left, int right, boolean leftmost) {
    int length = right - left + 1;

    // 小数组使用插入排序
    if (length < INSERTION_SORT_THRESHOLD) { // 47
        // 插入排序...
        return;
    }

    // 检查是否接近有序，是则使用归并排序
    if (length < COUNTING_SORT_THRESHOLD &&  // 286
        nearlySorted) {
        // 归并排序...
        return;
    }

    // 双轴快速排序
    dualPivotQuicksort(a, left, right);
}
```

### 4.7.2 引用类型排序：TimSort

`Arrays.sort(Object[])`、`Collections.sort()` 等对**引用类型**使用 **TimSort**。

#### TimSort 是什么？

TimSort 是 Peter McIlroy 于 1993 年发明，后由 Tim Peters 在 2002 年为 Python 实现的混合排序算法。Java 在 JDK 1.7 引入（JSR 166），现已被多个语言采用（Python、Java、Android、Kotlin 等）。

#### TimSort 的核心思想

TimSort = **归并排序 + 插入排序**的混合体，并针对**部分有序**的数据进行了深度优化：

1. **找出天然有序的片段（Runs）**：扫描数组，识别已经有序（升序或严格降序）的连续子序列
2. **扩展短 Run**：如果某个 Run 太短（小于 `minRun`，通常为 16~32），使用插入排序将其扩展到 `minRun` 长度
3. **优雅地合并 Runs**：维护一个 Run 栈，当栈顶的 Run 长度不满足某些约束时，合并相邻的 Run
4. **合并优化**：使用 **Galloping Mode（飞奔模式）**——当一个 Run 中的元素连续多次被选中时，使用二分查找批量移动

#### 为什么引用类型用 TimSort？

| 原因 | 说明 |
|------|------|
| **稳定性要求** | 引用类型排序通常要求稳定（保持相等元素的相对顺序），而快速排序不稳定 |
| **部分有序优化** | 工程实践中，引用类型数据经常是部分有序的（如数据库查询结果按某字段排序后再按另一字段排序） |
| **比较成本高** | 引用类型的 `compareTo()` 可能包含复杂逻辑，TimSort 在合并时会尽量减少比较次数 |
| **安全性** | 快速排序的最坏情况 $O(n^2)$ 可能导致生产事故，TimSort 保证 $O(n \log n)$ |

### 4.7.3 为什么需要两种实现？

这是一个经典的设计决策问题：

| 对比项 | 基本类型（Dual-Pivot QuickSort） | 引用类型（TimSort） |
|--------|--------------------------------|--------------------|
| 稳定性 | 不需要（基本类型相等即相同） | 需要（引用类型排序通常要求稳定） |
| 比较成本 | 极低（直接比较数值） | 可能很高（`compareTo` 可能有复杂逻辑） |
| 内存使用 | 尽量原地排序 | 可以接受 $O(n)$ 额外空间 |
| 适应性 | 不专门优化 | 深度优化部分有序数据 |
| 最坏性能 | $O(n^2)$（概率极低） | $O(n \log n)$（保证） |

**核心结论**：`Arrays.sort()` 对基本类型和引用类型采用不同算法，是因为**它们对稳定性、内存、最坏性能的要求不同**。基本类型不需要稳定但需要尽量少用内存（可能处理数十亿个 `int`），而引用类型需要稳定且 `compareTo()` 的成本可能很高。

### 4.7.4 `Arrays.parallelSort()`

JDK 1.8 引入了 `Arrays.parallelSort()`，使用 **Fork/Join 框架** 并行排序：

- 当数组长度小于阈值（约 8192 或根据 CPU 核心数调整）时，退化为串行排序
- 大于阈值时，将数组分割成多个子任务并行排序，最后合并
- 在大型数组上（$\ge 10^7$），并行排序比串行排序快 2~4 倍（视 CPU 核心数而定）

## 4.8 排序算法选择策略

面对一个具体的排序需求，如何选择合适的算法？以下是基于工程实践的决策指南。

### 决策流程图

```
待排序数据
    │
    ├── 数据量大到无法全部加载到内存？
    │   └── → 外部排序（多路归并）
    │
    ├── 数据是基本类型？
    │   └── → Arrays.sort()（Dual-Pivot QuickSort）
    │
    ├── 数据是引用类型？
    │   └── → Arrays.sort() / Collections.sort()（TimSort）
    │
    ├── 需要写入高性能排序算法（面试/手写）？
    │   ├── 数据量小（< 1000） → 插入排序
    │   ├── 数据量大，不要求稳定 → 快速排序（三数取中 + Hoare 分区）
    │   ├── 数据量大，要求稳定 → 归并排序
    │   ├── 最坏性能有严格要求 → 堆排序
    │   ├── 整数，值域范围小 → 计数排序
    │   ├── 整数，值域范围大但位数少 → 基数排序
    │   └── 浮点数，均匀分布 → 桶排序
    │
    └── 需要并行排序？
        └── → Arrays.parallelSort()
```

### 按维度详细决策

#### 1. 按数据规模

| 规模 | 推荐算法 | 原因 |
|------|---------|------|
| $n \le 47$ | 插入排序 | 常数因子小，小规模下最快 |
| $47 < n \le 10^4$ | 快速排序 | 常数因子小，平均性能好 |
| $10^4 < n \le 10^7$ | 快速排序 / TimSort | JDK 默认选择，经过深度优化 |
| $n > 10^7$ | `parallelSort()` / 外部排序 | 利用多核，或数据无法一次性加载 |

#### 2. 按数据特征

| 特征 | 推荐算法 | 说明 |
|------|---------|------|
| 部分有序 | TimSort、插入排序、冒泡排序（带 early exit） | 自适应算法在部分有序数据上显著更快 |
| 大量重复元素 | 三路快排（3-way partition） | 将等于 pivot 的集中处理，避免退化 |
| 小值域整数 | 计数排序 | $O(n + k)$，$k$ 不大时极快 |
| 多位数整数 | 基数排序 | $O(d \cdot n)$，$d$ 不大时快于 $O(n \log n)$ |
| 浮点数 | JDK 默认排序 | JDK 处理了 NaN、-0.0 等边界情况 |

#### 3. 按稳定性需求

| 场景 | 策略 |
|------|------|
| 多关键字排序 | 必须用稳定排序（归并排序或插入排序） |
| 基本类型 | 不需要稳定（相等元素不可区分） |
| 引用类型 | 默认应使用稳定排序 |

#### 4. 按内存限制

| 内存限制 | 可选算法 |
|---------|---------|
| 严格原地（$O(1)$ 额外空间） | 堆排序、希尔排序 |
| 少量额外空间（$O(\log n)$） | 快速排序（递归栈） |
| 允许 $O(n)$ 额外空间 | 归并排序、计数排序 |

### 工程最佳实践总结

1. **能交给 JDK 的，绝不自己写**：`Arrays.sort()` 和 `Collections.sort()` 已经过数十年的深度优化
2. **大数据量用 `parallelSort()`**：多核环境下，并行排序能充分利用 CPU
3. **需要稳定排序用 TimSort**：JDK 的 TimSort 实现兼顾了稳定性、适应性和最坏性能保障
4. **手写排序时**：
   - 小数据（$\le 47$）：插入排序
   - 大数据，快速排序（三数取中 + 插入排序兜底小数组）
   - 数据有特殊性质时考虑线性排序
5. **外部排序**：数据量超出内存时，使用多路归并，注意 I/O 优化
6. **性能测试**：对业务数据做实际的基准测试，不要只看复杂度理论

> 排序算法选择的最高原则是：**理解你的数据特征**。没有万能的排序算法，只有最适合你数据的排序策略。
