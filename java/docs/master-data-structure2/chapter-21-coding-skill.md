# 第21章 代码实现能力

## 21.1 手写数据结构的艺术

> **核心价值**：手写数据结构是检验理解深度的最好方式。读源码100遍抵不过手写一遍。

**手写的层次**：

```
Level 1: 能写出核心API（如ArrayList的add/get/remove）
Level 2: 能处理边界情况（空、满、并发）
Level 3: 能像JDK一样优化（懒加载、位运算、扩容策略）
Level 4: 能根据场景设计新的数据结构
```

**手写练习建议**：
1. 先理解，再默写，不参考源码
2. 写完后用测试用例验证
3. 对比JDK源码，找出差异
4. 理解差异的原因（为什么JDK这么设计）

## 21.2 代码质量与可读性

**质量维度**：

| 维度 | 要求 | 示例 |
|------|------|------|
| 正确性 | 处理所有边界情况 | null、空、满、单元素 |
| 清晰性 | 命名准确、逻辑直观 | isEmpty()而非check() |
| 效率 | 时间/空间复杂度明确 | 文档注释说明复杂度 |
| 健壮性 | 参数验证、异常处理 | 非null检查、越界检查 |
| 可测试性 | 方法有明确输入输出 | 纯函数>有副作用 |

## 21.4 重构与设计模式

**数据结构中的设计模式**：

| 模式 | 应用 | 示例 |
|------|------|------|
| 迭代器 | 遍历集合 | Iterator |
| 工厂 | 创建集合 | Collections.unmodifiableList() |
| 适配器 | 接口转换 | Arrays.asList() |
| 装饰器 | 功能增强 | SynchronizedCollection |
| 模板方法 | 算法骨架 | AbstractList |

---

> **本章总结**：手写数据结构是深入理解原理的最佳方式。代码质量的关键在于处理所有边界情况。TDD能够确保数据结构的正确性。设计模式在Java集合框架中广泛应用，理解它们有助于写出更优雅的代码。
