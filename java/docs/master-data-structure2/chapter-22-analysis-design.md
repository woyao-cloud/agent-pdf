# 第22章 分析设计能力

## 22.1 如何分析问题

### 问题分析框架

面对一个需要数据结构的工程问题时，按以下步骤分析：

```
1. 明确约束条件
   - 数据量级（千？万？百万？亿？）
   - 操作频率（读多写少？读写均衡？）
   - 实时性要求（毫秒级？秒级？）
   - 内存限制（内存充足？有限？）
   
2. 确定核心操作
   - 主要操作是什么？（查找？插入？遍历？）
   - 需要支持什么特殊操作？（范围查询？前缀匹配？）
   
3. 选择合适的数据结构
   - 根据操作复杂度选择
   - 考虑实现复杂度
   - 考虑维护成本
   
4. 验证和优化
   - 用JMH验证性能
   - 观察实际运行指标
   - 持续优化
```

## 22.2 数据结构选择决策树

```
需要什么操作？
├── 快速查找 → HashMap
│   ├── 有序 → TreeMap
│   └── 线程安全 → ConcurrentHashMap
├── 快速插入/删除
│   ├── 首部 → LinkedList
│   └── 尾部 → ArrayList
├── 优先级 → PriorityQueue
├── FIFO → ArrayDeque / LinkedBlockingQueue
├── LIFO → ArrayDeque
├── 字符串前缀 → Trie
├── 区间查询 → SegmentTree / FenwickTree
└── 连通性 → UnionFind
```

## 22.3 系统设计中的数据结构

### 经典系统设计案例

| 系统 | 核心数据结构 | 原因 |
|------|-------------|------|
| Redis | 跳表、哈希表、双链表 | 内存+高性能 |
| MySQL InnoDB | B+树 | 磁盘I/O优化 |
| 搜索引擎 | 倒排索引 | 全文搜索 |
| 消息队列 | 链表/环形缓冲区 | FIFO+高性能 |
| 缓存系统 | LRU LinkedHashMap | 淘汰策略 |

---

## 22.4 架构设计原则

**数据结构在架构中的角色**：
- 底层存储决定系统性能上限
- 数据结构的选择影响代码复杂度
- 并发数据结构决定系统的扩展性

---

> **本章总结**：分析问题的关键是从约束条件出发，确定核心操作，再选择合适的数据结构。系统设计中的数据结构选择直接影响系统的性能和可维护性。数据结构决策树是快速选型的有力工具。
