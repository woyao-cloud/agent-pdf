# 第25章：模拟试题与解析

## 章节概述

本章提供一套完整的 Claude Certified Architect 认证考试模拟试题，包含 20 道精心设计的题目，全面覆盖考试大纲中的 10 个知识领域。每道题目都配有详细的答案解析，不仅给出正确答案，还深入分析错误选项的陷阱所在、考察的知识点细节以及相关的实践建议。通过完成这套模拟试题，读者可以准确评估自己的备考水平，发现知识盲区，并熟悉真实考试的题风和难度。

## 学习目标

- 通过模拟试题全面检验各知识领域的掌握程度
- 理解每道题目背后的考察意图和解题思路
- 掌握常见考点和易错点，避免在真实考试中犯类似错误
- 通过错题分析制定针对性的复习计划
- 适应考试题量和时间压力，提升应试能力

## 核心知识点

### 第一模块：基础知识题（共 6 题）

**第 1 题（选择题）** Claude Code 的核心工作模式是什么？

A. 作为独立的代码生成器，一次性生成完整项目代码
B. 通过对话式交互与开发者协作，在上下文中理解和修改代码
C. 仅作为代码补全工具，辅助 IDE 的自动补全功能
D. 作为静态代码分析工具，检测代码中的语法错误

**答案：B**

**解析：** Claude Code 的核心工作模式是对话式交互协作。它不是一个独立的代码生成器（选项 A），而是与开发者形成协作关系，通过理解上下文来逐步完成代码任务。虽然 Claude Code 有代码补全的能力，但这只是其功能的一小部分（选项 C 过于狭隘）。Claude Code 也具备代码分析能力，但其核心价值在于主动理解和修改代码，而不是单纯的静态分析（选项 D）。理解这一核心区别对于后续学习至关重要，因为许多高级功能（如 Agent 模式、多文件编辑）都建立在对话式交互的基础上。常见误区是将 Claude Code 简单等同于"代码生成工具"，而忽视了其作为"编程协作者"的本质定位。

**第 2 题（判断题）** 在 Claude Code 中，`/init` 命令用于初始化一个新的 Git 仓库。

**答案：错误**

**解析：** `/init` 命令的作用是在当前项目目录中初始化 Claude Code 的配置文件（生成 CLAUDE.md 文件），而不是初始化 Git 仓库。CLAUDE.md 文件用于定义项目范围、编码规范、技术栈等上下文信息，帮助 Claude Code 更好地理解项目。初始化 Git 仓库应该使用 `git init` 命令。这是一个常见的概念混淆点，考生需要清晰区分 Claude Code 的初始化命令与常规开发工具的操作。

**第 3 题（选择题）** 以下哪个命令用于查看 Claude Code 的当前会话统计信息？

A. `/help`
B. `/stats`
C. `/info`
D. `/status`

**答案：B**

**解析：** `/stats` 命令用于显示当前会话的统计信息，包括已处理的文件数量、执行的命令次数、消耗的 Token 数量等。`/help` 显示帮助信息，`/info` 显示 Claude Code 的版本和配置信息，`/status` 不是 Claude Code 的内置命令。掌握这些基本命令的区别对于日常使用和考试都非常重要，建议通过实际操作加深记忆。

**第 4 题（选择题）** CLAUDE.md 文件的主要作用是什么？

A. 存储 API Key 和认证信息
B. 定义项目的开发规范和上下文信息，指导 Claude Code 的行为
C. 记录项目的依赖关系
D. 保存 Claude Code 的插件配置

**答案：B**

**解析：** CLAUDE.md 是项目级别的配置文件，用于向 Claude Code 描述项目的关键信息，包括技术栈、代码风格、项目结构、常用命令、编码规范等。这些信息帮助 Claude Code 在生成代码和建议时与项目现有风格保持一致。API Key 应该通过环境变量或配置文件管理（选项 A 错误），依赖关系通常由 package.json、requirements.txt 等文件管理（选项 C 错误），插件配置不在 CLAUDE.md 中管理（选项 D 错误）。编写高质量的 CLAUDE.md 是使用 Claude Code 的重要技能，考试中可能会考察 CLAUDE.md 的推荐内容组织方式。

**第 5 题（选择题）** 在 Claude Code 中，以下哪个命令用于清除当前对话历史并开始新的会话？

A. `/clear`
B. `/new`
C. `/reset`
D. `/reload`

**答案：C**

**解析：** `/reset` 命令用于清除当前会话的对话历史，让 Claude Code "忘记"之前的对话内容，从全新的状态开始交互。这在切换任务或需要重新设定上下文时非常有用。`/clear` 不是 Claude Code 的有效命令，`/new` 和 `/reload` 也不是标准的会话管理命令。需要注意的是，`/reset` 只清除对话历史，不会影响项目的文件状态或配置。理解 `/reset` 的使用场景——例如在完成一个功能后切换到另一个不相关的任务时——能够帮助开发者更高效地管理会话。

**第 6 题（判断题）** Claude Code 可以在没有网络连接的情况下正常运行。

**答案：错误**

**解析：** Claude Code 依赖云端的 AI 模型进行代码理解和生成，因此必须保持网络连接才能正常工作。虽然命令行的交互界面是本地的，但所有的代码分析、生成和推理都需要发送到 Anthropic 的服务器进行处理。这一点与传统的本地开发工具有本质区别。在考试环境下，确保网络稳定也是一个重要的注意事项。不过，某些辅助功能（如本地缓存的文件信息）在离线状态下可能部分可用，但核心功能无法工作。

### 第二模块：技能应用题（共 8 题）

**第 7 题（选择题）** 当需要 Claude Code 分析项目中未被使用的依赖时，最合适的提示策略是什么？

A. 直接要求"分析 package.json 中的依赖"
B. 提供项目入口文件和依赖配置文件，要求 Claude Code 追踪代码路径找出未使用的依赖
C. 要求 Claude Code 逐一检查每个依赖的官方文档
D. 手动列出所有依赖并逐个询问 Claude Code

**答案：B**

**解析：** 最佳策略是提供项目结构和入口文件，利用 Claude Code 的代码分析能力来追踪哪些依赖被实际引用。选项 A 虽然简单，但 Claude Code 仅检查 package.json 无法判断依赖的实际使用情况。选项 C 耗时且不切实际，因为 Claude Code 不需要查阅官方文档来判断代码中的引用。选项 D 效率极低。正确的做法是使用类似"分析 src/ 目录下所有源文件中 import/require 语句，与 package.json 中的 dependencies 进行对比，列出未被引用的依赖"这样的提示。这体现了 Claude Code 的代码分析能力——它能够在项目范围内追踪代码引用关系。

**第 8 题（选择题）** 在 TDD 流程中使用 Claude Code，以下哪个步骤顺序是正确的？

A. 编写实现代码 → 运行测试 → 优化代码
B. 编写测试用例 → 运行测试（预期失败） → 编写实现代码使测试通过 → 重构优化
C. 编写实现代码 → 编写测试用例 → 运行测试 → 修复 Bug
D. 设计架构 → 编写测试用例 → 编写实现代码 → 部署

**答案：B**

**解析：** TDD 的核心流程是 Red-Green-Refactor：先编写测试用例（预期失败，Red），然后编写最小量的实现代码使测试通过（Green），最后在测试保护下重构优化代码（Refactor）。选项 A 是传统的先实现后测试流程，不是 TDD。选项 C 虽然包含测试，但顺序却是先实现后测试，偏离了 TDD 的核心理念。选项 D 混入了架构设计和部署环节，超出了 TDD 的标准范围。使用 Claude Code 进行 TDD 时，可以先让 Claude Code 生成测试用例，然后根据测试失败的信息逐步完善实现代码。关键优势在于 Claude Code 能快速生成符合规范的测试用例，并能根据测试反馈快速迭代实现代码。

**第 9 题（选择题）** 当 Claude Code 生成的代码出现错误时，最有效的调试策略是什么？

A. 直接告诉 Claude Code "代码有错误，请修复它"
B. 提供错误信息、相关代码片段和复现步骤，让 Claude Code 有足够上下文进行诊断
C. 关闭当前会话，重新开始一个新任务
D. 手动修复代码后继续对话

**答案：B**

**解析：** 有效的调试依赖于充分的上下文信息。选项 B 提供了最完整的调试上下文，包括三个关键要素：错误信息（告诉 Claude Code 出了什么问题）、相关代码片段（提供问题发生的位置）和复现步骤（让 Claude Code 理解如何触发问题）。选项 A 过于模糊，Claude Code 无法精确定位问题。选项 C 是极端做法，会丢失当前会话的所有上下文。选项 D 虽然能解决问题，但浪费了利用 Claude Code 进行学习的机会。最佳实践是：先让 Claude Code 分析错误日志，然后逐步提供更多上下文，形成一个迭代式的调试循环。

**第 10 题（选择题）** 在重构大型函数时，以下哪个提示最有效地引导 Claude Code 进行安全重构？

A. "把这个函数拆分成小函数"
B. "重构 processData 函数，将其拆分为 validate、transform 和 format 三个独立函数，每个函数保持单一职责。重构前后需保持相同的输入输出接口，请先分析函数的所有调用方以确保兼容性"
C. "优化这个函数"
D. "重写这个函数，让它更好"

**答案：B**

**解析：** 选项 B 提供了最完整的重构指令：明确指出目标函数、拆分的具体方案、每个新函数的职责、关键的约束条件（保持接口兼容性）以及安全措施（分析调用方）。这种具体的提示能显著提高 Claude Code 重构的成功率。选项 A 和 C 过于笼统，Claude Code 可能不理解拆分粒度的要求。选项 D 中的"更好"主观且模糊。安全重构的关键原则是：精确描述目标、明确约束条件、确保行为不变。在 Claude Code 中进行重构时，建议在 CLAUDE.md 中预先定义好项目的测试要求，这样 Claude Code 重构后可以自动验证是否破坏了现有功能。

**第 11 题（选择题）** 关于 Claude Code 的多文件编辑功能，以下说法正确的是？

A. Claude Code 可以在一次响应中编辑任意数量的文件，没有限制
B. Claude Code 的多文件编辑需要通过多次请求逐个完成
C. Claude Code 可以在一次响应中编辑多个文件，但需要在提示中清晰描述所有更改，并注意文件之间的依赖关系
D. Claude Code 不支持多文件编辑

**答案：C**

**解析：** Claude Code 可以在一轮交互中编辑多个文件，但前提是指令清晰且文件之间的依赖关系明确。选项 A 错误，因为没有限制是不准确的——大量编辑可能受到上下文窗口的限制。选项 B 错误，因为 Claude Code 确实支持一次多文件编辑。选项 D 明显错误。正确使用多文件编辑需要：在提示中明确指出需要修改的所有文件、每个文件的具体更改内容、以及文件之间的交互关系（例如新增模块如何在其他文件中导入更新）。考试中可能会考察多文件编辑的注意事项，如避免同时修改过多文件导致上下文溢出，以及合理安排编辑顺序处理依赖关系。

**第 12 题（判断题）** 在 Claude Code 中，使用 Agent 模式时，开发者不需要对 Claude Code 的操作进行任何监督。

**答案：错误**

**解析：** Agent 模式虽然允许 Claude Code 自主执行多步骤任务，但开发者仍然需要进行监督和审核。Agent 模式的特点是 Claude Code 可以自主规划和执行一系列操作（如创建文件、运行命令、分析结果等），但这并不意味着它可以完全脱离开发者的控制。开发者应在关键决策点进行干预，审查生成的重要代码，确保操作符合项目目标。最佳实践是在 Agent 模式下设定明确的目标范围和约束条件，并定期检查执行进度。考试中需要理解 Agent 模式是一种增强的协作模式，而非完全的自主模式。

**第 13 题（选择题）** 以下关于提示工程中"角色设定"的描述，哪一项是正确的？

A. 角色设定对 Claude Code 的输出质量没有实质影响
B. 角色设定应该尽可能复杂和详细
C. 合理的角色设定可以帮助 Claude Code 采用特定视角分析问题，从而产生更符合需求的结果
D. 角色设定只适用于创意写作任务，不适用于编程任务

**答案：C**

**解析：** 合理的角色设定是提示工程的重要技巧。当要求 Claude Code "以一名资深的 Python 安全工程师的视角审查以下代码"时，它会倾向于采用更严格的安全审查标准，关注安全漏洞和最佳实践。选项 A 错误，大量实践表明角色设定确实能影响输出质量和风格。选项 B 错误，角色设定应该简洁明确，过于复杂的角色描述可能使 Claude Code 混淆。选项 D 错误，角色设定在编程任务中同样有效，可以引导 Claude Code 从不同专业角度分析问题。掌握角色设定的技巧，能在不增加指令复杂度的情况下显著提升输出质量。

**第 14 题（选择题）** 在 Claude Code 中使用 Task 模式时，以下哪项是定义任务的关键要素？

A. 任务名称、任务描述、执行频率
B. 任务目标、所需文件范围、成功标准、约束条件
C. 任务优先级、分配人员、截止日期
D. 任务预算、资源需求、时间估计

**答案：B**

### 第三模块：架构设计题（共 4 题）

**第 15 题（选择题）** 在设计一个大型微服务项目的 AI 辅助开发工作流时，以下哪个 CLAUDE.md 配置策略最合理？

A. 所有微服务共享一个全局 CLAUDE.md，包含所有技术栈信息
B. 每个微服务维护独立的 CLAUDE.md，只包含该服务的相关规范，并在全局项目中设置基础规则
C. 不使用 CLAUDE.md，完全依靠对话中的指令
D. 在根目录放置一个详细的 CLAUDE.md，然后在子目录中不添加任何配置

**答案：B**

**解析：** 对于微服务架构项目，分层配置是最佳实践。在项目根目录设置全局 CLAUDE.md 定义通用的编码规范、Git 工作流、CI/CD 信息等，然后每个微服务模块维护独立的 CLAUDE.md 定义各自的技术栈、框架约定和特定规则。选项 A 会导致信息混杂，各服务的技术差异难以体现。选项 C 完全依赖对话指令效率低下，且每次新会话都需要重复说明。选项 D 缺少了关键的层级细化。这个题目考察的是对 CLAUDE.md 分层管理策略的理解，这在大型项目中尤为重要。

**第 16 题（选择题）** 当你需要 Claude Code 在一个不熟悉的开源项目中添加一个新功能时，最合理的操作流程是？

A. 直接要求 Claude Code "添加 XX 功能"，相信它能自动理解项目结构
B. 先让 Claude Code 分析项目结构和技术栈，了解代码组织方式，然后再逐步引导添加功能
C. 手动阅读所有源代码，然后逐行指导 Claude Code 修改
D. 放弃使用 Claude Code，完全手动开发

**答案：B**

**解析：** 在陌生项目中，循序渐进是最有效的策略。第一步是让 Claude Code 分析项目结构、核心技术、代码组织模式等，建立对项目的理解。然后基于这个理解来设计和实现新功能。选项 A 跳过项目理解阶段，可能导致生成的代码与项目风格不符。选项 C 效率太低，没有充分利用 Claude Code 的能力。选项 D 完全放弃了 AI 辅助的优势。"先理解再行动"的原则不仅适用于 Claude Code，也是与 AI 编程工具协作的基本方法论。

**第 17 题（选择题）** 在评估 Claude Code 生成的代码方案时，以下哪个做法最重要？

A. 完全信任 Claude Code 的输出，直接应用到生产环境
B. 代码方案需要经过审查，重点关注正确性、安全性、性能影响和与现有代码的一致性
C. 只检查语法错误，忽略逻辑和设计问题
D. 要求 Claude Code 多次生成不同方案，选择最长的那个

**答案：B**

**解析：** 虽然 Claude Code 具有很强的代码生成能力，但开发者必须保持批判性思维。审查 Claude Code 生成的代码时，应重点关注：功能正确性（是否满足需求）、安全性（是否引入漏洞）、性能影响（是否导致性能退化）和代码一致性（是否符合项目现有风格）。选项 A 完全放弃审查，在生产环境中风险极高。选项 C 只关注表面问题，忽略了更深层次的质量维度。选项 D 的方法没有意义，代码长度不代表质量。考试中强调的是"AI 辅助"而非"AI 替代"，开发者的判断和审核能力仍然是核心竞争力。

**第 18 题（判断题）** MCP（Model Context Protocol）允许 Claude Code 与外部工具和数据进行安全交互。

**答案：正确**

**解析：** MCP 是 Anthropic 推出的开放协议，定义了 AI 模型与外部工具、数据源之间的标准化交互方式。通过 MCP，Claude Code 可以安全地连接数据库、API、文件系统等外部资源，扩展其能力边界。MCP 的设计注重安全性和标准化，确保交互过程可控可审计。理解 MCP 的工作原理和价值是高级使用者的必备知识，考试中可能会考察 MCP 的使用场景和配置方法。

### 第四模块：综合案例题（共 2 题）

**第 19 题（简答题）** 你正在开发一个 Node.js + React 的全栈项目。项目需要添加用户认证功能，涉及后端 API 开发、前端页面更新、数据库模型修改和测试用例编写。请描述你将如何使用 Claude Code 完成这个任务，包括具体的提示策略和执行步骤。

**参考答案：**

步骤 1：项目理解阶段。首先让 Claude Code 分析现有项目结构："请分析当前项目的目录结构和主要技术栈，列出 src/ 目录下的所有模块及其职责。" 这一步确保 Claude Code 充分理解现有项目。

步骤 2：任务分解。将认证功能分解为子任务：用户模型设计、认证中间件开发、认证 API 路由、前端登录页面、JWT Token 管理、测试用例编写。向 Claude Code 说明整体任务计划："我将分步实现用户认证功能，首先从后端用户模型和数据库迁移开始，然后是认证 API，最后是前端集成。"

步骤 3：逐步实现。每个子任务使用明确的提示，例如："在 server/models/ 中创建 User 模型，包含 email（唯一）、passwordHash、name、createdAt 字段。使用 bcrypt 进行密码哈希。请同时生成对应的数据库迁移文件。" 完成一个子任务后再进行下一个，确保每个步骤都经过验证。

步骤 4：测试与验证。完成实现后要求 Claude Code 编写测试："请为认证 API 编写完整的测试用例，包括注册成功、重复邮箱注册、密码强度验证、登录成功、登录失败（错误密码）、Token 过期处理等场景。" 运行测试并修复问题。

步骤 5：集成测试。请求 Claude Code 进行全流程验证："请检查认证功能的完整数据流：从前端登录表单提交到后端 API 处理，再到 JWT Token 返回和前端存储使用。确认所有环节正确衔接。"

**评分要点：** 答案需体现分阶段执行策略（2 分）、合理的任务分解（2 分）、具体的提示示例（2 分）、测试意识（2 分）和全流程校验（2 分）。满分 10 分。

**第 20 题（简答题）** 你的同事在使用 Claude Code 时遇到了以下问题：Claude Code 在重构一个包含 500 行代码的函数时，生成的代码经常忽略边缘情况，并且在多轮对话后开始出现"遗忘"之前讨论过的需求。请分析问题的可能原因并给出改进建议。

**参考答案：**

问题原因分析：

1. 上下文窗口限制：Claude Code 的上下文窗口有限，500 行的大函数加上重构历史可能超出有效上下文范围。当上下文溢出时，Claude Code 会"遗忘"早期讨论的内容，表现为忽略之前明确讨论过的边缘情况和需求。

2. 任务粒度过大：直接将重构一个大函数作为单一任务提交，没有分解为合理的子步骤。500 行的函数通常包含多个职责，一次性重构容易遗漏细节。

3. 缺少明确的约束记录：边缘情况需求仅通过对话口头约定，没有以文档形式固定下来，导致每次新的交互都需要重新明确。

改进建议：

1. 任务拆分：将重构任务拆分为多个小步骤。例如：先分析函数的功能和所有输入输出路径；然后识别可以独立提取的子逻辑；再逐一分离和重构每个子功能；最后组合和集成测试。

2. 使用 CLAUDE.md 记录关键需求：将识别出的边缘情况和业务约束记录到 CLAUDE.md 或一个单独的规范文档中，让 Claude Code 在每次交互前都能读取这些信息。

3. 定期使用 `/reset`：在完成一个子任务后使用 `/reset` 开始新的会话，避免上下文累积导致的问题。重置后通过良好的提示重新提供必要的上下文。

4. 增量验证：每个子任务完成后立即运行测试或进行人工审查，确保没有引入新问题，而不是等到所有重构完成后才验证。

5. 提供测试用例：在重构开始前，先让 Claude Code 为现有函数编写全面的测试用例，覆盖所有已知的边缘情况。这样重构后有测试作为安全保障。

**评分要点：** 能够识别上下文窗口限制问题（2 分）、任务粒度过大的问题（2 分）、提出任务拆分方案（2 分）、提出使用 CLAUDE.md 记录约束（2 分）、提出增量验证策略（2 分）。满分 10 分。

## 本章小结

1. 模拟试题覆盖 10 个知识领域，题目风格和难度参照真实考试设计，包括选择题、判断题和简答题三种题型。

3. 判断题考察对知识点的精确理解，常见陷阱包括绝对化表述和概念混淆。

6. 模拟练习的目的不仅是检验知识，更是训练考试节奏和时间管理能力。
