# 第20章：全栈应用开发

## 章节概述

本章通过开发一个完整的用户管理系统，展示如何使用 Claude Code 进行前后端联通的**全栈开发**。你将学会从架构设计、接口契约定义、前后端协作联调到部署运维的完整生命周期。这是前四章技能的综合运用——用 FastAPI 构建后端 API，用 React 构建前端界面，在 Claude Code 的帮助下打通全栈。

## 学习目标

- 掌握全栈项目的整体架构设计
- 学会前后端接口定义和联调
- 理解全栈调试和数据流追踪
- 能够完成全栈应用的部署

## 核心知识点

### 1. 全栈架构设计

#### 前后端分离架构

用户管理系统的整体架构如下：

```
┌─────────────────────────────────────────────────┐
│                  浏览器 (React)                   │
│             localhost:3000 (/api -> 8000)         │
└──────────────────────┬──────────────────────────┘
                       │ HTTP/JSON
                       ▼
┌─────────────────────────────────────────────────┐
│              API Server (FastAPI)                 │
│              localhost:8000/api/v1/*              │
└──────────────────────┬──────────────────────────┘
                       │ SQLAlchemy
                       ▼
┌─────────────────────────────────────────────────┐
│              Database (PostgreSQL/SQLite)         │
└─────────────────────────────────────────────────┘
```

架构决策依据：
- **前后端分离**：前端和后端可以独立开发、测试和部署。前端团队和后端团队（或同一人不同时间）可以并行工作
- **RESTful API**：前后端通过 HTTP JSON 接口通信，标准化、无状态、可缓存
- **Proxy 代理联调**：开发时 Vite 将 `/api` 请求代理到 FastAPI，无需处理 CORS
- **单体仓库**：将前后端放在同一个 git 仓库中，方便版本管理和 CI/CD 集成

向 Claude Code 发起项目初始化：

```
/start 我要创建一个全栈用户管理系统 user-management。
包含：
1. 后端：FastAPI + SQLAlchemy + SQLite
2. 前端：React + TypeScript + Vite + TanStack Query + Tailwind CSS
功能：
- 用户 CRUD（列表、创建、编辑、删除）
- 用户搜索和分页
- 用户详情页
- 角色管理（管理员/普通用户）
前后端在同一目录下的 backend/ 和 frontend/ 子目录中。
帮我搭建整体项目骨架。
```

#### 数据流设计

全应用的数据流路径：

```
用户操作 → React 组件 → API Hook (TanStack Query)
  → axios 请求 → FastAPI Router → Service Layer
  → SQLAlchemy ORM → Database
  → 响应 JSON → TanStack Query 缓存
  → React 组件重新渲染
```

关键设计原则：
- **单向数据流**：数据从数据库流向 UI，用户操作通过 API 反向写入数据库
- **缓存策略**：TanStack Query 自动缓存 GET 请求结果，使用 queryKey 管理缓存失效
- **乐观更新**：创建/编辑用户时可以立即更新 UI，待后端确认后再同步

### 2. 前后端协作

#### API 契约定义

前后端协作的第一步是定义 API 接口契约。Claude Code 可以先生成后端的 Pydantic 模型，前端再根据同样的结构定义 TypeScript 类型。

**后端 Pydantic Schema** (`backend/app/schemas/user.py`):

```python
from pydantic import BaseModel, EmailStr, Field
from datetime import datetime
from typing import Optional

class UserBase(BaseModel):
    username: str = Field(..., min_length=3, max_length=50, pattern="^[a-zA-Z0-9_]+$")
    email: EmailStr
    full_name: str = Field(..., min_length=1, max_length=100)
    role: str = Field("user", pattern="^(admin|user)$")

class UserCreate(UserBase):
    password: str = Field(..., min_length=6, max_length=100)

class UserUpdate(BaseModel):
    email: Optional[EmailStr] = None
    full_name: Optional[str] = Field(None, min_length=1, max_length=100)
    role: Optional[str] = Field(None, pattern="^(admin|user)$")
    is_active: Optional[bool] = None

class UserResponse(UserBase):
    id: int
    is_active: bool
    created_at: datetime
    updated_at: datetime

    class Config:
        from_attributes = True

class UserListResponse(BaseModel):
    items: list[UserResponse]
    total: int
    page: int
    page_size: int
    total_pages: int
```

**前端 TypeScript 类型** (`frontend/src/types/user.ts`):

```typescript
export interface User {
  id: number;
  username: string;
  email: string;
  full_name: string;
  role: "admin" | "user";
  is_active: boolean;
  created_at: string;
  updated_at: string;
}

export interface UserCreate {
  username: string;
  email: string;
  full_name: string;
  password: string;
  role: "admin" | "user";
}

export interface UserUpdate {
  email?: string;
  full_name?: string;
  role?: "admin" | "user";
  is_active?: boolean;
}

export interface UserListResponse {
  items: User[];
  total: number;
  page: number;
  page_size: number;
  total_pages: number;
}

export interface UserQueryParams {
  page?: number;
  page_size?: number;
  search?: string;
  role?: string;
  is_active?: boolean;
}
```

**前后端类型一致性**：使用 Claude Code 生成前端类型时，可以要求：

```
根据后端 app/schemas/user.py 中的 Pydantic 模型，
自动生成对应的 TypeScript 接口定义，保持字段名和类型一致。
```

#### 接口联调策略

开发阶段的联调流程：

1. **后端先启动**：`uvicorn app.main:app --reload --port 8000`
2. **前端配置 proxy**：Vite 将 `/api` 请求转发到 `localhost:8000`
3. **同时启动前后端**：两个终端分别运行

当接口出现问题时，Claude Code 可以帮助调试：

```
前端请求 POST /api/v1/users 返回 422 错误，
响应体是 {"detail":[{"loc":["body","email"],"msg":"value is not a valid email address"}]}。
说明前端的 email 字段格式不对，请检查 UserCreate 类型和表单验证。
```

#### 错误处理一致性

定义统一的错误响应格式，前后端共同遵守：

```python
# 后端统一错误格式
from fastapi import HTTPException
from pydantic import BaseModel

class ErrorResponse(BaseModel):
    detail: str
    code: str  # 机器可读的错误码
    field: str | None = None  # 关联的表单字段

# 使用示例
raise HTTPException(
    status_code=400,
    detail=ErrorResponse(
        detail="Username already exists",
        code="DUPLICATE_USERNAME",
        field="username",
    ).model_dump(),
)
```

前端统一处理错误：

```typescript
// 前端 API 拦截器
api.interceptors.response.use(
  (response) => response,
  (error) => {
    const errData = error.response?.data;
    // 统一错误格式
    const formatted = {
      message: errData?.detail || "Unknown error",
      code: errData?.code || "UNKNOWN",
      field: errData?.field || null,
      status: error.response?.status || 500,
    };
    return Promise.reject(formatted);
  }
);
```

### 3. 全栈调试

#### 端到端调试流程

全栈调试通常需要追踪数据从 UI 到数据库的完整路径。Claude Code 可以帮你分析问题。

**场景示例**：用户编辑后页面没有更新。

```
Claude，用户编辑功能有问题。编辑提交后，TanStack Query 的缓存没有失效，
导致列表仍然显示旧数据。请帮我修复。
```

Claude Code 会建议在 `useMutation` 的 `onSuccess` 回调中调用 `queryClient.invalidateQueries`：

```typescript
// frontend/src/hooks/useUsers.ts
import { useQuery, useMutation, useQueryClient } from "@tanstack/react-query";
import { userApi } from "../api/users";
import type { User, UserCreate, UserUpdate, UserListResponse, UserQueryParams } from "../types/user";

export function useUsers(params: UserQueryParams) {
  return useQuery<UserListResponse>({
    queryKey: ["users", params],
    queryFn: () => userApi.list(params),
  });
}

export function useUser(id: number) {
  return useQuery<User>({
    queryKey: ["users", id],
    queryFn: () => userApi.get(id),
    enabled: !!id,
  });
}

export function useCreateUser() {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: (data: UserCreate) => userApi.create(data),
    onSuccess: () => {
      // 创建成功后，使用户列表缓存失效，触发重新获取
      queryClient.invalidateQueries({ queryKey: ["users"] });
    },
  });
}

export function useUpdateUser() {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: ({ id, data }: { id: number; data: UserUpdate }) =>
      userApi.update(id, data),
    onSuccess: (updatedUser) => {
      // 同时使列表和详情缓存失效
      queryClient.invalidateQueries({ queryKey: ["users"] });
      queryClient.setQueryData(["users", updatedUser.id], updatedUser);
    },
  });
}

export function useDeleteUser() {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: (id: number) => userApi.delete(id),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ["users"] });
    },
  });
}
```

#### 网络请求分析

在 Chrome DevTools 的 Network 面板中，你可以：
- 查看每个 API 请求的状态码、耗时、请求体和响应体
- 过滤 `/api` 路径集中的请求
- 查看请求的 `X-Request-Id` 追踪全链路

Claude Code 可以帮助添加请求日志：

```
请给后端添加请求日志中间件，记录每个 API 请求的方法、路径、
状态码和耗时（毫秒），格式为 JSON 日志。
```

```python
# 后端添加的日志中间件
import time
import logging
from fastapi import Request

logger = logging.getLogger("api")

@app.middleware("http")
async def log_requests(request: Request, call_next):
    start = time.time()
    response = await call_next(request)
    elapsed = int((time.time() - start) * 1000)
    logger.info({
        "method": request.method,
        "path": request.url.path,
        "status": response.status_code,
        "elapsed_ms": elapsed,
    })
    return response
```

#### 性能瓶颈定位

全栈性能问题可能发生在三个环节：

1. **数据库查询慢**——用 SQLAlchemy 的 `echo=True` 查看 SQL
2. **API 响应慢**——用日志中间件记录耗时
3. **前端渲染慢**——用 React DevTools 的 Profiler

向 Claude Code 请求优化：

```
用户列表页面加载 1000 条数据时非常慢。
请分析后端接口，添加分页和数据库查询优化。
```

Claude Code 会建议：
- 强制分页，限制最大 `page_size`
- 添加数据库索引
- 使用 `selectinload` 避免 N+1 查询（如果有关联数据）
- 前端添加虚拟滚动

class User(Base):

## 本章小结

1. **全栈架构核心是前后端分离**：前端负责 UI 渲染和交互，后端负责业务逻辑和数据存储，接口契约（API 定义）是两者的桥梁。Vite proxy 解决开发联调的 CORS 问题。

2. **类型一致性减少联调 Bug**：后端 Pydantic Schema 和前端 TypeScript 类型应保持同步。Claude Code 可以根据 Pydantic 模型自动生成 TypeScript 接口，避免手动导致的字段名不同步问题。

3. **TanStack Query 缓存管理是关键**：创建/更新/删除操作后必须使相关 queryKey 的缓存失效，否则列表不会自动刷新。`onSuccess` 回调中调用 `invalidateQueries` 是标准做法。

4. **从 SQLite 到 PostgreSQL 的无缝切换**：开发阶段使用 SQLite 零配置启动，生产环境切换到 PostgreSQL。只需修改 `DATABASE_URL` 环境变量，代码无需任何改动。

5. **全栈调试需要逐层排查**：浏览器 Network → 后端日志 → 数据库日志。Claude Code 可以帮助在每一层添加调试信息，快速定位瓶颈或 Bug。

6. **Docker Compose 简化部署**：一个 `docker-compose up -d` 命令启动前端（Nginx 提供服务 + 代理 API），后端（Uvicorn），数据库（PostgreSQL），简化环境配置流程。

## 思考题

1. **全栈开发中最容易出现问题的环节是什么？**
   - **提示**: 接口对接阶段最容易出问题。典型问题包括：(1) 前后端对字段名大小写理解不一致（Python 用 snake_case，JavaScript 用 camelCase）；(2) 后端返回的日期时间格式前端未正确处理；(3) 后端修改了 API 响应结构但前端未同步更新。解决方案：使用 OpenAPI 生成客户端代码，或采用类型共享的 monorepo 结构。

2. **如何确保前后端接口的一致性？**
   - **提示**: 三种方案：(1) **OpenAPI 代码生成**——后端根据 Pydantic 模型自动生成 OpenAPI 规范，前端用 openapi-generator 生成 TypeScript 客户端代码；(2) **Monorepo 类型共享**——在 monorepo 中定义 shared 包，导出前后端共用的类型定义；(3) **定期自动化测试**——前端测试中 mock 后端响应，确保类型兼容；后端测试中验证全部端点的响应结构。Claude Code 可以帮助生成 OpenAPI 规范和自动化测试。
